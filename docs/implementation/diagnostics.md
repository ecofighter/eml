# 診断の出し方

位置づけ: 手引き。

番号ごとの診断が指す場所 (primary と secondary)、メッセージと note の言い方、help と fix の文言と付ける条件を書く。番号の意味、データ構造、診断の順、番号の範囲、連鎖する診断の抑止は [診断](../spec/diagnostics.md) で定める。

## 番号の置き場所

E0xxx は `eml_syntax::codes` (E0004 だけは `eml_diagnostics`)、E1xxx は `eml_hir::codes`、E2xxx、E3xxx、E4xxx は `eml_types::codes` に置く。

## 番号ごとの出し方

番号の意味は [診断](../spec/diagnostics.md) の「割り当て済みの番号」が定める。この表は、表示の決まりがある番号について、今の行の全体を写したものである。

| 番号 | 定数 | 内容 |
|---|---|---|
| E0002 | `UNTERMINATED_STRING` | 閉じていない文字列リテラル (複数行の文字列、raw 文字列、コマンドリテラルを含む) と、閉じていない補間の穴。単一行の文字列 (「unterminated string literal」) とコマンドリテラル (「unterminated command literal」) は、開きから改行かファイルの終わりの手前までを指す。複数行の文字列 (「unterminated multi-line string」) は開きの `"""` を、raw 文字列 (「unterminated raw string」) は開きの `r"` か `r#"` を指す。ラベルは閉じの書き方を示す (「missing closing `"`」など)。閉じていない穴は、見出しを「unterminated string interpolation」にして `\{` を指し、ラベルを「missing closing `}`」にする。改行で閉じた穴には、note「an interpolation must be closed on the same line」を付ける。ファイルの終わりで閉じた穴には付けない。層が重なっても、報告は一番内側の層の1件だけである ([字句](../spec/lexical.md) の「改行での回復」)。報告する単一行の文字列かコマンドリテラルのすぐ外が穴なら、その穴の `\{` を secondary にする。ラベルは、文字列なら「this interpolation is not closed; a `"` inside `\{…}` starts a new string」、コマンドリテラルなら「this interpolation is not closed; a backtick inside `\{…}` starts a new command literal」である |

| E1001 | `UNDEFINED_NAME` | 未定義の値の名前。修飾した名前と import の並びでは、メッセージにモジュールの名前を書く (「in module `Report.Csv`」)。修飾子がユーザーのモジュール (`Fs`) を指し、そのモジュールに隠された同じパスの標準ライブラリのモジュールが名前を `pub` で定義しているときは、help「the standard `Fs` is hidden by your module `Fs`; `import Std.Fs as F` reaches it」を付ける。`fn` の節の本体 (入れ子のラムダを含む) で `k` が見つからないときは、note「a `fn` clause has no `k`; write `ctl` to take the continuation」を付ける。`fn` の節は継続を名前で受けないためである。`never` の操作の節は `ctl` にしても継続を持たないので、付けない |

## 型エラー

制約の由来 (引数の位置、`if` の各枝、型注釈など) をもとに、「expected / found」と、その根拠になった場所を示すラベルを出す ([型と Kind](../spec/types.md))。

`fn` の節の本体の型の誤りは、本体を指し、期待する型の由来を「`fn` の節の本体」(`Origin::FnClauseBody`) にして報告する。note は「the `fn` clause for `ask` must return the result type of `ask`」で、パラメータ付き handler では「the `fn` clause for `ask` must return a pair of the result of `ask` and the next state」である。HIR が足した隠れた `k` の呼び出しの引数の誤りとしては報告しない。

リストのパターン `[p1, …, pn]` の型の誤りは、HIR が組んだ `::` と `Nil` のコンストラクタのパターンとして報告する。そのため、ほかのコンストラクタのパターンと同じく「`::` is a constructor of `List`」の note が付く。`::` はユーザーが書ける名前なので、リストのパターンだけの言い方を作らず、この note のままにする。

## 線形性の診断

| 誤り | 指す場所 |
|---|---|
| 二重使用 | 1回目に消費した場所と、2回目に使った場所 |
| 消費されていない | 束縛した場所とスコープの終わり。同じブロックの後の `let` で隠されたときは、隠した束縛。help と fix で `drop x` の追加を提案する |
| `_` で `Lin` の値を受けた | そのパターン。help で、変数に束縛して `drop` するよう提案する。省いた `return` の節が `Lin` の状態を捨てたときは、`from` の初期値 |
| `multi` の呼び出しをまたぐ | primary はその呼び出し、または `handle` で、起こしうる `multi` の操作を書く。secondary は値 (変数の束縛、途中の値の部分式、`return` の節、`fn` の節) と、`multi` と宣言した操作。値が handler の状態のときは、`from` の初期値を値の secondary にする。help で、呼び出しの前に使い終えるよう提案する |
| 呼んだ関数が `multi` の呼び出しをまたがせる | primary は呼んだ関数を参照した位置。secondary は、呼んだ関数の中で値をまたがせている呼び出し、またはその先の関数の参照 (1段だけ) |
| 再帰する組のローカル関数が `Lin` の値を捕まえた | 組の関数を参照した位置。関数の本体に組の関数への参照があればその最初の参照、なければ組の中の最初の参照である。見出しは、自分を呼ぶ場合も相互に呼ぶ場合も「a recursive local function cannot capture a linear value」にする。ラベルは「`f` refers to `g` here, so it may be called any number of times」にする (`f` は参照した関数、`g` は参照された関数の名前)。note は、`LINEAR_NOTE` の後に「pass linear values to a recursive local function as arguments」を続ける。制約は上限の由来の位置に出るので、primary は捕まえた変数でなく組の関数への参照を指す。捕まえた関数の本体に組の関数への参照がないときは、primary のラベルがその関数を名指ししないので、その関数の束縛を secondary にし、ラベルを「`h` is in this recursive group and captures a linear value」にする (`h` は捕まえた関数の名前)。再帰する組の関数そのものには、使用回数の誤り (E3002、E3003) を出さない。その関数の型は `Unr` に限られ、数えて誤りになるのは型が `Lin` のときだけで、そのときはこの E3001 が出ているためである |
| 継続の扱い忘れ | `k` を呼びも `drop` もしていない handler の節 |
| 操作の型が何回でも使える値を求める所に、線形な値が届いた | その操作の handler の節の頭 (操作の名前から最後の引数まで)。見出しは「a linear value is used where the type of `mk` requires a value that may be used any number of times」、ラベルは「this clause handles `mk`」である。引数の型から出た制約なら、操作の引数は何回でも使えるので線形な値として扱えない、という note を付ける。結果の型から出た制約なら、操作を呼ぶ側は結果の中の関数を何回でも呼べる、という note を付ける。制約は節の中の値ではなく操作の型から出るので、primary は値の位置を指さない。線形の下限がラムダの捕獲から来たときは、そのラムダを secondary にし、ラベルを「this lambda captures a linear value」にする |
| 分解のパターンに書かない `Lin` なフィールド | レコードのパターンの全体。見出しは「the field `log` is discarded, but it holds a linear value」、ラベルは「this pattern leaves out `log`」で、help「bind `log` in the pattern and pass it to `drop`」を付ける |
| 射影の残りの `Lin` なフィールド | 射影の式。見出しは「the field `log` is discarded, but it holds a linear value」、ラベルは「this projection leaves the field `log` behind」で、help「take the value apart with a record pattern and pass `log` to `drop`」を付ける。タプルでは「the element `0`」と言い、help を「take the tuple apart with a pattern and pass element `0` to `drop`」にする。フィールドのセクションの射影には help を付けない。隠れた引数は分解を書けないためである |
| 更新で上書きされる `Lin` な古い値 | 更新の式。見出しは「the old value of the field `log` is discarded, but it holds a linear value」、ラベルは「this update overwrites `log`」で、help「take the old `log` out with a record pattern and pass it to `drop`」を付ける |

## 網羅性の診断

| 番号 | 誤り | 重大度 | 指す場所 |
|---|---|---|---|
| E4001 | 網羅されていない `match` | Error | `match` 式。漏れているパターンの例を note で示し、fix で枝の追加を提案する (fix は、どの型にもなる仮置きの式を言語に入れるときに一緒に入れる) |
| E4002 | 網羅されていない等式 | Error | primary はシグネチャの関数名、secondary は各等式の先頭。漏れている引数の並びの例 (`f None _`) を note で示し、fix で最後の等式の後への等式の追加を提案する (fix は、どの型にもなる仮置きの式を言語に入れるときに一緒に入れる) |
| E4004 | 到達しない枝 | Warning | その枝のパターン |
| E4005 | 到達しない等式 | Warning | その等式の引数のパターン |
| E4003 | 反駁可能な `let` / ローカル関数の引数 / ラムダの引数 / handler の節と `return` の節の引数のパターン | Error | そのパターン |

等式の場合はソースに `match` 式がないので、指す場所を等式に合わせて決めている。handler の節はラムダと同じく持ち上げる関数で、引数のパターンも同じ経路でコンパイルするため、ラムダの引数と同じ E4003 にする。

漏れているパターンの例は、note に最大3つ並べる。3つより多ければ、残りがあることを書き添える。
