# 式

位置づけ: 規範。

式の構文と、HIR で行う脱糖を定める。handler については構文と脱糖だけを扱い、意味 (deep handler、操作の多重度、継続の線形性) は [エフェクトと handler](effects.md) で定める。

## ブロックと `let`

```haskell
copy : String -> String -> <IO> Unit
copy src dst =
  let f = Fs.open src
  let (f, text) = Fs.read_all f
  Fs.close f
  write_text dst text
```

- ブロックは文を並べたものである。最後の文が式ならその値がブロックの値で、そうでなければ `()` になる
- 最後でない式文は `Unit` 型でなければならない
- `let` による同じ名前の再束縛 (シャドーイング) を許す
- この2つと `Lin` の値の関係 (式文で捨てる、消費前に隠す) は [線形性](linearity.md) の「基本の規則」で定める
- 1行で書くための式の形 `let p = e in e2` を用意する。ブロックの `let` と同じ意味である
- ローカルの `let` は単相で、注釈なしで推論する ([型と Kind](types.md))。関数の形の `let` は下の「ローカル関数」で定める

## ローカル関数

```haskell
pub map : (a -> <e> b) -> List a -> <e> List b
map f xs =
  let go acc ys =
    match ys with
      | Nil -> reverse acc
      | y :: rest -> go (f y :: acc) rest
  go Nil xs
```

- ブロックの文 `let name apat+ = body` は、ローカル関数 `name` を定義する。引数はラムダの引数と同じく `apat` で書き、`(acc : Int)` のように型を明示できる
- 1行の形 `let name apat+ = e in e2` も書ける。ブロックの文と同じ意味である
- 等式は1つだけである。同じ名前の `let` を続けて書くと、後の定義が前の定義を隠す
- 引数の後ろに `: type` は書けない。書いたら E0011 である
- 関数の形の `let` の後に、`and name apat+ = body` を続けて書ける。`let` と、続く `and` のすべての定義が1つの組になり、互いに呼び合える (下の「組」)
- 引数のパターンは、ラムダの引数と同じく反駁できないものでなければならない。`let go (Some x) = x` や `let go 0 = 1` は E4003 である。parser は受け付け、網羅性の検査が拒む ([網羅性](exhaustiveness.md))
- 関数の形かどうかは、`let` の後の2つのトークンで決める ([文法](grammar.md) の「文法上の補足」)

### 組

```haskell
parity : Int -> <Panic> Bool
parity n =
  let even k = if k == 0 then True else odd (k - 1)
  and odd k = if k == 0 then False else even (k - 1)
  even n
```

- 組は、相互再帰するローカル関数を書くためのものである (OCaml の `let rec … and …` と同じ)。1行の形も同じで、`let f x = a and g y = b in e` と書ける
- `and` を `let` と同じ列の行の先頭に書くと、parser は直前の `SEP` を読み飛ばす ([レイアウト規則](layout.md) の「`then` / `else` / `and` の前の `SEP`」)。前の定義の本体が字下げしたブロックなら、`and` の行がそのブロックを閉じる
- `and` の後ろは関数の形の定義でなければならない。引数のない `and x = 1` と、値の `let` の後の `and` は E0011 である。`and` の定義も、引数の後ろに `: type` を書けない (E0011)
- 組の中で同じ名前を2回定義したら、2つ目の定義を指して E1017 にする。組の中の参照は1つ目の定義を指す
- `and` のない、続けて書いた関数の形の `let` は、別々の組である
- 組の中のどれかの本体が組の関数 (自分を含む) を参照する組を、再帰する組と呼ぶ。自分を呼ぶ1つの関数も再帰する組である
- 組を `and` で明示するのは、組を書いた所だけにするためである。続けて書いた関数の形の `let` を暗黙に1つの組にすると (Haskell の `let` と同じ)、組の後ろの関数が、組の前の本体の中でも外側の同じ名前を隠す。そのため、続けて書いた `let` の名前を1つ変えるだけで、前の本体の参照先が知らないうちに変わりうる。続けて書いた同じ名前の `let` も、前の定義を隠せなくなる

### 有効範囲

- 関数の形の `let` では、組のすべての名前の有効範囲が、組のすべての本体と、ブロックの残り (1行の形なら `in` の後ろ) を含む。本体の中で自分と組の相手を呼べる
- `and` のない、続けて書いた `let` では、後の `let` が前の `let` の名前を隠し、前の本体から後の `let` の名前は見えない
- 引数の名前は本体の中で `name` を隠せる (`let go go = …` の本体の `go` は引数である)
- パターンの束縛の有効範囲は変わらない。`let x = x + 1` と `let f = fn y -> f y` の右辺の `x` と `f` は、外側の束縛を指す

### 型

- ローカル関数の型は単相である。注釈のない引数の型には、ラムダと同じく推論用の型変数を使う。外側の関数のシグネチャの型変数と row 変数は、本体でも見える
- 最後の矢印の row は、本体の後で閉じない。組の関数の呼び出しも自分への呼び出しも、ほかの呼び出しと同じく row の包含になり、外側の本体全体で解く。値として参照するときは、関数の row 変数をそのまま共有する (詳細は [型と Kind](types.md) の「ローカル関数の推論」と「呼び出しの包含を解く」)
- 組は1つの単位として検査する。組の関数は、関数ごとに最後の矢印の row を持つ ([型と Kind](types.md) の「ローカル関数の推論」)
- 多相なローカル関数は書けない
- `Lin` の値との関係は [線形性](linearity.md) で定める。再帰する組の関数は何度も呼ばれうるので、`Unr` の値しか捕まえられない

### 性能

- ローカル関数は、どこから呼んでも直接呼び出しになる。呼ぶたびに閉包を確保しない ([Core IR](core-ir.md) の「ローカル関数の持ち上げ」)

## ラムダ

```haskell
people |> filter (fn p -> p.age >= 18)
each items (fn item ->
  println item)
```

- `fn x y -> e`、`fn (a, b) -> e`、`fn () -> e`、`fn (x : Int) -> e` と書く
- 型の明示 `(p : T)` は、ラムダの引数だけでなく、どのパターンの位置でも書ける。タプルの要素に書くときは `((a : Int), b)` とする。`(a : Int, b)` は構文エラーである
- 関数の引数や演算の項にするときは、括弧で囲む ([文法](grammar.md) の「文法上の補足」)。ブロックの残りを渡すなら、`use item <- each items` とも書ける (「`use`」)
- `->` で行が終われば、本体はブロックになる。括弧の中でも同じで、そのブロックは閉じ括弧か `,` で閉じる ([レイアウト規則](layout.md))

## 関数適用

- 関数はカリー化する。部分適用はクロージャになる
- 関数適用 `e0 e1 … en` は、呼ばれる式 `e0`、引数 `e1`、…、`en` をこの順にすべて評価し、その後で矢印 `1` から `n` を順に適用する。OCaml の `f a b` と同じ順である。括弧は順を変えない (`(f 1) (g ())` と `f 1 (g ())` は同じ式である)。`x |> f a` は `(|>) x (f a)` の呼び出しなので、引数の順に `x` を先に評価する ([宣言](declarations.md) の `|>`)。矢印 `1` を適用してから `e2` を評価したいときは、`let g = e0 e1` と書いて順を文面に出す
  - 引数が呼び出しの前に出そろうので、`pick 1 (Fs.open "x")` と `let f = Fs.open "x"` の後の `pick 1 f` は同じ意味になり、持ち越し規則 ([エフェクトと handler](effects.md)) も同じに扱う。矢印 `1` が `multi` の操作を起こすなら、どちらも E3006 である
- 矢印の適用の間に評価は入らないので、処理系は引数をまとめて渡せる。既知の関数、ローカル関数、extern の関数、操作、コンストラクタの引数の数までの引数は、本体が引数のそろうまで動かないので、1回の呼び出しで直接渡す。それを超える引数は、返った関数値に順に適用する。クラスのメソッドの引数の数は、メソッドのシグネチャの矢印の数である。instance の等式の引数の数を使うと、どの instance を選ぶかで直接呼ぶ範囲が変わるためである。引数のないトップレベルの値は、参照するたびに計算して関数値を返すので、既知の関数に含めず、関数値として扱う。関数値の呼び出しは、すべての引数を1つの適用で渡す。handler の節の `k` は、引数の数が分かる呼び出し先として扱う (状態なしは1、状態ありは2)。そのため `k st (st + 1)` は1回の再開になる。手順は持ち越し規則にも効くので、`eml_hir::call_steps` の1か所で決める

## `if`

```haskell
if errors > 0 then
  eprintln "\{show errors} errors"
if s >= 1 then println line
else if verbose () then println "skipped"
```

- **then 節の型が `Unit` の場合、`else` を省略できる。** `else ()` を補ったものとして扱う (HIR は `else` のない `if` として残し、型検査は then 節が `Unit` でなければ診断する)。正格評価なので、Haskell の `when c (println x)` は `println x` を必ず評価してしまう。そのため構文で用意する
- `else` の枝はできるだけ遠くまで伸びる (`if c then 1 else 2 + 3` は `else (2 + 3)`)
- `else if` を連ねられる。1行の中に入れ子にした場合、`else` は一番近い `if` に付く
- ブロックの中で `then` / `else` を `if` と同じ列に書いた場合の扱いは [レイアウト規則](layout.md) にある

## `match`

```haskell
match first_word line with
  | "ERROR" -> 2
  | "WARN"  -> 1
  | _ ->
      log "other"
      0

match b with | True -> 1 | False -> 0
```

- 枝は `|` で始める。`with` で行が終われば字下げしたブロック、そうでなければ同じ行に枝を並べる
- 1行の形では、枝の本体の式は次の `|` の手前で終わる (`|` 単独は演算子ではないため)。入れ子の `match` を1行に書いた場合、後ろの枝は内側の `match` に付く
- 網羅性の検査は [網羅性](exhaustiveness.md) で定める

## リスト

```haskell
let xs = [1, 2, 3]
let ys = 0 :: xs
match ys with
  | [] -> 0
  | [a, b] -> a + b
  | x :: rest -> x
```

- 式 `[e1, …, en]` は、Prelude の `List` の値 `e1 :: … :: en :: Nil` である。`[]` は空のリストである。要素の後に末尾のカンマを書ける。型は `List t` で、要素はどれも型 `t` を持つ
- 要素は左から評価する。関数適用の引数と同じ方針である (上の「関数適用」)。値を組み立てるのは、すべての要素を評価した後である
- パターン `[p1, …, pn]` は、パターン `p1 :: … :: pn :: Nil` と同じ意味である。変数は要素の順 (左から) に束縛する。`[]` のパターンは `Nil` である
- `[…]` は、式でもパターンでも、名前を引かずに Prelude の `Nil` と `::` を指す。自分の `Nil` を定義したモジュールでも、`[]` は Prelude の空のリストである。誤りのないプログラムでは、中置の `x :: xs` は、ふつうの名前解決で Prelude の `::` に届く。ほかのモジュールで `::` を宣言すると E1044 になり、`::` を宣言するモジュールが Prelude だけになるためである ([宣言](declarations.md) の「`data` と `type`」)
- 期待する型が `List t` の形に決まっているときは、各要素を `t` に対して検査し、型の誤り (E2001) を要素の位置で報告する。それ以外では、最初の要素の型を `t` にし、2つ目からの要素を `t` に対して検査する。このときの誤りには、最初の要素の型を示す secondary を付ける。空のリストの `t` は、新しい型変数のまま残る
- 要素の型が決まらない `[]` の `show` や `==` は、既定の型を選ばないので E2009 になる。型の明示 (`([] : List Int)`) で直す ([型と Kind](types.md) の「制約」)
- 括弧の中で要素を読む規則は、タプルと同じである。要素は `expr` なので、`if` や `fn` も括弧なしで書ける。複数の行に分けて書ける ([レイアウト規則](layout.md) の規則 2 と規則 4)
- 型の構文は `List a` だけで、`[a]` の形はない ([文法](grammar.md))

## レコード

```haskell
data Person =
  | Person { name : String, age : Int }

older : Person -> <Panic> Person
older p = { p | age = p.age + 1 }

-- map : (a -> b) -> List a -> List b
names : List Person -> List String
names people = map (.name) people
```

構文の一覧、線形性の規則、実行時の表現は [直積型とレコード](records.md) にある。

- 作る式 `C { f1 = e1, …, fn = en }` は、コンストラクタ `C` の値を作る。値は、位置のコンストラクタの呼び出しにフィールドの値を宣言の順に渡したものと同じである。コンストラクタは名前で引き、修飾もできる (`M.Person { … }`)。省略形 `{ name }` の値は、その位置で `name` を普通に名前解決した参照である
- 作る式のフィールドの式は、書いた順に評価する。値を組み立てるのは、すべてのフィールドを評価した後である
- 射影 `e.f` と `e.0` は、`e` を評価して、そのフィールドの値を取り出す。フィールドは `e` の型から引く ([型と Kind](types.md) の「フィールドの解決」)
- 更新 `{ e | f = v, … }` は、`e` の値を写し、書いたフィールドを新しい値に置き換えた値である。型は `e` の型のままで、型を変える更新はない。`e` を先に評価し、次にフィールドの式を書いた順に評価する。意味は写しで、一意な値をその場で書き換えるのは処理系の最適化 (Perceus の reuse) に任せる
- 分解のパターン `C { f = p, g }` は、位置のコンストラクタのパターンに、各フィールドのパターンを宣言の順に並べたものと同じ意味である。書かないフィールドは `_` になる。パターンの変数は書いた順に束縛する。決定木と網羅性の検査は、コンストラクタのパターンと同じである
- 作る式、パターン、更新に同じフィールドを2回書いたら E1045、コンストラクタにないフィールドを作る式かパターンに書いたら E1046 にする。フィールドの名前を持たないコンストラクタに `{…}` を書いた場合 (`P {}` を含む) も E1046 である。作る式に書いていないフィールドがあれば、足りない名前をすべて並べて、作る式の位置に E1047 を1件出す。E1047 は、その作る式にほかの誤りがないときだけ出す
- 誤りのある作る式と更新は、式全体を誤りの跡にする。正しく書いたフィールドの式は変換し、その中の誤りは報告する。誤りのあるパターンも、中のパターンの変数は束縛して、パターン全体を誤りの跡にする。同じフィールドを2回書いた `{ name, name }` は E1045 だけを報告し、同じ変数の2回目の束縛の E1017 を重ねない
- 更新が書いたフィールドがその型にあるかは、型検査が調べる (E2014)

## 補間

```haskell
wrap : Show a => a -> String
wrap x = "<\{x}>"

main : Unit -> <IO> Unit
main () =
  let name = "eml"
  println "Hello, \{name}! \{[1, 2]} \{wrap "hi"}"
```

この例は `Hello, eml! [1, 2] <hi>` を出す。

- 穴のある文字列は、各穴の式を Prelude の `display` で文字列にし、前後の本文とつないだ `String` である。`String` の穴は引用符なしで入る。ほかの型の穴は、instance が `display` を上書きしていなければ `show` と同じ形になる ([宣言](declarations.md) の「Prelude のクラス」)。そのため、穴の値の中の文字列は引用符付きのままで、`"\{Some "x"}"` は `Some "x"`、`"\{(1, "a")}"` は `(1, "a")` になる
- 穴は名前を引かずに Prelude の `display` を呼ぶ。自分の `display` を定義したモジュールでも、補間の意味は変わらない。つなぐのも Prelude の extern の連結で、ユーザーの `++` によらない
- 穴の式の型 `a` には、`display` の参照が `Show a` の制約を付ける。instance がなければ E2006、型が決まらなければ E2009 になる。どちらもほかのメソッドと同じ文言で、`display` の名前が出る (「`display` requires `Show Foo`」、「cannot decide which instance of `Show` to use for `display`」)。`display` は補間の意味としてこの文書に書くメソッドなので、補間のための文言は足さない
- 多相の穴も instance で決まる。上の `wrap "hi"` は `<hi>` になる。穴の型を見て `show` を呼ぶかを決める方式では、同じ値でも書いた位置の型で表示が変わる。`display` を呼ぶ方式では、そうならない
- 穴は左から評価する。関数適用の引数と同じ方針である (上の「関数適用」)。穴の値は `display` に渡して消費する。線形性と持ち越し規則の検査も、穴を左から順にたどる
- HIR は各穴を `display e` の呼び出しにし、本文と穴の並びとして持つ。呼び出しの範囲は `\{…}` の全体である。`++` の呼び出しにまで脱糖しないのは、連結を Core IR への変換がまとめて組むためである ([Core IR](core-ir.md) の「変換の規則」)

## 演算子の列と単項マイナス

- CST では、`a op1 b op2 c` を平たい列 (`OP_SEQ` ノード) のまま持つ
- HIR への変換で、名前解決の後に fixity の表を引いて木に組み直す (GHC の renamer と同じ方式)。結合しない演算子同士の並び (`a < b < c`) や、優先順位が同じで結合の向きが違う演算子の並びは、エラーとする (E1006)
- 単項の `-` は Haskell と同じ扱いにする。Prelude のクラス `Num` のメソッド `negate` の呼び出しとして、優先順位 6 で組み直す。ユーザーが `negate` という名前を定義しても、Prelude のメソッドを呼ぶ。`f -1` は `f - 1` (引き算) と読むので、負の数を渡すときは `f (-1)` と書く
- 単項の `-` の直後に整数か浮動小数のリテラルのトークンが続くとき (`-1`、`- 1`、`-1.5`) は、`negate` の呼び出しにせず、負のリテラルとして1つにまとめる。そのため、負のリテラルは `Panic` を起こさない定数である。`-0.0` は符号のビットの立った `Float` で、`0.0` とは別の値である。`-(1)` や `-x` は `negate` の呼び出しのままである。パターンの負のリテラルは構文の段階で読む
- 標準の演算子の表は [宣言](declarations.md) の「fixity」にある

## セクション

| 書き方 | 意味 |
|---|---|
| `(+)` | `fn a b -> a + b` |
| `(+ 1)` | `fn x -> x + 1` |
| `(1 +)` | `fn x -> 1 + x` |
| `(.name)` | `fn x -> x.name` |
| `(.0)` | `fn x -> x.0` |
| `(- 1)` | 負の数 -1 (セクションではない。Haskell と同じ) |
| `(+ a * b)` | `fn x -> x + a * b` |
| `(a * b +)` | `fn x -> a * b + x` |

- セクションの被演算子は演算子の列でもよい。HIR で fixity の表を引いて組み直し、セクションの演算子を空いた側に置いた式として読めるときだけ許す。被演算子の中の演算子は、セクションの演算子より強く結合するか、優先順位が同じで結合の向きが空いた側に合っていなければならない。そうでなければエラーとする (E1023)。たとえば `(* a + b)` はエラーである。左結合の `+` では、`(a + b +)` は許し、`(+ a + b)` はエラーとする
- フィールドのセクション `(.f)` は、HIR が `fn x -> x.f` のラムダに組む。`x` は書き手の名前と重ならない隠れた引数で、引数と射影の範囲はどれもセクション全体である
- 被演算子が前置の `-` で始まるときも、演算子の列と同じ規則で読む。右が空いたセクション `(- e op)` では、前置の `-` を優先順位 6 の左結合の演算子として数える。そのため `(- 2 *)` はエラー (E1023) で、`(- 2 +)` は `fn x -> (- 2) + x` である。左が空いたセクション `(op - e)` は、演算子の列 `x op - e` で前置の `-` が許されないときにエラー (E1006) とする。たとえば `(+ -1)` と `(* - 2)` はエラーである

## `use`

```haskell
main () =
  use with_env
  use tmp <- with_temp_dir
  use with_log "\{tmp}/build.log"
  build tmp
  deploy ()
```

`use` は、ブロックの残りを最後の引数のラムダとして渡す糖衣構文である。

| 書き方 | 脱糖後 |
|---|---|
| `use f a b` の後にブロックの残り | `f a b (fn () -> 残り)` |
| `use p <- f a b` の後にブロックの残り | `f a b (fn p -> 残り)` |

- 純粋な糖衣構文で、型、線形性、エフェクトの規則は増えない
- `<-` は代入 (「`var`」) と同じく、左辺が右辺から値を受け取ることを表す。`use p <- f a b` では、`p` が `f a b` の渡す値を受け取る
- ブロックの最後の文が `use` の場合はエラーとする (包む残りがない) (E1024)
- `use` の後ろのコードは、すべてラムダの中に入る。そのラムダが `multi` で複数回再開されれば、`use` の後ろのコードも複数回実行される。この点は LSP の hover とドキュメントで補う

## `var`

```haskell
sum_to : Int -> <Panic> Int
sum_to n =
  var total = 0
  for 0 n (fn i -> total <- total + i)
  total
```

- `var x = e` と `var x : T = e` はブロックの文である。`var` の後には名前を1つだけ書く。パターン (`var (a, b) = …`) は E0011 である。`var` はトップレベルの item にも REPL の入力の形にもならない
- 変数の範囲は同じブロックの、その文より後ろのすべてである。初期値の中の `x` は外側の `x` を指す (`let` と同じ)。変数は `let` と同じく前の同じ名前を隠し、後の束縛に隠される
- 変数のブロックの最後の式は、そのブロックの最後の式である。ブロックが文で終われば、最後の式はない。最後の式も変数の範囲に入る
- 変数の名前を書いた所は変数の読み出しである。範囲の中のラムダと局所関数も変数を読み書きできる。閉包は変数を捕まえず、変数のエフェクト (下の「HIR の形」) を通して変数に届く
- `lhs <- e` は、右辺の値を左辺の変数か要素が受け取る式で、値は `()` である。`<-` の向きは `use p <- e` と同じである (「`use`」)。左辺は `var` の名前か、`var` の名前の添字 `x[i]` に限る。それ以外は E1053 である
- `e[i]` は後置の添字である。`e` は `var` の名前でも、ほかの式でもよい。添字の読み書きの型は [型と Kind](types.md) で定める

### HIR の形

- `var` の文は1つの式のノード (`ExprKind::Var`) になる。ノードはブロックの残りの文と最後の式を本体のブロックに持ち、値は本体の値である。`use` と同じく、残りの文を入れ子にする。ノードは元のブロックの最後の式も持ち、同じブロックのどの `var` も同じ式を指す
- `var` の地点ごとに、そのモジュールに合成のエフェクトの項目を1つ作る。項目は名前空間に入らず、型引数も操作も持たない。名前は `var$<k>$<x>` で、`k` はモジュールの中の `var` の地点の番号 (本体を下ろす順に 0 から)、`x` は変数の名前である。診断では `var x` と表示する
  - 名前を地点ごとに変えるのは、VM が効果を名前で番号に引くためである。2つの地点が同じ名前になると、外側の地点の閉包が内側の地点の handler に届いてしまう
  - 合成のエフェクトの多重度は `Once` である。操作を持たないが、変数の操作はどれもすぐに再開するためである
- 変数の参照、代入、添字の書き込みは、それぞれ専用のノード (`VarGet`、`Assign`、`IndexAssign`) になる。添字の読み (`Index`) は、左側が `var` の名前そのものなら変数を、そうでなければ式を持つ
- 変数は地点で見えている局所変数と外側の変数を記録する。範囲の外へ出る閉包を型検査が調べるのに使う

### 意味と脱糖

- 変数の値は、地点ごとの合成のエフェクトの handler が状態として持つ ([エフェクトと handler](effects.md) の「`var` のエフェクト」)。型は [型と Kind](types.md) の「`var` の変数」で定める
- 変数は、型によって `Unr` の変数と配列の変数 (型が `MutArray _`) に分かれる。配列の変数の名前だけを書いた所は取り出しで、今の配列を返し、変数の状態を空の配列に替える。取り出しの規則は [線形性](linearity.md) の「配列の変数」にある
- translate は、変数の分類をもとに handle、節、`perform` を組む ([Core IR](core-ir.md) の「`var` の変換」)。範囲外の添字の `Panic` は、節の中でなく添字を書いた所で起こる

## handler

例は [エフェクトと handler](effects.md) の「handler の意味」にある。

- 操作の節は `| ctl op 引数... k -> 本体` と `| fn op 引数... -> 本体` の2種類で、ほかに `| return x -> 本体` の節がある。操作の節は `|` の直後に `fn` か `ctl` を書いて始める。`return` の節にはどちらも書かない
- `ctl` の節は継続 `k` を受け取り、`k` を呼ぶか `drop k` で捨てる。戻らない呼び出し (`fail` など) で終わる経路では、どちらもしなくてよい ([線形性](linearity.md) の「戻らない経路の検査」)。`never` の操作の節も `ctl` で書く (`| ctl fail e -> 本体`)。継続を受け取らないが、中断で制御を移すためである
- `fn` の節は `k` を受け取らず、本体の値ですぐに再開する。`| fn op 引数 -> 本体` は `| ctl op 引数 k -> k (本体)` と同じ意味である。HIR は `fn` の節を、引数の後に隠れた `k` (`$k`) を足し、本体を `let $r = 本体 in $k $r` に書き換えた `ctl` の節に下ろす。隠れた名前は、利用者のコードから解決できない。そのため、`fn` の節では `k` を `drop` することも、データにしまうこともできない
- 節の引数の個数は、`never` の操作と `fn` の節なら「操作の引数の個数」、それ以外の `ctl` の節なら「操作の引数の個数 + 1 (`k`)」とする。個数は HIR で検査する (E1010)。`fn` の節の E1010 の文言は `k` に触れない
- 次の誤りは E1051 である。操作の節に `fn` も `ctl` もない (`|` の後に `ctl ` を足す fix を付け、`ctl` の節として下ろす)。`never` の操作の節に `fn` を書いた (`ctl` の節として下ろす)。`return` の節に `fn` か `ctl` を書いた
- `fn` と `ctl` を書かせるのは、その場で値を返す節と継続を操作する節を、行の先頭で読み分けるためである。名前は Koka の `fun` と `ctl` の節に合わせた。引数の個数で区別する案は採らない。パラメータ付き handler では、最後の引数が `k` か状態かを、操作の引数の個数を知らないと読み分けられないためである。`ctl` を省ける形にしないのは、同じ節の書き方が2つになるためである
- `fn` の節の本体の型が合わなければ、隠れた `k` の引数の誤りではなく、本体が操作の結果の型 (パラメータ付き handler では、操作の結果と次の状態の組) と合わない誤りとして報告する
- `fn` の節の本体で `k` を書くと、名前が見つからない誤り (E1001) になる。`never` でない操作の節なら、`ctl` にして継続を受けるよう note を付ける
- 節の先頭の名前は、エフェクトの操作だけから解決する ([モジュールと名前解決](modules.md))。操作でない名前は E1001 にする。ただし `IO` を起こす extern の関数 (`println`、`Fs.open` など) は E1009 にする
- `return` の節は省略でき、省略したら `| return x -> x` とみなす
- `ctl` の節の継続 `k` は普通の関数で、状態のない handler では `k v` で再開する。`drop k` で捨てる。`drop` の引数が1個でなければ、HIR で E1011 にする
- 1つの handler は1つのエフェクトのすべての操作に節を書く ([エフェクトと handler](effects.md) の「handler の意味」)

handler の意味、`k` の線形性、extern のエフェクト `IO` を起こす関数に節を書けないことなどは [エフェクトと handler](effects.md) で定める。

## パラメータ付き handler

```haskell
with_log : String -> (Unit -> <Log, IO | e> a) -> <IO | e> a
with_log path action =
  handle action () from Fs.open path with
    | ctl log lv msg k f ->
        let f = write f "[\{show_level lv}] \{msg}"
        k () f
    | return x f ->
        Fs.close f
        x
```

- `from 初期値` で handler の状態の初期値を与える。各節 (`return` を含む) は、最後の引数として状態を受け取る。状態のある handler の `k` は、`k v st` で次の状態を渡して再開する
- 初期値を先に評価し、その後で本体を実行する
- パラメータ付き handler の `fn` の節は `| fn op 引数 st -> 本体` と書き、本体は操作の結果と次の状態の組を返す。意味は `| ctl op 引数 k st -> let (v, st2) = 本体 in k v st2` と同じである。組の順は `k v st` の引数の順に合わせる。HIR は、隠れた `k` を状態の前に足し、本体を `let ($v, $st) = 本体 in $k $v $st` に書き換える
- 状態は handler が持ち、脱糖しない。観測できる振る舞いは、次のように関数を返す handler に初期値を適用した形と同じで、handler の意味論 (deep handler、中断時の後始末) も変わらない。ただし、評価の順は上の規則に従う

  ```haskell
  (handle action () with
     | ctl log lv msg k -> fn f -> (k ()) (... f ...)
     | return x -> fn f -> ...) (Fs.open path)
  ```

  脱糖しないのは、状態を handler の実行ごとの evidence に置くと、`| fn get () st -> (st, st)` のような節がすぐに再開する形のまま残るためである。evidence passing は、そうした節を継続を作らずにその場で実行する ([Core IR](core-ir.md) の「`perform` と節の3つの形」)
- `return` の節を省略したら、`| return x _ -> x` とみなす。状態を `_` で捨てるので、状態の型に `Unr` の制約が付く。`Lin` の状態で省くと E3004 になり、`from` の初期値を指す。`Lin` の状態では `return` の節を書く
- 状態の線形性の規則は [線形性](linearity.md) の「パラメータ付き handler の状態」で定める
- `k` の引数の個数の誤りは、普通の関数適用の誤り (E2001 など) として型検査が報告する。状態のない handler の `k` は1引数、状態のある handler の `k` は2引数の関数である ([エフェクトと handler](effects.md) の「パラメータ付き handler」)
- `Ref` には `Unr` の値しか入れられない ([マルチコア対応の設計](../future/multicore.md) の「可変状態」)。そのため、`Lin` なリソースを handler に持たせる方法は、この構文が基本になる

## 並行処理

並行処理のための構文は追加しない。`par` / `spawn` / `run_scheduler` ([マルチコア対応の設計](../future/multicore.md)) は、ラムダと `use` で書ける。非同期の処理は、row に `Async` を持つ普通の関数として直接の形で書け、`async` / `await` も関数の色分けも要らない。

```haskell
fetch_all : List String -> <IO> List Int
fetch_all urls =
  use run_scheduler
  let tasks = map (fn url -> Async.start (fn () -> Http.status url)) urls
  map Async.await tasks
```

並行処理はまだ実装していない ([マルチコア対応の設計](../future/multicore.md))。

`(e : T)` と書く。`e` を check モードで `T` に対して検査する ([型と Kind](types.md))。

## HIR で行う脱糖と検査

この文書の構文のうち、HIR への変換で次の脱糖と検査を行う。

- 演算子の列の組み直し、単項マイナス、セクション、`&&` と `||` の `if` への脱糖 ([宣言](declarations.md) の標準の演算子の表)
- `use`、`if` の `else` の補完、`let ... in`
- `var` の範囲の組み立てと合成のエフェクト、代入の左辺の検査 (E1053) (上の「`var`」)
- handler の節の引数の個数、`drop` の引数の個数、節の `fn` と `ctl` の検査 (E1051)、`fn` の節の `ctl` の節への書き換え
- パターンのリストの、`::` と `Nil` のコンストラクタのパターンへの組み立て (上の「リスト」)
- 補間の穴への `display` の呼び出しの挿入 (上の「補間」)。連結は HIR でなく、Core IR への変換が組む
- 作る式とパターンのフィールドの検査 (E1045、E1046、E1047)、パターンに書かないフィールドの `_` の補完、更新のフィールドの重複の検査、フィールドのセクションのラムダへの組み立て (上の「レコード」と「セクション」)
- コマンドリテラルの `Cmd` の構築 (コマンドリテラルの段で実装する)

宣言とレコードに関する脱糖は [宣言](declarations.md) と [直積型とレコード](records.md) にある。
