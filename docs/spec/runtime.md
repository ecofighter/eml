# ランタイム

位置づけ: 規範。

`eml_runtime` が持つオブジェクトのモデル、ヒープ、参照カウント、`debug_heap` の検査、実行の API を定める。マルチコア対応のために、マイルストーン1 の時点から入れておく決定 (予防的な決定) もここにまとめる。マルチコア版の設計そのものは [マルチコア対応の設計](../future/multicore.md) にある。

## ヒープと参照カウント

- メモリ管理は Perceus 方式の参照カウントである。`Lin` 値は静的に一意なので、RC 操作を付けない ([Core IR とインタプリタ](core-ir.md))。
- Rust の `Rc` は使わず、自前のヒープと参照カウントを `eml_runtime` に持つ。Core IR の `dup` / `decref` 命令が、実際にカウントを増減する。
- ヒープは、インデックス方式のアリーナと世代番号で実装する。解放済みのオブジェクトへのアクセスは、世代番号の不一致で検出する。この方式は解放済みアクセスの検出がほぼ無料で、`unsafe` が要らない。検出がほぼ無料なので、`debug_heap` に関係なく常に検査する。
- `decref` で解放するときは、子のオブジェクトを再帰ではなく作業リストでたどる。長い連鎖の解放で Rust のスタックを溢れさせないためである。
- マイルストーン1 のヒープはシングルスレッドで、RC は常に正 (局所) である。

## オブジェクトのヘッダ

- ヘッダは、符号付きの RC と、記述子への参照を持つ。
- RC は符号付きの `AtomicI32` とする。正なら局所、負なら共有を表す。マイルストーン1 では常に正である。
- ヘッダから記述子 (フィールドのレイアウトと `Lin` の破棄処理) を引けるようにする。`decref` で子のオブジェクトをたどるときや `drop k` の後始末で、静的な型の情報なしに処理するためである。
- 記述子はペイロードの種類から決める。継続のフレームは、どの種類も同じ記述子にする。

## ランタイムの API

- 確保、`dup` / `decref`、フィールドの読み出し、一意かどうかの判定、共有されたオブジェクトの複製を API とする。この API は、マルチコア版と同じものに固定する。
- 共有の印付け `mark_shared` は、API に名前だけ予約する。実装はマルチコアの段階で行う。それまでは、呼ぶと「未実装」の実行時エラーにする。
- マルチコア化では、`eml_runtime` の内部だけを差し替える。
- 継続のフレームと環境も、同じ RC で管理するランタイムのオブジェクトにする。
- クロージャも、同じ RC で管理するオブジェクトである。関数と、捕まえた値や部分適用で渡された引数の並びを持ち、並びの値を子として所有する ([Core IR とインタプリタ](core-ir.md))。
- 共有されたオブジェクトの中身を使う側 (クロージャの呼び出し、段階3の multi-shot の再開) は、中身を写し、写した中身の子の参照を1つずつ増やしてから、元の参照を1つ手放す。写すときと解放するときで、数える子を一致させる。
- 将来の LLVM バックエンドも、このランタイムを C ABI でリンクして使う。インタプリタとネイティブでオブジェクトのモデルが一致するので、並列化のバグをインタプリタで再現しやすい。

## `debug_heap`

- `RunConfig` の `debug_heap` を有効にすると、プログラムの終了時にすべてのオブジェクトが解放されていることを確認する (リーク検出)。残っていれば、記述子ごとの件数を添えて実行時エラーにする。解放済みのオブジェクトへのアクセスは、`debug_heap` に関係なく検出する (上の「ヒープと参照カウント」)。
- CLI では `eml run --debug-heap` で有効にする。UI テストでは常に有効にし、違反があればテストを失敗させる ([テスト戦略](../implementation/testing.md))。

## 実行の API

- `run` の出力先 `OutputSink` は、`Send + Sync` な共有の出力先の型とする (`Arc<Mutex<dyn Write + Send>>` を包む型など)。将来、複数のスレッドから `println` するためである。テストでは、出力を捕まえられるバッファを渡す。
- `RunConfig` は `Default` を実装し、フィールドを後から足せるようにする。将来、`threads` (worker の数) と `schedule_seed` (スケジュールのシード) を足す。

## マイルストーン1 に入れた予防的な決定

マルチコア対応はマイルストーン1 では実装しない。ただし、後で作り直さずに済むよう、次の決定をマイルストーン1 の時点から守る。

| 領域 | 決定 | この文書群での記載先 |
|---|---|---|
| 型システム | 内部の row の Kind の束を `Never ≤ Once ≤ Multi` の3要素にする | [型と Kind](types.md) |
| 型システム | 持ち越し規則の制約を `σ ≤ Once` と書く (3要素では `σ = Once` は誤り) | [エフェクトと handler](effects.md) |
| ランタイム | ヒープと RC を `eml_runtime` に分離する (crate は 8 つ) | [コンパイラの構成](../implementation/architecture.md) |
| ランタイム | ヘッダの RC を符号付きの `AtomicI32` にする。マイルストーン1 では常に正 | この文書 |
| ランタイム | ヘッダから記述子 (フィールドのレイアウトと `Lin` の破棄処理) を引けるようにする | この文書 |
| ランタイム | ヒープはインデックス方式のアリーナと世代番号にする。API を固定し、`mark_shared` は名前だけ予約する | この文書 |
| ランタイム | 継続のフレームと環境もランタイムのオブジェクトにする | この文書 |
| ランタイム | インタプリタの値とフレームに `Rc` と `RefCell` を使わない。Core IR は `Arc<Program>` で共有する | [Core IR とインタプリタ](core-ir.md) の「実行時の規約」 |
| API | `run` の出力先を `Send + Sync` な共有の出力先の型にする | この文書 |
| API | `RunConfig` は `Default` を実装し、フィールドを後から足せるようにする | この文書 |
