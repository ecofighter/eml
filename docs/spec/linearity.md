# 線形性

位置づけ: 規範。

`Lin` の値の使い方の規則、`drop`、線形性の検査パスを定める。エフェクトの呼び出しをまたぐ持ち越し規則は [エフェクトと handler](effects.md)、レコードの射影と更新の規則は [直積型とレコード](records.md) で定める。

## 基本の規則

- `Lin` の値は、ちょうど1回使わなければならない。`drop x` も1回の使用に数える。
- Affine は持たない。値を捨てるときは組み込みキーワード `drop` を明示する。
- すべての `Lin` 型は捨て方を持つ。組み込みリソースは宣言された破棄処理を、複合型は各フィールドの再帰的な drop を、クロージャと継続は捕まえた値の drop を行う。
- `Lin` の値をワイルドカードのパターン `_` で受けることはエラーとする。捨てるときは `drop` を明示する。
- 型の Kind が Kind 変数 (例えばシグネチャの型変数 `a`) の場合、その型の値を2回以上使う、使わない、`_` で受ける、のいずれかがあれば、エラーではなく `Unr` の制約を加える。制約が `Lin` と矛盾したときにエラーにする。
- ラムダが変数を捕まえることは、ラムダの位置での1回の使用に数える。ラムダの本体の中でも、捕まえた変数の使用回数を別に数える。本体の中での使用が1回でなければ、その変数の Kind に `Unr` の制約を加える。
- handle の本体と `return` の節が変数を捕まえることも、handle 式の位置での1回の使用に数える。操作の節は操作が起きるたびに呼ばれるので、節が捕まえる変数の Kind には、使用の回数によらず `Unr` の制約を加える ([エフェクトと handler](effects.md) の「handler の意味」)。`return` の節が捕まえた値は、本体の row 全体をまたいで持つ値として持ち越し規則にかかる ([エフェクトと handler](effects.md) の「継続の多重度と持ち越し規則」)。
- 操作の引数の型に現れる Kind 変数には `Unr` の制約を加える。操作は本体を持たないので、節が引数をどう使うかを操作の型に推論できないためである。そのため、線形な値 (`k` など) を多相な操作の引数に渡すとエラーになる。節では、その引数を何回使ってもよい。単相な `Lin` 型の引数には関わらない ([エフェクトと handler](effects.md) の「handler の意味」)。エフェクトの型引数には加えない。handle ごとに具体的な型で節を検査するためである。
- ブロックの最後でない式文は `Unit` 型でなければならない。そのため、`Lin` の値を式文で捨てることは型エラーとして検出される。
- `let` による同じ名前の再束縛 (シャドーイング) を許す。隠された変数が `Lin` でまだ消費されていなければ、消費漏れとして診断する。
- 「捨てることも許さない使い切り必須の型」は、マイルストーン1 では表現しない ([ロードマップ](../future/roadmap.md))。

例として、パラメータ付き handler の `put` の節で `_` により古い状態を捨てると、状態の型 `s` に `Unr` の制約が付く ([エフェクトと handler](effects.md) の `run_state`)。

## 暗黙の後始末

通常の制御フローでは、暗黙の後始末を一切行わない。`File` などのリソースは明示的に `open` / `close` し、`close` を忘れれば線形性の検査が検出する。Python の `with` や Haskell の `bracket` に当たる構文は用意しない。

中断時 (`drop k` や `never` 操作) だけ、捕まっていた `Lin` 値を、その型に宣言された破棄処理で drop する ([エフェクトと handler](effects.md)、[Core IR とインタプリタ](core-ir.md))。

## レコードとタプル

`Lin` なフィールドを1つでも持つレコード (タプルを含む) は `Lin` になる。射影と更新では、捨てられるフィールドが `Unr` でなければならない。`Lin` なレコードは分解パターンで分解する。規則の表と例は [直積型とレコード](records.md) の「線形性の規則」にある。

## パラメータ付き handler の状態

パラメータ付き handler の状態は、節の中では普通の引数なので、線形性の検査がそのまま当てはまる。状態が `Lin` なら、各節で `resume` に渡すか、`close` / `drop` しなければならない。`drop k` する節でも、状態の後始末を忘れればエラーになる。handle の本体を実行している間、状態は handler フレームにあるので、handle の外側の row をまたいで生きている値として持ち越し規則にかける。扱うエフェクトの操作が起きると状態は節に渡り、継続の区間に入らないので、本体の row 全体ではなく、外側の row の `multi` の操作だけが対象になる。構文は [式](expressions.md) の「パラメータ付き handler」で、状態の意味は [エフェクトと handler](effects.md) の「パラメータ付き handler」で定める。

## 線形性の検査パス

- 型推論の後に、型付き HIR の上で別のパスとして行う。Kind の制約は呼び出し関係を通じて伝わるので、このパスは、呼び出しグラフの SCC ごとに、その SCC の型推論の直後に走らせる ([型と Kind](types.md) の「推論」)。複数の等式で定義した関数は、HIR で脱糖した `match` に対して検査する ([宣言](declarations.md))。
- 制御フローに沿って変数の使用回数を数える。分岐の各枝で消費する `Lin` 変数の集合が一致していることを確認する。
- 呼び出しの row と、その時点で持っている値を照らし合わせる (持ち越し規則。[エフェクトと handler](effects.md))。使用回数のパスは評価の順を区別しないので、持ち越し規則は使用回数のパスの直後に、評価の順に沿って生存を求める別のパスで行う。型検査は呼び出しごとの row を記録し、このパスが読む。違反は E3006 にし、使用回数のパスと同じく、誤りのある本体では由来を記録しない。
- handler の節の中で、`once` の `k` が必ずちょうど1回 `resume` または `drop` されていることを確認する。
- レコードの射影と更新で、捨てられる側が `Unr` であることを確認する ([直積型とレコード](records.md))。

使用回数のパスは、使った位置と使わなかった経路を制約の由来に入れる。制約が破れたら、由来の種類から E3002 (二重使用)、E3003 (消費されていない)、E3004 (`_`)、E3005 (継続の扱い忘れ) を選び、どれにも当たらない由来 (受け渡し、単一化、捕獲) は E3001 にする。HIR の誤りがある本体、誤りの跡 (`Missing`) がある本体、型の誤りを報告済みの本体では、使った回数を正しく数えられないので、使用回数のパスの制約は由来を記録せず、その違反を報告しない。

違反は E3xxx の診断として報告する。どの誤りでどこを指すかは [診断](diagnostics.md) の「線形性の診断」で定める。
