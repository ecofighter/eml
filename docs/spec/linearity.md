# 線形性

位置づけ: 規範。

`Lin` の値の使い方の規則、`drop`、線形性の検査パスを定める。エフェクトの呼び出しをまたぐ持ち越し規則は [エフェクトと handler](effects.md)、レコードの射影と更新の規則は [直積型とレコード](records.md) で定める。

## 基本の規則

- `Lin` の値は、ちょうど1回使わなければならない。`drop x` も1回の使用に数える。
- `once` の矢印の値 (`once a -> b`) は `Lin` である。`Lin` と宣言した型 (`data T : Lin`) の値は、フィールドによらず `Lin` である ([型と Kind](types.md) の「1回だけ呼べる関数の型」と「`Lin` の宣言」)。
- Affine は持たない。値を捨てるときは組み込みキーワード `drop` を明示する。
- すべての `Lin` 型は捨て方を持つ。組み込みリソースは宣言された破棄処理を、複合型は各フィールドの再帰的な drop を、クロージャは捕まえた値の drop を行い、継続は区間が捕まえた値の drop を行う。
- `Lin` の値をワイルドカードのパターン `_` で受けることはエラーとする。捨てるときは `drop` を明示する。
- 型の Kind が Kind 変数 (例えばシグネチャの型変数 `a`) の場合、その型の値を2回以上使う、使わない、`_` で受ける、のいずれかがあれば、エラーではなく `Unr` の制約を加える。制約が `Lin` と矛盾したときにエラーにする。
- ラムダが変数を捕まえることは、ラムダの位置での1回の使用に数える。ラムダの本体の中でも、捕まえた変数の使用回数を別に数える。本体の中での使用が1回でなければ、その変数の Kind に `Unr` の制約を加える。
- 再帰する組 (どれかの本体が組の関数を参照する組。自分を参照する1つの関数を含む。[式](expressions.md) の「組」) の関数は、何度も呼ばれうる。相互に呼ぶ組では、ある関数が自分を参照しなくても、相手から何度も呼ばれうる。そのため、再帰する組のすべての関数の型の Kind は `Unr` でなければならない。関数の型の最初の矢印の線形性に `Unr` の制約を加える。後の矢印は、前の引数の Kind で下から抑えられるので、これで足りる。この制約の由来は、その関数の本体の中の組の関数への最初の参照で、本体に参照がない関数では組の中の最初の参照である
- ローカル関数が捕まえた値の Kind は、ラムダと同じ規則で矢印の線形性以下になる。そのため、再帰する組の関数は `Unr` の値しか捕まえられない (E3001)。`File` や `once` の継続 `k` のような `Lin` の値は、捕まえずに引数で受け渡す。再帰しない組 (組の中の参照がない `and` の組と、自分を参照しない1つの関数) の関数は、ラムダと同じ扱いで、`Lin` の値を捕まえて1回だけ使える関数になれる
- 使用回数のパスと持ち越しのパスは、組の関数への参照を、自分への参照と同じく捕まえた値に数えない
- 再帰するローカル関数が型変数の値を捕まえると、その型変数に `Unr` の制約が付き、外側の関数の Kind のスキームに残る (`rep x n` の中の `go` が `x : a` を捕まえると `a` が `Unr` になる)。`x` を引数として受け渡せば付かない制約なので、避けたいときは引数で渡す
- 継続の線形性は、`k` の矢印の線形性である。`once` の `k` は `Lin` の矢印を持つので、ちょうど1回呼ぶか `drop` する。`k` を捕まえたラムダや `k` を入れたデータは、`Lin` の値を捕まえた値と同じ規則で `Lin` になる。`multi` の `k` は `Unr` の矢印を持つが、状態のある handler の `k v` を部分適用したクロージャは `v` を捕まえるので、`v` が `Lin` なら、そのクロージャは1回しか呼べない ([エフェクトと handler](effects.md) の「パラメータ付き handler」)。
- handle の本体と `return` の節が変数を捕まえることも、handle 式の位置での1回の使用に数える。操作の節が捕まえる変数に付く制約と、`return` の節が捕まえた値の持ち越しは、[エフェクトと handler](effects.md) の「handler の意味」で定める。
- 操作の引数の型に現れる Kind 変数は `Unr` に固定する。結果の型だけに現れる操作ごとの型変数は、節の中では `Lin` として扱う。結果の型の矢印は、節が受け取る位置と両方の向きに現れる位置なら `Unr` に固定し、節が作って渡す位置なら節の中で `Unr` として扱う。操作ごとの row 変数は、節の中では `multi` の操作を含みうるものとして扱う。規則と理由は [エフェクトと handler](effects.md) の「handler の意味」で定める。
- ブロックの最後でない式文は `Unit` 型でなければならない。そのため、`Lin` の値を式文で捨てることは型エラーとして検出される。
- `let` による同じ名前の再束縛 (シャドーイング) を許す。隠された変数が `Lin` でまだ消費されていなければ、消費漏れとして診断する。
- 「捨てることも許さない使い切り必須の型」は、今は表現しない ([ロードマップ](../future/roadmap.md))。

例として、パラメータ付き handler の `put` の節で `_` により古い状態を捨てると、状態の型 `s` に `Unr` の制約が付く ([エフェクトと handler](effects.md) の `run_state`)。

## 暗黙の後始末

通常の制御フローでは、暗黙の後始末を一切行わない。`Fs.File` などのリソースは明示的に `Fs.open` / `Fs.close` し、`Fs.close` を忘れれば線形性の検査が検出する。Python の `with` や Haskell の `bracket` に当たる構文は用意しない。

中断時 (`drop k` や `never` 操作) だけ、捕まっていた `Lin` 値を、その型に宣言された破棄処理で drop する ([エフェクトと handler](effects.md)、[LIR](lir.md) の「実行の意味」)。

## レコードとタプル

`Lin` なフィールドを1つでも持つ名前付きのレコードとタプルは `Lin` になる。射影で取り出さない残りのフィールド、更新で上書きされる古い値、分解のパターンに書かないフィールドは、`_` で受けたのと同じ扱いで、`Unr` でなければならない。`Lin` なレコードは分解のパターンで分解する。規則の表と例は [直積型とレコード](records.md) の「線形性の規則」にある。

使用回数のパスは、射影を `e` の1回の消費として、更新を `e` とフィールドの式の評価の順に、作る式をフィールドの式を書いた順にたどる。射影と更新が捨てるフィールドは型検査が記録した型から、パターンに書かないフィールドは HIR の印から、フィールドの名前を出して E3004 にする。書き手の `_` と区別するためである。持ち越しのパスは、作る式と更新を、タプルと同じく左から評価する部分として扱う。

## パラメータ付き handler の状態

パラメータ付き handler の状態は、節の中では普通の引数なので、線形性の検査がそのまま当てはまる。状態が `Lin` なら、各節で `k` の呼び出しに渡すか、`Fs.close` / `drop` しなければならない。`drop k` する節でも、状態の後始末を忘れればエラーになる。handle の本体を実行している間の状態の持ち越しは [エフェクトと handler](effects.md) の「パラメータ付き handler」で、構文は [式](expressions.md) の「パラメータ付き handler」で定める。

## 線形性の検査パス

- 型推論の後に、型付き HIR の上で別のパスとして行う。使用回数のパスと持ち越しのパスは、関数ごとに本体をたどって Kind の制約を集める。Kind の制約は呼び出し関係を通じて伝わるので、制約は呼び出しグラフの SCC ごとに解き、違反はそこで見つかる ([型と Kind](types.md) の「推論」)。複数の等式で定義した関数は、HIR で脱糖した `match` に対して検査する ([宣言](declarations.md))。
- 制御フローに沿って変数の使用回数を数える。分岐の各枝で消費する `Lin` 変数の集合が一致していることを確認する。
- 呼び出しの row と、その時点で持っている値を照らし合わせる (持ち越し規則。[エフェクトと handler](effects.md))。使用回数のパスは評価の順を区別しないので、持ち越し規則は使用回数のパスの直後に、評価の順に沿って生存を求める別のパスで行う。型検査は呼び出しごとの row を記録し、このパスが読む。違反は E3006 にし、使用回数のパスと同じく、誤りのある本体では由来を記録しない。
- handler の節の中で、`once` の `k` が必ずちょうど1回、呼ばれるか `drop` されていることを確認する。
- レコードとタプルの射影と更新で、捨てられる側が `Unr` であることを確認する ([直積型とレコード](records.md))。

使用回数のパスは、使った位置と使わなかった経路を制約の由来に入れる。制約が破れたら、由来の種類から E3002 (二重使用)、E3003 (消費されていない)、E3004 (`_`)、E3005 (継続の扱い忘れ) を選び、どれにも当たらない由来 (受け渡し、単一化、捕獲、再帰する組の関数の参照、操作の型が節に求める制約) は E3001 にする。HIR の誤りがある本体、誤りの跡 (`Missing`) がある本体、型の誤りを報告済みの本体では、使った回数を正しく数えられないので、使用回数のパスの制約は由来を記録せず、その違反を報告しない。

違反は E3xxx の診断として報告する。番号と意味は [診断](diagnostics.md) の「割り当て済みの番号」で定める。どの誤りでどこを指すかは [診断の出し方](../implementation/diagnostics.md) の「線形性の診断」にある。
