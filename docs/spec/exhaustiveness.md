# 網羅性

位置づけ: 規範。

パターンの網羅性と到達可能性の検査を定める。

## 検査パス

- 型推論の後に、型付き HIR の上で別のパスとして行う。アルゴリズムは Maranget の行列アルゴリズムを使う。
- 網羅されていない `match` はエラー、到達しない枝は Warning にする。
- タプルは、要素の数だけのフィールドを持つコンストラクタが1つの型として扱う。漏れているパターンの例は `(Some _, None)` の形で示す
- Int と String のリテラルは無限に値があるものとして扱う。ワイルドカードか変数の枝がない限り、網羅されていないとみなす。同じリテラルの2つ目の枝は到達しない枝である。リテラルの位置の漏れの例は `_` で示す。
- `let` の左辺とラムダの引数のパターンも、反駁可能 (網羅されていない) ならエラーにする。
- 変数、`_`、`()` はどれもワイルドカードとして扱う。`Unit` の値は1つしかないためである。型を明示したパターンは、中のパターンとして扱う。
- 型が `Error` を含むパターンと scrutinee は検査しない。診断を連鎖させないためである ([診断](diagnostics.md) の「連鎖する診断の抑止」)。
- トップレベルの関数の等式は、HIR で「引数のタプルに対する `match`」1つに脱糖する。網羅性はその `match` に対して検査する ([宣言](declarations.md))。等式が1つだけの場合も同じで、反駁可能な引数のパターンは「網羅されていない等式」として報告する。
- 等式の `match` は、`match` 式としてではなく等式として報告する。網羅されていなければ E4002、到達しない等式は E4005 (Warning) である。
- 漏れているパターンの例は、現れていないコンストラクタを見つけた段階で、現れているコンストラクタの中の漏れを探さない (Maranget の作り方どおり)。そのため、note の例が漏れのすべてを表さないことがある (`| Some (Some _) -> …` の漏れは `None` だけが出る。`| [a] -> a` の漏れは `[]` だけが出る)。
- パターンのリストは、HIR が `::` と `Nil` のコンストラクタのパターンに組むので ([式](expressions.md) の「リスト」)、検査はほかのコンストラクタと同じである。漏れの例の Prelude の `Nil` と `::` は、次のように書く
  - `Nil` は `[]` と書く。自分の `Nil` を定義したモジュールでも修飾しない
  - `Nil` で終わる `::` の鎖は、リストの形で `[_, Some _]` と書く。要素は、タプルの要素と同じく括弧なしの形で書く
  - それ以外の `::` の鎖は、右結合として `_ :: _ :: _` と書き、右の被演算子に括弧を付けない。左の被演算子は、引数を持つコンストラクタを括弧で囲む (`(Some _) :: _`)。`::` は Prelude だけが宣言できるので ([宣言](declarations.md) の「`data` と `type`」)、修飾しない
  - `[]` とリストの形は、括弧の要らない形として扱い、引数の位置と `::` の左の被演算子にも括弧なしで書く (`Some [_]`、`[[_]]`、`[_] :: _`)
  - ユーザーが定義した中置のコンストラクタには、この書き方を使わない

```haskell
is_error : Level -> Bool
is_error Error = True
is_error _ = False
```

この定義は、引数のタプルに対する2つの枝の `match` として検査される。

## 診断

各誤りの番号と重大度は [診断](diagnostics.md) の「割り当て済みの番号」で定める。診断が指す場所は [診断の出し方](../implementation/diagnostics.md) の「網羅性の診断」にある。番号の範囲は E4xxx である。

## 範囲外

or パターン、ガード、as パターンはまだない ([実装の現在地](../implementation/status.md) の「今の言語の範囲」)。
