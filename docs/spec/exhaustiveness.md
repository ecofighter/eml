# 網羅性

位置づけ: 規範。

パターンの網羅性と到達可能性の検査を定める。

## 検査パス

- 型推論の後に、型付き HIR の上で別のパスとして行う。アルゴリズムは Maranget の行列アルゴリズムを使う。
- 網羅されていない `match` はエラー、到達しない枝は Warning にする。
- Int と String のリテラルは無限に値があるものとして扱う。ワイルドカードか変数の枝がない限り、網羅されていないとみなす。
- `let` の左辺とラムダの引数のパターンも、反駁可能 (網羅されていない) ならエラーにする。
- トップレベルの関数の等式は、HIR で「引数のタプルに対する `match`」1つに脱糖する。網羅性はその `match` に対して検査する ([宣言](declarations.md))。等式が1つだけの場合も同じで、反駁可能な引数のパターンは「網羅されていない等式」として報告する。

```haskell
is_error : Level -> Bool
is_error Error = True
is_error _ = False
```

この定義は、引数のタプルに対する2つの枝の `match` として検査される。

## 診断

| 誤り | 重大度 | 指す場所 |
|---|---|---|
| 網羅されていない `match` | Error | `match` 式。漏れているパターンの例を note で示し、fix で枝の追加を提案する |
| 網羅されていない等式 | Error | シグネチャの関数名と、各等式の先頭。漏れている引数の並びの例を note で示し、fix で等式の追加を提案する |
| 到達しない枝 | Warning | その枝のパターン |
| 到達しない等式 | Warning | その等式の引数のパターン |
| 反駁可能な `let` / ラムダの引数のパターン | Error | そのパターン |

等式の場合はソースに `match` 式がないので、指す場所を等式に合わせて決めている。詳細は [診断](diagnostics.md) の「網羅性の診断」にある。

番号の範囲は E4xxx である ([診断](diagnostics.md))。
