# REPL の端末

`eml repl` の端末の規則を定める。セッションの意味 (入力ごとのモジュール、名前の解決、受け付ける入力) は [モジュールと名前解決](modules.md) の「REPL のセッション」に、入力の終わりの判定は [レイアウト規則](layout.md) の「REPL の入力の終わり」に、入力の読み分けは [文法](grammar.md) の「REPL の入力」にある。

## コマンドライン

- `eml repl [--debug-heap] [file]` でセッションを始める。`--debug-heap` は `eml run` と同じく検査モードにする。`file` を渡すと、最初に `:load file` と同じことをする。ただし `file` を読めなければ、`eml run` と同じく使い方の誤り (``error: cannot read `file`: …``、終了コード 2) にする
- REPL のプログラムは引数を持たないので、`Env.args ()` は `[]` を返す。標準入力は REPL 自身が入力の行を読むので、プログラムは読めず、`Stdin` の関数は I/O の失敗 (`cannot read the standard input: not available`) になる ([標準ライブラリ](stdlib.md) の「`Stdin`」)
- import の根と Host の相対パスの基準は、`eml run` と同じくカレントディレクトリである。`:load` の後は、import の根はファイルのディレクトリである (「ファイルの読み込み」)
- 上限は `eml_cli::repl_limits()` が決める。深さは `eml run` と同じ 2^27 語で、確保量は物理メモリの 40% である。回復は写す間に古いヒープと写しを同時に持ち、写しは根から届く物体だけなので古いヒープより大きくならない。合わせて、`eml run` の上限と同じ 80% を目安に収める。どちらの上限も、安全点で止めるまでの間に少し超えうる目安である。物理メモリを読めない OS では上限を置かない

## 行の編集

- 標準入力が端末なら、`rustyline` で行を編集する。履歴はメモリだけに持ち、読んだ行ごとに足す。空の行と直前と同じ行は足さず、100 行まで持つ。標準出力をリダイレクトしても、プロンプトと編集の表示は端末に書く。ただし `TERM` が `dumb` などの未対応の端末では、`rustyline` はプロンプトを標準出力に書く
- 評価の間に打った行と、bracketed paste でない速い入力も、失わずに次の読みで順に読む。`rustyline` は、読みのたびに作る読み手のバッファに残った入力を、`buffer-redux` の feature を入れたときだけ次の読みに渡すので、この feature を入れる
- 標準入力が端末でなければ、1行ずつ読み、プロンプトは書かない
- 1回の読みが複数の行を返すことがある (端末の bracketed paste)。返った文字列を `\n` で行に分け、行末の `\r` を除いて、1行ずつ次の「行のまとめ方」に渡す。同じ読みで `:quit` より後にある行と、セッションを続けられなくした入力より後にある行は捨てる
- `TERM` が `dumb` などの端末では、`rustyline` は行を編集せずに読む。このとき Ctrl-C は読みかけの入力を捨てない (下の「割り込み」)

## 行のまとめ方

- プロンプトは、入力の始めが `> `、入力の続きと `:{` の中が `. ` である
- 入力の終わりは、読んだ行を `\n` でつないだテキストで決める ([レイアウト規則](layout.md) の「REPL の入力の終わり」)。空行で終わった入力は、その空行を含めずに評価する
- 入力の始めの行が空白だけなら、何もせずに入力の始めのままにする。コメントだけの行は入力として評価する
- 入力の始めの行で、最初の空白でない文字が `:` なら、その行をコマンドとして読む。入力の続きの行と `:{` の中の行は、`:` で始まっても入力の本文である
- EOF では、読みかけの入力を評価してから終わる。終わっていない入力も評価して、その診断を見せる

## コマンド

コマンドの名前は、`:` の直後から最初の空白の前までの文字である。名前の後の行の残りすべてが引数になるので、空白を含むパスもそのまま書ける。引数の前後の空白は除く。

| コマンド | 動作 |
|---|---|
| `:quit` | セッションを終える |
| `:help` | コマンドの一覧と `:{ … :}` の使い方を標準出力に書く |
| `:load` | 引数のパスのファイルから新しいセッションを始める。引数がなければ空のセッションにする (「ファイルの読み込み」) |
| `:reload` | 最後に `:load` したファイルを読み直す (「ファイルの読み込み」) |
| `:type` | 引数の式の型を書く (「型の表示」) |
| `:{` | 次の行から、前後の空白を除くと `:}` だけになる行の前までを、1つの入力にする。空行も入力に含め、入力の終わりの判定はしない。本文が空白だけなら何もしない |

- コマンドは表の名前の接頭辞で書ける。GHCi と同じく、表の順に見て最初に接頭辞が合う名前を選ぶ (`:q` は `:quit`)。表の順は `quit`、`help`、`load`、`reload`、`type` である (`:l`、`:r`、`:t` は GHCi と同じ)
- `{` と `}` は接頭辞で引かない。`:{` が引数を持てば誤りにする。入力の始めの `:}` は誤り (`':}' without ':{'`) である
- 名前が空なら誤り (`missing command name`)、合う名前がなければ誤り (`unknown command ':foo'`)、引数を取らないコマンド (`:quit`、`:help`、`:reload`) に引数があれば誤り (`':quit' takes no argument`、`':reload' takes no argument`)、引数のない `:type` も誤り (`':type' needs an expression`) である。誤りは標準エラーに書き、何も評価しない
- `:{` の中で EOF になったら、`missing ':}'` を標準エラーに書き、何も評価しない

## ファイルの読み込み

`:load path` は、セッションを捨てて新しく始め、ファイルをその最初の入力として読む。GHCi と同じ扱いである。ファイルを今のセッションに足す形にすると、E1035 と import のキャッシュのために `:reload` が成り立たない。作り直すので、`:load` で型が変わった値を持ち越す問題も起きない。

1. パスの綴りを決める。`eml run` と同じく、大文字小文字を区別しないファイルシステムでは、ディレクトリの一覧にある綴りに直す。この綴りを表示のパスにする
2. ファイルを読む。相対パスはカレントディレクトリから読む。読めなければ、標準エラーに ``error: cannot read `path`: {error}`` を書く。セッションも覚えたファイルも変えない
3. 読めたら、今のセッションを閉じる (`Repl::close`)。検査モードのリークか根を手放すときの誤りがあれば、標準エラーに `runtime error: {error}` を書いて続ける。その誤りは覚えておき、REPL が終わるときの終了コードを 1 にする (「終わり方」の `close` の誤りと同じ扱い)
4. 端末が新しいセッションを作り、ファイルをその最初の入力 (入力 1) として評価する (`Repl::with_file`)。ファイルの文法で読み、診断と実行時エラーの位置は表示のパスで見せる。`main` は実行しない
5. import の根は、ファイルのあるディレクトリにする。`eml run` が入口のファイルのディレクトリを根にするのと同じである。Host の相対パスの基準はカレントディレクトリのままにする (`eml run` と同じ)
6. 結果は普通の入力と同じく表示する。受け付けたときは何も書かない
7. 結果によらず、そのファイルを覚えて `:reload` の対象にする。ファイルに誤りがあるときや、前端の検査の間に割り込まれたときは、診断か `interrupted` を見せ、セッションは空のままにする。直してから `:reload` で読み直せる。空かコメントだけのファイルも、セッションは空のままである (`Outcome::Empty`)

引数のない `:load` は、今のセッションを 3. と同じく閉じて空のセッションを作り、覚えたファイルを忘れる。import の根はカレントディレクトリに戻す。

ファイルのトップレベルの item は、後の入力からすべて見える。`pub` は見ない。前の入力のトップレベルを `pub` を見ずに引く規則 ([モジュールと名前解決](modules.md) の「REPL のセッション」) がそのまま当たるためである。後の入力は、ファイルの item を普通の前の入力の item と同じく定義し直せる。古い版は `Shape#1` と表示する。ファイルの instance は、前の入力の instance と同じく、後の入力で定義し直せない (E1035)。

ファイルは、`eml run` の入口のファイルと同じく import できない。ファイルの依存先が import しても、後の入力が import しても E1030 になる。ファイルを受け付けなかったセッション (誤り、割り込み、空のファイル) でも同じである。診断の文言は `eml run` の入口のファイルのもの (`the entry module cannot be imported`) をそのまま使う。`:load` のファイルは REPL の入口のファイルだからである。

`:reload` は、覚えたファイルで `:load` の 1. から 7. をやり直す。ディスクからファイルを読み直し、新しいセッションの import のキャッシュは空なので、import したファイルも読み直す。

- 覚えたファイルがなければ、標準エラーに `no file to reload; use ':load'` を書き、セッションを変えない。打ち間違えた `:r` で `let` の束縛が消えないようにするためである
- 読めなければ (ファイルを消したときなど)、`:load` と同じく誤りを書き、セッションと覚えたファイルを変えない

## 型の表示

`:type e` は、式の型を実行せずに表示する。

- 引数を1つの式として読む。入力の読み分け (item か `let` か式か) はしないので、`f x = 1` を渡すと構文の誤り (`':type' takes one expression`) になる ([文法](grammar.md) の「REPL の入力」)
- 今のセッションに対して型を検査する。lowering も実行もせず、入力を受け付けず、入力の番号も進めない
- 誤りがなければ、標準出力に `e : T` を書く。`e` は引数の前後の空白を除いたテキストである。診断は普通の入力と同じく標準エラーに書く (警告は、受け付けた入力までに読んでいないファイルのものだけ)。誤りが1つでもあれば型を書かない
- `:type` は、前端の検査の診断を書いた後で、誤りの有無によらず止める語を読む。割り込みが立っていれば、型を書かずに `interrupted` を書き、同じ読みで届いた残りの行を捨てる (「割り込み」)。普通の入力は、誤りのないときだけ実行の前に止める語を読むので、ここが違う。`:type` も、`eval` と同じく始めに `Control::clear` を呼ぶので、入力を待つ間に来た割り込みでは止まらない

型 `T` は次のように書く。推論の詳しい規則は [型と Kind](types.md) の「REPL の入力」にある。

- 式の入力と違い、型に現れる型変数を `Unit` に決めない (defaulting しない)
- 型に現れる型変数は、書いた型を左から読んで最初に現れた順に `a`、`b`、`c`、`d`、`f`、…、`z`、`a1`、`b1`、… と名付ける。`e` で始まる名前は、番号が付いても型変数に使わない。row 変数の名前と重ねないためである
- row 変数は、書いた型 (文脈を含む) の中に2回以上現れるものと、負の位置に現れるものを、左から最初に現れた順に `e`、`e1`、`e2`、… と名付ける。正の位置に1回だけ現れる row 変数は閉じた row として書く (row がラベルを持たなければ省く)。入力の row の defaulting と同じ扱いで、`fn x -> x` を `a -> <e> a` でなく `a -> a` と見せるためである。2つの矢印が同じ row 変数を持つ `(>>)` は `(a -> <e> b) -> (b -> <e> c) -> a -> <e> c` になる。数えるのは書いた型の木の上で、同じ部分の型が2か所に現れれば、その中の row 変数も2回と数える
- 位置の正負は、型全体を正とし、矢印の引数で反転する。矢印の結果と矢印自身の row は矢印の正負を保つ。データ型とタプルの引数と、row のラベルの型引数も正負を保つ (データ型の変性は調べない)
- 負の位置の row 変数を閉じないのは、書いた型が、本当の型の受け付ける引数を受け付けなくなるためである。`ignore_fn : (Unit -> <e> Int) -> Int` は `ignore_fn ask` を受け付けるが、`(Unit -> Int) -> Int` と宣言した関数は `ask` を受け付けない。そのため `:type ignore_fn` は `(Unit -> <e> Int) -> Int` になる。引数の引数は正の位置なので、`((Unit -> <e> Int) -> Int) -> Int` は `((Unit -> Int) -> Int) -> Int` と書く
- 型に現れる型変数に残った制約は文脈にする。1つなら `Show a => …`、2つ以上なら `(Eq a, Show b) => …` と書く。制約は、型変数が現れた順に並べ、同じ型変数の中ではクラスの表示の名前の順 (同じなら定義の順) に並べる。同じ制約は1つにし、ほかの制約の上位クラスでたどれる制約は書かない (`Ord a` があれば `Eq a` を書かない)
- 型に現れない型変数に残った制約は、式の入力と同じく、その型変数を `Unit` に決めて解く。表示する型を変えないので、上で述べた、型変数を `Unit` に決めない規則とは食い違わない。`Unit` で解けなければ E2009 にする。そのため `:type show []` は `String` を返し、`:type name (make ())` (`Unit` の instance のないクラス) は E2009 になる。型変数でない型に残った制約は、今と同じく E2006 にする
- Kind (矢印の線形性) は書かない。表面の型の構文に Kind はないためである
- 型と制約の名前は、診断と同じ表示 (`DisplayNames`) で書く。定義し直した item の古い版は `Shape#1` になる

式の入力の規則のうち、次の3つは `:type` に当てない。

- row が `<IO, Panic>` に収まらなければ E2015 にする規則。`:type ask ()` は `Int` を返す
- 型が `Unr` でなければ E2016 にする規則。`:type Fs.open "x"` は `File` を返す
- 型に現れる型変数を `Unit` に決める規則 (上のとおり名前を付け、制約は文脈にする)

本体の線形性の検査、網羅性の検査、ほかの型の誤りは、普通の式と同じく報告する。

```
> :type (>>)
(>>) : (a -> <e> b) -> (b -> <e> c) -> a -> <e> c
> :type fn x -> x
fn x -> x : a -> a
> :type []
[] : List a
> :type show []
show [] : String
> :type fn x y -> x < y && x == y
fn x y -> x < y && x == y : Ord a => a -> a -> Bool
> :type println "hi"
println "hi" : Unit
```

## 結果の表示

| 入力の結果 (`Outcome`) | 表示 |
|---|---|
| 診断 | 標準エラーに書く。`Repl::eval` は実行の後で診断を返すので、その入力で初めて読んだファイルの警告は、入力の出力の後に出る |
| `Empty`、`Accepted`、`Rejected` | 診断のほかに書くものはない。式の入力の値は、`Repl` が整形して Host の標準出力に書き、書き出す (下の「値の書き方」) |
| `Failed` | 割り込みで止まったなら `interrupted`、ほかは `runtime error: {error}` を標準エラーに書く。位置があれば `  at path:line:column` が続く |
| `Interrupted` | 標準エラーに `interrupted` を書く |
| `Exited(n)` | 標準エラーに `exited with code n` を書き、次の入力へ進む (「割り込みと実行時エラー」) |
| `Broken` | 標準エラーに `runtime error: {error}` を書き、`close` を呼ばずに終了コード 1 で終わる。後の入力はどれも実行できないためである |

- 割り込みは、止まった所によらず `interrupted` と書く。VM の中で止まったときの関数の名前 (`entry$` や `f@[Int]`) は、利用者が書いた名前でないので見せない
- VM は実行の終わりに、誤りのときも入力の出力を書き出す。式の入力の値は、`Repl` がその後に Host に書いて書き出す。どちらも次のプロンプトと `:type` の出力より前に見え、値は入力の出力の後に出る

### 値の書き方

式の入力の値は、型に従う表示器 ([Core IR](core-ir.md) の「表示関数」) が文字列にする。

- 型が `Show` を持つ式の入力は、値だけを書く
- 型が `Show` を持たない式の入力は、`値 : 型` を書く。型の書き方は診断の表示と同じである。OCaml のトップレベルは `- : 型 = 値` と書くが、eml は値を先に書く
- 型が `Unit` の入力は何も書かない
- 関数型の入力も、式を評価してから `<fn> : 型` を書く (式の中の `println` などは動く)

```
> inc : Int -> <Panic> Int
. inc x = x + 1
.
> inc
<fn> : Int -> <Panic> Int
> fn x -> x * 2
<fn> : Int -> <Panic> Int
> data Box = | Box (Int -> <Panic> Int)
> Box inc
Box <fn> : Box
> [fn x -> x, inc]
[<fn>, <fn>] : List (Int -> <Panic> Int)
> data R = | R { f : Int -> <Panic> Int, n : Int }
> R { f = inc, n = -3 }
R { f = <fn>, n = -3 } : R
```

表示器は、値の部分 (入力の値そのものを含む) ごとに、書き方を次の順で決める。

1. 型が `Show` を持たなければ (型検査が式の入力の表示の仕方を決めるのと同じ判定で、制約が完全に解けなければ)、構造で書く。`instance Show a => Show (Box a)` のもとの `Box (Int -> Int)` のように、instance はあるが文脈が型引数で解けない型も、ここに入る
2. 型が `Show` を持ち、その `Show` が導出した instance (`deriving Show`)、タプルの構造的な instance (`()` を含む)、Prelude の `List` の instance のどれかなら、構造で書く。Prelude の `List` は、型の頭が `LangItems` の `list` であることで見分けるので、セッションの利用者が定義した `List` は含まない。Prelude の `Bool`、`Ordering`、`Option`、`Result` は導出した instance なので、構造で書く
3. ほかの型 (`Int`、`String`、利用者が書いた `Show` の instance を持つ型) は、その型の `show_prec` で書く。入力の値そのものと `List` の要素は `show` で書く

構造で書く規則は導出した `Show` ([宣言](declarations.md) の「`deriving`」) と同じなので、`Show` を持つ型を構造で書いた結果は、上限で切れる所を除き、`show` の結果と同じ文字列になる。

- 関数 (handler の継続を含む) は `<fn>` と書く
- タプルは `(…, …)` と書き、要素を優先度 0 で書く
- `List` は `Show` のリストと同じく `[…, …]` と書く。空のリストは `[]` である。リストは外から渡された優先度によらず括弧で囲まず、要素を優先度 0 で書く。要素が `show_prec` で書く部分なら、Prelude の `Show (List a)` と同じく `show` で書く (優先度 0 の `show_prec` ではない)
- `data` のコンストラクタは、導出した `Show` と同じく書く。前置のコンストラクタは `Box <fn>` で、引数を優先度 11 で書く。中置のコンストラクタは `a :+ b` で、優先度 p の演算子の左右を p + 1 で書く (fixity を宣言していない中置のコンストラクタは `infixl 9`)。外から渡された優先度が前置なら 10、中置なら p を超えると括弧で囲む。レコードは `P { f = <fn> }` で、フィールドを優先度 0 で書き、括弧で囲まない
- `show_prec` で書く部分は、利用者の instance の書き方をそのまま使う。`"a"` は引用符付きで書き、負の数はコンストラクタの引数の位置で括弧に入る (`Box (-3)`)
- コンストラクタの名前は、導出した `Show` と同じく書いた名前のまま (修飾も `#N` も付けない) である。定義し直した型の古い版の値は `Circle : Shape#1` になる。表示器は、届いたどの型のコンストラクタの名前も書く。セッションの `pub` でない型も、import したモジュールの `pub` でない型も同じで、導出した `Show` と同じ扱いである
- `Show` を持たない extern の型は、中身を読めないので `<extern>` と書く (`Array Int` の入力は `<extern> : Array Int`)。`File` の値は式の入力の結果にならない (E2016)。`Show` を持つ extern の型は、ほかの型と同じく `show_prec` で書く

### 上限

値の大きさには上限がなく、部分を共有した値 (`t(k+1) = Node t(k) t(k)`) は、小さなヒープでも巨大な木になる。そのため、OCaml のトップレベルの既定の値 (`print_depth` 100、`print_length` 300) と同じ2つの上限を置く。

- 予算: 値全体で 300 個の節点まで書く。節点は、構造で書くコンストラクタ、タプル、リスト、`<fn>`、`<extern>`、`show_prec` で書く部分、深さで切って書く `...` の1つずつで、それぞれ予算を1つ使う。区切りと括弧は予算を使わない。予算が尽きた後の部分は、予算を使わずに `...` と書く
- リスト: リストは節点として予算を1つ使い、要素はそれぞれの節点の分を使う。要素を書く前に予算が尽きていれば、その要素から後を書かずに `...` を最後の要素として書いて閉じる (`[a, b, ...]`。1つも書いていなければ `[...]`)。残りの要素がなければそのまま閉じる。100 万個の `Int` のリストは、299 個と `...` を書く
- 深さ: 構造で書く入れ子のコンストラクタ、タプル、リストを 100 段たどった先の部分は `...` と書く。コンストラクタのフィールド、タプルの要素、リストの要素は、それを持つ値より1段深い。`List` の背骨 (`::` のつながり) は段を増やさない。利用者が定義したリストの形の型 (`data L = | LNil | LCons (Int -> Int) L`) は、背骨のコンストラクタが段を増やすので、予算か深さで切れる
- 深さで切って書く `...` も予算を1つ使う (OCaml と同じ)。そのため、深さで切れた大きなリストも、予算の分の要素で止まる
- 型の数: 1つの入力の表示器が構造で書く型は 1000 種類までで、それより多くの型をたどる値は、越えた所を `...` と書く。入れ子の型でだけ起きる
- 長さ: `show_prec` で書く部分の中には、上の上限が届かない。値の文字列が 10,000 文字を超えたら、10,000 文字までを残して ` ...` を足す (下の「整形の規則」)。VM は 10,001 文字までを写し ([VM](vm.md) の「追記」)、整形が超えたかを見分ける。型の ` : T` は切らない

### 整形の規則

結果が幅に収まらなければ、括弧の位置で行に分ける。整形は `eml_cli::pretty::format(text, suffix, width)` が行う。`suffix` は型の ` : T` か空で、切らずに結果の最後の行の後ろに付け、幅に収まるかの判定に数える。端末にも VM にも依存しない純粋な関数なので、`eml_cli::lines` と同じく feature によらず組み立てる。

幅は `Repl::set_width(usize)` で渡す。既定は 80 で、20 より狭い幅は 20 にする。端末は始めに標準出力の端末の列の数を `ioctl(TIOCGWINSZ)` で読んで渡す。unix だけで、標準出力が端末でないか、読めないか、0 なら 80 である。`:load` で作り直すセッションにも同じ幅を渡す。端末の大きさの変更は追わない。

- 字句: 文字列のリテラル (`"` から、`\` の後の1文字を読み飛ばして、閉じる `"` まで)、開き括弧 `(`、`[`、`{`、閉じ括弧、カンマ、空白、ほかの文字の並び
- 切る: 10,000 文字を超えたら、10,000 文字までを文字の境界で残す。残した文字列の後に ` ...` を足す
- 整形しない文字列: 改行 (`\n` か `\r`) を含む、閉じていない文字列のリテラルがある、括弧が対にならない (閉じ括弧の種類が違う、開いていない括弧を閉じる) のどれかなら、整形せずにそのまま返す (`suffix` は付ける)。ただし、10,000 文字で切った所で開いたままの括弧と文字列のリテラルは、閉じているとみなす (閉じる文字は書かない)。タブはほかの文字と同じく1文字と数える
- 組: 開き括弧から対の閉じ括弧までが1つの組である。組の要素は、組の中の外側のカンマで分けた部分で、前後の空白は含めない。カンマのない組の要素は1つである。組の前後の文字 (`P `、`Node `、組の後ろの ` :+ x`) は、組を含む要素か行の一部である
- 幅に収まるか: 組を1行に書いたとき、組の開き括弧の列から、閉じ括弧と、閉じ括弧の後に同じ行に続く文字までを含めて、幅に収まるかで決める。続く文字は、次の開き括弧かカンマか、1要素ずつ書く組 (下) の閉じ括弧の手前までである (その閉じ括弧は別の行に書くため)。次の組の前の空白は数えない。文字列の終わりまで続くなら `suffix` (切ったときは ` ...` も) を含める。文字の数で数える (全角の文字も1文字と数える)
- 収まる組は1行に書く
- 基準の列: 組を並べる所ごとに、行を分けた組を置く列の基準を持つ。一番外側では 0、1要素ずつ書く組の要素では要素の始めの列 (開き括弧の列 + 2)、要素が1つの組の中では、その組を書いた行の始めの列 (字下げの列か、要素の始めの列) である。同じ所に並ぶ組 (`Node (Leaf 1) (Node …)` の2つの組) は、同じ基準の列を持つ
- 収まらない組:
  - 要素が1つの組 (`(Leaf 1)`、`(-3)`、`{ f = 1 }`) は、前に文字があれば、その文字の後で改行し、基準の列 + 2 の列に置く。改行した行の終わりの空白は消す。改行するのは、組の直前が開き括弧でもカンマでもなく (要素の始めと開き括弧の直後では改行しない)、基準の列 + 2 が今の列より左のときだけである。置いた列で収まれば1行に書く。収まらなければ、開き括弧を中身に付けたまま (`(` の直後では改行しない)、括弧の中の要素の中の組に同じ規則を当てる。同じ所に並ぶ組は、収まらないものだけが、それぞれ次の行の同じ列に並ぶ
  - 要素が2つ以上の組は、今の列のまま、括弧の位置で分ける。要素が2つ以上で、どの要素も組を含まない組は詰めて書く。`[ ` の後に最初の要素を書き、残りの要素を `, ` で区切って幅まで並べ、収まらない要素の前で改行して、開き括弧と同じ列から `, ` で続ける。最後の行の後ろに ` ]` を書く
  - ほかの組は1要素ずつ書く。開き括弧の行に `[ ` と最初の要素を書き、2つ目からの要素は、開き括弧と同じ列から `, ` で始まる行に書く。閉じ括弧は、開き括弧と同じ列の行に書く。要素の中の組は同じ規則で整える。内側の組の `, ` の行と閉じ括弧の行は、内側の組の開き括弧の列に揃う。要素の始めの列は、外側の開き括弧の列に2を足した列である
- 1行に収まらない要素 (幅より長い文字列のリテラルや、組を含まない長い文字の並び) は、分けずにそのまま書く
- 整形した結果の閉じ括弧の後に続く文字と `suffix` (`] : List P` の ` : List P`) は、閉じ括弧と同じ行に続ける。それで幅を超えても分けない。組でない文字 (切った部分の `...` など) の前でも行を分けない。入れ子が深く、字下げが幅を超える行も、そのまま書く
- 出力の上限: 整形した結果 (`suffix` を除く) が 100,000 文字を超えるなら、整形せずに、切った文字列 (10,000 文字までと ` ...`) に `suffix` を付けて返す。字下げは入れ子の深さに比例して伸びるので、利用者の `show` が返す深い入れ子の文字列では、整形した結果が入力の2乗の大きさになりうるためである
- 手間は、高々 10,000 文字の入力と 100,000 文字の出力で抑えられる。入れ子は 5,000 段にもなりうるので、組の入れ子を再帰でなく明示した作業の列でたどる (テストのスレッドのスタックは 2 MiB である)

`people` は2人の `P { name : String, age : Int, greet : Int -> Int }` のリストで、`numbers` は 1 から 100 万までの `Int` のリストである。幅は 80 で、`(中略)` はこの文書で省いた行である。

### 割り込みと実行時エラー

値を書く表示器は、入力と同じ実行の中の普通のコードで動く。表示の間の Ctrl-C は VM の安全点 (呼び出しと戻り) で止まり、ほかの入力の実行と同じく `interrupted` になる。確保量と深さの上限も同じである。利用者の `show_prec` が実行時エラーを起こせば、入力の実行時エラーとして表示する。整形は実行の後の Rust の処理で、高々 10,000 文字を読むだけなので割り込みを見ない。

結果を標準出力に書けなければ (パイプの相手が閉じたときなど)、`println` の失敗と同じく出力の誤り (`Fault::Output`) の実行時エラーにする。関数の名前は `<repl>` で、位置は入力の式の先頭である。表示は `cannot write the output: {error}` と `  at path:line:column` になる。式の入力はセッションを変えないので、ほかの扱いは要らない。

入力が `exit` を呼んだときは次のとおりにする ([標準ライブラリ](stdlib.md) の「`exit`」)。

- 入力が `exit n` を呼んでも、REPL は終わらない。後始末の後、標準エラーに `exited with code n` を書いて次の入力へ進む。GHCi と同じ扱いである。`n` は `& 255` をしない値をそのまま書く
- `exit` を呼んだ入力は、実行時エラーで終わった入力と同じく受け入れない。`let` の入力なら束縛を作らず、どの入力でもセッションの覚え (読んだファイル、表示のパス、一様な位置) を変えない
- `let x = exit 3` は `x` の型が決まらないので型検査で拒まれる (E2017)。`let` の入力で `exit` を試すには `let x : Int = exit 3` と書く
- 式の入力が `exit` したら、値を表示しない (`run_shown` は文字列を写さない)
- 中断で後始末が済み、ヒープに残るのはセッションの根だけになる。そのため、ヒープの回復 (`Ctx::recover`) は呼ばない

## 終わり方

- `:quit` と、入力の始めでの EOF (端末では空の行での Ctrl-D) で終わる。入力の途中の EOF では、読みかけの入力を処理してから終わる
- 終わるときは `Repl::close` を呼ぶ。終了コードは 0 である。`close` が誤りを返したら (検査モードのリーク、根を手放すときの誤り)、標準エラーに `runtime error: {error}` を書いて 1 で終わる
- 入力の誤り、実行時エラー、コマンドの誤りでは終了コードを変えない。対話の中の誤りだからである
- 行を読めない誤り (端末の誤り、UTF-8 でない入力) では、標準エラーに `error: cannot read input: {error}` を書き、`close` を呼んで 1 で終わる
- `:load` と `:reload` が閉じたセッションの `close` が誤りを返したら、その誤りを書いて続け、REPL が終わるときの終了コードを 1 にする
- 使い方の誤りは 2 である ([アーキテクチャ](../implementation/architecture.md) の「CLI と lib API」)

## 割り込み

REPL は Ctrl-C で終わらない ([VM](vm.md) の「上限と割り込み」の REPL の動き方)。Ctrl-C の扱いは unix だけのもので、ほかの OS ではハンドラを入れず、Ctrl-C は OS の既定の動作でプロセスを終わらせる。

- 行を編集する間の Ctrl-C は、読みかけの入力と `:{` の状態を捨て、入力の始めに戻す。端末を raw にする間に来た SIGINT で読みが `EINTR` で戻ったときも同じである
- 前端の検査に誤りのない入力は、実行を始める前 (lowering の後、`Machine::load` の前) に止める語を読む。割り込みが立っていれば、入力の種類によらず受け付けず、`Interrupted` にする ([モジュールと名前解決](modules.md) の「REPL のセッション」)。VM は入口では安全点を通らないので、ここで止めないと、入口から最初の呼び出しまでの extern と `root_set` が動くためである
- Ctrl-C で入力を止めたときは、同じ読みで届いた残りの行 (貼り付けた行や、先に打っておいた行) も捨て、入力の始めに戻す
- `:type` は始めに止める語を下ろし、前端の検査の後で止める語を読む。割り込みが立っていれば、型を書かずに `interrupted` を書き、同じ読みで届いた残りの行を捨てる
- 実行の間の割り込みは、VM の安全点か `File` の読み (`Fs.read_all` など) の中で止まり、`Failed` になる。待っている読みも、ハンドラが `SA_RESTART` を外して入れるので止まる ([オブジェクトモデル](object-model.md) の「`File`」)。最後の安全点の後に来た割り込みでは、入力は終わりまで動き、`let` の束縛もできる
- 入力を待つ間と、行を読み終えてから次の入力の始めまでに来た割り込みは、次の入力の始めの `Control::clear` が捨てる

### 残る制限

次の処理からは Ctrl-C で抜けられない。`eml run` は2回目の Ctrl-C で抜けられるが、REPL は終わらないためである。抜けるには、Ctrl-\ (SIGQUIT。既定の動作でプロセスを終わらせる) か `kill` を使う。

1. 前端の検査と回復。どちらも有限の時間で終わるので、終わるのを待つ。検査の間の割り込みは、上のとおり入力を取り消す
2. import で読むファイルと `:load` のファイルが、FIFO か遅いファイルのとき。std の読みが `EINTR` で読み直すためである
3. 書き手のいない FIFO を開く `Fs.open`。std の `File::open` が `EINTR` で開き直すためである。止めるには `O_NONBLOCK` で開いてから `fcntl` で戻す必要があり、`eml_rt` に `libc` の依存が要る
4. 詰まった標準出力への書き込み (`eml repl | less` で `less` を止めたときなど)。std の `write_all` が `EINTR` で書き直すためである
5. SIGINT が、止める語を見た後で `read` のシステムコールに入る前に届くと、`read` は待ち続ける。次の SIGINT の `EINTR` で止まる。防ぐには `ppoll` か self-pipe が要る
