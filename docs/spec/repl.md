# REPL の端末

`eml repl` の端末の規則を定める。セッションの意味 (入力ごとのモジュール、名前の解決、受け付ける入力) は [モジュールと名前解決](modules.md) の「REPL のセッション」に、入力の終わりの判定は [レイアウト規則](layout.md) の「REPL の入力の終わり」に、入力の読み分けは [文法](grammar.md) の「REPL の入力」にある。

## コマンドライン

- `eml repl [--debug-heap]` でセッションを始める。`--debug-heap` は `eml run` と同じく検査モードにする
- import の根と Host の相対パスの基準は、`eml run` と同じくカレントディレクトリである
- 上限は `eml_cli::repl_limits()` が決める。深さは `eml run` と同じ 2^27 語で、確保量は物理メモリの 40% である。回復は写す間に古いヒープと写しを同時に持ち、写しは根から届く物体だけなので古いヒープより大きくならない。合わせて、`eml run` の上限と同じ 80% を目安に収める。どちらの上限も、安全点で止めるまでの間に少し超えうる目安である。物理メモリを読めない OS では上限を置かない

## 行の編集

- 標準入力が端末なら、`rustyline` で行を編集する。履歴はメモリだけに持ち、読んだ行ごとに足す。空の行と直前と同じ行は足さず、100 行まで持つ。標準出力をリダイレクトしても、プロンプトと編集の表示は端末に書く。ただし `TERM` が `dumb` などの未対応の端末では、`rustyline` はプロンプトを標準出力に書く
- 評価の間に打った行と、bracketed paste でない速い入力も、失わずに次の読みで順に読む。`rustyline` は、読みのたびに作る読み手のバッファに残った入力を、`buffer-redux` の feature を入れたときだけ次の読みに渡すので、この feature を入れる
- 標準入力が端末でなければ、1行ずつ読み、プロンプトは書かない
- 1回の読みが複数の行を返すことがある (端末の bracketed paste)。返った文字列を `\n` で行に分け、行末の `\r` を除いて、1行ずつ次の「行のまとめ方」に渡す。同じ読みで `:quit` より後にある行と、セッションを続けられなくした入力より後にある行は捨てる
- `TERM` が `dumb` などの端末では、`rustyline` は行を編集せずに読む。このとき Ctrl-C は読みかけの入力を捨てない (下の「割り込み」)

## 行のまとめ方

- プロンプトは、入力の始めが `> `、入力の続きと `:{` の中が `. ` である
- 入力の終わりは、読んだ行を `\n` でつないだテキストで決める ([レイアウト規則](layout.md) の「REPL の入力の終わり」)。空行で終わった入力は、その空行を含めずに評価する
- 入力の始めの行が空白だけなら、何もせずに入力の始めのままにする。コメントだけの行は入力として評価する
- 入力の始めの行で、最初の空白でない文字が `:` なら、その行をコマンドとして読む。入力の続きの行と `:{` の中の行は、`:` で始まっても入力の本文である
- EOF では、読みかけの入力を評価してから終わる。終わっていない入力も評価して、その診断を見せる

## コマンド

コマンドの名前は、`:` の直後から最初の空白の前までの文字である。名前の後の空白でない文字が引数になる。

| コマンド | 動作 |
|---|---|
| `:quit` | セッションを終える |
| `:help` | コマンドの一覧と `:{ … :}` の使い方を標準出力に書く |
| `:{` | 次の行から、前後の空白を除くと `:}` だけになる行の前までを、1つの入力にする。空行も入力に含め、入力の終わりの判定はしない。本文が空白だけなら何もしない |

- `:quit` と `:help` は、表の名前の接頭辞で書ける。GHCi と同じく、表の順に見て最初に接頭辞が合う名前を選ぶ (`:q` は `:quit`)。表の順は `quit`、`help` である
- `{` と `}` は接頭辞で引かない。`:{` が引数を持てば誤りにする。入力の始めの `:}` は誤り (`':}' without ':{'`) である
- 名前が空なら誤り (`missing command name`)、合う名前がなければ誤り (`unknown command ':foo'`)、引数を取らないコマンドに引数があれば誤り (`':quit' takes no argument`) である。誤りは標準エラーに書き、何も評価しない
- `:{` の中で EOF になったら、`missing ':}'` を標準エラーに書き、何も評価しない

## ファイルの読み込み

`:load path` は、セッションを捨てて新しく始め、ファイルをその最初の入力として読む。

1. パスの綴りを決める。`eml run` と同じく、大文字小文字を区別しないファイルシステムでは、ディレクトリの一覧にある綴りに直す。この綴りを表示のパスにする
2. ファイルを読む。相対パスはカレントディレクトリから読む。読めなければ、標準エラーに ``error: cannot read `path`: {error}`` を書く。セッションも覚えたファイルも変えない
3. 読めたら、今のセッションを閉じる (`Repl::close`)。検査モードのリークか根を手放すときの誤りがあれば、標準エラーに `runtime error: {error}` を書いて続ける。その誤りは覚えておき、REPL が終わるときの終了コードを 1 にする (「終わり方」の `close` の誤りと同じ扱い)
4. 端末が新しいセッションを作り、ファイルをその最初の入力 (入力 1) として評価する (`Repl::with_file`)。ファイルの文法で読み、診断と実行時エラーの位置は表示のパスで見せる。`main` は実行しない
5. import の根は、ファイルのあるディレクトリにする。`eml run` が入口のファイルのディレクトリを根にするのと同じである。Host の相対パスの基準はカレントディレクトリのままにする (`eml run` と同じ)
6. 結果は普通の入力と同じく表示する。受け付けたときは何も書かない
7. 結果によらず、そのファイルを覚えて `:reload` の対象にする。ファイルに誤りがあるときや、前端の検査の間に割り込まれたときは、診断か `interrupted` を見せ、セッションは空のままにする。直してから `:reload` で読み直せる。空かコメントだけのファイルも、セッションは空のままである (`Outcome::Empty`)

引数のない `:load` は、今のセッションを 3. と同じく閉じて空のセッションを作り、覚えたファイルを忘れる。import の根はカレントディレクトリに戻す。

ファイルのトップレベルの item は、後の入力からすべて見える。`pub` は見ない。前の入力のトップレベルを `pub` を見ずに引く規則 ([モジュールと名前解決](modules.md) の「REPL のセッション」) がそのまま当たるためである。後の入力は、ファイルの item を普通の前の入力の item と同じく定義し直せる。古い版は `Shape#1` と表示する。ファイルの instance は、前の入力の instance と同じく、後の入力で定義し直せない (E1035)。

ファイルは、`eml run` の入口のファイルと同じく import できない。ファイルの依存先が import しても、後の入力が import しても E1030 になる。ファイルを受け付けなかったセッション (誤り、割り込み、空のファイル) でも同じである。診断の文言は `eml run` の入口のファイルのもの (`the entry module cannot be imported`) をそのまま使う。`:load` のファイルは REPL の入口のファイルだからである。

`:reload` は、覚えたファイルで `:load` の 1. から 7. をやり直す。ディスクからファイルを読み直し、新しいセッションの import のキャッシュは空なので、import したファイルも読み直す。

- 覚えたファイルがなければ、標準エラーに `no file to reload; use ':load'` を書き、セッションを変えない。打ち間違えた `:r` で `let` の束縛が消えないようにするためである
- 読めなければ (ファイルを消したときなど)、`:load` と同じく誤りを書き、セッションと覚えたファイルを変えない

## 型の表示

`:type e` は、式の型を実行せずに表示する。

- 引数を1つの式として読む。入力の読み分け (item か `let` か式か) はしないので、`f x = 1` を渡すと構文の誤り (`':type' takes one expression`) になる ([文法](grammar.md) の「REPL の入力」)
- 今のセッションに対して型を検査する。lowering も実行もせず、入力を受け付けず、入力の番号も進めない
- 誤りがなければ、標準出力に `e : T` を書く。`e` は引数の前後の空白を除いたテキストである。診断は普通の入力と同じく標準エラーに書く (警告は、受け付けた入力までに読んでいないファイルのものだけ)。誤りが1つでもあれば型を書かない
- 前端の検査の間に来た割り込みは、ほかの入力と同じく扱う。型を書かずに `interrupted` を書き、同じ読みで届いた残りの行を捨てる (「割り込み」)。`:type` も、`eval` と同じく始めに `Control::clear` を呼ぶので、入力を待つ間に来た割り込みでは止まらない

型 `T` は次のように書く。推論の詳しい規則は [型と Kind](types.md) の「REPL の入力」にある。

- 式の入力と違い、型に現れる型変数を `Unit` に決めない (defaulting しない)
- 型に現れる型変数は、書いた型を左から読んで最初に現れた順に `a`、`b`、`c`、`d`、`f`、…、`z`、`a1`、`b1`、… と名付ける。`e` で始まる名前は、番号が付いても型変数に使わない。row 変数の名前と重ねないためである
- row 変数は、書いた型 (文脈を含む) の中に2回以上現れるものだけを、左から最初に現れた順に `e`、`e1`、`e2`、… と名付ける。1回だけ現れる row 変数は閉じた row として書く (row がラベルを持たなければ省く)。入力の row の defaulting と同じ扱いで、`fn x -> x` を `a -> <e> a` でなく `a -> a` と見せるためである。2つの矢印が同じ row 変数を持つ `(>>)` は `(a -> <e> b) -> (b -> <e> c) -> a -> <e> c` になる。数えるのは書いた型の木の上で、同じ部分の型が2か所に現れれば、その中の row 変数も2回と数える
- 型に現れる型変数に残った制約は文脈にする。1つなら `Show a => …`、2つ以上なら `(Eq a, Show b) => …` と書く。制約は、型変数が現れた順に並べ、同じ型変数の中ではクラスの表示の名前の順 (同じなら定義の順) に並べる。同じ制約は1つにし、ほかの制約の上位クラスでたどれる制約は書かない (`Ord a` があれば `Eq a` を書かない)
- 型に現れない型変数に残った制約は、式の入力と同じく、その型変数を `Unit` に決めて解く。表示する型を変えないので、上の「defaulting しない」とは食い違わない。`Unit` で解けなければ E2009 にする。そのため `:type show []` は `String` を返し、`:type name (make ())` (`Unit` の instance のないクラス) は E2009 になる。型変数でない型に残った制約は、今と同じく E2006 にする
- Kind (矢印の線形性) は書かない。表面の型の構文に Kind はないためである
- 型と制約の名前は、診断と同じ表示 (`DisplayNames`) で書く。定義し直した item の古い版は `Shape#1` になる

式の入力の規則のうち、次の3つは `:type` に当てない。

- row が `<IO>` に収まらなければ E2015 にする規則。`:type ask ()` は `Int` を返す
- 型が `Unr` でなければ E2016 にする規則。`:type Fs.open "x"` は `File` を返す
- 型に現れる型変数を `Unit` に決める規則 (上のとおり名前を付け、制約は文脈にする)

本体の線形性の検査、網羅性の検査、ほかの型の誤りは、普通の式と同じく報告する。

```
> :type (>>)
(>>) : (a -> <e> b) -> (b -> <e> c) -> a -> <e> c
> :type fn x -> x
fn x -> x : a -> a
> :type []
[] : List a
> :type show []
show [] : String
> :type fn x y -> x < y && x == y
fn x y -> x < y && x == y : Ord a => a -> a -> Bool
> :type println "hi"
println "hi" : Unit
```

## 結果の表示

| 入力の結果 (`Outcome`) | 表示 |
|---|---|
| 診断 | 標準エラーに書く。`Repl::eval` は実行の後で診断を返すので、その入力で初めて読んだファイルの警告は、入力の出力の後に出る |
| `Empty`、`Accepted`、`Rejected` | 診断のほかに書くものはない。式の値は VM が標準出力に書く |
| `Failed` | 割り込みで止まったなら `interrupted`、ほかは `runtime error: {error}` を標準エラーに書く。位置があれば `  at path:line:column` が続く |
| `Interrupted` | 標準エラーに `interrupted` を書く |
| `Broken` | 標準エラーに `runtime error: {error}` を書き、`close` を呼ばずに終了コード 1 で終わる。後の入力はどれも実行できないためである |

- 割り込みは、止まった所によらず `interrupted` と書く。VM の中で止まったときの関数の名前 (`entry$` や `f@[Int]`) は、利用者が書いた名前でないので見せない
- VM は実行の終わりに、誤りのときも出力を書き出す。そのため、入力の出力は次のプロンプトより前に見える

## 終わり方

- `:quit` と、入力の始めでの EOF (端末では空の行での Ctrl-D) で終わる。入力の途中の EOF では、読みかけの入力を処理してから終わる
- 終わるときは `Repl::close` を呼ぶ。終了コードは 0 である。`close` が誤りを返したら (検査モードのリーク、根を手放すときの誤り)、標準エラーに `runtime error: {error}` を書いて 1 で終わる
- 入力の誤り、実行時エラー、コマンドの誤りでは終了コードを変えない。対話の中の誤りだからである
- 行を読めない誤り (端末の誤り、UTF-8 でない入力) では、標準エラーに `error: cannot read input: {error}` を書き、`close` を呼んで 1 で終わる
- 使い方の誤りは 2 である ([アーキテクチャ](../implementation/architecture.md) の「CLI と lib API」)

## 割り込み

REPL は Ctrl-C で終わらない ([VM](vm.md) の「上限と割り込み」の REPL の動き方)。Ctrl-C の扱いは unix だけのもので、ほかの OS ではハンドラを入れず、Ctrl-C は OS の既定の動作でプロセスを終わらせる。

- 行を編集する間の Ctrl-C は、読みかけの入力と `:{` の状態を捨て、入力の始めに戻す。端末を raw にする間に来た SIGINT で読みが `EINTR` で戻ったときも同じである
- 前端の検査に誤りのない入力は、実行を始める前 (lowering の後、`Machine::load` の前) に止める語を読む。割り込みが立っていれば、入力の種類によらず受け付けず、`Interrupted` にする ([モジュールと名前解決](modules.md) の「REPL のセッション」)。VM は入口では安全点を通らないので、ここで止めないと、入口から最初の呼び出しまでの extern と `root_set` が動くためである
- Ctrl-C で入力を止めたときは、同じ読みで届いた残りの行 (貼り付けた行や、先に打っておいた行) も捨て、入力の始めに戻す
- 実行の間の割り込みは、VM の安全点か `Fs.read_all` の中で止まり、`Failed` になる。待っている読みも、ハンドラが `SA_RESTART` を外して入れるので止まる ([オブジェクトモデル](object-model.md) の「`File`」)。最後の安全点の後に来た割り込みでは、入力は終わりまで動き、`let` の束縛もできる
- 入力を待つ間と、行を読み終えてから次の入力の始めまでに来た割り込みは、次の入力の始めの `Control::clear` が捨てる

### 残る制限

次の処理からは Ctrl-C で抜けられない。`eml run` は2回目の Ctrl-C で抜けられるが、REPL は終わらないためである。抜けるには、Ctrl-\ (SIGQUIT。既定の動作でプロセスを終わらせる) か `kill` を使う。

1. 前端の検査と回復。どちらも有限の時間で終わるので、終わるのを待つ。検査の間の割り込みは、上のとおり入力を取り消す
2. import で読むファイルが FIFO か遅いファイルのとき。std の読みが `EINTR` で読み直すためである
3. 書き手のいない FIFO を開く `Fs.open`。std の `File::open` が `EINTR` で開き直すためである。止めるには `O_NONBLOCK` で開いてから `fcntl` で戻す必要があり、`eml_rt` に `libc` の依存が要る
4. 詰まった標準出力への書き込み (`eml repl | less` で `less` を止めたときなど)。std の `write_all` が `EINTR` で書き直すためである
5. SIGINT が、止める語を見た後で `read` のシステムコールに入る前に届くと、`read` は待ち続ける。次の SIGINT の `EINTR` で止まる。防ぐには `ppoll` か self-pipe が要る
