# 字句

位置づけ: 規範。

ソースの文字コード、空白とコメント、識別子、キーワード、演算子、リテラルの字句の規則を定める。字句の後に行うレイアウトの処理は [レイアウト規則](layout.md) で扱う。

## 文字コードと先頭行

- ソースは UTF-8 とする。識別子は ASCII に限る。文字列とコメントには任意の文字を書ける
- ファイルの先頭の BOM (U+FEFF) は、ソースを読み込むときに取り除く。字句、レイアウトの列、診断の位置は、BOM を除いたテキストで数える。ファイルの途中の U+FEFF は認識できない文字 (E0001) とする
- ファイルの先頭行が `#!` で始まる場合、その行全体を `SHEBANG` トークンとし、trivia として扱う

## 空白とコメント

- 空白はスペース、タブ、`\r`、`\n` とする。改行は `\n` (`\r\n` を含む) で、単独の `\r` は空白だが改行ではない。**行頭のインデントにタブを使うことはエラー**とする (E0006)。行の途中のタブは空白として読み、レイアウトの列には影響しない。列を読むのは行の先頭のトークンだけだからである
- 行コメントは `--` から行末までとする。ただし、`--` の後ろに演算子の文字が続く場合 (例: `-->`) は演算子とする (Haskell と同じ規則)
- ブロックコメントは `{-` から `-}` までとする。入れ子にできる。閉じていなければ E0005 とする
- ドキュメントコメントは `-- |` で始まる行コメントとする (Haddock と同じ)。字句としては普通のコメントで、ドキュメント生成と LSP の hover が解釈する

## 識別子

| 種類 | 規則 | 用途 |
|---|---|---|
| 小文字識別子 | `[a-z_][A-Za-z0-9_']*` (`_` 単独を除く) | 変数、関数、型変数、row 変数、操作名、メソッド名、フィールド名 |
| 大文字識別子 | `[A-Z][A-Za-z0-9_']*` | 型名、コンストラクタ、エフェクト名、クラス名、モジュール名 |
| `_` 単独 | 専用のトークン | ワイルドカード |

- `x'` のように `'` を含められる (Haskell と同じ)
- 「大文字 = 具体的なもの、小文字 = 変数」という区別により、パターンの `Some x` と `x`、row の `<IO>` と `<e>` を構文だけで区別できる

## キーワード

```
data type effect where pub extern abstract import as infixl infixr infix
let in if then else match with handle from drop return
never once multi use fn ctl and var
class instance deriving
```

`forall` を予約する。項目の位置に書くと E0011 になる。

`true` / `false` はキーワードではない。`Bool` は組み込みの `data Bool = | False | True` で、値は `True` / `False` と書く。

## 演算子

- 演算子の文字は `! $ % & * + - . / < = > ? @ ^ | ~ :` とする。これらを1文字以上並べたものが演算子のトークンになる (最長一致)
- `=` `|` `:` `.` `->` `<-` `..` `=>` の並びは予約記号で、演算子にはならない。`=>` は制約の文脈の終わりに使う ([文法](grammar.md) の `context`)。`<-` は `use p <- e` と代入 `x <- e` に使い、どちらでも左辺が右辺から値を受け取ることを表す ([文法](grammar.md) の `stmt` と `expr`)。そのため、ユーザーは `=>` を演算子として定義できない。演算子のシグネチャや等式の形 (`(=>) : …`、`a => b = …`) で書くと、`=>` を指す E0011 になる
- 演算子の並びが `-><` で始まるときは、最長一致の例外として、先頭の `->` を1つのトークンにし、残りを改めて演算子のトークンにする (`Int -><IO> Int` は `->`、`<`、`IO`、`>`、`Int`)。レイアウト段が row の始まりを `->` の直後の `<` で見分けるためである ([レイアウト規則](layout.md) の規則 4)。そのため `-><` で始まる演算子は定義できない。`infixl 5 -><` は演算子の代わりに `->` を見つけて E0011 になり、`(-><) : …` は E0003 になる。`--><` は `-><` で始まらないので分けない
- `<-` で始まる3文字以上の並びは、最長一致のとおり1つの演算子である。`<->` のような演算子を定義できるようにするためである。空白のない `a<-1` は `a`、`<-`、`1` で代入になるので、比較は `a < -1` と書く
- `:` で始まる演算子は、予約記号の `:` を除いて、コンストラクタの演算子とする (例: `::`、`:=`)。「大文字の名前 = コンストラクタ」の規則を、演算子に当てはめたものである
- 区切り記号は `( ) [ ] { } , ;` とバッククォートとする

演算子の優先順位と結合は、ユーザーが fixity の宣言で決める。標準の演算子の表は [宣言](declarations.md) の「fixity」に載せる。

## 数値と文字

| リテラル | 形 | 今の扱い |
|---|---|---|
| 整数 | `123`、`1_000_000`、`0xff`、`0o17`、`0b1010` | 使える |
| 浮動小数 | `1.5`、`1e9`、`2.5e-3`、`1_000.5` | 使える。型は `Float` |
| バイト | `65u8`、`0xffu8`、`0b1010_0000u8`、`0o17u8`、`'a'u8`、`'\n'u8` | 使える。型は `Byte` |
| 文字 | `'a'`、`'\n'` | 使える。型は `Char` |

整数のリテラルの値は 0 から 2^63 - 1 まで (`Int` の最大値まで) である。超えたら E0007 (不正な数値リテラル) にする。不正な形の数も E0007 である。接頭辞は小文字の `0x`、`0o`、`0b` だけで、大文字の `0X`、`0O`、`0B`、`1abc` のように数の直後に英字が続く形、`0xZZ`、`0b12`、`0x` のように接頭辞の後ろがその進数の数字だけでできていない形がこれにあたる。

浮動小数のリテラルは、小数点の前後に数字のある形 (`1.5`) か、指数を持つ形 (`1e9`、`2.5e-3`、`1E+2`) である。数字の間には `_` を書ける。値は `_` を除いた文字列を Rust の `f64` の読み取りと同じく読み、IEEE 754 の倍精度の最も近い値に丸める。大きすぎる値 (`1e400`) は無限大になる。`inf` と `nan` のリテラルはない。リテラルは単相で、整数のリテラルは `Int`、浮動小数のリテラルは `Float` である ([型と Kind](types.md) の「数の型」)。

`Byte` のリテラルは、整数のリテラルの直後に小文字の接尾辞 `u8` を付けた形で、字句は1つの `BYTE` にする。接尾辞は基数を調べる前に外すので、`0xffu8` のように `u` が16進の数字でなくても曖昧にならない。値は 0 から 255 までで、超える `256u8` は E0007 (``byte literal `256u8` is too large``、ラベルは ``the largest `Byte` is 255``) である。大文字の `65U8`、ほかの幅の `65u16`、浮動小数の `1e5u8` は、不正な形として E0007 (`invalid number literal`) のままである。型は `Byte` で、式とパターンの両方に書ける ([型と Kind](types.md) の「数の型」)。

文字のリテラルの直後に `u8` を付けた `'x'u8` も `Byte` のリテラルで、字句は1つの `BYTE` にする。値は文字のコードポイントで、`'\n'u8` は `10u8` である。引用符の間の規則は文字のリテラルと同じで、誤りも同じ診断になる (下の説明)。コードポイントが 255 を超える `'あ'u8` は E0007 (``byte literal `'あ'u8` is too large``、ラベルは ``the largest `Byte` is 255``) である。`b'x'` の形は識別子と区別できないので採らない。

空白のない `.` の直後にある `数字.数字` の形 (`t.0.1` の `0.1`) は、浮動小数でなく、`INT`、`.`、`INT` の3つのトークンに分ける。射影の連なりとして読むためである (Rust と同じ)。小数点より後ろに数字と `_` 以外を含む形 (`t.0.1e5` の `0.1e5`) は分けない。

負の数は単項の `-` で書く。直後が整数か浮動小数のリテラルのときは、HIR が負のリテラルにまとめる。`Byte` のリテラルの直前の `-` は E1054 である。扱いは [式](expressions.md) の「演算子の列と単項マイナス」で定める。`Int` の最小値 -2^63 はリテラルと単項の `-` では書けない。

文字のリテラル `'x'` は、Unicode のスカラー値をちょうど1つ持つ。型は `Char` で、式とパターンの両方に書ける ([型と Kind](types.md) の「数の型」)。引用符の間の escape は `\n` `\t` `\r` `\\` `\'` `\"` `\0` `\u{XXXX}` で、文字列の escape と同じ表を使う。文字のリテラルの中の `\{` は escape ではなく、不明な escape (E0008) になる。

- 字句は、`'` から同じ行の次の `'` までを1つの `CHAR` にする。`\` の後ろの1文字は `'` でも本文に含める。そのため、誤ったリテラルにも診断は1件だけ出る
- 同じ行に閉じる `'` がない `'` は、`CHAR` にならず E0001 になる。`x'` のように識別子の後ろにある `'` は、識別子の一部である
- 本文が空 (`''`) か、スカラー値が2つ以上 (`'ab'`、e と U+0301 で書いた `'é'`) のときは E0016 (`INVALID_CHAR_LITERAL`) にする。範囲はリテラル全体で、本文に `"` と `\` と見えない文字がなければ、文字列で書く案を help に出す。メッセージに埋めるリテラルは、ほかの字句の誤りと同じく、見えない文字を escape し、長ければ切り詰める
- 未知の escape と不正な `\u{...}` (サロゲート、0x10FFFF を超える値、桁の数の誤り) は E0008 にする。範囲は escape だけである。`\u{` の `}` は閉じの `'` の手前までで探す

## 文字列

| 種類 | 形 | エスケープ | 補間 |
|---|---|---|---|
| 通常 | `"..."` | あり | あり |
| 複数行 | `"""` + 改行 ... `"""` | あり | あり |
| raw | `r"..."`、`r#"..."#` (`#` は何個でも) | なし | なし |

- エスケープは `\n` `\t` `\r` `\\` `\'` `\"` `\0` `\u{XXXX}` とする。`\u{…}` の中身は1〜6桁の16進数で、Unicode のスカラー値を表す。ほかの `\` の並びは不正なエスケープ (E0008) にする
- `\u{` の閉じの `}` は、行末と、最初の `"`、`\`、バッククォートより手前で探す。`"\u{4\{x}}"` の穴を、不正なエスケープに飲み込まないためである
- 補間は `\{式}` と書く。穴には式を1つ書き、その中に文字列や `{}` を入れ子にしてよい。穴の値は Prelude の `display` で文字列にする ([式](expressions.md) の「補間」)。`\\{` は `\` のエスケープと `{` の並びで、補間にならない
- 穴の中には改行を書けない (下の「穴の中の改行」)。`if` や `match` も、1行で書けば穴に入れられる
- `r` と `"` の間に空白を入れると、識別子 `r` と通常の文字列の並置になる

### 文字列のトークン

文字列は、穴がなくてもいつも次のトークンに分ける ([文法](grammar.md) の `string`)。

| トークン | 中身 |
|---|---|
| `STRING_START` | `"` か `"""` |
| `STRING_TEXT` | エスケープでない本文の並び。複数行の文字列では改行を含みうる |
| `ESCAPE` | エスケープ1つ (`\n`、`\u{…}` など)。不正なエスケープも1つの `ESCAPE` にする |
| `INTERP_START` | 補間の開き `\{` |
| (穴の中) | ふつうのトークン |
| `INTERP_END` | 穴を閉じる `}`。閉じていない穴では幅 0 になる (下の「改行での回復」) |
| `STRING_END` | `"` か `"""` |

- raw 文字列は中に構造がないので、閉じまでを1つの `RAW_STRING` にする
- `ESCAPE` を分けるのは、値の取り出しと E0008 の検査が同じトークンを見るためと、LSP がエスケープを色分けできるようにするためである
- 穴の閉じを `R_BRACE` でなく専用の `INTERP_END` にするのは、ほかの括弧と取り違えないためである。`R_BRACE` にすると、`"\{(x}"` の `}` をレイアウト段とパーサが `(` の閉じと読み、穴が閉じなくなる。`"\{x)}"` では逆に、穴の中の `)` が、穴の `\{` を対になる開き括弧として閉じてしまう
- 単一行の文字列とコマンドリテラルの、行末かファイルの終わりにある `\` は、長さ1の `ESCAPE` にし、E0008 を出さない。リテラルは閉じていない扱いになり、E0002 だけが出る。複数行の文字列の行末の `\` は E0008 になる (下の「複数行の文字列」)
- コマンドリテラルも同じ形に分ける (下の「コマンドリテラル」)

### モードのスタック

lexer は、`Code`、`String`、`Command` のモードからなるスタックを持つ。底は `Code` である。

- `Code` のモードで `"` か `"""` を読むと、`STRING_START` を出して `String` を積む。バッククォートを読むと、`CMD_START` を出して `Command` を積む
- `String` か `Command` のモードで `\{` を読むと、`INTERP_START` を出して穴の `Code` を積む
- 穴の `Code` は、開いている `{` の数を数える。数が 0 のときの `}` は、`INTERP_END` を出してモードを1つ戻す。ほかの `}` は `R_BRACE` である。底の `Code` では、`}` はいつも `R_BRACE` で、モードを変えない
- `Command` のモードは、開いている `'` の位置を覚える。`'` を読むたびに、開閉を切り替える (下の「コマンドリテラル」)
- 閉じの `"`、`"""`、バッククォートを読むと、`STRING_END` か `CMD_END` を出してモードを1つ戻す
- 穴の中の `"` は新しい `String` を積むので、`"a \{f "b \{x}"}"` のような入れ子も読める
- lexer は、どの `INTERP_START` にも対応する `INTERP_END` を必ず1つ出す (幅 0 のものを含む)。パーサとレイアウト段は、これを頼りに穴の終わりを決める

### 穴の中の改行

穴の中には改行を書けない。単一行の文字列でも、複数行の文字列でも同じである。

- 改行を許すと、`"a \{x` のように `}` を書き忘れたとき、ファイルの残りを穴として読んでしまう。改行を書けなくするのは、この回復のためである
- 穴の中のトークンは、改行 (`\n` か `\r\n`) の手前で切る。改行を含みうるトークン (空白、ブロックコメント、raw 文字列) も、穴の中では改行の手前で終わる
- 穴の中の `"""` は E0014 にして、単一行の文字列として読む (下の「改行での回復」)

### 改行での回復

単一行の文字列、コマンドリテラル、穴の中で改行かファイルの終わりに着いたら、スタックの上からモードを取り除く。止まるのは、穴の外にある複数行の文字列か、底の `Code` に着いたときである。

- 取り除いた穴には、改行の手前 (ファイルの終わりではその位置) に幅 0 の `INTERP_END` を出す。パーサは穴を普通に閉じるので、次の行のトークンを穴の中として読まない。レイアウト段の穴の文脈も、この `INTERP_END` が取り除く
- 報告するのは、一番内側の層の1件だけである。外側の層は黙って閉じる。1つの書き忘れに、層の数だけ誤りを並べないためである。`"a \{f "b` は、内側の文字列の E0002 の1件になる
  - 文字列とコマンドリテラル: E0002。コマンドリテラルに閉じていない `'` があれば、その E0017 を先に出す (下の「コマンドリテラル」)。すぐ外の層が穴なら、その穴の `\{` を secondary で示す。`"count: \{n"` のように `}` を書き忘れると、閉じのつもりの `"` が穴の中で新しい文字列を開き、報告は書き手が開いた覚えのない文字列になるためである
  - 穴: E0002。範囲は `\{` である。改行で閉じた穴には、穴は同じ行で閉じるという note を付ける
  - 穴の中で閉じていないブロックコメント: E0005
  - 穴の中で閉じていない raw 文字列: E0002
  - 穴の中の `"""`: 開いたときに出した E0014 をこの層の報告にし、E0002 は重ねない
- 複数行の文字列は改行では閉じない。中の穴が改行に着けば、穴とその中の層だけを改行の手前で閉じ、文字列は続く。文字列が閉じれば、閉じていない穴も、読めたところまでの式を持つ穴として文字列に残る
- ファイルの終わりでは、複数行の文字列も含めて、開いているモードをすべて取り除く。報告は上と同じく一番内側の層の1件だけにする。ただし、閉じていない複数行の文字列の開きの行の検査 (下の「複数行の文字列」) は、ほかの層の報告とは別に行う

### 複数行の文字列

形は Swift と同じである。

- 開きの `"""` の後ろは、行末まで空白しか書けない。その空白は値に入れない。閉じの `"""` の前も、その行の先頭から空白しか書けない
- 中身は `\n` か `\r\n` で行に分ける。改行の一部でない単独の `\r` は行の中身で、空白には数えない。閉じの `"""` の列を N とする (前に空白しかないので、文字の数とバイトの数は同じである)。中身の各行から、先頭の N 個の空白を取り除く。空白だけの行は N より短くてもよく、空の行になる。N より長い空白だけの行は、N 個を除いた残りの空白を保つ。それ以外の行で、先頭の N 文字に空白でない文字 (タブ、エスケープの `\`、穴の `\{` を含む) があれば誤りにする
- 開きの直後の改行と、閉じの直前の改行は値に入れない。`"""` の次の行が閉じの `"""` なら、2つの改行は同じもので、値は空の文字列である
- エスケープと補間は、通常の文字列と同じに書ける。`"` と `""` はそのまま書け、`"""` を中身に入れるときは `\"""` と書く。行末の `\` で行をつなぐ書き方はなく、行末の `\` は E0008 にする (範囲は `\` だけである)
- 字下げを取り除くのはソースの本文だけで、穴の値は変えない。行頭の穴の前の空白は、ほかの行と同じく字下げとして扱う
- 形の誤りは E0014 にする。範囲はいつも文字列のトークンの中に収め、文字列の外のコードを含めない ([診断の出し方](../implementation/diagnostics.md) の「番号ごとの出し方」)
  - 開きと閉じが同じ行にある (`"""m"""`)。字下げは検査しない
  - 開きの行の `"""` の後ろに、空白でない文字がある
  - 閉じの `"""` の前に、空白でない文字がある。N が決まらないので、字下げは検査しない
  - 字下げが足りない行がある。行ごとに1件出す
- 閉じていない複数行の文字列は、開きの `"""` に E0002 を出し、字下げは検査しない。開きの行は検査する
- E0014 があっても、トークンと CST は同じ形に組む。その文字列は値を持たない

```haskell
main : Unit -> <IO> Unit
main () =
  let name = "eml"
  println """
    Hello, \{name}!
      indented line
    """
```

この例は `Hello, eml!` と `  indented line` の2行を出す。

### raw 文字列

- `r"…"`、`r#"…"#` (`#` は何個でもよい) と書く。閉じは、`"` の後に開きと同じ数の `#` を並べたものである。エスケープも補間もなく、書いたとおりの値になる
- Rust と同じく、改行を含められる。字下げは取り除かない。字下げを付けて複数行のテキストを書くときは、複数行の文字列を使う
- 穴の中では、改行の手前で止まる (上の「穴の中の改行」)
- 閉じていなければ、ファイルの終わり (穴の中では改行の手前) までを1つの `RAW_STRING` にして、E0002 を出す

### 改行の正規化

複数行の文字列と raw 文字列のどちらも、ソースの `\r\n` を値では `\n` にする。ファイルの改行の種類で値が変わらないようにするためである。

## コマンドリテラル

```haskell
run `rsync -a --delete \{..files} \{dest}`
```

- バッククォートで囲む。結果は `Cmd` 型の値になる ([式](expressions.md) の「コマンドリテラル」)
- 本文は空白で引数に分ける。シェルは介さない。`'...'` で囲んだ部分は、空白を含んでも1つの引数になる (下の「引用と区切り」)
- `\{x}` (`x : String`) は、中身に空白があっても、常に1つの引数 (または引数の一部) になる
- `\{..xs}` (`xs : List String`) は、要素ごとに別の引数として展開する。単独の引数の位置にだけ書ける
- パイプ、リダイレクト、`$VAR`、glob は解釈しない。標準ライブラリの関数で組み立てる
- エスケープは通常の文字列と同じで、さらに `` \` `` を使える
- 字句は文字列と同じ形に分ける。トークンは次のとおりである。穴の中の `..` は `DOT2` のトークンになる。コマンドリテラルの中の `"` は本文である
- Haskell のバッククォートによる中置 (`` x `div` y ``) は採用しない。中置で使いたい関数は演算子として定義する

| トークン | 中身 |
|---|---|
| `CMD_START` | 開きのバッククォート |
| `CMD_TEXT` | エスケープでも引用でもない本文の並び |
| `CMD_QUOTE` | 引用の開きと閉じの `'`。幅は1である |
| `ESCAPE` | エスケープ1つ |
| `INTERP_START`、`INTERP_END` | 穴の開き `\{` と閉じ `}` |
| `CMD_END` | 閉じのバッククォート |

### 引用と区切り

- エスケープでない `'` を `CMD_QUOTE` にし、読むたびに引用の開閉を切り替える。引用の中でも、エスケープと穴は外と同じに読む。引用の中に `'` を入れるときは `\'` と書く
- 引用の中でも、バッククォートはリテラルを閉じる。バッククォートを引数に入れるときは `` \` `` と書く
- 穴の中の `'` は、穴の `Code` モードの文字のリテラルで、引用とは関係がない
- 区切りは、引用の外の `CMD_TEXT` にある空白とタブだけである。`\t` などのエスケープ、穴、引用の中の空白は区切らない。改行はリテラルに書けない
- 区切りを挟まずに隣り合う本文、エスケープ、引用、穴は、1つの引数になる。`--out=\{dir}` は1つの引数で、`a'b c'd` は `ab cd` という1つの引数である。`''` は空の引数である
- 引用が開いたまま、閉じのバッククォート、改行、ファイルの終わりに着いたら、E0017 (`UNTERMINATED_QUOTE`) にする。範囲は開きの `'` の1文字である。改行とファイルの終わりでは、リテラルも閉じていないので、E0017 の後に E0002 を出す。閉じのバッククォートで気づいたときは、リテラルは閉じているので E0017 だけになる
- 改行の手前の `\` は長さ1の `ESCAPE` で、E0002 だけが出る (上の「文字列のトークン」)

プログラムと引数の決め方、spread の穴の位置、`Cmd` への脱糖は [式](expressions.md) の「コマンドリテラル」で定める。
