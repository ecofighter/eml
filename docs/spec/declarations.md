# 宣言

位置づけ: 規範。

トップレベルに書く宣言 (シグネチャと等式、`data` と `type`、`effect`、`extern`、fixity、クラスと instance、`pub`) の構文と、HIR で行う検査と脱糖を定める。文法は [文法](grammar.md) にある。

## シグネチャと等式

```haskell
len : List a -> Int
len [] = 0
len (_ :: rest) = 1 + len rest
```

シグネチャは Haskell / Idris と同じく、等式とは別の行に書く。1つの関数を複数の等式で定義できる。

- トップレベルの関数と値は、シグネチャが必須である ([型と Kind](types.md) の「推論」)。構文上はシグネチャと等式が別の item なので、HIR で次を検査する
  - シグネチャのない等式 (E1004)
  - 等式のないシグネチャ (E1005)。`extern` のシグネチャは除く
  - 同じ名前の等式が連続していない (間に別の item がある) (E1018)。`extern` のシグネチャの等式は除く
  - シグネチャと等式が隣り合っていない (E1019)。`extern` のシグネチャの等式は除く
  - 等式ごとに引数の個数が違う (E1020)
- 診断には、シグネチャの追加を提案する help を付ける
- 複数の等式は、HIR で「引数のタプルに対する `match`」1つに脱糖する。網羅性と線形性の検査は、その `match` に対して行う
- ローカルの `let` は、注釈なしで推論する
- 引数のない値 (`pi : Int`、`pi = 3`) も書ける。「引数のない関数は `()` を取る」という規約は、エフェクトを持つ計算に使う

シグネチャを複数の行に分けるときは、`->` を行の先頭に置く。

```haskell
fold_lines : String
  -> (a -> String -> a)
  -> a
  -> <IO> a
```

`->` は [レイアウト規則](layout.md) のブロックの開始トークンなので、`->` で行を終えて次の行を同じ列に揃えると、字下げしたブロックが必要というエラー (E0009) になる。行末の `->` の E0009 には、次の行をより深く字下げするか、型なら `->` を次の行の先頭に置くよう促す help を付ける (行末の `->` はラムダや `match` の枝にもあるので、どちらにも当てはまる言い方にする)。揃えた行がさらに `->` で終わっても、E0009 は最初の1件だけ出す ([コンパイラの構成](../implementation/architecture.md) の「構文解析の回復」)。

## `data` と `type`

```haskell
data Option a =
  | None
  | Some a

data Color = | Red | Green | Blue

-- Prelude の宣言。コンストラクタ `::` は Prelude だけが宣言できる
pub infixr 5 ::

pub data List a =
  | Nil
  | a :: List a
  deriving (Eq, Ord)

data Shape =
  | Circle { radius : Int }
  | Rect { width : Int, height : Int }
  | Empty
```

- `data` は名前的な直和型である。各選択肢は `|` で始める。選択肢は字下げしたブロックにも、同じ行にも並べられる
- 中置のコンストラクタは、`:` で始まる演算子で宣言できる。両側には型の適用を書ける (`| List a :+ L a`)
- コンストラクタ `::` は、Prelude の `List` だけの名前である (Haskell の `:` と同じ)。Prelude 以外のモジュールでコンストラクタ `::` を宣言すると、宣言ごとに E1044 にする。そのコンストラクタは宣言したものとして置き、そのモジュールの `::` の使用には誤りを重ねない。予約により、誤りのないプログラムでは、`x :: xs` は式でもパターンでも、どのモジュールでも Prelude の `::` を指す。`::` を宣言するモジュールが Prelude だけになるためである。名前の引き方は変えない
  - 予約する理由は2つある。1つ目に、自分の `::` を定義したモジュールでは、Prelude のリストを頭と残りに分解する書き方がなくなる。修飾した演算子の構文 (`Prelude.::`) はないためである。2つ目に、2つのモジュールが `::` を定義すると、表示の表が両方を `Prelude.::` と `Main.::` に修飾し、診断と網羅性の例に書けない形が出る
  - `Nil` は予約しない。自分の `Nil` は Prelude の `Nil` を隠す。Prelude の空のリストは `[]` か `Prelude.Nil` で書ける
- 型とコンストラクタは別の名前空間にあるので、同じ名前を付けられる ([モジュールと名前解決](modules.md))
- 選択肢のコンストラクタには、名前付きのフィールドを `{ name : T, … }` の形で書ける。フィールドの後に型の atom は続けない。どの選択肢にも書け、位置のコンストラクタや中置のコンストラクタと同じ `data` に混ぜてよい。`{}` (フィールドが0個) も書ける。同じコンストラクタの中で同じフィールドの名前を2回書くと E1045 にする。作る式、射影、更新、パターンは [直積型とレコード](records.md) にある
- `type` は型の別名の構文として予約する。型の別名はまだ実装しておらず、`type` の宣言は HIR が E0004 にする ([ロードマップ](../future/roadmap.md) の「言語機能と構文」)
- `extern` でない `data` に `=` がないものは、値を作れない型になるので E1025 とする。どのモジュールでも同じである
- `Int`、`String`、`Unit` は `Prelude` の、`File` は標準ライブラリのモジュール `Fs` の `extern data` で、`Bool` は `Prelude` の `data Bool = | False | True` である (下の「`extern`」)。`List`、`Option`、`Result` も `Prelude` の `data` である (下の「Prelude のクラス」)

## `effect`

```haskell
effect State s where
  get : Unit -> s
  put : s -> Unit

effect Log where
  log : Level -> String -> Unit

effect Fail where
  never fail : String -> a
```

- 多重度は `never` / `once` / `multi` を操作の前に付ける。省略したら `once` とする。多重度の意味は [エフェクトと handler](effects.md) で定める
- エフェクトは型引数を持てる (`effect State s`)。型引数は型だけで、row を引数に取るエフェクトはまだ書けない。型引数の名前が重複したら E1003 にする
- 操作のシグネチャで、エフェクトの型引数と同じ名前の型変数はその型引数を指す。ほかの型変数は、操作ごとに暗黙に量化する
- row の中のエフェクトには、宣言と同じ個数の型引数を付ける (`<State Int>`)。個数が違えば E1015 にする
- **操作のカリー化を許す。** 操作の引数の個数は、シグネチャの一番外側の `->` の数とする
- 操作のシグネチャの一番外側の `->` には row を書けない (書いたらエラー)。カリー化した操作では、この規則を外側のすべての `->` に適用する
- `never` の操作の結果の型は、宣言で自由な型変数として書く (`never fail : String -> a`)。結果の型は操作自身の型変数で、引数に現れてはならない。エフェクトの型引数は、呼び出した側が自由に選べないので、結果の型に使えない (E1008)
- エフェクトの操作は、値の名前空間に置くトップレベルの値である。名前の重複の扱いは [モジュールと名前解決](modules.md) の「名前空間」にある

## `extern`

```haskell
pub extern data Int
pub extern effect IO
pub extern println : String -> <IO> Unit
```

`extern` は、処理系が実装を持つ組み込みを宣言する修飾子である。`pub` の後に書き、宣言は次の3つの形だけである。

- 等式のないシグネチャ (`pub extern println : String -> <IO> Unit`)。実装は処理系が持ち、eml のコードで本体は書かない
- `=` のない型引数なしの `data` (`pub extern data Int`)。値の表し方と Kind は処理系が決める
- `where` のない型引数なしの `effect` (`pub extern effect IO`)。操作を持たない、ラベルだけのエフェクトである ([エフェクトと handler](effects.md) の「組み込みの `IO`」)

extern の型とエフェクトに型引数を持たせないのは、row の中で重なったラベルを1つにまとめる規則が、型引数のないエフェクトでだけ正しいためである。これ以外の位置の `extern` は構文エラー (E0011) になる ([文法](grammar.md))。型引数を書いた extern の型も E0011 にするが、書いた型引数は型引数として数える。使う位置の型引数の数の誤り (E1015) を重ねないためである。

- `extern` は標準ライブラリ ([モジュールと名前解決](modules.md) の「標準ライブラリ」) のモジュールにだけ書ける。ユーザーのモジュールに書くと、宣言ごとに E1033 にする。help で `extern` を外すよう示すが、外すと E1005 や E1025 になるので自動の修正にはしない。宣言は extern として読み、E1005、E1025、`where` がないことの誤りは重ねて出さない。extern のシグネチャに続く等式は、離れていても読み捨て、E1018 と E1019 も出さない。E1033 は宣言ごとに1つで、その宣言を使った位置には重ねない。handler の節の先頭にユーザーの extern の関数を書いても、E1009 を重ねずに節を捨てる
- extern の宣言は、処理系が持つ表の行を、モジュールの正式な名前で修飾した名前 (`Prelude.println`、`Std.Fs.open`) で指す。表にない名前や、表の行と食い違う宣言は処理系の誤りで、診断ではなくテストで防ぐ
- extern でない宣言の規則は変わらない。等式のないシグネチャは E1005、`=` のない `data` は E1025 で、`Prelude` を含むすべてのモジュールで同じである。extern でない `effect` には、今までどおり `where` と操作が要る
- extern の関数の型は、ほかの関数と同じくシグネチャから決まる。引数のそろった呼び出しは、eml のコードを呼び返さずにその場で実行される

instance の `where` のブロックには、メソッドを処理系の表の行に結ぶ `extern` の行も書ける (`extern (==)`。下の「`instance`」)。

```haskell
instance Eq Int where
  extern (==)
  extern (!=)
```

- 行の名前は `<モジュールの正式な名前>.<クラス> <型>.<メソッド>` (`Prelude.Eq Int.==`) である。クラスと型は、その instance のモジュールで書いた名前である
- 行の型は、クラスのメソッドのシグネチャのクラスの型変数を、instance の頭の型に置き換えたものである
- instance の中の `extern` も、標準ライブラリのモジュールにだけ書ける。ユーザーのモジュールに書くと、行ごとに E1033 にする。その行のメソッドは定義したものに数え、E1036 を重ねない

## fixity

```haskell
pub infixr 5 </>
pub (</>) : Path -> String -> Path
dir </> name = join_path dir name
```

- トップレベルに `infixl` / `infixr` / `infix` + 優先順位 (0〜9) + 演算子 (カンマ区切りで複数) を書く
- fixity は、演算子の名前が解決した先の定義 (関数、コンストラクタ、操作、クラスのメソッド) に付く。Prelude の演算子は Prelude の宣言を使い、ユーザーが定義した演算子 (関数、中置のコンストラクタ、メソッド) はユーザーの宣言を使う。Prelude の `pub infix 4 ==, !=, <, <=, >, >=` は、`Eq` と `Ord` のメソッドに付く
- 別のモジュールの定義に解決した演算子では、その fixity の宣言が `pub` のときだけ宣言が効く。`pub` でなければ `infixl 9` である
- fixity の宣言がない演算子は `infixl 9` とする (Haskell と同じ)。ユーザーが `+` を定義して Prelude の `+` を隠したときも、宣言がなければ `infixl 9` である
- 宣言の位置は問わない。後ろに書いた宣言も、モジュール全体の演算子の列の組み直しに効く
- 標準ライブラリの演算子の fixity は変えられない。このモジュールで定義していない演算子への宣言は E1022 になる。このモジュールのクラスのメソッドは、このモジュールで定義した演算子に数える
- `&&` と `||` も、ユーザーの定義が Prelude のものを隠せる。その場合は短絡しない普通の関数になり、`if` への脱糖は行わない。`|>` と `<|` は脱糖しない普通の関数なので、ほかの演算子と同じように隠せる
- `pub` を付けた fixity は、演算子と一緒に公開される。fixity は演算子の定義に付属し、import した先でも同じ fixity を使う
- 同じ演算子に2回宣言すること、定義されていない演算子に宣言することは、エラーとする (それぞれ E1021、E1022)
- CST では演算子の列を平たいまま持ち、HIR で解決した先の定義の fixity を引いて木に組み直す ([式](expressions.md) の「演算子の列と単項マイナス」)

標準の演算子の fixity は、Prelude が宣言する。優先順位と結合は次の表のとおり。

| 優先順位 | 演算子 | 結合 |
|---|---|---|
| 0 | `<\|` | 右 |
| 1 | `\|>` | 左 |
| 2 | `\|\|` | 右 |
| 3 | `&&` | 右 |
| 4 | `==` `!=` `<` `<=` `>` `>=` | 結合しない |
| 5 | `++` `::` | 右 |
| 6 | `+` `-` | 左 |
| 7 | `*` `/` `%` | 左 |
| 9 | `>>` `<<` (関数合成) | 右 |
| (10) | 関数適用、射影 | 左 |

- `::` の fixity (`infixr 5`) は、Prelude が `List` と一緒に宣言する
- 合成演算子 `.` は採用しない (`.` は射影とモジュール修飾に使うため)
- 単項の `!` はない。否定は関数 `not` で書く

標準の演算子の型と意味は次のとおり。`==`、`!=`、`<`、`<=`、`>`、`>=` は Prelude のクラス `Eq` と `Ord` のメソッドで、型ごとの instance が比べ方を決める (下の「Prelude のクラス」)。算術の演算子と `++` は、`Prelude` の `extern` の関数で、型を1つに固定する。`Num` のクラスは `Float`、`Char`、`Num` の段で入れる ([ロードマップ](../future/roadmap.md) の「段の列」)。

| 演算子 | 型と意味 |
|---|---|
| `+` `-` `*` `/` `%` | `Int -> Int -> Int`。`Int` は 64 ビットの符号付き整数で、オーバーフローとゼロ除算は実行時エラーにする。`/` と `%` は Rust と同じく、商を 0 の方向に切り捨てる (`%` の結果は被除数と同じ符号になる) |
| 単項の `-` (`negate`) | `Int -> Int`。オーバーフローは実行時エラー |
| `==` `!=` | `Eq a => a -> a -> Bool`。クラス `Eq` のメソッドである。`Eq` の instance のない型 (関数型、instance のない `data` の型、制約のないシグネチャの型変数) の値を比べると E2006 にする |
| `<` `<=` `>` `>=` | `Ord a => a -> a -> Bool`。クラス `Ord` のメソッドで、`compare` からの既定を持つ |
| `++` | `String -> String -> String` |
| `&&` `\|\|` | `Bool -> Bool -> Bool`。短絡評価する。HIR で `a && b` を `if a then b else False` に、`a \|\| b` を `if a then True else b` に脱糖する |
| `\|>` `<\|` | `x \|> f` は Prelude の関数 `x \|> f = f x` の呼び出しである。引数を左から評価するので、`x` を先に評価する。評価の順は [式](expressions.md) の「関数適用」に従う。`f <\| x` は Prelude の関数 `f <\| x = f x` の呼び出しである |
| `>>` `<<` | 関数合成 |
| `::` | `a -> List a -> List a`。Prelude の `List` のコンストラクタ |

`&&`、`||`、`|>`、`<|`、`>>`、`<<` と関数 `not` は、Prelude に eml で本体を書いた関数である。ただし `&&` と `||` は、上の表のとおり HIR が短絡評価の `if` に脱糖する。演算子の参照もラムダにしたうえで同じく脱糖するので、この2つの本体は呼ばれない。`::` は Prelude の `List` のコンストラクタである。比較の演算子は、クラスのメソッドとして instance の定義を呼ぶ。`Int`、`String`、`Bool` の instance は、メソッドを instance の中の `extern` で表の行に結ぶ (上の「`extern`」)。残りの演算子は、Prelude の `extern` の関数で、処理系が実装を持つ。

## クラスと instance

```haskell
pub class Describe a where
  describe : a -> String
  loud : a -> String
  loud x = describe x ++ "!"

data Box a = | Box a

instance Describe a => Describe (Box a) where
  describe (Box x) = "box of " ++ describe x

data Color =
  | Red
  | Green
  deriving (Eq, Ord, Show)
```

型クラスは、Haskell 98 の形の単一引数のクラスである。等価、比較、表示は、Prelude のクラス `Eq`、`Ord`、`Show` で作る (下の「Prelude のクラス」)。高カインドのクラス、多引数のクラス、関連型、`Add<Rhs, Output>` 形の演算子のトレイトはない。制約の意味、解き方、Kind の規則は [型と Kind](types.md) の「制約」に、名前空間、import、instance の見え方は [モジュールと名前解決](modules.md) にある。証拠 (どの instance を使うか) は Core IR への変換の単相化で決め、実行時の辞書は持たない ([Core IR とインタプリタ](core-ir.md) の「メソッドの解決」)。

### `class`

- `class C a` は、型変数を1つ持つクラスを宣言する。`where` のブロックに、メソッドのシグネチャと既定のメソッドの等式を並べる。メソッドのないクラスは `where` を省ける
- `class Eq a => Ord a` の文脈は上位クラスである。上位クラスの文脈には、クラスの型変数への制約だけを書ける。上位クラスの関係は循環してはならない。`Ord T` の instance には、同じ型の `Eq T` の instance が要る ([型と Kind](types.md) の「instance と既定のメソッドの検査」)。制約 `Ord a` を与えられた本体は、上位クラスの `Eq a` も使える
- メソッドのシグネチャは、クラスの型変数を含まなければならない。メソッドは、クラスの型変数のほかに自分の型変数を持てる (`tagged : Describe b => f -> b -> String`)。メソッドのシグネチャの文脈には、メソッド自身の型変数への制約だけを書ける。クラスの型変数への制約は、クラスがすでに求めているので書けない
- メソッドの型は、クラスの型変数を先頭に、メソッド自身の型変数を後ろに並べた型で、制約の先頭にクラスの制約 `C a` を持つ (`(==) : Eq a => a -> a -> Bool`)
- 既定のメソッドの等式は、そのメソッドのシグネチャの直後に置く。等式の規則と診断は、トップレベルの関数のシグネチャと等式と同じである (E1004、E1018、E1019、E1020)。ただし、等式のないメソッドのシグネチャは E1005 にしない。既定のないメソッドである。同じメソッドのシグネチャが2つあれば E1003 にする
- 既定のメソッドの本体は、クラスの制約 `C a` とメソッド自身の制約を、与えられた制約として持つ。本体の型の明示に書ける型変数は、クラスの型変数とそのメソッドのシグネチャの型変数である。既定のメソッドはクラスの中で1回だけ検査する

### `instance`

- `instance C T where …` は、クラス C の、型 T の instance を宣言する。instance は名前を持たない。`pub instance` は書けない ([文法](grammar.md) の「文法上の補足」)
- instance の頭 T は、`data` の型か extern の型のコンストラクタに、互いに異なる型変数を宣言の数だけ適用した形でなければならない (E1039)。タプル、`Unit`、関数型、型変数、型の別名は頭にできない。タプルと `Unit` は型の表で `data` でなくタプルなので、処理系の構造的な instance (`Eq`、`Ord`、`Show`) だけを持ち、ユーザーのクラスの instance は持てない。型引数の数の誤りは E1015 にする
- `instance Describe a => Describe (Box a)` の文脈には、頭の型変数への制約だけを書ける。instance のメソッドの本体は、この文脈とメソッド自身の制約を、与えられた制約として持つ
- `where` のブロックには、メソッドの等式と `extern` の行 (上の「`extern`」) を書く。等式には、E1018 と E1020 をメソッドごとに当てはめる。同じメソッドを `extern` の行と等式の両方で、または `extern` の行2つで定義したら、2つ目を E1003 にする。instance が定義しないメソッドは、クラスの既定のメソッドを使う
- instance のメソッドの本体は、クラスのメソッドのシグネチャのクラスの型変数を、頭の型に置き換えた型で検査する。メソッド自身の型変数の名前が頭の型変数の名前と重なるときは、メソッド自身の型変数の名前の後に番号を付けて区別する。型の表と単相化の代入が、型変数を名前で引くためである
- instance のメソッドの本体の型の明示に書ける型変数は、頭の型変数だけである。メソッド自身の型変数の名前は、別のモジュールにあるかもしれないクラスのシグネチャが決めるので、名前で書けない
- 等式の引数は、メソッドのシグネチャの矢印より少なくてもよい (`same = same_box`)。トップレベルの関数と同じく、本体は残りの型に対して検査する。メソッドの呼び出しの評価の順は、どの instance を選んでも同じになるよう、メソッドのシグネチャの矢印の数で決める ([式](expressions.md) の「関数適用」)

### `deriving`

- `data` の宣言に `deriving` を付けると、書いたクラスの instance を処理系が作る。書けるのは Prelude の `Eq`、`Ord`、`Show` だけである (E1038)。名前でなく解決したクラスで判定するので、ユーザーが `Eq` という名前のクラスを定義しても導出できない
- 導出した instance の文脈は、フィールドの型に現れる `data` の型引数のそれぞれに、そのクラスを付けたものである。Haskell のような文脈の推論 (フィールドの制約を簡約して最小の文脈を求めること) はしない。各フィールドの型は、この文脈のもとで同じクラスの instance を持たなければならない ([型と Kind](types.md) の「導出した instance の検査」)
- `Ord` を導出するには、上位クラスの規則で `Eq` の instance が要る。手で書いたものでも、導出したものでもよい
- 導出したメソッドの意味は次のとおりである。`!=`、`<`、`<=`、`>`、`>=` は、クラスの既定のメソッドを通る
  - `==`: 両辺が同じコンストラクタで、フィールドを左から `==` で比べてすべて等しいときに `True` である。最初に等しくないフィールドで止める
  - `compare`: 違うコンストラクタなら、宣言の順で前のものが小さい。同じコンストラクタなら、フィールドを左から `compare` し、最初の `EQ` でない結果を返す。すべて `EQ` なら `EQ` である
  - 名前付きのフィールドのコンストラクタも、`==` と `compare` はフィールドを宣言の順に比べる (Haskell と同じ)。作る式やパターンに書いた順にはよらない
  - `show_prec d x`: フィールドのないコンストラクタは、その名前である。フィールドのあるコンストラクタは、名前の後に、各フィールドを `show_prec 11` で表示して空白で区切って並べ、`d > 10` なら括弧で囲む (`Some (Box 1)`)。中置のコンストラクタは、fixity の優先度 p (宣言がなければ 9) について、両辺を `show_prec (p + 1)` で表示して演算子の前後に空白を置き、`d > p` なら括弧で囲む (Haskell 98 の導出と同じ)。名前付きのフィールドのコンストラクタは、`Person { name = "a", age = 3 }` の形で、フィールドを宣言の順に `名前 = 値` と書いて `, ` で区切る。値は中括弧の中なので `show_prec 0` で表示する。`Con { … }` は atom なので、`d` によらず括弧で囲まない (`Some Person { name = "a", age = 3 }`)。フィールドが0個なら `A {}` と書く。どれも、そのまま読み戻せる形である。コンストラクタの名前は修飾しない。`show x` は `show_prec 0 x` である
- タプルと `Unit` は、`Eq`、`Ord`、`Show` の構造的な instance を処理系から得る。タプルは、コンストラクタが1つの型として上の規則に従い、要素ごとに同じクラスの instance を求める。タプルの `show` は `(1, "a")` の形で、要素を `show_prec 0` で表示して `, ` で区切る。`Unit` の `==` は `True`、`compare` は `EQ`、`show` は `"()"` である

### 宣言の検査

HIR への変換で、クラスと instance の宣言を次のように検査する。名前の引き方の誤り (E1041、E1043) は [モジュールと名前解決](modules.md) の「名前空間」にある。

- 上位クラスの文脈の型変数が、クラスの型変数でない (E1040)。上位クラスの関係が循環した (E1042)。循環を閉じる上位クラスの辺を持つクラスで報告し、そのクラスの上位クラスを空にして検査を続ける
- メソッドのシグネチャが、クラスの型変数を含まない (E1040)
- シグネチャの制約の型変数が、そのシグネチャの型に現れない (E1040)。現れない型変数への制約は、どの参照でも型が決まらないためである。メソッドのシグネチャの制約がクラスの型変数を指す場合も E1040 にする
- instance の文脈の型変数が、頭の型変数でない (E1040)
- 制約の形が、クラスの名前と1つの型変数でない (E1040)
- extern のシグネチャと操作のシグネチャに文脈を書いた (E1040)。操作に制約を書けると、handler の節が perform の位置で選んだ証拠を実行時に受け取る必要が生じ、実行時の辞書が要るためである。`data` のフィールドの型には文脈の構文がない
- instance の頭の形 (上の「`instance`」) の誤り (E1039)
- orphan 規則: instance は、クラスか頭の型を定義したモジュールにだけ書ける (E1034)。`deriving` は型を定義したモジュールにあるので、いつも満たす ([モジュールと名前解決](modules.md) の「instance の一貫性」)
- 同じ (クラス, 型) の2つ目の instance (E1035)。プログラムのモジュールの順 (Prelude、入口、標準ライブラリ、import したモジュール) とモジュールの中の位置で、後にあるものを報告する。1つのモジュールの中では、手で書いた instance をすべて置いてから `deriving` の instance を置くので、手で書いた instance と `deriving` が重なると、`deriving` の側を報告する。同じ `deriving` にクラスを2回書いた場合も含む
- instance の等式の名前が、クラスのメソッドでない (E1037)
- 既定のないメソッドを、instance が定義していない (E1036)。`extern` で結んだメソッドは、E1033 にしたものも含めて、定義したものに数える
- `deriving` に、Prelude の `Eq`、`Ord`、`Show` 以外のクラスを書いた (E1038)

### Prelude のクラス

```haskell
pub data Ordering =
  | LT
  | EQ
  | GT
  deriving (Eq, Ord, Show)

pub class Eq a where
  (==) : a -> a -> Bool
  (!=) : a -> a -> Bool
  x != y = not (x == y)

pub class Eq a => Ord a where
  compare : a -> a -> Ordering
  (<) : a -> a -> Bool
  x < y = match compare x y with
    | LT -> True
    | _ -> False
  -- (<=)、(>)、(>=) も compare からの既定を持つ

pub class Show a where
  show : a -> String
  show_prec : Int -> a -> String
  show_prec _ x = show x
  display : a -> String
  display x = show x
```

- `Show` の `show` は既定を持たない。`show` と `show_prec` を互いの既定にすると、どちらも書かない instance が止まらなくなるためである
- `show_prec d x` の `d` は、`x` を置く位置の優先度である。関数適用の引数の位置は 11 である。導出した `Show` は、これで入れ子の値と中置のコンストラクタに括弧を付ける (上の「`deriving`」)
- `show` は読み戻せる形、`display` は人が読む形を返す。補間の穴は `display` を呼ぶ ([式](expressions.md) の「補間」)。`display` の既定は `show` である。Prelude の instance では `String` だけが上書きし、文字列をそのまま返す。Haskell の `Show` が `String` の表示のために `showList` を持つのと同じく、クラスのメソッドで `String` だけを特別に扱う
- `display` はクラスの普通のメソッドなので、ユーザーが呼ぶことも、instance で上書きすることもできる。導出した instance、タプルと `Unit` の instance、`List` の手書きの instance は既定の `display` を使う。そのため `display (Some "x")` は `Some "x"` で、引用符が付かないのは値そのものが `String` のときだけである

Prelude は、標準のデータ型 `List`、`Option`、`Result` も宣言する。

```haskell
pub infixr 5 ::

pub data List a =
  | Nil
  | a :: List a
  deriving (Eq, Ord)

pub data Option a =
  | None
  | Some a
  deriving (Eq, Ord, Show)

pub data Result e a =
  | Err e
  | Ok a
  deriving (Eq, Ord, Show)
```

- `::` の fixity は、`++` と同じく `infixr 5` で、Haskell の `:` と同じである
- `Result` の型引数は `Result e a` の順で、Haskell の `Either e a` と同じである。`Err`、`Ok` の順に宣言するので、導出した `Ord` では `Err _ < Ok _` になる
- `List` の導出した `Ord` は `Nil < _ :: _` と要素ごとの辞書順で、Haskell のリストの順と同じである
- `List` の `Show` は手で書いた instance で、`[1, 2]` の形で表示する。空のリストは `[]` である。要素は `show` で表示し、`, ` で区切る。`show_prec` は既定のままにする。角括弧で閉じているので、引数の位置でも括弧が要らないためである。表示は左辺の文字列を一意なまま伸ばして作るので、リストの長さに比例する時間で済む ([ランタイム](runtime.md) の「文字列の連結」)。`Option` と `Result` の導出した `Show` は、`Some [1]`、`Some (-1)`、`Ok "a"` のように表示する
- リストを扱う関数 (`map`、`length` など) は、まだ Prelude にない

Prelude の instance は次のとおりである。

| instance | 定義 |
|---|---|
| `Eq Int` | `extern (==)`、`extern (!=)` |
| `Ord Int` | `extern compare`、`extern (<)`、`extern (<=)`、`extern (>)`、`extern (>=)` |
| `Show Int` | `extern show`。`show_prec` は Prelude に書き、`d > 6` で負の数なら括弧で囲む (`Some (-1)`) |
| `Eq String` | `extern (==)`、`extern (!=)` |
| `Ord String` | `extern compare`。順はバイト順で、妥当な UTF-8 ではコードポイントの順と一致する。`<` などは既定のメソッドを通る |
| `Show String` | `extern show`。下のエスケープで表示する。`display s = s` で、文字列をそのまま返す。恒等関数で足りるので、extern にしない |
| `Eq Bool` | `extern (==)`、`extern (!=)` |
| `Ord Bool`、`Show Bool` | `data Bool = \| False \| True deriving (Ord, Show)` |
| `Eq Ordering`、`Ord Ordering`、`Show Ordering` | `deriving (Eq, Ord, Show)` |
| `Eq (List a)`、`Ord (List a)` | `deriving (Eq, Ord)` |
| `Show (List a)` | Prelude に eml で書いた instance (上の `List` の `Show`) |
| `Eq (Option a)`、`Ord (Option a)`、`Show (Option a)` | `deriving (Eq, Ord, Show)` |
| `Eq (Result e a)`、`Ord (Result e a)`、`Show (Result e a)` | `deriving (Eq, Ord, Show)` |
| タプルと `Unit` の `Eq`、`Ord`、`Show` | 処理系の構造的な instance (上の「`deriving`」) |

- `compare` の extern の行は、`Ordering` の宣言の順のタグ (`LT` が 0) を返す
- `String` の `show` は、文字列を `"` で囲み、`"` を `\"`、`\` を `\\`、改行を `\n`、タブを `\t`、復帰を `\r`、NUL を `\0` と書く。ほかの U+0001〜U+001F と U+007F は `\u{…}` (16進の小文字で、先頭の 0 を省く) と書く。それ以外の文字はそのまま書く。どれも [字句](lexical.md) の「文字列」のエスケープとして読み戻せる。`{` はそのまま書く。`\` は `\\` と書くので、`\` の後に `{` が来ても補間の開きにならず、読み戻せる。`{` を `\{` と書くと補間の開きになり、読み戻せない
- `max` と `min` はまだない

## `pub`

- シグネチャ、`data`、`type`、`effect`、fixity、`class` に `pub` を付けると公開される。付けないものはモジュールの中だけで見える。`pub class` は、クラスとそのメソッドをまとめて公開する。instance は名前を持たず、いつもプログラム全体で見えるので、`pub` を付けられない
- 等式と import には `pub` を付けられず、付けると構文エラー (E0011) になる。等式で定義する関数は、シグネチャに `pub` を付けて公開する
- `pub data` は、型とコンストラクタを公開する。コンストラクタを隠した抽象型は、将来の課題とする ([ロードマップ](../future/roadmap.md))
- `pub` を付けた item の型に、同じモジュールの `pub` でない型かエフェクトが現れたら E1032 にする。制約に書いた `pub` でないクラスも同じである ([モジュールと名前解決](modules.md) の「公開の範囲」)

標準ライブラリのモジュールは、ユーザーに見せる名前を `pub` で選ぶ。`pub` でない item (`Prelude` の `negate` など) はユーザーには見えず、処理系だけが引く。モジュールの規則は [モジュールと名前解決](modules.md) にある。
