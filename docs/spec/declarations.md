# 宣言

位置づけ: 規範。

トップレベルに書く宣言 (シグネチャと等式、`data` と `type`、`effect`、`extern`、fixity、`pub`) の構文と、HIR で行う検査と脱糖を定める。文法は [文法](grammar.md) にある。

## シグネチャと等式

```haskell
len : List a -> Int
len Nil = 0
len (Cons _ rest) = 1 + len rest
```

シグネチャは Haskell / Idris と同じく、等式とは別の行に書く。1つの関数を複数の等式で定義できる。

- トップレベルの関数と値は、シグネチャが必須である ([型と Kind](types.md) の「推論」)。構文上はシグネチャと等式が別の item なので、HIR で次を検査する
  - シグネチャのない等式 (E1004)
  - 等式のないシグネチャ (E1005)。`extern` のシグネチャは除く
  - 同じ名前の等式が連続していない (間に別の item がある) (E1018)。`extern` のシグネチャの等式は除く
  - シグネチャと等式が隣り合っていない (E1019)。`extern` のシグネチャの等式は除く
  - 等式ごとに引数の個数が違う (E1020)
- 診断には、シグネチャの追加を提案する help を付ける
- 複数の等式は、HIR で「引数のタプルに対する `match`」1つに脱糖する。網羅性と線形性の検査は、その `match` に対して行う
- ローカルの `let` は、注釈なしで推論する
- 引数のない値 (`pi : Int`、`pi = 3`) も書ける。「引数のない関数は `()` を取る」という規約は、エフェクトを持つ計算に使う

シグネチャを複数の行に分けるときは、`->` を行の先頭に置く。

```haskell
fold_lines : String
  -> (a -> String -> a)
  -> a
  -> <IO> a
```

`->` は [レイアウト規則](layout.md) のブロックの開始トークンなので、`->` で行を終えて次の行を同じ列に揃えると、字下げしたブロックが必要というエラー (E0009) になる。行末の `->` の E0009 には、次の行をより深く字下げするか、型なら `->` を次の行の先頭に置くよう促す help を付ける (行末の `->` はラムダや `match` の枝にもあるので、どちらにも当てはまる言い方にする)。揃えた行がさらに `->` で終わっても、E0009 は最初の1件だけ出す ([コンパイラの構成](../implementation/architecture.md) の「構文解析の回復」)。

## `data` と `type`

```haskell
data Option a =
  | None
  | Some a

data Color = | Red | Green | Blue

data List a =
  | Nil
  | a :: List a

type Person = { name : String, age : Int }
type Unit = {}
```

- `data` は名前的な直和型である。各選択肢は `|` で始める。選択肢は字下げしたブロックにも、同じ行にも並べられる
- 中置のコンストラクタは、`:` で始まる演算子で宣言できる。両側には型の適用を書ける (`| List a :: L a`)
- 型とコンストラクタは別の名前空間にあるので、同じ名前を付けられる ([モジュールと名前解決](modules.md))
- `type` は型の別名で、構造的なレコードに名前を付けるのに使う。別名は展開して扱う
- 直積型は `data` では宣言しない。直積型は構造的なレコードに統一している ([直積型とレコード](records.md))
- `extern` でない `data` に `=` がないものは、値を作れない型になるので E1025 とする。どのモジュールでも同じである
- `Int`、`String`、`Unit` は `Prelude` の、`File` は標準ライブラリのモジュール `Fs` の `extern data` で、`Bool` は `Prelude` の `data Bool = | False | True` である (下の「`extern`」)

`type` と名前付きのレコードは S4 で実装する。

## `effect`

```haskell
effect State s where
  get : Unit -> s
  put : s -> Unit

effect Log where
  log : Level -> String -> Unit

effect Fail where
  never fail : String -> a
```

- 多重度は `never` / `once` / `multi` を操作の前に付ける。省略したら `once` とする。多重度の意味は [エフェクトと handler](effects.md) で定める
- エフェクトは型引数を持てる (`effect State s`)。型引数は型だけで、row を引数に取るエフェクトはまだ書けない。型引数の名前が重複したら E1003 にする
- 操作のシグネチャで、エフェクトの型引数と同じ名前の型変数はその型引数を指す。ほかの型変数は、操作ごとに暗黙に量化する
- row の中のエフェクトには、宣言と同じ個数の型引数を付ける (`<State Int>`)。個数が違えば E1015 にする
- **操作のカリー化を許す。** 操作の引数の個数は、シグネチャの一番外側の `->` の数とする
- 操作のシグネチャの一番外側の `->` には row を書けない (書いたらエラー)。カリー化した操作では、この規則を外側のすべての `->` に適用する
- `never` の操作の結果の型は、宣言で自由な型変数として書く (`never fail : String -> a`)。結果の型は操作自身の型変数で、引数に現れてはならない。エフェクトの型引数は、呼び出した側が自由に選べないので、結果の型に使えない (E1008)
- エフェクトの操作は、値の名前空間に置くトップレベルの値である。名前の重複の扱いは [モジュールと名前解決](modules.md) の「名前空間」にある

## `extern`

```haskell
pub extern data Int
pub extern effect IO
pub extern println : String -> <IO> Unit
```

`extern` は、処理系が実装を持つ組み込みを宣言する修飾子である。`pub` の後に書き、宣言は次の3つの形だけである。

- 等式のないシグネチャ (`pub extern println : String -> <IO> Unit`)。実装は処理系が持ち、eml のコードで本体は書かない
- `=` のない型引数なしの `data` (`pub extern data Int`)。値の表し方と Kind は処理系が決める
- `where` のない型引数なしの `effect` (`pub extern effect IO`)。操作を持たない、ラベルだけのエフェクトである ([エフェクトと handler](effects.md) の「組み込みの `IO`」)

extern の型とエフェクトに型引数を持たせないのは、row の中で重なったラベルを1つにまとめる規則が、型引数のないエフェクトでだけ正しいためである。これ以外の位置の `extern` は構文エラー (E0011) になる ([文法](grammar.md))。型引数を書いた extern の型も E0011 にするが、書いた型引数は型引数として数える。使う位置の型引数の数の誤り (E1015) を重ねないためである。

- `extern` は標準ライブラリ ([モジュールと名前解決](modules.md) の「標準ライブラリ」) のモジュールにだけ書ける。ユーザーのモジュールに書くと、宣言ごとに E1033 にする。help で `extern` を外すよう示すが、外すと E1005 や E1025 になるので自動の修正にはしない。宣言は extern として読み、E1005、E1025、`where` がないことの誤りは重ねて出さない。extern のシグネチャに続く等式は、離れていても読み捨て、E1018 と E1019 も出さない。E1033 は宣言ごとに1つで、その宣言を使った位置には重ねない。handler の節の先頭にユーザーの extern の関数を書いても、E1009 を重ねずに節を捨てる
- extern の宣言は、処理系が持つ表の行を、モジュールの正式な名前で修飾した名前 (`Prelude.println`、`Std.Fs.open`) で指す。表にない名前や、表の行と食い違う宣言は処理系の誤りで、診断ではなくテストで防ぐ
- extern でない宣言の規則は変わらない。等式のないシグネチャは E1005、`=` のない `data` は E1025 で、`Prelude` を含むすべてのモジュールで同じである。extern でない `effect` には、今までどおり `where` と操作が要る
- extern の関数の型は、ほかの関数と同じくシグネチャから決まる。引数のそろった呼び出しは、eml のコードを呼び返さずにその場で実行される

## fixity

```haskell
pub infixr 5 </>
pub (</>) : Path -> String -> Path
dir </> name = join_path dir name
```

- トップレベルに `infixl` / `infixr` / `infix` + 優先順位 (0〜9) + 演算子 (カンマ区切りで複数) を書く
- fixity は、演算子の名前が解決した先の定義 (関数、コンストラクタ、操作) に付く。Prelude の演算子は Prelude の宣言を使い、ユーザーが定義した演算子 (関数と中置のコンストラクタ) はユーザーの宣言を使う
- 別のモジュールの定義に解決した演算子では、その fixity の宣言が `pub` のときだけ宣言が効く。`pub` でなければ `infixl 9` である
- fixity の宣言がない演算子は `infixl 9` とする (Haskell と同じ)。ユーザーが `+` を定義して Prelude の `+` を隠したときも、宣言がなければ `infixl 9` である
- 宣言の位置は問わない。後ろに書いた宣言も、モジュール全体の演算子の列の組み直しに効く
- 標準ライブラリの演算子の fixity は変えられない。このモジュールで定義していない演算子への宣言は E1022 になる
- `&&` と `||` も、ユーザーの定義が Prelude のものを隠せる。その場合は短絡しない普通の関数になり、`if` への脱糖は行わない。`|>` と `<|` は脱糖しない普通の関数なので、ほかの演算子と同じように隠せる
- `pub` を付けた fixity は、演算子と一緒に公開される。fixity は演算子の定義に付属し、import した先でも同じ fixity を使う
- 同じ演算子に2回宣言すること、定義されていない演算子に宣言することは、エラーとする (それぞれ E1021、E1022)
- CST では演算子の列を平たいまま持ち、HIR で解決した先の定義の fixity を引いて木に組み直す ([式](expressions.md) の「演算子の列と単項マイナス」)

標準の演算子の fixity は、Prelude が宣言する。優先順位と結合は次の表のとおり。

| 優先順位 | 演算子 | 結合 |
|---|---|---|
| 0 | `<\|` | 右 |
| 1 | `\|>` | 左 |
| 2 | `\|\|` | 右 |
| 3 | `&&` | 右 |
| 4 | `==` `!=` `<` `<=` `>` `>=` | 結合しない |
| 5 | `++` | 右 |
| 6 | `+` `-` | 左 |
| 7 | `*` `/` `%` | 左 |
| 9 | `>>` `<<` (関数合成) | 右 |
| (10) | 関数適用、フィールドアクセス | 左 |

- `::` の fixity (`infixr 5`) は、S4 で `List` のコンストラクタと一緒に Prelude に宣言する。fixity は定義に付くので、定義のない今の `::` (E0004) には fixity の宣言がない
- 合成演算子 `.` は採用しない (`.` はフィールドアクセスとモジュール修飾に使うため)
- 単項の `!` はない。否定は関数 `not` で書く

標準の演算子の型と意味は次のとおり。`&&`、`||`、`|>`、`<|`、`>>`、`<<`、`::` を除く表の演算子は、`Prelude` の `extern` の関数である。アドホック多相がないので、今は `==` と `!=` を除いて型を1つに固定する。

| 演算子 | 型と意味 |
|---|---|
| `+` `-` `*` `/` `%` | `Int -> Int -> Int`。`Int` は 64 ビットの符号付き整数で、オーバーフローとゼロ除算は実行時エラーにする。`/` と `%` は Rust と同じく、商を 0 の方向に切り捨てる (`%` の結果は被除数と同じ符号になる) |
| 単項の `-` (`negate`) | `Int -> Int`。オーバーフローは実行時エラー |
| `==` `!=` | `a -> a -> Bool`。`a` は `Int`、`String`、`Bool` のどれかでなければならない。型検査が引数の型から比べ方を決め、それ以外の型 (`data` の型、タプル、関数、シグネチャの型変数) は E2006 にする。S5 の型クラス `Eq` の `Int`、`String`、`Bool` のインスタンスにあたる ([ロードマップ](../future/roadmap.md) の「S5 型クラス」) |
| `<` `<=` `>` `>=` | `Int -> Int -> Bool` |
| `++` | `String -> String -> String` |
| `&&` `\|\|` | `Bool -> Bool -> Bool`。短絡評価する。HIR で `a && b` を `if a then b else False` に、`a \|\| b` を `if a then True else b` に脱糖する |
| `\|>` `<\|` | `x \|> f` は Prelude の関数 `x \|> f = f x` の呼び出しである。引数を左から評価するので、`x` を先に評価する。評価の順は [式](expressions.md) の「関数適用」に従う。`f <\| x` は Prelude の関数 `f <\| x = f x` の呼び出しである |
| `>>` `<<` | 関数合成 |
| `::` | リストのコンストラクタ (S4 で `Prelude` に入る) |

`&&`、`||`、`|>`、`<|`、`>>`、`<<` と関数 `not` は、Prelude に eml で本体を書いた関数である。ただし `&&` と `||` は、上の表のとおり HIR が短絡評価の `if` に脱糖する。演算子の参照もラムダにしたうえで同じく脱糖するので、この2つの本体は呼ばれない。`::` はリストのコンストラクタで、S4 で Prelude に入る。残りの演算子は、Prelude の `extern` の関数で、処理系が実装を持つ。`==` と `!=` は、型検査が決めた比べ方に応じて、Prelude に `pub` なしで宣言した `int_eq`、`string_ne`、`bool_eq` などの extern に置き換わる。

## `pub`

- シグネチャ、`data`、`type`、`effect`、fixity に `pub` を付けると公開される。付けないものはモジュールの中だけで見える
- 等式と import には `pub` を付けられず、付けると構文エラー (E0011) になる。等式で定義する関数は、シグネチャに `pub` を付けて公開する
- `pub data` は、型とコンストラクタを公開する。コンストラクタを隠した抽象型は、将来の課題とする ([ロードマップ](../future/roadmap.md))
- `pub` を付けた item の型に、同じモジュールの `pub` でない型かエフェクトが現れたら E1032 にする ([モジュールと名前解決](modules.md) の「公開の範囲」)

標準ライブラリのモジュールは、ユーザーに見せる名前を `pub` で選ぶ。`pub` でない item (`Prelude` の `negate` など) はユーザーには見えず、処理系だけが引く。モジュールの規則は [モジュールと名前解決](modules.md) にある。
