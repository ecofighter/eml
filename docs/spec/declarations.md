# 宣言

位置づけ: 規範。

トップレベルに書く宣言 (シグネチャと等式、`data` と `type`、`effect`、fixity、`pub`) の構文と、HIR で行う検査と脱糖を定める。文法は [文法](grammar.md) にある。

## シグネチャと等式

```haskell
len : List a -> Int
len Nil = 0
len (Cons _ rest) = 1 + len rest
```

シグネチャは Haskell / Idris と同じく、等式とは別の行に書く。1つの関数を複数の等式で定義できる。

- トップレベルの関数と値は、シグネチャが必須である ([型と Kind](types.md) の「推論」)。構文上はシグネチャと等式が別の item なので、HIR で次を検査する (E1xxx)
  - シグネチャのない等式
  - 等式のないシグネチャ
  - 同じ名前の等式が連続していない (間に別の item がある)
  - シグネチャと等式が隣り合っていない
  - 等式ごとに引数の個数が違う
- 診断には、シグネチャの追加を提案する help を付ける
- 複数の等式は、HIR で「引数のタプルに対する `match`」1つに脱糖する。網羅性と線形性の検査は、その `match` に対して行う
- ローカルの `let` は、注釈なしで推論する
- 引数のない値 (`pi : Int`、`pi = 3`) も書ける。「引数のない関数は `()` を取る」という規約は、エフェクトを持つ計算に使う

シグネチャを複数の行に分けるときは、`->` を行の先頭に置く。

```haskell
fold_lines : String
  -> (a -> String -> a)
  -> a
  -> <IO> a
```

`->` は [レイアウト規則](layout.md) のブロックの開始トークンなので、`->` で行を終えて次の行を同じ列に揃えると、字下げしたブロックが必要というエラー (E0009) になる。行末の `->` の E0009 には、次の行をより深く字下げするか、型なら `->` を次の行の先頭に置くよう促す help を付ける (行末の `->` はラムダや `match` の枝にもあるので、どちらにも当てはまる言い方にする)。揃えた行がさらに `->` で終わっても、E0009 は最初の1件だけ出す ([レイアウト規則](layout.md) の「エラー回復」)。

## `data` と `type`

```haskell
data Option a =
  | None
  | Some a

data Color = | Red | Green | Blue

data List a =
  | Nil
  | a :: List a

type Person = { name : String, age : Int }
type Unit = {}
```

- `data` は名前的な直和型である。各選択肢は `|` で始める。選択肢は字下げしたブロックにも、同じ行にも並べられる
- 中置のコンストラクタは、`:` で始まる演算子で宣言できる。両側には型の適用を書ける (`| List a :: L a`)
- 型とコンストラクタは別の名前空間にあるので、同じ名前を付けられる ([モジュールと名前解決](modules.md))
- `type` は型の別名で、構造的なレコードに名前を付けるのに使う。別名は展開して扱う
- 直積型は `data` では宣言しない。直積型は構造的なレコードに統一している ([直積型とレコード](records.md))
- `Bool` は組み込みの `data Bool = | False | True` である

`type` と名前付きのレコードは S2 で実装する。

## `effect`

```haskell
effect State s where
  get : Unit -> s
  put : s -> Unit

effect Log where
  log : Level -> String -> Unit

effect Fail where
  never fail : String -> a
```

- 多重度は `never` / `once` / `multi` を操作の前に付ける。省略したら `once` とする。多重度の意味は [エフェクトと handler](effects.md) で定める
- **操作のカリー化を許す。** 操作の引数の個数は、シグネチャの一番外側の `->` の数とする
- 操作のシグネチャの一番外側の `->` には row を書けない (書いたらエラー)。カリー化した操作では、この規則を外側のすべての `->` に適用する
- `never` の操作の結果の型は、宣言で自由な型変数として書く (`never fail : String -> a`)
- エフェクトの操作は、値の名前空間に置くトップレベルの値である。名前の重複の扱いは [モジュールと名前解決](modules.md) の「名前空間」にある

## fixity

```haskell
pub infixr 5 </>
pub (</>) : Path -> String -> Path
dir </> name = join_path dir name
```

- トップレベルに `infixl` / `infixr` / `infix` + 優先順位 (0〜9) + 演算子 (カンマ区切りで複数) を書く
- fixity の宣言がない演算子は `infixl 9` とする (Haskell と同じ)
- `pub` を付けた fixity は、演算子と一緒に公開される。fixity は演算子の名前に付属し、import した先でも同じ fixity を使う
- 同じ演算子に2回宣言すること、定義されていない演算子に宣言することは、エラーとする (E1xxx)
- CST では演算子の列を平たいまま持ち、HIR で fixity の表を引いて木に組み直す ([式](expressions.md) の「演算子の列と単項マイナス」)

標準の演算子は Prelude で宣言する。優先順位と結合は次の表のとおり。

| 優先順位 | 演算子 | 結合 |
|---|---|---|
| 0 | `<\|` | 右 |
| 1 | `\|>` | 左 |
| 2 | `\|\|` | 右 |
| 3 | `&&` | 右 |
| 4 | `==` `!=` `<` `<=` `>` `>=` | 結合しない |
| 5 | `++` `::` | 右 |
| 6 | `+` `-` | 左 |
| 7 | `*` `/` `%` | 左 |
| 9 | `>>` `<<` (関数合成) | 右 |
| (10) | 関数適用、フィールドアクセス | 左 |

- 合成演算子 `.` は採用しない (`.` はフィールドアクセスとモジュール修飾に使うため)
- 単項の `!` はない。否定は関数 `not` で書く

標準の演算子の型と意味は次のとおり。アドホック多相がないので、マイルストーン1 では型を1つに固定する。

| 演算子 | 型と意味 |
|---|---|
| `+` `-` `*` `/` `%` | `Int -> Int -> Int`。`Int` は 64 ビットの符号付き整数で、オーバーフローとゼロ除算は実行時エラーにする。`/` と `%` は Rust と同じく、商を 0 の方向に切り捨てる (`%` の結果は被除数と同じ符号になる) |
| 単項の `-` (`negate`) | `Int -> Int`。オーバーフローは実行時エラー |
| `==` `!=` `<` `<=` `>` `>=` | `Int -> Int -> Bool`。`String` などの等値を `==` で書けるようにするかは、`data` と `match` を実装するときに決める |
| `++` | `String -> String -> String` |
| `&&` `\|\|` | `Bool -> Bool -> Bool`。短絡評価する。HIR で `a && b` を `if a then b else False` に、`a \|\| b` を `if a then True else b` に脱糖する |
| `\|>` `<\|` | `x \|> f` は `x` を先に評価してから `f` に適用する。HIR で、`x` を先に評価する印を付けた関数適用 `f x` に脱糖する。型の検査は普通の関数適用と同じである。`f <\| x` は関数適用 `f x` に脱糖する |
| `>>` `<<` | 関数合成 |
| `::` | リストのコンストラクタ (S2 の `Prelude`) |

## `pub`

- シグネチャ、`data`、`type`、`effect`、fixity に `pub` を付けると公開される。付けないものはモジュールの中だけで見える
- `pub data` は、型とコンストラクタを公開する。コンストラクタを隠した抽象型は、将来の課題とする ([ロードマップ](../future/roadmap.md))

`pub` は、モジュールと import と一緒に S2 で実装する。モジュールの規則は [モジュールと名前解決](modules.md) にある。
