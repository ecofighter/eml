# `Char` の段

- 作成: 2026-10-22
- 状態: 計画は確定。T-4 の Verus の証明が通らないときだけ、利用者に相談する (U-1)

## 1. 目的と完了の条件

- 目的: roadmap の段の列の1つ目「`Char`」を実装する。文字の型 `Char`、文字のリテラル、Prelude の `Eq`/`Ord`/`Show` の instance、`Std.Char` の変換と ASCII の判定を入れる
- 完了の条件:
  - 6章の各タスクの完了の条件をすべて満たす
  - `cargo test`、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check` と、CLAUDE.md にある非既定の feature の clippy が通る
  - `crates/eml_rt` を変えたコミットでは、`cargo verus verify -p eml_rt` が `0 errors` を出し、`verusfmt --verus-only --check $(git ls-files 'crates/eml_rt/src/*.rs')` が 0 で終わる
  - `grep -rn "character literals are not supported" crates docs` が何も出さずに 1 で終わる
  - docs/implementation/benchmarks.md の「今の数値」の3つの表を、きれいな作業ツリーで測り直している (`eml_vm`、`eml_rt`、`std/` が変わるため)

## 2. 範囲

- 範囲に入るもの: 字句 (文字のリテラルと `\'` の escape)、`ast::LiteralValue::Char`、HIR の `Literal::Char`、型 `Char` と literal の型付け、網羅性、Core IR と LIR への写し、VM の命令の割り当て、`eml_rt` の `char_show`/`char_display`/`char_of_int`、`std/Prelude.em` の instance、`std/Char.em`、REPL の表示、対応する docs/spec と docs の文書
- 範囲に入らないもの:
  - `Byte`、ビット演算、`Bytes`、ハンドル (第2段「バイト列とハンドル」の計画 `docs/plans/2026-10-22-bytes-and-handles.md`)
  - UTF-8 の核 (検証付きのデコード、エンコード、バイト位置から `Char` と次の位置を読む操作)、文字の反復、文字から `String` を組むこと、大文字と小文字の変換、Unicode の分類 (第3段「UTF-8 と標準ライブラリ」)
  - `tests/ui/run/scripts/csv2jsonl/main.em` などの、バイトを数で比べる所の書き換え (第3段。`String.byte_at` が `Int` を返すのは第3段まで変わらない)

## 3. 背景の事実

行番号は HEAD baea5793 のもの。

- 字句: `CHAR` のトークンはすでにある (`crates/eml_syntax/src/lexer/mod.rs:86-87`)。パーサは式と pattern で受け、HIR が E0004 `character literals are not supported yet` を出す (`crates/eml_hir/src/lower/expr.rs:309-316`、pattern は `917-926` で `value()` が `None` のとき `unsupported_literal` を通る)。HIR は値を読む前にトークンの種類で E0004 を判定する
- `ast::LiteralValue` は `Int`、`Float`、`String` だけを持つ。文字の値を読む関数はない
- `'` は識別子の後ろ (`[A-Za-z0-9_']*`) と `CHAR` のトークンにしか現れない。`tests/`、`std/`、`bench/` のどの `.em` にも、トークンの頭の `'` はない (コメントを除いて grep で確かめた)
- 文字列の escape は `\n \t \r \\ \" \0 \u{1〜6桁の16進}` と補間の `\{` で、`\x` はない。`\u{...}` は `char::from_u32` で読み、サロゲートと 0x10FFFF を超える値を E0008 にする (`crates/eml_syntax/src/literal.rs:25-34`)
- 今の挙動: `''` は E0001 ``unexpected character `''` ``、`'ab'` は E0001 と E1001 ``cannot find value `ab'` ``、`'\q'` と `'\u{D800}'` は E0004 だけを出す
- 構文の診断の番号は E0015 までが使われている (`crates/eml_syntax/src/lib.rs:24-38`)
- リテラルは単相で、`fromInteger` にあたる脱糖も defaulting もない (docs/spec/types.md:98)
- 組み込みのスカラー型の多くは `crates/eml_extern/src/lib.rs` の表 (`ExternType` の行、`Extern` の関数の行、`Repr`) で決まる。型から Repr への写しは表を読む (`crates/eml_core_ir/src/translate/types.rs:64-76`)。表で決まらない所は、literal の構文と型付け (`eml_hir` の `Literal`、`eml_types` の `table.int`/`float`/`string` と `check/body.rs:359-362`、`1065-1075`)、literal の pattern (`CasePattern::Int`/`String`)、Core IR と LIR の `Atom::Int`/`Float`、VM の専用の命令 (`crates/eml_vm/src/op.rs:89-207`、選ぶのは `compile/emit.rs:963-1010`)、`eml_rt` の extern と Verus と検査の表である
- LIR の検査は、Repr が `Int` のどの scrutinee にも int の case を許す (`crates/eml_lir/src/check.rs:662-664`)
- 網羅性: `Ctor::Literal` は汎用で、頭の数が無限なので、`Int` の `match` には wildcard が要る (E4001。`crates/eml_types/src/exhaustive.rs:48-55,355,403`)
- `int_show` は結果を `[u8]` の buffer に書き、`lemma_ascii_utf8` で `valid_utf8` を示し、`str::from_utf8_unchecked` の後に `self.heap.alloc_string` で作る (`crates/eml_rt/src/heap/ctx/strings.rs:961-1050`)。vstd には `encode_scalar`、`encode_utf8_valid_utf8` がある (`vstd-0.0.0-2026-10-04-0306/utf8.rs:428,453,687`)
- `eml_rt` の `Fault` に内部の誤りの variant はない (`crates/eml_rt/src/externs.rs:104-117`)
- instance の `extern` のメンバーは、既定を持つメソッドも含めて `"<Class> <Type>.<member>"` の名前で表の行を引く (`crates/eml_hir/src/lower/instance.rs:136-142`)
- yield の仮の値は、`int` では 0、ダミーの `unbox` も 0 である (docs/spec/lir.md と docs/spec/object-model.md の「ダミーの値」)
- `Int` は 64 ビットで、一様な位置では 63 ビットの即値になる。それを超える値は `BigInt` の箱に入る (docs/spec/object-model.md:29)

## 4. 決定

### 4.1 長期の方針 (変えるには見直しが要る)

実装中にこれと食い違ったら、止めて報告する。

#### D-1: `Char` は `Repr::Int` の語で表し、新しい Repr を作らない

- 決定: `ExternType::Char` の行は `("Prelude.Char", Unr, Repr::Int)` にし、Prelude に `pub extern data Char` を置く。どの `Char` の語も Unicode のスカラー値 (0..=0xD7FF か 0xE000..=0x10FFFF) を持つ。この不変条件を docs/spec/lir.md の「値の表現」に新しい箇条「`Char` と `Byte` の語」として書く (`Byte` の行は第2段で足す)。`Char` の語を作るのは、字句が確かめたリテラル、確かめる `Char.of_int`、yield の仮の値 (0) だけである
- 理由: Repr は表で決まるので、LIR のどのパスも、箱、int の switch、定数もそのまま働く。一様な位置では `Int` と同じく箱に入れ (`BoxInt`)、どのスカラー値も 63 ビットに収まるので、いつも即値である。ネイティブ化の要件 (`Char` は生の語で、箱に入れても即値であること) もこれで満たす
- 退けた案: 新しい `Repr::Char` (すべての `Repr` の match と verifier の規則に枝が増え、得るものがない)、`Repr::Enum` (タグの switch は配置を要する。`check.rs:652-668`)
- 見直す条件: 一様な位置で `Char` を区別する必要が出たとき (今の設計にはない)

#### D-2: VM の命令を割り当てる規則

- 決定: extern の行を専用の命令に写すのは、今ある命令がその行を正確に計算するときだけにする。それ以外の行は汎用の `Op::Extern` を通す。この段では VM の命令を足さない
  - 今ある命令に写す行: `Char` の比較の7行 (`Op::IntEq` から `Op::IntCompare` まで)、`Char.to_int` (`Op::Move`)
  - 汎用の `Op::Extern` を通す行: `Char.of_int`、`Show Char` の `show` と `display`
- 理由: 規則を1つにし、VM の表面 (`op.rs`、`vm.rs`、`disasm.rs`、`step_failed`、`emit.rs`) を変えない。この段に、命令の数が効くほど `Char` を使う処理はない (スクリプトは第3段まで `Int` のバイトを読む)
- 退けた案: `Char` の算術や表示に専用の命令を足すこと (使う処理がなく、比較を今の命令に載せることと釣り合わない)
- 見直す条件: `bench/` のプログラムかスクリプトで、汎用の `Op::Extern` の費用が目立つとき。第2段の `String`/`Bytes` を読む命令はこの規則の外にあり、第2段の計画で決める

#### D-3: この段は第2段の表現の作業に依らない

- 決定: `Show Char` の2つの関数は、`int_show` と同じく今の `alloc_string(&str)` だけで文字列を作る。核の操作、信頼の一覧の T10、文字列の配置を変えない
- 理由: 利用者の前提で、第1段は第2段の表現の作業 (T10 を `&[u8]` に載せ替えることなど) に依らない。第2段が T10 を載せ替えるとき、この2つの関数は `int_show` と一緒に機械的に移す
- 見直す条件: なし

### 4.2 短中期の設計

理由があれば実装中に変えてよい。変えたら記録する。

#### D-10: 文字のリテラルの形と診断

- 形: `'x'` は Unicode のスカラー値をちょうど1つ持つ
- escape: `\n \t \r \\ \' \" \0 \u{1〜6桁の16進}`。文字列の escape に `\'` を足したもので、文字列も `\'` を受ける。2つのリテラルは1つの表 (`literal::simple_escape`) を共有する。文字のリテラルの中の `\{` は escape でなく、`'\{'` は E0008 である
- 字句: `Raw::Char` の正規表現を閉じた形 `'(\\[^\n]|[^'\\\n])*'` だけにする。同じ行の次の `'` までが1つの `CHAR` になるので、誤ったリテラルにも診断は1つだけ出る。閉じない `'` を行末まで飲む規則は作らない。閉じない `'` は今と同じ E0001 である。`x'` は識別子の正規表現が `'` まで読むので、1つの `LIDENT` のままである
- 読む関数: `literal::char_value(body: &str) -> Result<char, CharLitError>` が引用符の間の文字列を読む。`\u{` が閉じる `'` の先を見ることはない
- 診断:

  | 入力 | 番号 | 文言 |
  |---|---|---|
  | `''` | E0016 `INVALID_CHAR_LITERAL` (新設) | `empty character literal`、label `a character literal holds exactly one character` |
  | `'ab'`、e と U+0301 で書いた `'é'` | E0016 | ``character literal `'ab'` has more than one character``、同じ label、help ``write a string: `"ab"` `` |
  | `'\q'` | E0008 | ``unknown escape sequence `\q` `` (今の文言) |
  | `'\u{D800}'`、`'\u{110000}'`、`'\u{}'`、`'\u{1234567}'` | E0008 | ``invalid unicode escape `…` `` (今の文言) |
  | 同じ行に閉じる `'` がない `'a` | E0001 | ``unexpected character `'` `` (今と同じ) |

#### D-11: 比較、pattern、網羅性

- 比較: 行 `CharEq`、`CharNe`、`CharCompare`、`CharLt`、`CharLe`、`CharGt`、`CharGe` (名前は `"Prelude.Eq Char.=="` などで、引数 `[Int, Int]`、結果 `Enum`、`Pure`)。`emit.rs` の `fn arithmetic` が今の `Op::Int*` に写す。`eml_rt` の期待値の表は、この7つの名前を `externs::int_eq` などに振り分ける。順序はコードポイントの順で、`Ord String` の UTF-8 のバイトの順に等しい
- `Ord Char` は `compare`、`(<)`、`(<=)`、`(>)`、`(>=)` の5つをすべて extern にする。`Ord Int` と同じく、どれも専用の命令に当たる
- literal と pattern: リテラルは `Atom::Int(スカラー値)`、literal の pattern は `CasePattern::Int(スカラー値)` になる。Core IR と LIR は Repr の段の IR なので、テキストには `97` と出る。元の型は instance の名前 (`f@[Char]`) に残る
- 網羅性: `Literal::Char(char)` を足す。`Int` と同じく無限の頭として扱い、`Char` の `match` には wildcard が要る (E4001)

#### D-12: `Show Char`

- `show c`: `escape_char(c)` を単引用符で囲む
  - `'` は `\'`、`"` はそのまま
  - `\`、改行、タブ、CR、NUL は `\\`、`\n`、`\t`、`\r`、`\0`
  - U+0001〜U+001F と U+007F は `\u{…}` (小文字の16進、先頭の0なし)
  - ほかはそのまま (`{` も)
  - 結果は文字のリテラルとして読み戻せる
- `display c`: その1文字の文字列。`"\{c}"` はその文字を補間する
- 実装: どちらも `Pure` の行 (`"Prelude.Show Char.show"`、`"Prelude.Show Char.display"`、引数 `[Int]`、結果 `Obj`、汎用の `Op::Extern`) で、`crates/eml_rt/src/heap/ctx/strings.rs` に `Ctx` のメソッドを足す
  - 型: `pub unsafe fn char_show(&mut self, c: i64) -> (w: Word)` と `char_display`。`requires old(self).wf(), is_scalar(c)`。呼ぶ側の責務を `requires` に書くのは、`unsafe fn string_eq … requires holds_strings` と同じ形である。VM の呼ぶ所は `unsafe {}` に入れ、`// SAFETY:` で docs/spec/lir.md の「値の表現」の不変条件を引く
  - 事後条件は `int_show` と同じものに、`text_of(w) == char_display_spec(c)` (vstd の `encode_scalar(c as u32)`) か `== char_show_spec(c)` を足す
  - 作り方は `int_show` と同じである。`[u8; 4]` か `[u8; 12]` の buffer に書き、`valid_utf8(bytes@)` を示し、`str::from_utf8_unchecked` の後に今の `self.heap.alloc_string(text)` を呼ぶ
  - 新しい証明の責務は buffer の `valid_utf8` だけである。c < 0x80 と escape には今の `lemma_ascii_utf8` を使う。ほかは vstd の `encode_utf8_valid_utf8` と `encode_utf8(seq![c]) == encode_scalar(c)` に、実行のバイトが `leading_byte_width_n` と続きのバイトに等しいという `bit_vector` の事実を足す
- 退けた案: eml で `show` を書くこと (`display` には符号化の extern がいずれ要り、Prelude からは `Std.Char.to_int` に届かない。同じ出力のためにコードが増える)、非スカラーの語に誤りを返す全域の関数 (`eml_rt` に内部の `Fault` がなく、語の不変条件がその場合を除く)

#### D-13: `Std.Char`

- `std/Char.em` を足し、`crates/eml_hir/src/lib.rs:26-41` の `STD` に登録する。使う側は `Std.Float` と同じく `Char.x` と書く
- `pub extern to_int : Char -> Int`: `Pure` の行 `CharToInt` (`"Std.Char.to_int"`、`[Int] -> Int`)。`emit.rs` が `Op::Move` で出す。move として出す最初の extern である。LIR には extern の節点が残るが、`Pure` で `int` なので RC はない
- `pub extern of_int : Int -> <Panic> Char`: `Panics` の行 `CharOfInt`。汎用の `Op::Extern` から `externs::char_of_int(n) -> Result<i64, ArithFault>` を呼ぶ。`0 <= n <= 0xD7FF || 0xE000 <= n <= 0x10FFFF` のとき Ok、ほかは新しい `ArithFault::NotScalar(i64)` で、文言は ``int `55296` is not a Unicode scalar value`` である
  - `Option` でなく `Panic` にするのは、`Float.truncate` と揃えるためと、extern が `Option` を作れないためである (`std/Float.em:5,39-41`)
- ASCII の判定 (どれも `Char -> Bool`、`Ord Char` と `&&`、`||` で eml で書く): `is_ascii` (`c <= '\u{7f}'`)、`is_ascii_digit` ('0'..'9')、`is_ascii_upper` ('A'..'Z')、`is_ascii_lower` ('a'..'z')、`is_ascii_alpha` (upper か lower)、`is_ascii_alphanumeric` (alpha か digit)、`is_ascii_space` (`c == ' ' || (c >= '\t' && c <= '\r')`。`std/String.em` の `is_space` と同じ)
- この段で `Char` と `String` をつなぐのは `show` と `display` だけである。`String` から `Char` を取り出す操作は第3段に置く

#### D-14: 第3段に残すもの

- UTF-8 の核 (検証付きのデコード、buffer への符号化、バイト位置から `Char` と次の位置を読む操作)、文字の反復、文字から `String` を組むこと、`to_ascii_upper`/`to_ascii_lower`、Unicode の分類と大文字小文字の変換、`Char` と `Byte` の変換
- 第3段は `char_display` の符号化の証明を使い回せる
- csv2jsonl などの書き換えは第3段で `Char` のリテラルを使って行う (`10`/`13`/`34`/`44` を `'\n'`/`'\r'`/`'"'`/`','` に、`escape` を `Char` のリテラルの `match` に、`wc` の `is_space` を `Char.is_ascii_space` に)

## 5. 実装の制約と約束

- 各コミットは単独で build でき、1章の検査がすべて通る (D-1〜D-3)

- テストの変更は種類を分けて扱う。この計画の表 (T-2) に載せた変更は承認済みである。それ以外に期待値が変わったら止めて報告する

### T-1: 字句で文字のリテラルを確かめる

- 目的: 誤った文字のリテラルに1つの正しい診断を出す。AST と HIR は変えない
- 対象: `crates/eml_syntax/src/lexer/mod.rs` (`Raw::Char` の正規表現と `Ok(Raw::Char)` の枝から `literal::char_value` を呼び E0016/E0008 を出す。トークンは `CHAR` のまま)、`crates/eml_syntax/src/literal.rs` (`char_value`、`simple_escape` に `'\''`)、`crates/eml_syntax/src/lib.rs` の `codes` (`INVALID_CHAR_LITERAL = ErrorCode(16)`)
- 作業: `ast::Literal::value` は `CHAR` に `None` を返したままにする。HIR はトークンの種類で E0004 を先に出すので、下流は変わらない
- docs/spec: lexical.md の「数値と文字」に文字のリテラルの形、escape、誤りを書く (表の行は E0004 のまま)。「文字列」の escape の一覧に `\'` を足す。diagnostics.md に E0016 の行を足し、E0008 の説明に「文字のリテラル」を足す
- テスト:
  - `crates/eml_syntax/tests/lexer.rs`: `''`、`'ab'`、`'é'` (e + U+0301) がそれぞれ1つの `CHAR` と1つの E0016 を出す。`'\q'`、`'\u{D800}'`、`'\u{110000}'` は E0008 を出す。`'a` は E0001 のまま。`x'` は1つの `LIDENT` のまま
