## 1. 目的と完了の条件

- 目的: TLS のクライアント `Std.Tls` を入れる。次の段 `std-http` の前提である。TLS の状態は rustls の上の sans-IO の crate `eml_tls` が持ち、ソケットの I/O はすべて `Std.Net` が行い、`std/Tls.em` の eml のコードが両者の間でバイトを汲む
- 完了の条件
  - 9節の全体の確認がすべて通る
  - テストの driver の仮想のホスト `tls.localhost` と `tls-cut.localhost` の上で、`tests/ui/run/tls/` と `tests/ui/run-fail/tls/` の UI テストが checked と fast の両方で通る
  - 本物の driver で、unix の Rust のテストが手元の TLS の server と往復する (T-9)
  - CI の全 job と、x86_64-linux と aarch64-darwin の `nix build` が aws-lc を組んで通る (T-1 の G1、G2)
  - `tls` を外した処理系では、`Std.Tls` が `NotAvailable` を投げ、テストの driver は `tls.localhost` を `NotFound` にする (`tls_off::` のテスト)

## 2. 範囲

## 5. 決定

### 5.1 長期の方針

実装でこれらとぶつかったら、止めて報告する。どれも `docs/future/async.md` の「TLS と HTTP」にある方針を、調べた事実で確かめて細部を決めたものである。

#### D-1: TLS は sans-IO の `eml_tls` に置き、I/O は `Std.Net` が行う

- 決定: `eml_tls` は eml のどの crate にも依存しない。`Conn` は rustls の接続と復号した平文の列を持ち、I/O を持たない。`eml_vm` がこれを `Lin` の `Foreign` (`Std.Tls.Conn`) として持ち、extern の行の腕を持つ。`eml_rt` は変えない。`std/Tls.em` が `Conn` と `Net.TcpStream` の間でバイトを汲み、待ち、取り消し、期限は `Net` のものを使う。本物の driver は `eml_tls` を参照しない
- 理由: 待ち、取り消し、期限が `Net` の1か所に集まり、driver に TLS の意味を足さずに済む
- 採らなかった案: driver の側の `TlsStream` (本物の driver に rustls が入り、取り消しと期限の意味が別に要る)、プラグイン (GUI のためのスレッドの固定やイベントループが要らない)
- 守る規則: `eml_tls` の `[dependencies]` に eml の crate がない。`crates/eml_io/src/real.rs`、`crates/eml_io/src/driver/`、`crates/eml_io/src/sys/` に `eml_tls` が出てこない (`grep -rn eml_tls crates/eml_io/src/real.rs crates/eml_io/src/driver crates/eml_io/src/sys` が何も出さない)
- リポジトリに残す場所: `docs/spec/stdlib.md` の「`Std.Tls`」と `docs/implementation/architecture.md` (T-1、T-3、T-7)

#### D-2: 暗号は aws-lc-rs、根は webpki-roots

- 決定: workspace の依存は `rustls = { version = "0.23.46", default-features = false, features = ["aws_lc_rs", "std", "tls12"] }` と `webpki-roots = "1.0.11"` で、PEM は `rustls::pki_types::pem::PemObject` で読む。`install_default` は呼ばず、provider は `builder_with_provider` で渡す。追加の CA は PEM で渡し、OS の証明書ストアは使わない。TLS 1.2 と 1.3 を受ける
- 理由: rustls の推奨の provider で、要るのは C のツールチェーンだけである。rustls の `aws_lc_rs` は aws-lc-sys の prebuilt-nasm を有効にするので、Windows で NASM がなくても組める (付録 C の2節で registry のソースを読んで確かめた)
- 見直す条件: T-1 の判断の表 (T-1 の「失敗したとき」) が ring への切り替えを求めたとき。ring でも組めなければ段を止め、設計を決め直す
- リポジトリに残す場所: workspace の `Cargo.toml` のコメントと `docs/implementation/architecture.md` の「crate の依存関係」(T-1)

#### D-3: feature の配線と、C の暗号を dev-dependency にしない規則

- 決定
  - `eml_io`: `tls = ["dep:eml_tls"]`。テストの driver の終端器と `tls.localhost` の名前だけを分ける
  - `eml_vm`: `tls = ["dep:eml_tls", "eml_io/tls"]`
  - `eml_cli`: `tls = ["run", "eml_vm/tls", "dep:eml_tls"]`、`default = ["run", "tls"]`。`dep:eml_tls` は T-9 で足す
  - `eml_test_support` には `tls` を足さない
  - `eml_tls` のほかの crate は、`eml_tls`、`rustls`、`rcgen`、`ring`、`aws-lc-*` を dev-dependency にしない。テストは optional の通常の依存を通し、`cfg(feature = "tls")` の下で使う
  - `tls` を外した振る舞いのテストは、`eml_io` と `eml_vm` の結合テストの `mod tls_off` に置き、`cfg(not(feature = "tls"))` だけで分け、OS では分けない
- 理由: workspace の実行では `eml_cli` の既定が `tls` を両方に入れ、`-p eml_vm` などを選ぶ Miri と ASan には C のコードが入らない。dev-dependency に C の暗号が入ると、C のツールチェーンを持たない `.#cross` の clippy が組めない
- 守る規則: T-4 で CI に入れる `cargo tree` の4行が通る。`tls_off` のモジュールに OS の `cfg` がない
- リポジトリに残す場所: `docs/implementation/testing.md` の「OS ごとのテスト」と「feature の組み合わせの確認」(T-1、T-4、T-5)

#### D-4: テストの相手は、テストの driver の仮想のホストが Rust で TLS を終端する

- 決定: `tls.localhost` と `tls-cut.localhost` への `connect` で、driver が終端器を作る。終端器は `eml_tls::Conn::server` と、暗号文の端の組、平文の端の組を持つ。平文の組の遠い側は、普通の `connect "localhost" port` と同じく仮想の listener の `accept` の待ち行列に入る。`settle` の最初 (handle の bin を空にした後、操作を試す前) に、終端器ごとに動かなくなるまで汲む。証明書と鍵は `eml_tls::fixtures` が持つテスト用の固定のもので、何も認証しない
- 理由: handshake は乱数が毎回違うので録音で再生できず、決定的にできる場所はテストの driver だけである
- 守る規則: `settle` の操作の順、seed での並べ替え、仮想の時計の進め方を変えない。終端器の平文の相手は、いつもプログラムが持つ端である (listener は `Op::Listen` だけが作る)
- リポジトリに残す場所: `docs/spec/vm.md` の「時計と driver」(T-5)、`docs/implementation/testing.md` の「UI テスト」(T-8)

### 5.2 短中期の設計

理由があれば実装中に変えてよいが、変えたらコミットのメッセージに残す。

- D-10 `eml_tls::Conn` の API: 付録 A の1.1節のとおり。状態の印は HANDSHAKING=1、HAS_OUTGOING=2、PEER_CLOSED=4 (close_notify を受けた)、TRUNCATED=8 (close_notify なしの EOF。handshake の途中も含む)、FAILED=16。`push_tls` は `process_new_packets` のたびに平文を自分の列へ移す。`set_buffer_limit(None)` にする。`pull_tls` は失敗の後も alert を出す。設定の誤りと証明書の拒否の文言は固定で、rustls の詳細を付けない (付録 A の1.1節の表)。`plaintext()` と `consume(n)` を足し、VM がその場で行を探せるようにする
- D-11 `read_line` の読み残しは `Conn` の平文の列に置く。設計の文書の「`Tls.Stream` は専用の読み残しの `Bytes` を持つ」は、同じ文書の2つのフィールドの `Stream` と食い違っている。行は `Net.read_line` と同じ関数で切り出す。T-6 で `cells.rs` の `find_line` と `open_line_len` を自由な関数にし、`eml_vm/src/tls.rs` の `line_state` が使う。そのために extern の行を2つ (`line_ready`、`take_line`) 足し、行は11になる
- D-12 `_within` は入れない。公開の関数は `connect`、`connect_with_ca`、`wrap`、`read_chunk`、`read_line`、`write`、`write_bytes`、`write_line`、`shutdown_write`、`close` と型 `Conn`、`Stream` である。理由: eml に時計がなく、`Async.timeout` は期限で `Stream` を落とすので、書けるのは `Net` の読み1回ごとに期限を付け直す形だけで、`Net.read_line_within` の「期限は1行の全体に付く」と意味が違う
- D-13 `eml_vm` の `tls.rs` は無条件に宣言し、`tls` を外したときは、同じ名前とメソッドを持つ値のない型 `enum Conn {}` と、いつも `not available` を返す `client` を使う。`vm.rs` に cfg を置かない。`client_raw` だけが投げ、種類は `tls` ありで `Other`、なしで `NotAvailable`
- D-14 失敗の扱い: TLS の誤りは、alert を `try_io` の中で書き出してから `Other` の IO の失敗にする。同じ押し込みで復号した平文は返さない。close_notify なしの EOF は、届いた平文を返し切った後で `ConnectionReset` にする。`read_chunk` と `read_line` は入口で取り消しを確かめる。`close` は `Cancelled` のほかは失敗しない。文言は付録 A の1.4節の表のとおり
- D-15 終端器の細部: 付録 B の1.1節の手順 0〜12 のとおり。設計の文書から2点変えた。(1) eml の server が閉じたとき、FAILED のとき、早い close のときは、暗号文の端を閉じずに `shutdown_write` する。閉じると、EOF を読んだクライアントが書く close_notify が `BrokenPipe` になり、`Tls.close` が壊れる。暗号文の端を閉じるのは、クライアントが自分の端を閉じたときだけで、終端器はその後の `settle` で取り除く。(2) 「handshake の前に server が閉じた」は、終端器がクライアントのバイトを1つも受け取る前に server が閉じたときだけとする。handshake の途中で閉じたときは、handshake を終えてから close_notify を送る。こうすると、acceptor が先に待っていれば結果がタスクの順によらない
- D-16 ポート: `tls.localhost` への1つの接続は、仮想のポートを2つ取る。先に平文の組のクライアントの端、次に暗号文のクライアントの端である。listener が 49152 なら、eml の server の `peer_addr` は `127.0.0.1:49153` を見せる
- D-17 fixtures: `crates/eml_tls/fixtures/{ca.pem,cert.pem,key.pem,gen.sh}` と、いつも組み立てる `pub mod fixtures` (`CA_PEM`、`CERT_PEM`、`KEY_PEM`)。CA も leaf も ECDSA P-256 で、期限は 2026-01-01 から 2126-01-01、leaf の SAN は `tls.localhost`、`localhost`、`127.0.0.1` である。`gen.sh` は OpenSSL 3.4 以上が要り、`nix shell nixpkgs#openssl -c crates/eml_tls/fixtures/gen.sh` で流す。CA は `tests/ui/run/tls/ca.pem` と `tests/ui/run-fail/tls/ca.pem` に写し、UI のプログラムは `Fs.read_text "ca.pem"` で読む (設計の文書の `FileIn.read_all "ca.pem"` は型が合わない)
- D-18 CI の関門と判断の表: 付録 C の T1 の G1、G2 と「Decision rule」のとおり。aws-lc の build script、リンク、実行のどれかが1つの OS か `nix build` で失敗したら ring に替える。OS ごとの環境変数や道具は足さない
- D-19 `max_bytes` に数えないメモリ: `Conn` の平文の列、rustls の buffer、`pull_tls` が埋める `Vec`。上限は付録 A の1.2節のとおりで、`docs/spec/vm.md` の「上限と割り込み」に書く

### 5.3 付録との差分

付録はサブタスクごとに書いたので、次の点は本文が優先する。

- 付録 A の `_within` の扱い、`read_chunk_within` の UI テスト、「未決」の1番: D-12 で入れない

  - `<msg:truncated>`: `cannot read the stream: the peer closed the connection without close_notify`
  - `<msg:handshake-eof>`: `cannot complete the TLS handshake with tls.localhost: the peer closed the connection`
  - `<S1:verb>`: 設計の文書の名前のまま (`connect_with_ca`、`wrap`、`read_chunk`、`read_line`、`write_line`、`shutdown_write`、`close`)
- 付録 B の `the_fixtures_parse` は `rustls_pki_types::pem::PemObject` と書いているが、別の crate は足さず `rustls::pki_types::pem::PemObject` を使う (D-2)

- 付録 B と付録 C のタスクの順は、8節の順で置き換える

## 6. 実装の決まり

- テストを先に書く (CLAUDE.md)。各タスクは、最後に `cargo clippy --all-targets -- -D warnings` と `cargo fmt --check` が exit 0 で終わる
- 日本語のコメントと文書は natural-japanese のスキルに従う。コメントは理由を書き、規則は `docs/` の節を引く。コードと `docs/` は `docs/plans/` を引かない
- spec の節は、規則を実装するコミットに入れる (roadmap の「進め方」)。`citations::every_cited_heading_exists` は、コメントが引く見出しがないと落ちる
- feature を宣言するコミットは、その crate で `cfg(feature = "tls")` か `cfg(not(feature = "tls"))` を最初に使うコミットと同じか、それより前に置く。宣言のない feature は `unexpected_cfgs` で `-D warnings` を落とす (D-3)
- CI の tls を外した段 (`cargo nextest run -p eml_io -p eml_vm -E 'test(tls_off::)'`) は、最初の `tls_off` のモジュールと同じコミットに入れる。何も合わないと nextest は exit 4 で落ちる (D-3)
- `.em` のプログラムは `timeout 20` の下で流す
- テストの変更の種類 (docs/implementation/testing.md の「テストの変更の運用」)
  - 期待値の変更: `crates/eml_core_ir/tests/externs.rs` の、借用と組を返す行の一覧と、`lin` と `poly` の印の一覧に `Std.Tls` の行を足す (T-7)。足すだけで、既存の行の期待値は変えない
  - 機械的な追随: T-6 の行の切り出しの共有。期待値はすべて同じ
  - 成否の変更: なし。ほかは新しいテストの追加だけである

## 付録: レビューで変わった主な点

- 終端器の早い close の規則は、最初は「handshake の途中で server が閉じたら打ち切る」だったが、クライアントの Finished をもう汲んだかで結果が変わるため、「クライアントのバイトを1つも受け取る前」に改めた (D-15)
- `close` は失敗をすべて捨てていたが、`Cancelled` だけは投げ直すようにした。`read_chunk` と `read_line` は入口で取り消しを確かめるようにした (D-14)
- `_within` は読み1回ごとの期限にしかならないので、利用者の判断でこの段から外した (D-12)
- `.#cross` の clippy、Miri、ASan に C の暗号が入らないことを、CI の `cargo tree` の4行で確かめることにした (D-3)
- aarch64-darwin の `nix build` を、段を閉じる時でなく T-1 の直後の関門にした (G2)
