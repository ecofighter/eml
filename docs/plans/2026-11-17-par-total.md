## 1. Goal and success criteria

- Goal: `par` and `compute` are std code over total children. Nothing aborts across a child boundary; a runtime error in a child ends the run. Fork evidence, `prim child_abort`, the repr `fev` and the re-raise of aborts leave Core IR, LIR, the VM, `eml_rt`, `eml_sched` and `eml_native`. The VM's scheduler is otherwise unchanged; native code keeps rejecting `Call::Par`.
- Success criteria:
  - S-1 (G-3, unchanged): `grep -rn 'child_abort\|ChildAbort\|fork\$\|reperform\$\|fork_ev\|fork_of\|alloc_fork_\|ForkTable\|MissingFork\|reraise' crates/*/src std` → empty.
  - S-2 (S-20): `grep -c '^\(pub \)\{0,1\}extern ' std/Par.em` → `1`, and that line is `extern fork_join : (Unit -> a) -> (Unit -> b) -> (a, b)`.
  - S-3 (SC-1, S-10, D-PT-7): a runtime error in a child ends the run from any worker, also while the other child still runs, and with two failing children the error reported is the one that was written first. Which child's error is written first can depend on timing; the rule is about the report, not about determinism. Pinned by `workers::a_child_error_ends_the_run_while_the_other_child_runs`, `workers::the_first_error_written_wins_on_either_worker` (deterministic, both orders, through a gate), `workers::two_failing_children_on_two_workers_report_the_first_error` and `workers::tests::the_first_error_written_is_the_one_reported`.
  - S-4 (D-PT-1): `tests/ui/run/par/lin_result_dropped_on_panic.em` passes in checked and fast mode, under both seeds and at 2 and 8 workers (the harness's runs).
  - S-5: a program that does not fork compiles to the same LIR and runs with byte-identical `RunStats` (SC-5 of 7.3.2).
  - S-6: `cargo verus verify -p eml_rt` → `1270 verified, 0 errors` on PT-8; `bench/rt-gate.sh <PT-7>` exits 0.
  - S-7: the gate of 10.1 holds on PT-8's commit.
  - S-8: CI `success` on every job for the Close commit.

- The end of a run [V: read]: worker 0's body (`entry_body`, `crates/eml_vm/src/lib.rs:1149`) runs `vm::run` inside a `catch_unwind` (`:1198-1224`), then drops `Shutdown` (`:1228`; its `Drop`, `workers.rs:829`, sets END on every stop word and wakes every worker) and joins every worker handle (`:1229-1233`); each joined worker returns its `Ctx` in `Retired`. Only after that does `settle(result, take_fatal())` run (`:1256`). A split run joins worker 0 after `run_main` has returned (`:1004-1016`) and settles once more (`:1044`). The `Machine` drops or recovers the heaps after all of this (`:439`). So no heap is dropped while any worker runs, whichever worker failed. `Machine::run` recovers when the reported error is not `is_broken()` (`crates/eml_sched/src/error.rs:143`). Workers 1..N-1 exist only in a run without session roots (`roots_free`, `crates/eml_vm/src/sched.rs:548-560`, `lib.rs:941`; a split run with roots is refused, `lib.rs:530-537`), and recovery without roots copies nothing and drops every heap of the run (`lib.rs:447-476`). ### 5.2 Short-term decisions (this plan)

- S-PT-1 (U-7): no new diagnostic code. The call sites that were E2020 are E2001 or E2002 as section 3 says; E2020 stays for user functions with `<never e>`.
- S-PT-2 (`Call::Par` and the row): `Call::Par`, its text `par (,) #0(a, b)`, `Op::Par` and the variant name `Extern::Par` stay; only the row's name becomes `"Std.Par.fork_join"`. `par` is now an ordinary generic std function, so user code has no partial application or value use of the extern; the `$externN` wrapper path stays generic for the other rows.
- S-PT-3 (D-PT-5's mechanism): `JoinNode` gains `parent_limit: Limit`. Invariant: `Task.boundaries` lists the task's open child boundaries outermost first (`par` pushes at `vm.rs:1889`, `child_done` pops). Only a task with a cell receives a flag; right-child and job tasks have `cell: None` (their `boundaries[0]` is their own join or the sentinel `JOB`) and are never matched. For a task with a cell, `boundaries` is not empty exactly while it runs inside a child, and then the only saved class that is not `Stops` is the one in `boundaries[0]`'s join (an inner fork saves `Stops`). `mark_limited` therefore flags `boundaries[0]`'s `parent_limit` instead of `task.limit`.
- S-PT-4 (`JobEnd`): the job's end is a bare `Word`; `Registry::finish_job`, `Registry::take_job` and the free `finish_job` get `surface.rs` entries with the reason `Stores` (PT-6's table).
- S-PT-5 (`may_fork`): deleted with all three users; `prim root_get` keeps no other tie to it [V: proto].
- S-PT-6 (`Ctx::evv_word`): kept; `eml_rt`'s tests read the list through it. Its doc comment loses the fork sentence.
- S-PT-7 (`bench/pfib.em`): runs `pfib 2 20` without an argument (10 945 forks; the size of the `RunStats` test and of the `bench/run.sh` row) and `pfib 2 30` with any argument (the record of D-PT-9). Size 30 takes about 50 s in the checked dev build, so it cannot be the tested size.
- S-PT-8 (`Notice`): `Notice::Child(Task)` is now much larger than the other variants; the enum gets `#[expect(clippy::large_enum_variant, reason = "a notice moves once into an inbox; a box would add an allocation per placed child")]`.
- S-PT-9 (the user's decision on G-3): `std/Async.em`'s private `reraise : Failure -> <IO, Panic> a` (6 lines: `grep -n 'reraise' std/Async.em`) is renamed `raise_failure` in PT-3. No snapshot moves [V: proto].
- S-PT-10 (D-PT-7's mechanism, "first written"): `Run.fatal` is the one place where the run's error is decided. (1) Worker 0 writes its own non-quiet error to the slot as soon as `vm::run` returns, before it stops the other workers (`Run::record`). (2) `set_fatal` keeps the first error written; nothing replaces it. (3) `settle` returns, in this order: an error an earlier `settle` chose (the split run's second call), the slot's error, worker 0's result. Workers 1..N-1, the main worker and the panic path write as before. No lock, counter or thread is added. Quiet stops (`Interrupted`, `Terminated`, `MemoryLimit`, `Ended`) are never written, as before: an error written by any worker wins over them.

## 6. Implementation constraints and conventions

- One unit = one commit; each passes G (7.3.1) and the SC lines in force (7.3.2). `cargo fmt` before every commit.
- Deletions are compile-driven: delete the named item, then fix every error and every `-D warnings` lint by deleting the dead arm, import, helper or test helper. A compile error whose fix is not a deletion and is not listed in the unit stops the unit.
- "Delete test `x`" means the `#[test]` function with its doc comment. A test helper or constant left unused by listed deletions is deleted too.
- `docs/spec/` text is written in the commit that implements the rule (each unit's "Docs" part); PT-9 rewrites what remains. Docs edits are addressed by anchors, not line numbers: an anchor is a quoted substring that `grep -nF '<anchor>' <file>` finds exactly once at the base [V: each anchor of this plan was checked with `grep -cF`]. The edit applies to the sentence, bullet or table row that contains the anchor. Each unit ends with a "docs done" grep and its expected output; a hit that no rule covers stops the unit. Code comments cite `docs/spec/` and `docs/implementation/` only; docs name no stage. After every unit `cargo nextest run -p eml_cli --test integration -E 'test(/^citations::/)'` passes (part of G): a comment or sentence that cites a deleted section is reworded or deleted in the same commit.
- Snapshots are accepted with `cargo insta review` after reading each diff against 7.4; never `cargo insta accept` over the whole tree.
- Japanese: see the header. Comments explain why, not what.
- Quote every glob (zsh). Run ad-hoc `.em` programs under `timeout 20`. Stop any Bash call moved to the background before finishing a unit.
