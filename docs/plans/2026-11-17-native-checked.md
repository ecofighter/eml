## 1. Goal and success criteria

- Goal: on the programs native code accepts, `eml run --native --debug-heap` and `eml run --native --stats` behave as the VM's checked mode. Checked lowering emits the same inline instructions as fast lowering; each inline access to a heap object is preceded by a call of an audit entry whose pass implies the safety premise of the access, each indirect call through a function value by an audit that checks its target, every direct heap entry call is the full checked operation, a run ends with the checked end-of-run checks, and the counters of `RunStats` equal the VM's.

- Direct `eml_rt_decref` callers: `lower/unwind.rs` L302 (the handler state at a landing point), L317 (each owned word of a cleanup), `lower/apply.rs` L398 (the last argument when an inner application aborts): unchanged since 4a2954c1. The entry-safepoint cleanup goes through the same `cleanup` (L317).
- `Step::slow()` (`lower/rc.rs`) names `eml_rt_dup_slow` and `eml_rt_decref`; `release_box` in `lower/apply.rs` reads the two names through `Step::slow()`.
- `Ctx<Fast>` and `Ctx<Checked>` have `Native` at offset 0 and the heap right after it (the `const` asserts after `CTX_JMP` in `crates/eml_rt/src/heap/ctx.rs`), so `mem.rs`'s offsets serve both lowerings.
- A checked-mode block has a one-word prefix before the header and the pointer points at the header in both modes (docs/spec/object-model.md 「前置き」), so every inline header, count and field access has the same offsets in checked mode. Only tokens differ (a checked token is an index into the heap's token table).
- `RunStats` has 23 fields. The VM's interpreter counts four of them itself, in checked mode only: `boxes` (each `BoxInt` / `BoxEnum` / `BoxFloat` / `BoxConst` instruction), `unboxes` (each `Unbox`), `unwound_frames` (each frame an abort pops, `vm.rs` L1692) and `reuses` (`data.rs` `con_reuse`, a `con` that got a non-empty token). 01 §9 names three; `reuses` is the fourth.
- The VM runs `Heap::field` / `Heap::raw` for a field read, `Heap::set_field` / `Heap::set_raw` for a field write, `Heap::meta` for a tag or kind, `Heap::is_unique` / `Heap::is_last` for a uniqueness test, `Heap::unbox_int` / `Heap::unbox_float` for a box read, and in checked mode `check_data` (kind `Data`, tag, scanned count; an internal error) before the fields of `unpack`, a `switch` case, `release` and a struct `unbox` (`crates/eml_vm/src/data.rs`). None of the read operations counts anything; `dup` and `decref` count `rc_increments` / `rc_decrements` and, for a counted immortal object, move the outstanding count in the prefix.
- `placement::checked_mode_is_not_named` asserts today that neither `eml_native` nor `eml_nrt` names `Checked`; `cli::native_conflicts_with_debug_heap_and_stats` asserts the usage error. Both change (7.4).
- `crates/eml_lir/tests` executes nothing: `eml_lir` has `insta` as its only dev-dependency and its tests parse, verify and print (`grep -ln 'eml_test_support\|eml_vm' crates/eml_lir/tests/*.rs` is empty). The hand-written LIR programs that run are in `crates/eml_vm/tests` (`common::run_lir`, `run_unverified`) and `crates/eml_native/tests`. The design plan's third test set does not exist (5.2 C-6).
- The negative tests `shared_capture` and `fresh_result` that 01 §9 names are defined nowhere (`git grep -n 'shared_capture\|fresh_result' -- crates docs ':!docs/plans'` finds no test). This plan defines the negative tests (S-NC-8).

### 5.1 Long-term guidelines (01 §9 as restated by 5.2)

| ID | Decision |

| D-NC-1 | Audit before inline (and, for an indirect call, before the call: C-11). ### 5.2 Changes to the design (00 §D D-19, appended by NC-1)

| # | 01 §9 says | This plan | Reason |
|---|---|---|---|
| C-1 | Seven audits `audit_x` with bodies `x_body` and predicates `x_passes`, all new functions of `eml_rt` (D-NC-5) | Only `dup` and `decref` are split (`audit_dup` / `dup_body`, `audit_decref` / `decref_body`). The audit of a field load, a field store, a uniqueness test, a header load and a box load is the existing checked operation (`field` / `raw`, `set_field` / `set_raw`, `is_unique`, `meta`, `unbox_int` / `unbox_float`) called by the audit entry, its value dropped; `eml_rt` only gains the converse `ensures` "`M::CHECKED && r is Ok ==>` the premise" on those operations | These operations count nothing and are idempotent (a store audit writes the word the inline store writes again), so "audit, then inline" needs no body function. ### 7.5 Soundness points and what holds each

| Point | Holds because |
|---|---|
| A passing audit implies the premise of the inline access that follows | `dup` / `decref`: `audit_dup` / `audit_decref` ensure `dup_passes` / `decref_audited` (Verus), which are the checked-mode facts the count step needs: a live block with a prefix, no `lin` bit where one is refused, the owner. Field, raw, store, unique, header, box: the converse `ensures` of S-NC-1 (Verus): `Ok` means readable and the index, owner or kind checked. `code`: `meta` and `scanned(w, 0)` both `Ok`, so the header and scanned word 0 are readable; the load `closure_code` makes is of scanned word 0 at the offset its own `scan` byte selects, the same rule `Heap::scanned` uses (`layout::data_first`). The four field and store entries, `header`, `code`, the float `box` entry and the `dup`, `decref` and `unique` entries refuse a word that is not a pointer before they call the operation, whose premise is a pointer (for `dup`, `decref` and `unique` because the predicates are vacuous for an immediate); the int `box` entry refuses a word that is neither an immediate nor a pointer, the premise of `Heap::unbox_int`; `data` accepts what its operations accept |
| The target of an indirect call | The `code` audit passes only if the code word is in `Image.entries` with the signature word the site passes (S-NC-15). The table is built by the JIT host from the closure entries and PAP adapters it defined, with each one's own signature, so the call lands on the first instruction of such an entry and passes the arguments that entry's signature takes. `closure_code` then reads the same word (nothing runs between). Pinned by the three native-only `fatal::an_apply_*` tests, the `eml_nrt` unit and fatal tests of NC-3, and by parity: every legitimate indirect call of the UI suite passes the audit [V: proto] |
| Premises the audits do not check (as in the VM's checked mode) | `word_in(w)`: a non-immediate word of a counted Repr points at a block of one of the run's heaps or of an attached region; the page table then refuses pages the run does not own, and the prefix tells a freed block. `written_at` for a raw field: a raw word is read only after it was written (a `con` writes every raw field). That the captures of a function value are those its entry expects: each capture load and each later use has its own audit |
| Nothing runs between an audit and its access | The audit call is the instruction before the inline sequence in the same block (or the block the immediate test falls into); no safepoint, no other entry. `twin`'s skeleton test pins the order per pinned function |
| The body without checks is reached only after its audit | `eml_rt_dup_slow` and `eml_rt_decref_slow` are named only by `Step::slow()` (NC-G2), whose two users (`rc::counted` through `FnLower`, and `release_box`) pass the audit's `FuncRef` in checked lowering; `the_slow_count_entries_are_named_only_by_step_slow` and the twins of `inline_dup_and_decref` and `a_closure_entry_and_a_pap_adapter` |
| An immortal object between audit and body | The audit has done the whole operation and the heap's invariant holds (`audit_dup` / `audit_decref` ensure `wf()`); generated code does nothing at count 0 and the body entry is not called for it; if it were, `dup_step` / `release_step` return at once for count 0 in checked mode |
| The state between audit and body | `wf()` and `settled()` hold after every audit (Verus), so any entry may run next; the body requires only the audit's predicate, `wf()` and `settled()` |
| A store audit writes | `set_field` / `set_raw` write the same word the inline store writes next; both are stores into an object the checked operation has just accepted as unshared. The model step (`written`, the edges) is the checked operation's own, as in the VM |
| Fast code | Unchanged but for one callee name; `eml_rt_decref_slow::<Fast>` is `decref_body`, whose fast arm is `decref`, and `eml_rt_dup_slow::<Fast>` is `dup_body`, whose fast arm is `dup`. `dup_body` and `decref_body` carry no `#[inline]`; whether the extra call level costs anything in fast native code is what the native gate (`bench/native.sh`) and the `nrt_bench` rows of 10.1 check, and the remedy is `#[inline]` on the two functions under the `eml_rt` gate. `dup`, `decref` and every read or store operation have no changed executable line; `dup_slow` and `release_ref` are the same statements split over two `#[inline(always)]` functions (10.2 measures) |
| Generic `extern "C"` entries | The same bodies at two monomorphizations; a `shim` still catches unwinding and takes the fatal path; `Ctx<Checked>` and `Ctx<Fast>` share the `Native` prefix that the stubs and generated code read (asserted in `eml_rt`) |
| Code lowered for one mode run against the other mode's entries | Not reachable: one `NativeMachine` reads `debug_heap` once at `new` and uses it for the lowering, the registered entries and `run` (S-NC-7); `Loaded` is tied to its machine by the existing id check |
| The surface | `Engine::end` / `Engine::stats` are safe trait methods: they call only safe functions of `eml_rt` and the crate-private `census`, and `Engine` cannot be implemented outside `eml_nrt` for another type (`Mode` is sealed), so they rely on no fact about their arguments. `surface.rs`'s scanner does not count trait methods, so they get no entry there. The new `eml_rt` functions are `pub unsafe fn` with `# Safety`; no new `unsafe` file in `eml_nrt`; `CodeRow.code` is a `pub` field of raw-pointer type like `PapRow.code`, which `surface.rs` lists as `("eml_nrt/src/image.rs: PapRow::code", Address)` [V: read]; NC-3 adds `("eml_nrt/src/image.rs: CodeRow::code", Address)`, the stage's one edit of `surface.rs` |
| `Trusted`'s two constructors (NC-3b) | Both are `unsafe fn` with `# Safety` (P1, P6), so `Trusted` is a type whose only constructors establish its fact. `Trusted::new` runs the whole ownership-stage `verify` in every build and keeps the tables of that walk, so a `Trusted` made by it is verified and every function has the walk's table. `Trusted::unverified` gives a function the walk refuses `unwind::unowned`'s table: an empty entry row and, at every statement `unwind::point` names (the function the recorder uses), a row that releases nothing; releasing nothing is memory-safe, and what the frame held is a leak in checked mode. Each other violation the caller puts in must be one the engine and mode report before an operation relies on it (P6), as with the VM's old unverified load. No engine verifies or special-cases a refused function; `FnLower::point` finds a row at every point statement. Only tests call `unverified` (no mechanical check, as for `Trusted::new`'s rule D-4); `surface.rs` checks that both have `# Safety` |
| Checked mode is not a sandbox | Unchanged promise (docs/spec/lir.md 「エンジンの約束」): `word_in(w)` stays the caller's premise in both modes; the audits report the misuses the VM's checked mode reports |

## 10. Risks and unresolved items

### 10.1 The VM gate and the native gate

The VM gate (`bench/run.sh`, +0.5 %; the rule of U-3 of 2026-11-20 as carried by the last stages): B = NC-1's commit, H = the tip after NC-3, or after NC-3b if the gate has not been run by then (the stage's changes on a VM path are NC-2's, and NC-3b's move of the load-time verifier walk into `Trusted::new`, which changes no run path and no walk count on `eml run`; the REPL append, which walks more, is not measured by `bench/run.sh`). A row whose median over three alternating pairs of 実行の分 deltas is over +0.5 % is re-measured alone over 15 alternating rounds (`gate-rounds.sh`); it stops the stage only if its 15-round median stays over +0.5 % and the stage changed code on that row's path; otherwise the Close message records it as layout. Path rule for this stage: the changed functions are `Heap::dup_slow` and `Heap::release_ref` (now each two `#[inline(always)]` halves). `dup_slow` runs for every `dup` of an immortal, shared or stuck object in fast mode, and `release_ref` for every child released by a free chain and for every `decref` that does not take the inline path. Every row frees objects and reads constants, so every row of `bench/run.sh` is on the path: an OVER row that stays over after 15 rounds stops the stage and goes to the user with the table. `par_tree` and `pfib` are judged on the whole minus their own load (`run --load-only`), as 00 §D D-16 says.

The native gate (a record with a stop rule; fast native code changes only in the symbol of one cold call, 7.4 kind 2):
- `bench/native.sh` at B and at the tip after NC-5, three alternating pairs: for each row the delta of the native run part (instructions). Expected: within ±0.5 % on every row. A row over +0.5 % on the median of the three is re-measured over 15 alternating rounds; if it stays over, the stage stops for the user: fast lowering was meant not to change, so a real move means NC-G3 is broken somewhere the pins do not look.

## 12. Hooks for the profiler

Nothing in this stage touches what a sampling profiler needs: frame pointers (`abi.rs`), the frame chain (an audit is an ordinary call of a `shim` entry, so generated function → entry is walkable), name-keyed symbols, the calling conventions, `Native`'s fields (no field is added), the `Image` rows.

Pieces a profiler can reuse:
- `Entry.class` (H-4), with every entry classified and the test `every_entry_has_its_class`: a sample inside an entry is attributed to `Alloc`, `Free`, `RcSlow`, `Reuse`, `Row`, `Service` or `Audit` without a second table; `Audit` makes the cost of checked mode visible as its own class. A profiler's own entries would be one more variant (the test lists classes by rule, so a new variant is a deliberate edit).
- `eml_nrt::entries::<M>()`: symbol and address of every entry at the mode the machine runs, for symbolizing a PC outside generated code. The rows of the two modes differ only in `address`.
- `eml_rt_audit_count(ctx, which)` and `Worker.counts` are the four statement counters of `RunStats` and nothing more. They do not overlap the profiler's counters, which are per-function arrays behind data symbols; per-site counters do not belong in this stage.
- `lower/audit.rs` and `lower::Lowering`: the pattern "one module emits every extra call of a lowering option, and the option is a field of one struct"; a `profile` field and a sibling module follow it without touching the signatures of `lower::program` or the lowering modules again.
- `twin` (S-NC-13): the test that an instrumented lowering is the fast lowering plus calls of a named set of entries.
- `Engine::stats`: the one place a run's counters are gathered at its end.

What the profiler design asks of this stage, and where the plan states it:
- (i) `Class` is `#[repr(u8)]` with fixed discriminants and a `name()`, pinned by a test: S-NC-3, `the_classes_have_fixed_numbers_and_names` (NC-3).
- (ii) `lower/audit.rs` emits through the `FnLower`'s builder and has no cursor or builder of its own, so the audit calls fall under the statement's source location once statements have one: 7.2 NC-4's `audit.rs` bullet.
- (iii) `ir-origins` starts after this stage closes, and the twin pins stay byte-identical through it because the dump the pins read prints no source locations: S-NC-13.
- D-NC-9 is about heap objects only (5.1), so an inline increment of a per-function counter behind a data symbol needs no audit.

What stays open towards the profiler (not load-bearing here; O-11):
- Audit calls carry no source position in this stage. They get one with the statement they belong to when `ir-origins` gives statements their origins, because they are emitted through the statement's builder ((ii) above).
