## 1. Goal and success criteria

- Goal: every public engine function that takes a program takes `&eml_lir::Trusted`, whose only constructor is `unsafe fn Trusted::new` (promise P1); outside tests only `eml_cli::Session` makes one. The other caller-kept promises of the engines' safe functions (P2..P5 and the rest) are closed by a type, a cheap run-time check or an `unsafe` boundary. The runtime layers' safe `pub` items that reach undefined behaviour become `unsafe fn` or `pub(crate)` (UJ-18 F-1). No language feature is added.
- Success criteria:
  - S-1 (G-1): SC-4 finds no public function that takes `&Program` and loads or runs it; `eml_vm::execute`, `Machine::load`, `AnyMachine::load`, `CodeBase::load`, `eml_native::execute`, `NativeMachine::load`, `eml_cli::execute_on` take `&Trusted`.
  - S-2: `Trusted::new` is called only in the files of SC-1.
  - S-8 (D-RL-2, D-RL-3): the 49 `pub fn` of `eml_sched::cells` that take a `Ctx` are `pub unsafe fn` under one contract (「呼ぶ側の約束」 C1..C4); `eml_rt::RawBuf` has crate-private fields and is made only by `unsafe fn RawBuf::new`; `Registry::take_queued` is `pub(crate)`; `crates/eml_cli/tests/surface.rs` pins every safe `pub fn` and `pub` field outside `eml_rt` that names runtime memory (ET-G7).
  - S-3: P2 `unsafe fn extend` on both VM machines and `CodeBase`; `load` on a machine with code panics; P3 `Loaded` has private fields and a machine refuses a `Loaded` it did not return; P4 `unsafe fn run_shown`; P5 `unsafe fn Session::load_with_std`; R-3 `unsafe fn Machine::with_driver`. Each has a test or an `unsafe` signature (7.4 "New tests").
  - S-4: every row of 7.5 is closed; R-7 by ET-R1 and R-8 by ET-R2; `surface::` passes; docs/spec/lir.md 「エンジンの約束」 states the list and the guarantee of engine-trust.md 「保証」 for every crate but `eml_test_support`, with no exception (00 §D D-3, D-9).
  - S-5: every expected value is byte-identical (UI outputs, transcripts, snapshots, `RunStats`); the only test changes are kind 3 and the new tests of 7.4.
  - S-6: the 2026-11-11 group's plan files and appendix are gone, 00 §C still holds, and the roadmap reads as Appendix R says (ET-1).

### 5.2 Short-term decisions (this plan)

- `Trusted` is defined in a new module `crates/eml_lir/src/trusted.rs`, re-exported from `eml_lir`'s root as `eml_lir::Trusted`. Derives `Debug` and `Clone` (a clone of a trusted program keeps the promise). No `into_inner`.
- `Compiled<P>` stays generic; `Session::compile` and `compile_native` return `Compiled<Trusted>`; `compile_with` returns what its argument returns. `eml_test_support::lir` returns `Trusted`; `lir_until` returns `Program`.
- Test helpers that call `Trusted::new` (the tests' own promise, engine-trust.md 「テスト」): `crates/eml_vm/tests/common/mod.rs` (one `pub fn trust(program: Program) -> Trusted`, used by `parse`-based helpers and by `miri.rs`), one `#[cfg(test)] pub(crate) fn trusted(text: &str) -> Trusted` in `crates/eml_vm/src/lib.rs` for the unit tests of `vm.rs` and `workers.rs`, `crates/eml_native/tests/common/native.rs` (`program` returns `Trusted`; `pub fn trust(program: Program) -> Trusted` for `raise.rs:373`, which mutates a parsed program before loading, and `effects.rs:854`), `crates/eml_test_support/src/lib.rs` (only if a helper there receives a `Program`; default: none, since `lir` already returns `Trusted`).
- "A machine has code": the VM's `CodeBase` has at least one function of a loaded program (`CodeBase::new` gives an empty table, docs/spec/vm.md L35); ET-5 adds `CodeBase::is_empty` (or reads the index) and decides from it.
- `Loaded` carries the machine's identity: a `u64` from a per-crate `static NEXT: AtomicU64` taken in each machine constructor (`Machine::with_checks`, `NativeMachine::new`), plus the entry. `run` with a foreign `Loaded` returns the engine's internal `RuntimeError` with the text `a loaded entry of another machine`. The REPL keeps the `Loaded` it got.
- The REPL always appends with `unsafe { extend }` (also for its first input: extending an empty machine is the same as loading it); its `// SAFETY:` comment states P2 (every input comes from the same session's lowering) and P4 (`shown` is `Some` only for an expression input, whose wrapper returns the shown string).
- Three new tests for P2 / P3 where 01 §4 says "two" (00 §D D-8): the VM pair and a native `Loaded` test; native machines load once, so the "load on a machine with code" test is VM-only.

## Appendix R: the roadmap rewrite (English source for PLaMo; ET-1 step 3)

### R.1 「段の列」

Replace the list (L32-40 at the base) by the items below, in this order; keep the section's first paragraph. Each item keeps the house style ("前提: …。設計: …"). Links point at `docs/future` or `docs/spec`, never at `docs/plans`.

1. `engine-trust`: the current text (L34) with "前提: `jit-repl`" → "前提: なし", and the guarantee widened: "No safe function of a crate outside the tests reaches undefined behaviour: besides the engine entries, the runtime layers' safe public functions that would reach it become `unsafe` or crate-private."
2. `async-root`: "Make `main` the root task and remove `Async.run`, `run_raw` and `run_result`. A `main` whose row has `Async` runs as the root task of the run: translate gives it a root entry that runs `main` under `Std.Async.bottom`, and the run ends when the root task has finished and the root scope is empty. A `main` without `Async` runs as today. An uncaught `IO` failure or `Panic` of the root task gives the runtime error a synchronous `main` gives, naming `main`. Every task starts with the whole depth. The REPL runs an input whose row has `Async` as the root task of that input's run. Every program, test and document that calls `Async.run` is rewritten. Prerequisite: none. Design: [非同期の設計](async.md)'s decision 2, [マルチコア対応の設計](multicore.md) 「`Async.run` と入れ子」."
3. `par-total`: "Make the children of `par` and `compute` total. `par` becomes std code over a std-private extern `fork_join` whose children have the empty row: each child is wrapped in `try_panic`, and a `Panic` of either child is raised again after both have run. A runtime error in a child ends the run, and children run at the limit class `Stops`. Fork evidence, `child_abort` and the re-raise of aborts leave Core IR, LIR, the VM, `eml_rt` and native code, and user `never` effects no longer cross `par` or `compute`. Prerequisite: none. Design: [マルチコア対応の設計](multicore.md) 「`par` の意味」."
4. `task-limits`: "Give memory one limit, `max_bytes`, which ends the run. The soft memory limit, the monitor's pressure role, the per-task byte counts and the limit classes `Pending` and `Aborting { pending }` go; the limit classes are `Stops`, `Task` and `Aborting`; the depth limit of a task stays a `ResourceLimit` the task can catch. Prerequisite: `async-root`, `par-total`. Design: [VM](../spec/vm.md) 「タスクの上限」."
5. `std-par`: "Add the data-parallel functions of `std/Par` (`for_range`, `reduce_range` and their `_grain` forms, `tabulate`, `map`, `mapi`, `reduce`, `for_mut`, `try_map`, `tabulate_unboxed`, `for_mut_unboxed`), written in eml over `par`. A range is cut into chunks of 1024 elements and the chunks into groups of about the square root of their number, so the shape depends only on the length and the grain, and `reduce` combines in that shape's order. Results are stitched by the pure rows `Array.concat` and `UnboxedArray.concat`; no runtime entry forks over a range and no block is written by two threads. Prerequisite: `par-total`. Design: [マルチコア対応の設計](multicore.md) 「データ並列での使い勝手」."
6. `native-checked`: "Give native code the checked mode and `--stats` on the programs it accepts. Checked lowering emits the same inline sequence as fast lowering, preceded by one audit entry for the operation; each audit is verified in `eml_rt`, so a passing audit implies the safety premise of the access. The runtime entries are generic over the mode, with a fast and a checked table, and a shipped app links no checked symbol. `eml run --native --debug-heap` and `--native --stats` work, and the UI tests compare every checked native run with the checked VM: the error class and every field of `RunStats` but `peak_stack`. Prerequisite: `engine-trust`. Design: [ネイティブ化の設計](native.md) 「中断と実行時エラー」, [オブジェクトモデル](../spec/object-model.md) 「検査モード」."
7. `sched-core`: "Write the scheduler of native code in `eml_sched`, complete and tested without an engine: per-worker open job lists, the worker loop, idle and wake-up, the deadlock verdict, I/O hosting, the clock, signals, limits, the monitor, the pool, the main worker's loop, recovery and the `Std.Atomic` counter table. The decisions (the open list, the loop's step choice, the limit table, the idle protocol, the verdict) are step functions in a new crate `eml_steps`, all inside `verus!` with no `unsafe`, with an exhaustive explorer over them in the tests. The VM keeps its own scheduler unchanged; the new one runs in tests through a closure-driven `Exec`. Prerequisite: `async-root`, `par-total`, `task-limits`. Design: [マルチコア対応の設計](multicore.md) 「層の構成」."
8. `jit-tasks`: "Run the task layer natively on the scheduler of `sched-core`: the task rows, `par` (the join runs its own job in the parent's frames, or blocks until the worker that took it sends the value), `compute`, blocking C calls, task limits at the safepoint, the main worker and its `Park`, workers 1..N-1, signals and the fatal path. Native code accepts every program; the E0004 refusals of native code and `eml_native::unsupported` go, and `--workers`, `--gui`, `--debug-heap` and `--stats` are accepted with `--native`. Native code switches no stack and has no asm but the entry stubs. Until `eml_vm` is deleted, [ネイティブの実行系](../spec/native.md) 「VMとの違い」 has two items: the depth limit is the thread's stack, and the schedule differs. Prerequisite: `async-root`, `std-par`, `native-checked`, `sched-core`. Design: [ネイティブ化の設計](native.md) 「並列の実行」."

10. `vm-retire`: "Delete `eml_vm` and merge `eml_rows` into `eml_nrt`, after a recorded precondition run: every UI file, seed and worker count passes on checked and fast native code, every checked-mode negative test fires natively, the transcripts, Miri through the scheduler's test `Exec`, both sanitizers, the four CI targets and the census pass.
