## 1. Goal and completion conditions

- Goal: native code is the only engine; `eml_vm` is deleted; `eml_rows` is merged into `eml_nrt` by the file map of 01 §13.3; every document describes one engine.
- Completion conditions:
  - G-20: D-VR-1's precondition run is recorded in the executable plan before the deletion; every file of `crates/eml_vm/tests` has the fate of 01 §11.10 or a listed change of it.
  - G-21: the crate graph is 01 §13.1; `nix/crate-graph.sh --check` passes with the rewritten EDGES, FEATURES and REEXPORTS tables; `grep -rn 'eml_fatal' crates/eml_sched/src` and `grep -rn 'extern "C" fn\|asm!' crates/eml_sched/src` → both empty (a pattern of `extern "C"` alone matches the comment at `cells.rs:3`); the closure checks use `eml_nrt/tls`, `eml_nrt/gui-native`; the three `eml_vm` checks are gone.
  - D-VR-5: `Finished` has no `preemptions`, `placed`, `placed_jobs`; `rows::call`, `SHARED`, `GateHost`, `eml_sched`'s feature `testing` and the `cells.rs` helpers behind it are deleted; one list `rows!`; `eml_nrt/src/constants.rs` and `rows/values.rs` merged.
  - D-VR-4: `max_depth` (words) is replaced by `Options.stack` (bytes); every `-- max-depth:` mark becomes `-- stack:` (8 files carry the mark at 4a2954c1 [V: `grep -rln 'max-depth' tests crates/eml_cli/tests/repl`]; 01 D-VR-4 says 29, so VR-1 recounts).
  - D-VR-3: `eml run` and `eml repl` run native code, the only engine; `ui::run` runs each file checked native then fast native; `ui::*_native`, parity, `native: skip`, `Engine`, `--native` go (there is no `--vm`: 00 UJ-20 (1)); seed runs for `async/` only.
  - VR-1 lists the vm.md sections runtime.md cites or lacks; VR-7 moves those and deletes the rest (00 UJ-19 (7)); native.md loses 「VMとの違い」.
  - D-ET-2: the promise list of docs/spec/lir.md 「エンジンの約束」 names the native entries only (A-38), re-read together with `surface.rs`'s `SAFE`.
  - G-24: `surface::` passes at every commit; after VR-6 every remaining `pub` item of `crates/eml_sched/src/cells.rs` is named in `crates/eml_nrt/src` (for each: `grep -rn '<name>' crates/eml_nrt/src` non-empty), the rest are `pub(crate)` (D-VR-5a).

- In: D-VR-1..D-VR-6; the test deletions of D-VR-2 (01 §11.10 as K2 restates it); the CLI and harness; the crate merge; docs, CLAUDE.md and crates/eml_rt/CLAUDE.md per 01 §13.4; `bench/run.sh` on native code.

## 4. Decisions (01 §12.2)

- D-VR-1: the precondition, run at VR-1 and recorded: (a) every UI file, seed and worker count passes checked native and fast native, with 01 §11.7's files listed with their native expectations; (b) every checked-mode negative test fires natively with the VM's error class; (c) the transcripts pass natively; (d) the Miri suite through `Script` names every row section and every `drive` path; (e) ASan and TSan lines green on native tests; (f) the four CI targets pass; (g) the fast-mode census passes on every `run` file at 1, 2 and 8 workers; (h) every CLIF pin of an inline sequence has its checked twin; (i) the hand-written LIR programs of `crates/eml_lir/tests` and `crates/eml_vm/tests/miri.rs` run natively checked; (j) every test restated in `jit-tasks` and `jit-repl` passes natively. If one item fails the stage does not start.
- D-VR-2: tests: delete the VM's files whose tests were restated (kind 3 with their restatements, each row naming the native file; the tests never restated listed one by one, kind 1); 01 §11.10's fates stand for `bench.rs`, `scaling.rs`, `miri.rs` and the bytecode files; the fixtures of `eml_vm/src/hosts.rs` move to `eml_test_support`; the `agree*` helpers of `crates/eml_native/tests/common/native.rs` (104 calls at the reorder's base; 00 §D D-21 (d)) compare checked with fast native code (kind 2, listed by VR-1); `bench.rs`'s snapshots re-pinned on checked native runs (kind 2).
- D-VR-3 (amended by 00 UJ-20 (1)): VR-3 makes native code the only engine in one step: `eml run` and `eml repl` without flags run native code and `--native` goes; no period has native code as the default with the VM as a fallback, and D-VR-1's precondition run is what stands for it. The harness as in section 1. The VM's seed runs end with the crate. The harness rule "every `run/par/` and `run/async/` file is preempted under each seed" (`Finished.preemptions > 0`) goes with `preemptions` (D-VR-5); what replaces it is the corpus count of `reorders` and the self-test of 00 §D D-15 (d). The `spin` helpers of the UI files stay as they are: they change no output, and removing them is not this stage's work.
- D-VR-4: depth as a stack size; a test may depend on the class of a depth error, never on the depth reached.
- D-VR-5: the deletions and merges as in section 1. The four `Std.Atomic` rows leave the task group: in `rows!` `AtomicNew` is an ordinary called row and the other three keep `Lowering::Atomic` and their entries (00 §D D-15); `Extern::is_async` no longer lists them (or goes with the VM's instruction it served); `std/Atomic.em` drops `import Async` and the comment that gives its reason.
- D-VR-5a: `surface.rs`'s `SAFE` follows the `eml_rows` move; `cells.rs` is narrowed to what `eml_nrt` names (architecture.md 「公開の面と`unsafe`」 step 3); `test_ctx` and `stream_on` go with the `testing` feature. The 62 `unsafe` call sites of the `cells` functions in `eml_vm` go with the crate.
- D-VR-6: docs: VR-1 lists the vm.md sections runtime.md cites or lacks; VR-7 moves those and deletes the rest, the VM's own scheduler (placement by inbox, preemption) and its instruction and frame sections among the deleted (00 UJ-19 (7)); native.md, multicore.md, architecture.md, testing.md, CLAUDE.md, crates/eml_rt/CLAUDE.md, benchmarks.md follow.
- Stated losses (written in the Close message and status.md): a second implementation; whole-run Miri (15 small runs); a deterministic word-count depth; an engine on a host that forbids executable memory; targets without a Cranelift backend; after VR-4 no program that ends in a fatal error runs under ASan (the native ASan lines skip `fatal::`: longjmp leaves ASan's stack marks).
