# T-8 の macOS の run (書きの重みの単位)

D-14 と付録 A4 Q4 の手順で、利用者の Mac で 58793d4 の 256、512、1024 を比べた。macOS では 1024 が判定 (a)(b)(c) をすべて満たし、256 は (a) と (b) を満たさない。1024 は Linux の run (ba32603) で2つ目の条件を破るので、単位は 512 のままである。表と判定は benchmarks.md の「書きの重みの単位」にも書いた。

- 機械: Apple M5、10 コア、メモリ 32 GiB、macOS 27.0.1 (26A434)。始めたときの load average は 2.29
- 生の JSONL: `wu-macos-256.jsonl`、`wu-macos-1024.jsonl` (`report.py` にそのまま渡せる)

## 手順から外れた点

`many-self-1000` だけを、時間の run 4 回、4 回、3 回 (`--stats` 付き) の3つに分けて流し、件の JSONL の `data` をつないだ。ほかの件は A4 Q4 のコマンドのまま1回で流した。

分けたのは、macOS の ephemeral port が尽きたためである。macOS には Linux の `tcp_tw_reuse` に当たる、loopback の接続で TIME_WAIT の port を使い直す仕組みがない。範囲は 49152〜65535 の 16384 個で、MSL は 15 s なので、TIME_WAIT は約 30 s 残る。1回で 1000 本張る run を 2 つのラベルで 11 回ずつ続けると、十数回目の `connect` が `EADDRNOTAVAIL` (os error 49) で落ちた。このとき TIME_WAIT は 16211 本あった。分けた run の間では、TIME_WAIT が 500 本以下になるまで待った。それぞれの run の中では2つのラベルを交互に流すので、比べの条件は変わらない。

## 512 → 256

| 件 | 512 (µs) | 256 (µs) | 比 | 判定 | 実時間の比 |
|---|---|---|---|---|---|
| echo-self-fresh | 13.91 | 14.04 | 1.01 | 差なし | 1.01 |
| echo-self-reuse | 15.02 | 14.98 | 1.00 | 差なし | 1.00 |
| bulk-self | 203.06 | 203.34 | 1.00 | 差なし | 1.00 |
| bulk-shared | 197.52 | 195.79 | 0.99 | 差なし | 0.99 |
| bulk-reuse | 202.56 | 201.47 | 0.99 | 差なし | 1.00 |
| bulk-1k | 1214.89 | 1357.45 | 1.12 | 差 (256 に不利) | 1.11 |
| bulk-send-py | 129.54 | 125.53 | 0.97 | 差なし | 0.97 |
| bulk-recv-py | 98.23 | 98.62 | 1.00 | 差なし | 1.00 |
| many-self-1000 | 39.06 | 39.06 | 1.00 | 差なし | 0.99 |

値は CPU (user+sys) の中央値から床を引いた単位あたりの値。

- (a) 不成立: bulk-self、bulk-shared、bulk-reuse、bulk-1k のどれにも 256 の側の「差」がない。
- (b) 不成立: bulk-1k で 256 に不利な「差」がある。比は 1.12 で、四分位は重ならない。minflt/単位は 1.42 と 1.27 で、違いが 1 未満なので「確保の揺れ」ではない。
- (c) 成立: 単位あたりの sys の比は bulk-self 1.00、bulk-shared 0.99、bulk-reuse 0.99。実時間の比は echo-self-fresh 1.01、echo-self-reuse 1.00。

## 512 → 1024

| 件 | 512 (µs) | 1024 (µs) | 比 | 判定 | 実時間の比 |
|---|---|---|---|---|---|
| echo-self-fresh | 13.85 | 13.90 | 1.00 | 差なし | 1.00 |
| echo-self-reuse | 14.97 | 14.94 | 1.00 | 差なし | 1.00 |
| bulk-self | 200.56 | 204.66 | 1.02 | 差なし | 1.02 |
| bulk-shared | 196.03 | 174.99 | 0.89 | 差 (1024 に有利) | 0.86 |
| bulk-reuse | 201.91 | 202.56 | 1.00 | 差なし | 1.00 |
| bulk-1k | 1226.45 | 1220.84 | 1.00 | 差なし | 1.00 |
| bulk-send-py | 127.39 | 126.83 | 1.00 | 差なし | 1.00 |
| bulk-recv-py | 97.45 | 97.76 | 1.00 | 差なし | 1.00 |
| many-self-1000 | 38.27 | 37.57 | 0.98 | 差なし | 0.99 |

- (a) 成立: bulk-shared で 1024 の側に「差」がある。比は 0.89 で、四分位は重ならない。minflt/単位は 0.09 と 0.08 で、「確保の揺れ」ではない。
- (b) 成立: 1024 に不利な「差」はない。bulk-self の比 1.02 は四分位が重ならないが、0.90〜1.10 の中なので「差なし」。
- (c) 成立: 単位あたりの sys は bulk-self 137.48 → 146.12 (1.06)、bulk-shared 160.82 → 146.46 (0.91)、bulk-reuse 140.96 → 147.29 (1.04)。実時間の比は echo-self-fresh 1.00、echo-self-reuse 1.00。

bulk-shared の非自発の切り替え (中央値) は、512 で 6330 回、1024 で 114 回だった。256 との run の 512 でも 5849 回あった。原因は調べていない。Q-10 (`EVFILT_WRITE` が ACK ごとに起こしうる) との関係も確かめていない。
