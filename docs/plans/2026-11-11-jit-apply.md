- 完了の条件: 7のA0〜A6をそれぞれ1コミットで入れ、各作業の完了の条件と9の全体の検証が、すべて期待どおりになること。特に次のとおりである

  - `tests/ui/run`のファイルのうち185以上がネイティブで動き、出力がVMと同じであること。正確な数はスナップショットが固定する (受け入れは208の見込み)
  - `apply::`のテスト12 (`apply`の道ごとにcensusで確かめる。最後の使用で解放されるクロージャ、そうでなければdupする捕捉、部分適用、部分適用の部分適用、引数が余る適用、引数が余る適用の中の中断) と固定`clif::an_apply_site`が通ること

## 5. 決定

### 5.1 長期の方針 (変えるには見直しが要る)

実装がこの節と食い違ったら、止めて報告する。全文は付録の`01-contract.md`と`00-decisions.md`にある。

#### D-1: ネイティブの関数の値の形
- 決定: ネイティブの関数の値は常に物体で、そのヘッダが記述子である。タグはまだ足りない引数の葉の数、`scan`する語の0番はエントリのコードのアドレスの即値、その後に捕捉が続く。`Atom::Fn(f)`は、読み込みのときに作る不死の静的なクロージャである。数がちょうどの`apply`は、ロード2つ、比較、`call_indirect`である。アダプタは、プログラムに出てくる`(f, k)`の分だけ作る。部分適用は汎用のPAPの物体 (`eml$pap$m$r`) を作るので、`k`ごとのアダプタも記述子のロードも要らない。`eml_rt`と`eml_sched`は関数の値を読み解かない。object-model.mdの即値の関数の番号はVMの形である (`01-contract.md`の1.3節、6.2節のU5、6.1節のC12とC13)
- 理由: ヘッダを記述子にすると、`apply`の速い道は依存するロード2つで済み、関数の表が要らない。汎用のPAPで、実行系の手続きは小さく保てる
- 及ぶ範囲: `eml_native/src/lower/apply.rs`、`mem.rs`、`eml_nrt/src/{constants,closures}.rs`
- 見直す条件: eml_rtの手続きがクロージャのタグを読む必要が出たとき (今はない)
- 適合の確かめ: A1の`entries::a_static_closure_is_immortal_with_its_arity_tag`。A2の`apply`のテスト。`grep -rn '\.tag()' crates/eml_rt/src | grep -v /tests/`に、3で分けた種類の読み手しか出ないこと (読んで確かめる。新しい読み手はD-1に照らす)
- リポジトリに残す所: `docs/spec/object-model.md`の「クロージャ」と`docs/spec/native.md`の「関数の値」(A1、A2、A4、A5)

#### D-2: 出すコードの形
- 決定: jit-coreと同じである。`tail`の規約。末尾の位置では`return_call`か`return_call_indirect`。アダプタと補助の関数の直接の呼び出しは、`Linkage::Local`の関数への`call`か`return_call`。`call_indirect`は呼ぶ先が実行時の値のときだけ (`apply`の所、`eml$apply$m`、`eml$pap$m$r`、thunk)。アダプタと補助の関数`eml$apply`、`eml$pap`は安全点のないトランポリンで、安全点のある関数への末尾呼び出しで終わる。シンボルの名前は名前と形だけで決まる (`c<k>:<f>`、`v:<f>`、`eml$apply$<m>`、`eml$pap$<m>$<r>`)。プログラムのほかの部分で変わる数はコードに入れない
- 理由: この段が足す関数でも、N-13、N-16、N-17、N-36、N-37を保つ
- 及ぶ範囲: `lower/apply.rs`、`lower/consts.rs`
- 見直す条件: native-aot
- 適合の確かめ: 7のG-grep (`call_indirect`に`crates/eml_native/src/lower/apply.rs`が加わる)。`machine::symbols_cover_every_function`がアダプタと補助の関数も含めること。固定`clif::an_apply_site`

### 5.2 短中期の設計

細部は付録03の§1.2にある (そこでのD-19〜D-24を、この計画ではD-10〜D-15と呼ぶ。下の括弧に元の番号を書く)。

- D-10 (付録03のD-19): クロージャの中身。ヘッダのタグは`n`で、まだ足りない引数の葉の数 (1..=65535)。`scan`する語の0番はエントリのコードのポインタの即値 (`mem::make_imm(func_addr)`)。その後に、関数の引数の順で、RCの捕捉 (`scan`する) とほかの捕捉 (生の語) が続く。形は`LayoutCtor { fields: [TObj] ++ 捕捉のRepr }`のものである。`lin`は束ねる変数の印から取る。`Atom::Fn(f)`は、読み込みのときに凍った領域に作る静的なクロージャ`{ tag = params(f), [c0:<f>のコード] }`の語である (`Datum::Fn(f)`、データのシンボル`v:<関数の名前>`、`DATUM_FN = 3`。`DatumRow`に`code: *const u8`を足す)。`mem::data_word`で読む。`FnRow`に`value: *mut u64` (関数の静的なクロージャのslot。なければnull) を足す。`eml_nrt`はコードの語を書くときに`Word::int(code as i64).is_some()`をassertする。退けた案は付録03のD-19にある
- D-11 (付録03のD-20): 出てくる`(f, k)`ごとに、アダプタ`c<k>:<f>`はシグネチャ`tail (ctx, clo, params(f)[k..]) -> rets(f)`を持つ。`k >= 1`なら、捕捉をReprごとにロードし、最後の参照なら`eml_rt_free_block(ctx, clo)`、そうでなければRCの捕捉をインラインで`dup`し、`clo`をインラインで`decref`する。その後`return_call f:<f>(ctx, caps.., args..)`。`k = 0`なら`return_call f:<f>(ctx, args..)`。`clause.is_none()`の関数では、下ろしは`params[k..]`がすべて一様 (`obj`、`tobj`、`unit`) で`rets`が一様な葉1つであることをassertするので、シグネチャは`uniform(n)` = `(ctx, I64, n x I64) -> I64`になる。違反はシグネチャの食い違いでなく、コンパイル時のpanicになる
- D-12 (付録03のD-21): `m = args.len() >= 1`の`Call::Apply { callee, args }`では、`n = mem::load_tag(callee)`とし、`n == m`なら`call_indirect uniform(m) mem::closure_code(callee)(ctx, callee, args..)`、そうでなければ`call eml$apply$m(ctx, callee, args..)`。その後`after_unwind_point(point, After::Call)` (末尾の位置では`return_call_indirect`か`return_call eml$apply$m`)。`eml$apply$m`は`1..=max(1, プログラムで最大のm)`のすべての`m`について出し、腕は3つである。`n == m`は末尾の間接呼び出し。`n > m`は`eml_nrt_pap(ctx, callee, mem::spill([a_1..a_m]), m)`。`n < m`は`n`の`Switch`で、最初の`n`個の引数で呼び、結果を`After::Call`で確かめ (中断なら`a_{n+1}..a_m`をそれぞれ1回捨てる)、結果と残りで`eml$apply$(m-n)`を末尾で呼ぶ。既定は`trap`
- D-13 (付録03のD-22): `eml_nrt_pap(ctx, callee, argv, m) -> word`。`n = tag(callee)`、`r = n - m`とし、`r <= 0`か`(m, r)`のアダプタがなければ`Internal("applying a value that is not a function")`でfatalにする。そうでなければ`{ tag = r, scanned: [eml$pap$m$rのコード, callee, a_1..a_m], lin = calleeのlin }`を割り当てる。`eml$pap$m$r`は`tail (ctx, pap, b_1..b_r) -> I64`で、`callee`と`a_1..a_m`をロードし、最後の参照なら`free_block(pap)`、そうでなければそれぞれを`dup`して`decref(pap)`し、`return_call_indirect code(callee)(ctx, callee, a.., b..)`する。`m in 1..A`、`r in 1..=A-m`について出す。`A`はプログラムのクロージャを作る所で最大の`n`である。`Image.paps: Slice<PapRow { args: u32, rest: u32, code: *const u8 }>`。アダプタは`A(A-1)/2`で、上限は置かない
- D-14 (付録03のD-23): `Closure`、`FnValue`、`Apply`は`Form`から抜ける (変種は8になる)。新しいエントリは`eml_nrt_pap` (`shim`、`closures.rs`の表`CLOSURES`)
- D-15 (付録03のD-24): テストは`apply::a_closure_is_freed_on_its_last_use`、`a_shared_closure_dups_its_captures`、`a_static_function_value_takes_no_rc`、`raw_captures_keep_their_bits`、`a_closure_with_255_captures`、`a_tail_apply_runs_in_constant_stack`、`an_apply_result_is_checked_for_an_abort`、`a_partial_application_waits_for_the_rest` (1回と2回呼ぶ)、`a_partial_application_of_a_partial_application`、`an_excess_application_applies_the_result`、`an_abort_inside_an_excess_application_drops_the_rest`、`a_lin_closure_stays_lin_through_a_partial_application`。固定`clif::an_apply_site`
- この段が敷く道の費用の模型 (速い道。「ロード」はメモリからのロード):

| 構文 | 速い道 | 払わないもの | 後に回すもの |
|---|---|---|---|
| 数がちょうどの`apply` | ロード2つ (meta、コードの語)、マスク、比較、シフト、`call_indirect` (と巻き戻しの確かめ) | 関数の表、記述子のロード、数の受け渡し | - |
| クロージャのエントリ`c<k>` | ロード`k`、rcのロードと比較。唯一の参照なら呼び出し1つ (`free_block`)。共有ならインラインの`dup`と`decref`。その後関数へ飛ぶ | 静的なクロージャ (`k = 0`) は飛ぶだけ | インラインの解放: native-inline |
| 部分適用 | 直接の呼び出し1つ (`eml$apply$m`) と呼び出し1つ (`eml_nrt_pap`: 割り当て1つ)。PAPを呼ぶと、ロード`m + 1`、rcは上と同じ、数がちょうどの呼び出しより間接の飛び越しが1つ多い | 記述子の検索 | - |

  見送るもの (きれいな設計を先にする): VMの`imm(f | k << 32)`と関数の表 (`apply`ごとに依存するロードが3つ)。引数の数とコードを1つの即値に詰めること (アドレスの幅に依存する)。`n`のためのヘッダの2つ目の語 (クロージャごとに8バイト)。静的な記述子を指す即値の関数の値 (呼び出しの所ごとに2回の読み解き)。部分適用のための`(f, k)`ごとのアダプタ。どの選択もVMに触らない
