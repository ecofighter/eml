## 1. Goal and completion conditions

- Goal: the REPL's machine is a `NativeMachine` on a session thread that appends code by name; session roots, recovery after a fatal error, `Async` inputs as root tasks and `--debug-heap` work natively; at the Close `eml repl --native` runs the REPL on native code as `eml run --native` runs a program, and the VM stays the default engine of both until `vm-retire` (00 UJ-20 (1)).
- Completion conditions:
  - Every REPL transcript passes on both engines; the tests of `crates/eml_vm/tests/machine.rs` are restated natively (K2, 00 UJ-19 (5); the tests that are not restated, listed).
  - `NativeMachine::extend` exists as an `unsafe fn` with the promise P2 of docs/spec/lir.md 「エンジンの約束」 (the shape `engine-trust` gave the VM), with the debug-build comparison of appended code.
  - Recovery is session-side: the scheduler's state lives for one run (00 §D D-22), so after a failed run the session quiesces or drops its driver, calls `Ctx::recover` on the session heap and takes a fresh `Owners` handle from the surviving heap (R4); `children` is empty because the `Worker` is rebuilt per run.
  - At the Close: `eml run` and `eml repl` without flags run the VM; `--native` selects native code in both; the UI harness's default engine is unchanged.
  - D-ET-2: the promise list re-checked against the native REPL path.

## 4. Decisions (01 §12.1)

- D-JR-1: the REPL's machine lives on a session thread; code is appended by name under "same name, same code"; session roots and the debug-build comparison are kept.
- D-JR-2: recovery after a fatal error is written in `eml_nrt` (session-side, JR-4); `eml_sched` has no reset and no `recover.rs`; `c_links` and `renumbered` are written in `eml_nrt/src/rows/blocking.rs`.
- D-JR-3: an `Async` input runs as the root task of its run; one worker, merged seat.
- D-JR-4: `eml repl --debug-heap` runs checked native code.
- D-JR-5 (amended by 00 UJ-20 (1)): the VM stays the default engine of `eml run` and `eml repl` until `vm-retire`; `--native` selects native code in both; there is no `--vm`.
