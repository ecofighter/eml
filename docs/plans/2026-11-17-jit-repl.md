## 1. Goal and completion conditions

- Goal: the REPL's machine is a `NativeMachine` on a session thread that appends code by name; session roots, recovery after a fatal error, `Async` inputs as root tasks and `--debug-heap` work natively; at the Close `eml run` and `eml repl` use native code by default and `--vm` selects the VM.
- Completion conditions:
  - Every REPL transcript passes on both engines before the default flips; `crates/eml_vm/tests/machine.rs` runs on both engines (its VM-only tests listed).
  - `NativeMachine::extend` exists as an `unsafe fn` with the promise P2 of docs/spec/lir.md 「エンジンの約束」 (the shape `engine-trust` gave the VM), with the debug-build comparison of appended code.
  - Recovery is `eml_sched::recover`; the reset empties `children` and the worker's `open`.
  - At the Close: `eml run` and `eml repl` without flags run native code; `--vm` selects the VM; `--native` is accepted and ignored; the UI harness's default engine follows.
  - D-ET-2: the promise list re-checked against the native REPL path.

## 2. Scope

- In: D-JR-1..D-JR-5; `c_links` and `renumbered` written in `eml_nrt/src/rows/blocking.rs`; the CLI default switch.
- Out: the REPL on several workers (roadmap item); `:stats` (roadmap item); deleting the VM (`vm-retire`).

- `engine-trust`: the P2 / P3 / P4 shapes (`extend`, `Loaded` with identity, `unsafe fn run_shown`).

## 4. Decisions (01 §12.1)

- D-JR-1: the REPL's machine lives on a session thread; code is appended by name under "same name, same code"; session roots and the debug-build comparison are kept.
- D-JR-2: recovery after a fatal error is `eml_sched::recover`; the reset also empties `children` and the worker's `open`; `c_links` and `renumbered` are written in `eml_nrt/src/rows/blocking.rs`.
- D-JR-3: an `Async` input runs as the root task of its run; one worker, merged seat.
- D-JR-4: `eml repl --debug-heap` runs checked native code.
- D-JR-5: at Close `eml run` and `eml repl` use native code; `--vm` selects the VM until `vm-retire`; `--native` is accepted and ignored until then.

## 6. Test changes by kind (scope)

- Kind 1: CLI tests that expect `eml run` / `eml repl` without flags to be the VM, or `--native` to change the engine (JR-1 lists them); VM-only tests of `machine.rs` (not a change; listed).
- Kind 2: transcripts whose text depends on the engine (none expected; a difference is a fix, not a re-pin, while both engines run them).
- Kind 3: `machine.rs` on both engines with byte-identical expectations.
- A kind 1 or kind 2 change found during execution that the executable plan does not list stops the unit for a plan amendment approved by the user.

| Item | Default |
|---|---|
| A transcript differs between engines | a `Fix native <topic>` commit with a regression test before the switch; no skip mark |
