## 3. 背景

- Linux の `sys::Os` は cfg だけで `Unix<Epoll>` に決まる。実行時に backend を選ぶ道も、環境変数もない (`crates/eml_io/src/sys/mod.rs:18-25`、`crates/eml_io/src/real.rs`)
- `Backend` の trait は完了型の値 (`Hold::Memory`、`Cancel::Pending`、`Arrival::Done`/`Cancelled`) をすでに持つが、Windows とテストのほかでは使わない (`crates/eml_io/src/driver/backend.rs`)。核は `Hold::Memory` を `Driver::drop` でだけ読み、取り消しを出してから 1 秒まで完了を読み、終わらなければ abort する
- `libc` 0.2.191 は `SYS_io_uring_setup/enter/register` の番号だけを持ち、`IORING_*` の定数と構造体はない
- `trust.rs` は、ファイルの一覧、`unsafe` を許すファイル、`abort` などを名指してよいファイル (`COMPLETION_BACKENDS`、今は `sys/iocp.rs` だけ) を固めている
- `crates/eml_io/tests/real.rs` の 50 件を含め、本物の driver のテストは backend で分けて流す仕組みを持たない。`.config/nextest.toml` の profile は `default` と `timing` だけである
- `bench/net/bench.py` はラベルごとの環境変数を渡せない。計測の機械は、`docs/implementation/benchmarks.md` の「ネットワークの計測」の数字と同じ型 (Xeon 2.10GHz、4 vCPU、kernel 6.18.44-fc-v185) で、この container では io_uring が使える (`/proc/sys/kernel/io_uring_disabled` が 0)
- `docs/future/async.md:243` は「io_uring は使わない」と書き、`docs/future/roadmap.md:31` がこの段の項目である
- 設計の検討では、2つの事実の調査、3つの設計 (試作の backend、計測と門、続ける道)、長く効く方針の設計、それぞれの敵対的な査読と改訂、方針への適合の確認を2回行った。最終の設計は付録のディレクトリ `docs/plans/2026-10-31-io-uring/` にある (英語)
  - `01-policy.md`: 長く効く方針と適合の基準 G-1〜G-11

## 5. 決定

### 5.1 長く効く方針 (変えるには検討し直す)

実装がこれとぶつかったら、止めて報告する。適合の基準の全文 (理由、範囲、確かめ方) は `01-policy.md` の §8 にあり、G-5 と G-11 は `05-rulings.md` の B の改訂が勝つ。

#### D-1: epoll は Linux の基準の backend のままにし、io_uring は既定になる形でだけ入れる
- 決定: io_uring は「Linux の既定で、作れなければ epoll」の形でだけリポジトリに置く。opt-in だけの backend にも、唯一の backend にもしない。大きな後退は直すか捨てるかで、epoll を既定にして io_uring を残す道はない (ユーザーが認めた)。epoll は syscall の目標、テストの driver との揃い、fallback の基準であり、legacy とは書かない
- 理由: 既定で流れない unsafe の backend は負債で、io_uring を拒む環境 (Docker 25 以降の seccomp、gVisor、`io_uring_disabled`) は多い
- 退けた案: io_uring を後の段が頼る主の backend にする — 貸した buffer を1つだけ渡す契約の下では利点が待ちの syscall に限られる
- 範囲: 選び方のコード、docs、CI
- 見直す条件: buffer の契約を変えるとき
- 適合の確かめ: G-1、G-2
- リポジトリに残す所: 続ける道では `docs/spec/vm.md` の「時計と driver」(T-9)、`docs/future/async.md:243` (T-12)。捨てる道では `docs/future/roadmap.md` の「その後の項目」(T-D2)

#### D-2: 試作は混ぜた形で、これが長く続く形である
- 決定: 各歩は epoll と同じ同期の試みを先に出し (direct の腕は `ready` の印が偽のときだけ省く)、塞がれたときだけ SQE を出す。multishot、provided buffer、zero-copy send は使わない。起こしの `POLL_ADD` は one-shot
- 理由: vm.md の「データのある `Read` は受け付けの1回の `recv` で終わる」を保ち、カーネルが書くのは貸した1つの物体だけにする
- 退けた案: すべてを完了で出す形 (即時の道が park と再開になる)、POLL_ADD で readiness を取る腕 (再試行の syscall が残る)
- 見直す条件: buffer の契約を変えるとき
- 適合の確かめ: G-3
- リポジトリに残す所: 続ける道では vm.md (T-7)

#### D-3: 束縛は `libc::syscall` の上に自前で書き、crate を足さない
- 決定: io_uring の ABI (約120行の `#[repr(C)]` と大きさの assert) を `sys/uring.rs` に書く。`io-uring`、rustix の `io_uring`、`polling`、`mio` は入れない
- 理由: すべての `unsafe` を `trust.rs` の監査の中に置き、出荷する依存と THIRD-PARTY-LICENSES を変えない。`polling` は Windows で AFD を使い、edge の1回の登録と起こしの drain に合わせる adapter が残る
- 見直す条件: io_uring の ABI の2つ目の使い手 (ネイティブの実行系、ファイルの操作) が出るか、自前の定義が約300行を超えるか、大きさの assert で固められない ABI を使うとき
- 適合の確かめ: G-4
- リポジトリに残す所: 続ける道では `docs/implementation/architecture.md` の「外部 crate」と async.md:243 (T-12)

#### D-4: 選び方は `eml_io` の1つの関数が変数を読み、値を受ける根の構築子を並べる
- 決定: `pub enum IoBackend { Auto, Epoll, IoUring }` を `real.rs` に置く。`IoBackend::from_env()` だけが `EML_IO_BACKEND` を読み (Linux だけ)、`RealDriver::with_backend_and_lookup(b, lookup)` が環境を読まない根で、`new`、`with_backend`、`with_lookup` は根への1行の委譲である。`RunConfig` や `Clock` には入れず、eml_vm と eml_cli は変えない。選択は driver を作るたびに、変数、kernel、sandbox だけで決まる
- 理由: 設定は process 全体で同じ意味を持ち、`worker-threads` の段で worker ごとに driver を作っても全員が同じ backend になる。`Clock` は `Copy + Send` で OS に依らないままにする
- 適合の確かめ: G-5 (改訂)、G-6、G-7
- リポジトリに残す所: vm.md (T-9)、architecture.md (T-12)

#### D-5: テストは process ごとに1つの backend で流し、機械の設定で飛ばさない
- 決定: 本物の driver のテストは、製品の変数で選んだ1つの backend で流す。1つの process で backend を回すこと、テストだけの選択の欄を足すことはしない。ring のテストは ring を作れなければ `set EML_IO_BACKEND=epoll` を示して落ち、`EML_IO_BACKEND=epoll` のときだけ1行を出して流れない。Linux の通常の実行は io_uring を要する
- 理由: 1 秒の規則、製品の道を試すこと、`docs/implementation/testing.md` の「機械の設定で飛ばすことはしない」
- 適合の確かめ: G-9
- リポジトリに残す所: testing.md の新しい「Linux の2つの backend」(T-10)

#### D-6: CI で io_uring を作れなければ既定にしない
- 決定: Linux の CI の脚が本物の driver のテストを io_uring に固めて通すまで、io_uring を既定にしない。hosted runner が io_uring を拒めば、段を捨てる (ユーザーが認めた)
- 理由: CI は再試行せず成否だけを見る。確かめられない既定は置かない
- 適合の確かめ: G-8 (閉じる時の確かめ)
- リポジトリに残す所: testing.md「Linux の2つの backend」(T-10)

#### D-7: 後の段は io_uring を頼らない
- 決定: `async-files` は通常のファイルのプールの道をどの OS でも基準にし、ring の `READ`/`WRITE` は ring の backend の中の選択肢にとどめる。`async-threads` は受け箱の回り道を既定のままにする (出荷する ring は `SINGLE_ISSUER`)
- 適合の確かめ: G-10
- リポジトリに残す所: 続ける道では roadmap.md の `async-files` の論点と async.md (T-12)

#### D-8: 計測は全ラベルの backend を固め、腕ごとに門を当てる
- 決定: 試作より後の binary を測るときは、すべてのラベルを `--env <label> EML_IO_BACKEND=…` で固め、ラベルごとに自分の `base` を引き、門は腕ごとに当てる。続ける道では docs に記録したコマンドも固める。捨てる道では `--env` と `EML_IO_BACKEND` が benchmarks.md の「io_uring と epoll」と roadmap.md にだけ残る
- 適合の確かめ: G-11 (改訂)。続ける道の確かめ方は `05-rulings.md` の R2-9
- リポジトリに残す所: benchmarks.md (T-1、T-D2 または T-12)

### 5.2 段の中の設計

正当な理由があれば実装の途中で直してよいが、直したことを記録する。

#### D-10: 試作の backend の形 (`02-prototype.md`)
- 最低の kernel は 6.1。`io_uring_setup(256, CQSIZE|SUBMIT_ALL|SINGLE_ISSUER|DEFER_TASKRUN, cq 1024)`、feature `SINGLE_MMAP|NODROP|FAST_POLL|EXT_ARG`、`IORING_REGISTER_RING_FDS` が 1 を返すこと、最後に非ブロックの enter 1回 (起こしの `POLL_ADD` を出し、1 を返す)。どれかが EINVAL か feature の欠けなら `Unsupported`、EPERM/EACCES は `PermissionDenied`、ENOSYS は `Unsupported`
- `user_data` は `generation << 32 | op_index`。`WAKE = u64::MAX`、`CANCEL = u64::MAX - 1`
- 起こしは今の eventfd を one-shot の `POLL_ADD` で見張り、起こしのたびに掛け直す。待ちの期限は `EXT_ARG` で正確に渡す。`EINTR` と `ETIME` は `Ok(())`
- 取り消しは `ASYNC_CANCEL` で `Cancel::Pending` を返す。`Uring::drop` は記憶を持つ操作が残っていれば `URING_HELD_ABORT` を書いて abort し、ring を閉じてから op の記憶を放す (`ring` を最初の欄にする)
- 腕は2つ: `io_uring` (try-first、epoll と同じ同期の試み) と `io_uring_direct` (ready-gated)。試作の `Auto` は epoll
- 歩ごとの写し方、`ready` の印の規則、ring の大きさ、溢れの扱いは `02-prototype.md` の §1 と §2 の表に従う

#### D-11: 門 (`03-measurement.md` §1)
- 件は `G='^(base|many-self-1000|echo-self-fresh|echo-py-fresh|echo-py-reuse|bulk-1k)$'`
- 腕 U と件 c について、「epoll → U」の表で `比 ≤ 0.800` かつ判定「差」が、セッション 1 と 2 の両方で成り立つこと (割れたらセッション 3 が決める)。echo-py の行は U の regime の行が `ok` のときだけ数える。A/A が5件とも差なしで、`backend` の行がすべて `ok` であること
- 両方の腕が通れば、通った件の多い腕、同数なら5件の比の平均が小さい腕を出荷する
- io_uring のカーネル側の仕事は eml の process の rusage に入る (設計のときに確かめた)

#### D-12: 後退の扱い (`04-continue.md` §1.7)
- 後退: CPU は判定「差」かつ比 ≥ 1.100、起動は `base` の行の判定「差」かつ生の CPU の比 ≥ 1.05、メモリは最大 RSS の中央値が max(1 MiB, 5%) 以上多いこと。実時間は記録だけ
- 塞ぐ後退: CPU の比 ≥ 1.250、起動の比 ≥ 1.10、残す後退の数が門を通った件の数より多いこと。塞ぐ後退は直すか捨てる
- 残す後退は、同じセッションの syscall の数か `RunStats` の数え上げで仕組みを示せるときだけで、benchmarks.md の箇条と roadmap の項目を足す

#### D-13: 変数の値と誤りの文言 (`04-continue.md` §1.1)
- 値: 未設定 → `Auto`、`epoll`、`io_uring`。ほかは `InvalidInput` で `EML_IO_BACKEND must be epoll or io_uring, not "bogus"` (試作の間は `io_uring_direct` も受け、文言は `EML_IO_BACKEND must be epoll, io_uring or io_uring_direct`)
- 固めた io_uring を作れないとき: 種類はそのままで `EML_IO_BACKEND is io_uring, but io_uring cannot be used here: {e}`
- `Auto` が epoll に落ちるのは `PermissionDenied` と `Unsupported` のときだけで、ほかの誤りは driver を失敗させる
- Linux 以外で `Epoll` か `IoUring` を渡すと `Unsupported` で `this OS has one I/O backend`
- 実行時の失敗は今の道どおり ``runtime error: the I/O driver failed: <text> in `entry$main` `` と終了コード 1 になる

  ```python
  import json, statistics as st, sys
  rows = [json.loads(l) for l in open(sys.argv[1])]
  get = {(r["case"], r["label"], r["kind"]): r for r in rows}
  labels = list(dict.fromkeys(r["label"] for r in rows if r["label"] != "python"))
  uring = lambda r: r["env"].get("EML_IO_BACKEND", "epoll") != "epoll"
  bad = 0
  for r in rows:   # 1) 各ラベルが名前どおりの backend で動いたか
      if r["kind"] == "strace":
          for d in r["data"]:
              m = d["syscalls"]["main"]; u, e = m.get("io_uring_setup", 0), m.get("epoll_create1", 0)
              ok = (u >= 1 and e == 0) if uring(r) else (u == 0 and e >= 1)
              bad += not ok; print("backend", r["case"], r["label"], u, e, "ok" if ok else "NG")
  for l in labels:   # 2) echo-py の切り替えの形
      for c in ("echo-py-fresh", "echo-py-reuse"):
          r = get.get((c, l, "time"))
          if not r:
              continue
          v, i = st.median(x["nvcsw"] for x in r["data"]), st.median(x["nivcsw"] for x in r["data"])
          ok = i <= 1000 and (uring(r) or v >= 15000)
          bad += not ok; print("regime", c, l, int(v), int(i), "ok" if ok else "NG")
  sys.exit(bad)
  ```
