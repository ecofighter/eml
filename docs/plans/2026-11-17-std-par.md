## 3. Background context (code at 975b8199 = base)

Rows [V: read, proto]:
- A row with a shared body lives in four places: the `eml_extern` table (`crates/eml_extern/src/lib.rs`, one `Variant => row(..)` line), the `extern_rows!` list (`crates/eml_rows/src/rows.rs`, one `fn Variant(ctx, ..) -> kind { body }` line), the std declaration, and nothing else. - Tests that list every row and change by count: `rows::tests::shared_lists_each_row_with_a_body_once` (`SHARED.len() == 230`), `eml_native` `rows::the_rows_are_partitioned` (`(45, 187, 1, 101)` and `rows == 232`), the two native UI count snapshots. - `FunctionRow.faults` is `purity != Pure`. A row without `faults` that returns `Err(Extern(..))` is an internal error natively (docs/spec/native.md 「externの失敗」), and `rows_that_do_not_fault_return_ok_on_an_exhausted_budget` requires such rows to succeed on an exhausted budget. `Ctx::array_make` / `unboxed_make` refuse a length over `MAX_LEN` (0xFFFF_0000) or over the budget with `Fault::Stopped(Stop::MemoryLimit)`, not with a `Panic`. So `concat`, which makes its result with them, must be a `faults` row, and with `Purity::Panics` and `<Panic>` in its type the refusal is the memory-limit run error with the call's position on both engines [V: proto, the two `concat_too_long` files; `ui::run_fail_native` accepts both]. Finding F-1 (a memory-safety bug at the base, independent of the prototype) [V: proto, reproduced with the binary built from main]:
- Reproducer: `Par.par (fn () -> 1) (fn () -> (Array.make 128 0, Array.make 128 0))` with `--workers 2`, the pair dropped by the parent. The process allocates without bound (3 GB in 0.3 s), in checked and in fast mode. 127 elements, or one array, do not trigger it.
- Cause [V: read `crates/eml_rt/src/remote.rs`, `heap/reclaim.rs`; a stack sample ends in `reclaim_held` → `remote_take`]: an array of 128 elements is a large object (`MAX_SMALL_WORDS` = 128) on its own page. A large page freed from another thread is pushed on the owner's list of large objects (`remote_large_push`), linked through the page's remote-free-list word. `Heap::reclaim_held` calls `remote_take` on every page of its list, large pages included, and `remote_take` reads that word as the head of a list of small blocks. With two large pages pushed, the second page's word holds the first page's address: `remote_take` swaps it out (breaking the large list), pushes the page header as a block and follows whatever word lies behind it. This is a read through a wild pointer in the trusted code T14, reachable from a safe eml program at two workers or more; the unbounded `Vec` growth is how it showed.
- docs/spec/object-model.md 「別のスレッドからの解放」 states the same rule (「一覧のページごとに遠隔の空きリストの語を読み」), so the spec is wrong with the code.
- Every chunk of `Par.tabulate` (1024 elements) is a large object made by a child, so the stage cannot pass its own tests without the fix. Earlier runs passed by the luck of where the wild chain ended.
- Fix [V: proto]: `remote_take` returns without touching the word when the page's class is `LARGE`, tested only after the word was found non-null, so a page without remote frees costs nothing more. With it the reproducer and every new UI file pass at 1, 2 and 8 workers.
- Tests of the fix are bounded [V: proto]: a regression must fail, not exhaust memory (review r1, finding 1). `remote_take_leaves_a_large_page_alone` sets the remote word of a large page to a stand-in block whose link is null and calls `remote_take` on the page: with the rule nothing is taken and the word is kept; without it exactly the stand-in is taken and the walk stops. `two_remote_large_frees_are_both_reclaimed` (two large objects freed by another thread, then the owner's reclaim) asserts the same probe first, so it fails before it would walk wild memory. With the fix reverted the `eml_rt` unit test binary ran to its end under a 1 GB watchdog: 920 passed, 4 failed, 1.1 s. No UI file pins F-1: an eml program that reaches the bug cannot fail boundedly, and the rule is checked in one place (testing.md 「テストの置き場所」). The data-parallel UI files of SP-4 and SP-5 would run away if the fix were reverted after them; the `trusted` tests fail first.

### 5.2 Short-term decisions (this plan)

- S-SP-1 (signatures; argument order follows `for`, `List.fold` and `List.map`: the function, then the unit, then the range or collection; a grain comes first):
  ```haskell
  pub for_range          : Int -> Int -> (Int -> <Panic> Unit) -> <Panic> Unit
  pub for_range_grain    : Int -> Int -> Int -> (Int -> <Panic> Unit) -> <Panic> Unit
  pub reduce_range       : (a -> a -> <Panic> a) -> a -> Int -> Int -> (Int -> <Panic> a) -> <Panic> a
  pub reduce_range_grain : Int -> (a -> a -> <Panic> a) -> a -> Int -> Int -> (Int -> <Panic> a) -> <Panic> a
  pub tabulate           : Int -> (Int -> <Panic> a) -> <Panic> Array a
  pub tabulate_unboxed   : Unboxed a => Int -> (Int -> <Panic> a) -> <Panic> UnboxedArray a
  pub map                : (a -> <Panic> b) -> Array a -> <Panic> Array b
  pub mapi               : (Int -> a -> <Panic> b) -> Array a -> <Panic> Array b
  pub reduce             : (a -> a -> <Panic> a) -> a -> Array a -> <Panic> a
  pub try_map            : (a -> <Panic> Result x b) -> Array a -> <Panic> Result x (Array b)
  pub for_mut            : (Int -> a -> <Panic> a) -> MutArray a -> <Panic> MutArray a
  pub for_mut_unboxed    : Unboxed a => (Int -> a -> <Panic> a) -> MutUnboxedArray a -> <Panic> MutUnboxedArray a
  pub extern concat : Array (Array a) -> <Panic> Array a                 -- std/Array.em, after `thaw`
  pub extern concat : Array (UnboxedArray a) -> <Panic> UnboxedArray a   -- std/UnboxedArray.em, after `thaw`
  ```
  `for_range_grain grain lo hi body`, `reduce_range_grain grain join unit lo hi f`, `reduce_range join unit lo hi f`, `reduce join unit xs`.
- S-SP-2 (where `GRAIN` and `B` live): `grain : Int` = 1024 is a private top-level constant of `std/Par.em`; `B` is the local `width` of `spine`, computed by the private `root n b` (the smallest `b` at or above the given one with `b * b >= n`, by counting up from 1: exact integers, at most `sqrt(chunks)` steps, which is the number of top-level forks). Neither is public; stdlib.md states the value 1024.
- S-SP-3 (the spine; code in `sp-4-range.patch`): one private function
  `spine : Int -> Int -> Int -> (Int -> Int -> <Panic> a) -> (a -> a -> <Panic> a) -> <Panic> a`, `spine size lo hi leaf join`, for a non-empty range. `chunks = (hi - lo - 1) / size + 1`; chunk `k` is `leaf (lo + k * size) (min hi (lo + (k + 1) * size))`; `group first last` is `chunk first` when `first == last`, else `par (group first (last - 1)) (chunk last)` joined; `top g` is group `g`'s chunks when `g == 0`, else `par (top (g - 1)) (group g)` joined; the result is `top ((chunks - 1) / width)`. `size < 1` raises `panic "Par: the grain is less than 1"` before anything else. Every public function is `spine` with a leaf and a join; callers handle the empty range, so `spine` takes no unit.
- S-SP-4 (the rope): `data Rope c = | Leaf c | Join (Rope c) (Rope c)`, private to `std/Par.em`, over the chunk type `c` (`Array a` or `UnboxedArray a`); `flatten : Rope c -> Array c` collects the leaves from right to left into a list and calls `Array.from_list`. `tabulate` and `tabulate_unboxed` with `n <= grain` (negative lengths included) are the sequential `tabulate`, so a short array is not copied by `concat` and a negative length raises `make`'s `Panic`.
- S-SP-5 (the `concat` rows; code in `sp-3-concat.patch`):
  - `eml_extern`: `ArrayConcat => row("Std.Array.concat", &[Obj], Obj, Purity::Panics),` after `ArrayThaw`; `UnboxedArrayConcat => row("Std.UnboxedArray.concat", &[Obj], Obj, Purity::Panics),` after `UnboxedArrayThaw`. The argument is consumed (no `borrowing`), so the later item that moves unique chunks changes only the body.
  - `extern_rows!`: `fn ArrayConcat(ctx, chunks: obj) -> obj { Ok(array_concat(ctx, chunks)?) }` after `ArrayThaw`; `fn UnboxedArrayConcat(ctx, chunks: obj) -> obj { Ok(unboxed_concat(ctx, chunks)?) }` after `UnboxedArrayThaw`.

### 7.5 Soundness points and what holds each

| Point | Holds because |
|---|---|
| `remote_take` on a large page (F-1) | the class is read from the page header, which is not written after the page is published (object-model.md 「ページの留め」: 級はページの頭から読む); `remote_take` loads a large page's word (an atomic load, used only for the null test) but neither swaps nor follows it, so the word is written and followed only by `remote_large_push` and `remote_large_take`; pinned by the two `trusted` tests in both modes, under Miri (SP-2) and ThreadSanitizer (7.3.3); both tests fail by an assertion without the rule. `remote_take` is `external_body`, and its `ensures taken(..)` holds for an unchanged `out` as on the null path |
| A stale link in a large page that stays in the list (checked mode quarantines it; a pinned page is kept) | the word stays non-null after `remote_large_take`; with the fix `remote_take` never reads it; a later push of the same page stores the link again before the page is published on the list |
| `array_concat` / `unboxed_concat` call `unsafe` `Ctx` operations | the rows are `unsafe fn` under the list's contract (live words of the row's kinds, consumed arguments); the type of `concat` makes `chunks` an array of arrays; every reference `array_get` returns is released or moved into `out` exactly once; `out` is made in the body and unique, so `array_set` / `unboxed_set` write in place and return the same word; indexes are below the lengths just read |
| Fault paths | a refused make releases `chunks` and returns the fault (unit test: no leak in checked mode); any other error is a heap error of checked mode, which ends the run |
| A result built from chunks other workers made | the chunks reach the parent through `par`'s join like every child value; `concat` only takes references (`array_get`) and reads words |
| No block written by two threads (E3) | `std/Par.em` writes no array after it crossed `par`: leaves build their own chunk, `concat` builds a new array on the caller's worker, `for_mut` thaws only the unique result |

A soundness question beyond these goes to Fable (CLAUDE.md).

Rule: a `bench/run.sh` row whose median over three alternating pairs of 実行の分 deltas is over +0.5 % is re-measured alone over 15 alternating rounds; it stops the stage only if its 15-round median stays over +0.5 % and the stage changed code on that row's path; otherwise the Close message records it as layout. B = SP-1's commit, H = the tip after SP-6. The five new rows have no base and are not gated.

The row's path, for this stage's changes (a row's path is the code whose number of calls grows with the row's iteration count; one-time code is on no row's path):

| Load of the std modules | `std/Par.em` (larger, four more imports), `std/Array.em`, `std/UnboxedArray.em`, the `Extern` table (+2 rows) | never: one-time. `$S/pairs.py` (rows present in both tables; `empty` is skipped):
```python
import re, statistics, sys
def parse(p):
    return {m.group(1): int(m.group(3)) for line in open(p)
            if (m := re.match(r"\| `([^`]+)` \| (\d+) \| ?(\d*) ?\|", line)) and m.group(3)}
f = sys.argv[1:]
pairs = [(parse(f[i]), parse(f[i + 1])) for i in range(0, len(f), 2)]
for n in sorted(set(pairs[0][0]) & set(pairs[0][1])):
    d = [(h[n] / b[n] - 1) * 100 for b, h in pairs]
    m = statistics.median(d)
    print(f"{n:24s} {m:+7.2f} %  [{' '.join(f'{x:+.2f}' for x in d)}]{' OVER' if m > 0.5 else ''}")
```

`$S/rounds.sh` (per round `empty` and the row with both binaries; the median of the deltas of 実行の分):
```sh
#!/usr/bin/env bash
# usage: rounds.sh BASE_BIN HEAD_BIN ROUNDS ROW...
set -euo pipefail
base_bin=${1:?BASE_BIN} head_bin=${2:?HEAD_BIN} rounds=${3:?ROUNDS}
shift 3
export EML_WORKERS=1
count() { { /usr/bin/time -l "$1" run "$2" >/dev/null; } 2>&1 | awk '/instructions retired/ {print $1}'; }
for row in "$@"; do
  deltas=()
  for _ in $(seq "$rounds"); do
    be=$(count "$base_bin" bench/empty.em); br=$(count "$base_bin" "bench/$row.em")
    he=$(count "$head_bin" bench/empty.em); hr=$(count "$head_bin" "bench/$row.em")
    deltas+=("$(python3 -c "print(f'{(($hr - $he) / ($br - $be) - 1) * 100:.3f}')")")
  done
  med=$(printf '%s\n' "${deltas[@]}" | sort -g | sed -n "$(( (rounds + 1) / 2 ))p")
  echo "$row $med"
done
```

`$S/rounds-load.sh`: the same file with `count`'s second use per binary replaced by the row's own load, i.e. the four counts of a round are `bl=$(load "$base_bin" "bench/$row.em")`, `br`, `hl=$(load "$head_bin" "bench/$row.em")`, `hr`, with `load() { { /usr/bin/time -l "$1" run --load-only "$2" >/dev/null; } 2>&1 | awk '/instructions retired/ {print $1}'; }`, and the delta `(($hr - $hl) / ($br - $bl) - 1) * 100`.
