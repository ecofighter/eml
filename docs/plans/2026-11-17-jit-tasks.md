## 4. Decisions (01 §11)

- 11.1: workers 0..N-1 run on threads of `Options.stack` (default 1 GiB), `hard = base + 1 MiB`, `real = hard + 2 MiB`; the main worker measures the calling thread once before any thread exists (Linux `base = max(queried, top - 8 MiB)`; macOS and Windows `base = queried`), `hard = base + 2 MiB`; with at most 4 MiB below `top` or a failed query, the first start of a pinned task ends the run with `the calling thread's stack is too small for main-thread tasks`; `execute_native` runs on a 16 MiB scoped thread; each worker writes `Slot.stack` (H-3). `Worker<M>`, `Child`, `Current`, `split(ctx)`, the boxed `Worker` under a guard.
- 11.2: the loop is `eml_sched::drive`, reached only through `sequence::run`; `NativeExec::enter(this, item)` is the one caller of `eml_enter`: it builds `argv` and sets the limit class from the item's kind, and returns `Halt::Panicked` when an entry caught a Rust panic and `Halt::Stopped` otherwise; `eml_nrt` has no loop; job open and close as stated.
- 11.3: the task rows in `eml_nrt/src/rows/task.rs` over `cells.rs` with `TaskCx` and `Aside`; each row's entry is a `shim`; `eml_fatal` only from an entry's epilogue after every guard is dropped; Rust panics caught by the shim, `on_own`, or `run_ready`'s `catch_unwind`; `exit` under a task entry or a job as stated.
- 11.4: `eml_nrt_fork` / `eml_nrt_left` / `eml_nrt_join` around two direct `eml$apply$1` calls; no cleanup path and no unwind point.
- 11.5: `eml_nrt/src/limits.rs` (`set` is the one writer of `stack_limit`); `eml_nrt_safepoint(ctx, function, defers)`'s three steps over `eml_steps::limit::hit`; `ACTION_RAISE` in `lower/safepoint.rs`; `ACTION_UNWIND` deleted; the `n < m` arm passes `defers = 1`; classes at creation. `Hit::Raise` has no payload; the message text is `eml_nrt`'s.
- 11.6: blocking C (`Image.c`, `CRow`, `DATUM_C`, `eml_x_c_submit`, `eml_x_c_take`, bodies in `rows/blocking.rs`); the run: `eml_nrt::run` builds `Start` (its `owners` is the table of every `Ctx` of the run) and calls `eml_sched::sequence::run` with its `Workers` implementation; on each worker's own thread `on_worker` measures the stack, makes the `Ctx` with `Ctx::for_worker` on the run's `Owners`, sets the stack limit, fills the data slots, makes the `Worker` (which takes the `WorkerCore` from `Env`), calls `run` once, then clears `runtime`, asserts the `Ctx` detached, converts a recorded fatal into a `RuntimeError` and returns `Retired`; nothing between making the `Ctx` and returning `Retired` may panic except through `run`, everything it allocates against the `Control` before the first item is allocated before it calls `run`, and it holds the `Ctx` so that an unwind of its frame leaks it (a panic there aborts the process); on `Err(Halt::Panicked)` it only detaches and wraps the `Ctx`; no item runs before every worker's `on_worker` has called `run` (the start barrier); after `sequence::run` returns, `eml_nrt` first takes in the remote frees on every retired heap (`Ctx::reclaim`, the calling thread's heap last), then runs the mode's end checks and builds `Finished`; it leaks a `Retired` whose `driver_kept` is true, checks nothing on a panicked worker's heap, and drops such a heap only after every thread of the run has been joined. `eml_nrt` spawns no thread and has no `clear_end`. `Options.masked` deleted; the CLI accepts `--workers`, `--gui`, `--debug-heap`, `--stats` with `--native`.
- 11.7: 「VMとの違い」's four items (G-14); `ui::limit_depth_native`; outputs and the schedule-free `RunStats` fields compared on every other file.
- 11.8: the three heap-store sites pinned; dominance pins in both lowerings; the N = 8 stress test.
- 11.9: a form is accepted natively only when everything its files need at one worker is in place; a VM test whose program native code now runs is restated in `crates/eml_native/tests` (K2, 00 UJ-19 (5)), and a test that asserts the VM's placement, preemption or `Seat` internals is not restated; the tests that are not restated are listed at that unit.
- Criteria: section 1's list; S-9..S-19, S-23.
- D-15, the four `Std.Atomic` rows:
  - `eml_extern`: `TypeRow` gains `address: Option<Address>`, `Address { made_by: &[Extern], used_by: &[Extern] }`: the word of a value of this type is an address native code reads and writes. `Counter` has `made_by: [AtomicNew]`, `used_by: [AtomicAdd, AtomicLoad, AtomicStore]`; every other row `None`. `Extern::reads_address()` is "in some type row's `used_by`". `Extern::is_async` is unchanged.
  - Entries, in `eml_nrt/src/rows/task.rs` with the other rows of the VM's task group (the file name is about that group; D-VR-5 regroups them): `AtomicNew` is `counters::new(n)?.word()`; `AtomicAdd` / `AtomicLoad` / `AtomicStore` are `counters::find(c)` then the operation; a word 0 is `Aside::Fault(RunFault::Internal("a counter word is 0"))`, any other miss `"a counter is not in the table"`. None reads the current cell or the budget. `crates/eml_rows/src/rows.rs` is not edited: the four rows stay in its task name group (line 620) with no shared body, `SHARED` keeps 230 rows, and the VM's arms stay.
  - Lowering, `crates/eml_native/src/lower/rows.rs`: a table `ATOMIC: &[(Extern, Atomic)]` (`Atomic::{Add, Load, Store}`) beside `INLINE`, and `Lowering::Atomic(Atomic)`. `lowering(ext)` stays a function of the row: it looks in `INLINE`, then in `ATOMIC`, and only then applies the `is_async` / `Par` test, so the three rows get `Some(Lowering::Atomic(..))` while still `is_async`. The statement lowering turns `Lowering::Atomic` into the inline sequence in fast mode and into `called_row` in checked mode; the rows have no `faults`, so `called_row` emits the call and nothing after it. Sequences: `add n c` is `old = atomic_rmw.i64 add c, n; old + n` (wrapping `iadd`); `load c` is `atomic_load.i64 c`; `store n c` is `atomic_store n, c` and binds unit; memory flags `trusted`; no unwind point, no site.
  - Verifier, `eml_lir`: the window rule of lir.md 「yieldの確認までの間」 treats an `extern` statement whose row `reads_address()` as it treats an unwind point: not between a yielding call and `prim yielding()`, not after a call without a check, not on the slow path. The four messages gain ", or a row that reads an address" after "`prim yield_to`".
