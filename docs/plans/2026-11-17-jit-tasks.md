## 1. Goal and completion conditions

- Goal: native code runs the task layer on `eml_sched::drive`: task rows, `par` and `compute`, blocking C, limits at the safepoint, the main worker and its `Park`, workers 1..N-1, signals and the fatal path; every program is accepted natively, fast and checked, at any worker count and under both seeds.
- Completion conditions:
  - No form is refused natively: `eml_native::{Unsupported, Form, unsupported}` are deleted and `Session::compile_native` loses the call; the native UI snapshots have no `rejected` line.
  - G-10: `Exec::enter` is called only by `drive`; no asm other than the entry stubs, no stack switch, no thread-locals in `eml_nrt` / `eml_native` (`grep -rn 'strand\|Stacks\|CreateFiber' crates` → empty; placement tests).
  - G-13: generated `par` code is the sequence of 01 §11.4 with no unwind point (CLIF pin).
  - G-14: native.md 「VMとの違い」 lists exactly the two items of 01 §11.7; every `native: skip` names item 1; outputs are compared on every file but the `-- workers: skip` ones.
  - G-15..G-17: the `Park` is entered only from the main worker's idle loop; a fatal or a panic crosses toolkit frames only as a value; `stack_limit` has one writer and the safepoint's hot path is unchanged (CLIF pin); the end of a native run is on the calling thread after both joins and `eml_nrt` has one `clear_end` call site.
  - G-18: every commit passes `cargo nextest run`; a test that reaches `eml_fatal` is in a module named `fatal`.
  - G-19: `grep -rn 'rows::call\|#\[used\]' crates/eml_nrt/src` → empty; nothing on the run path reads a descriptor table.
  - G-7: checked native and the checked VM agree on error classes and on every compared `RunStats` field at one worker, and on the schedule-free fields at every worker count and seed.
  - The rt-concurrent-proofs hooks of 01 §11.8: `heap_stores_have_three_sites`, the dominance CLIF pins in both lowerings, the repeated N = 8 checked `par/` run with census as an `#[ignore]` test CI runs.
  - G-22 (this stage's hooks): `the_frame_chain_reaches_eml_enter` (H-1) and a test that reads `Slot.stack` from another thread (H-3) pass.
  - `Finished` has `claims` and `join_waits`, filled by the native run from `WorkerCore`'s counts (00 §D D-6).
  - G-24: `surface::` passes at every commit. The task rows of `eml_nrt` call the `cells` functions inside row bodies, which are already `unsafe fn`: no new rule; a new safe public function that names a `surface.rs` token gets its `SAFE` entry in its unit.
  - D-ET-2: the promise list of docs/spec/lir.md 「エンジンの約束」 is re-checked against the new native entries (task rows, `Worker`, `NativeExec`), together with `surface.rs`'s `SAFE`.
  - A Fable whole-branch review before the Close (UJ-7's kept part, A-6).

## 4. Decisions (01 §11)

- 11.1: workers 0..N-1 run on threads of `Options.stack` (default 1 GiB), `hard = base + 1 MiB`, `real = hard + 2 MiB`; the main worker measures the calling thread once before any thread exists (Linux `base = max(queried, top - 8 MiB)`; macOS and Windows `base = queried`), `hard = base + 2 MiB`; with at most 4 MiB below `top` or a failed query, the first start of a pinned task ends the run with `the calling thread's stack is too small for main-thread tasks`; `execute_native` runs on a 16 MiB scoped thread; each worker writes `Slot.stack` (H-3). `Worker<M>`, `Child`, `Current`, `split(ctx)`, the boxed `Worker` under a guard.
- 11.2: the loop is `eml_sched::drive::<NativeExec<M>>`; `NativeExec::enter` is the one caller of `eml_enter`; `eml_nrt` has no loop; job open and close as stated.
- 11.3: the task rows in `eml_nrt/src/rows/task.rs` over `cells.rs` with `TaskCx` and `Aside`; each row's entry is a `shim`; `eml_fatal` only from an entry's epilogue after every guard is dropped; Rust panics caught by the shim, `on_own`, or `run_ready`'s `catch_unwind`; `exit` under a task entry or a job as stated.
- 11.4: `eml_nrt_fork` / `eml_nrt_left` / `eml_nrt_join` around two direct `eml$apply$1` calls; no cleanup path and no unwind point.
- 11.5: `eml_nrt/src/limits.rs` (`set` is the one writer of `stack_limit`); `eml_nrt_safepoint(ctx, function, defers)`'s three steps over `eml_steps::limit::hit`; `ACTION_RAISE` in `lower/safepoint.rs`; `ACTION_UNWIND` deleted; the `n < m` arm passes `defers = 1`; classes at creation.
- 11.6: blocking C (`Image.c`, `CRow`, `DATUM_C`, `eml_x_c_submit`, `eml_x_c_take`, bodies in `rows/blocking.rs`); the run's four steps on the calling thread; `Options.masked` deleted; the CLI accepts `--workers`, `--gui`, `--debug-heap`, `--stats` with `--native`.
- 11.7: 「VMとの違い」's two items; `ui::limit_depth_native`; outputs and the schedule-free `RunStats` fields compared on every other file.
- 11.8: the three heap-store sites pinned; dominance pins in both lowerings; the N = 8 stress test.
- 11.9: a form is accepted natively only when everything its files need at one worker is in place; a test of a switched file that asserts the VM's placement, preemption or `Seat` internals is listed at that unit and stays VM-only until deleted.
- Criteria: section 1's list; S-9..S-19, S-23.
