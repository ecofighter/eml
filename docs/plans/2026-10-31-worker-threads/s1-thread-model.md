# S1 (r3): thread/worker model and scope of `worker-threads`

Tags: [V] verified by reading the cited file/line in /home/user/eml at 0f9cd9b or by running the command named in §7; [I] inferred. r3 applies the user's amendments X2-X7 and the name alignment with S4 (Cf-7..Cf-10); nothing else is reopened. Change log at the end.

## 1. Conclusion

Q1 scope and consumer: option (b) with a small roadmap reshuffle (partial (c)).
- Consumer = **`par` right-child placement**: at fork, if N ≥ 2 and some worker is idle (worker 0 included: it is eligible when it is parked), the already-marked right child `Task` is handed to that worker's inbox and runs there; the parent waits at join by releasing its worker; the child's completion travels back as `Joined { join, outcome }` to the parent's home worker. No deque, no stealing (those stay in `par-steal`). The roadmap sentence "`par` の子はこの段ではまだ親の worker で動く" is removed; "スレッドをまたぐ join の待ち" moves from `par-steal` into this stage.
- What survives `par-steal` unchanged: per-worker `Ctx`/scheduler/loop, inbox + wake, the `Joined` notice and join completion on the parent's worker (a stolen child finishes elsewhere exactly as a placed one), idle set, `in_flight` deadlock rule, virtual-time rule, shutdown, masks, `Control` words. What `par-steal` replaces: the fork decision "pop idle worker → push `Child` to its inbox" becomes "push to own deque → wake one idle worker", and the `Child` notice disappears.
- This gives every stage artifact an end-to-end eml path: per-worker heaps, `share` on thread A / `transfer_back` on thread B, remote free in both directions, run-wide owner-ID table, per-worker stop words, shutdown with a running child, SIGINT masking, and N-heap recovery after an error/abandon at N ≥ 2 as far as its order and the ID-table reset go (the copy from foreign pages is pinned by S2's Miri test (g), because a run with roots never spawns, see Q2).
- Out: `Async` tasks off worker 0, cross-worker `Chan`, `Registry` under a run lock, `Counter` as atomic, `compute`, rescue, deque/steal, `eml_sched` crate, REPL with N ≥ 2, `rescue-always`, `--main-dedicated`.
- Granularity: placement at every fork while an idle worker exists; no granularity control in this stage (`std-par` adds the grain); `bench/par_tree.em` deltas are recorded per unit by the cachegrind gate (C7') and at close in benchmarks.md.

Q2 thread model:
- `eml run`: the process main thread is the host. It installs the signal handlers, loads and compiles, then `eml_vm::execute` spawns **worker 0** (`eml-worker-0`, 8 MiB stack) which owns the whole one-shot `Machine`, loads, runs, closes; the host blocks SIGINT/SIGTERM while it joins worker 0 and unblocks after the join.
- Workers 1..N-1 are spawned **lazily, all at once, at the first `par` fork of a run whose session has no roots and whose loaded code has no `RootSet`** (`eml-worker-k`, 8 MiB, `spawn_masked`), by worker 0 inside `Machine::run` using `std::thread::scope`; a run that cannot spawn runs at N = 1; a run without `par` spawns no thread. Each worker creates its own `Ctx` on its own thread and returns it to worker 0 at run end. **Workers ≥ 1 have no driver in this stage**: nothing on them can submit an op or register a timer (`Row<Never>`), so this stage creates none and `driver_mut()` on worker k ≥ 1 is an internal error (`VmFault::Internal("a worker without a driver")`); their idle wait is a parker. Worker threads and heaps 1..N-1 live until the end of the run that spawned them.
- `eml repl`: unchanged thread model, **N = 1**, VM on the main thread. No `--workers` for `repl`.
- N: `Limits.workers: usize` (default 1) fixed at `Control::new`. `eml run --workers N` > `EML_WORKERS` > `available_parallelism()` (error → 1); `0`, non-numbers → usage error, exit 2. UI tests and library default: 1. `Finished.workers` reports the worker threads the run started, `Finished.placed` the children placed on another worker.
- Ownership: `Machine` (single-threaded, not `Send`) owns Ctx 0, driver 0, `CodeBase`, `Arc<Control>`, `HostRef`, and after a run that spawned, `others` (heaps 1..N-1) until they are dropped (success) or recovered (error). The per-run `Run` struct (Sync) is borrowed by the scoped worker threads. The worker-ID table lives in `Control` (`Control.workers: WorkerIds`, S2), i.e. for the `Machine`'s life, reset by `recover`; it is not part of `Run`.

Q3: no `eml_sched` in this stage. Worker loop, inbox, slots and monitor stay in `eml_vm` (`sched.rs`, `monitor.rs`, new `workers.rs`). Deferred item added to roadmap.

Q4 Control: per-worker stop words live **inside `Control`** as `words: Box<[Arc<AtomicU32>]>` of length `limits.workers`, allocated once in `Control::new` and never resized; `Ctx.word: Arc<AtomicU32>` is the worker's own word so `poll` is "load field, load word" (S4 B1). Fallback if Verus rejects the `Arc` form: `Box<[AtomicU32]>` plus an index in `Ctx`, which is the shape verified in §7 ([V] `Vec<AtomicU32>`); the fallback is gated by the cachegrind criterion. `words[0]` is today's `worker` word. **Writers write every word directly** (`raise` loops; async-signal-safe: N relaxed `fetch_or`). `PREEMPT`/`NOTICE` are per word (`preempt(k)`, `take_preempt(k)`, `notice(k)`, `take_notice(k)`, `worker_bits(k)`). New per-word bit `END` (`Control::END = 4`), set by `Control::end_run()`, cleared by `clear_end`; not in `stop`; `stop_reason` ranks `END` below `MEMORY`. The monitor copies nothing; it wakes. `end`/`code` CAS unchanged (exit code only).

Q5 Monitor: one per run, owned by worker 0's scheduler, started at run start for every run with a sleeping driver (`Clock::Real` or injected) and for every run with `limits.workers ≥ 2`; `Clock::Virtual` runs at N = 1 as today (`PREEMPTS` policy). Duties: (1) per-worker PREEMPT from per-worker switch counters; (2) signal relay into worker 0's inbox + `NOTICE` on word 0; (3) wake every worker (parker, and the driver waker where a driver exists) whenever `Control` stop bits are set or a notice was pushed; (4) doorbell wait as today. **Tick bound (X2)**: with a doorbell, the monitor ticks (10 ms) only while `Run.running > 0` and otherwise sleeps on the doorbell without timeout, a worker leaving park unparking it; **without a doorbell it keeps ticking every 10 ms** (`park_timeout(TICK)`), so a parked worker sees a stop bit within one tick. Stop latency ≤ one tick is pinned by `a_monitor_without_a_doorbell_wakes_a_parked_worker_on_a_stop_bit` (W10) and `an_interrupt_reaches_a_parked_worker_without_a_doorbell` (W12). **Start failure**: at N ≥ 2 the run proceeds with N = 1 (no placement); in any run whose monitor did not start, the VM keeps today's 10 ms idle-wait cap as the fallback (`WAIT_CAP_MS` stays, used only then). Runs with a monitor have uncapped idle waits.

Q6 Shutdown (this stage): (1) the end is decided either by worker 0's run loop returning (Ok / `Stop` / fault / `Ended`) or by a **fatal error on worker k ≥ 1** (heap error, internal error), which writes `Run.fatal` (first writer wins), sets `END` in every word and wakes all; (2) worker 0 sets `END` in every word and wakes every worker when its own loop ends; (3) each worker k ≥ 1 seeing `END` or a stop bit at its next safe point or idle wake drops its current task without unwinding and returns its `Ctx`; (4) worker 0 joins all (scope end), drains every heap's remote list (S2 `reclaim`), **flushes Host (today's order, before any check or recovery: output precedes the error under `> out 2>&1`, lib.rs:566-572)**, then on success runs the checked-mode checks over all N heaps and drops heaps 1..N-1; on error/abandon keeps them in `Machine.others` and hands all N heaps to recovery; returns `Run.fatal` if set, else its own result; (5) the host joins worker 0, unblocks signals, maps the exit code (unchanged). `Control::exit` is written only by task bottoms on worker 0. Quiescence = "all worker threads joined"; recovery and leak checks run only then, on one thread, over owned heaps.

Q7 Signals: unix: host blocks SIGINT/SIGTERM right after spawning worker 0 and unblocks after joining it; workers ≥ 1 are `spawn_masked`; monitor/pool/resolver as today; `CaptureHost` drain threads (hosts.rs:331) switch to `spawn_masked`. Rule: every thread spawn in `eml_vm`, `eml_io`, `eml_cli` `src/` goes through `spawn_masked` except worker 0, pinned by a grep test in `eml_vm` like `eml_io/src/trust.rs:265`. Windows unchanged; REPL unchanged; blocking reads on worker 0 behave as on today's main thread (only unmasked thread during the run).

Q8 Run-wide structures now: owner-ID/count table in `Control` (S2), per-worker inboxes, idle set, `in_flight`, `running`, `fatal`; join nodes stay in the parent's worker's scheduler and are written only by that worker (the outcome arrives in `Joined`). Later (`async-threads`): `Registry` under the run lock, `Counter` atomic (stdlib.md:1256 / roadmap:329 wording → "`Async` のタスクが複数の worker で動くとき").

Q9 Tests: UI `par/` (run and run-fail) additionally at N = 2 and N = 8 (checked, `Sequential`, `Clock::Virtual`), comparing stdout/stderr/files/exit and the aggregated schedule-independent `RunStats` (C12). `async/` not at N ≥ 2. eml_vm `workers.rs` (S4 names): `a_run_without_par_starts_no_worker`, `the_first_fork_starts_the_workers`, `code_with_roots_starts_no_worker`, `an_interrupt_ends_a_run_with_idle_workers`, `a_child_runs_on_another_worker` (checked, `placed ≥ 1`, output equal to N = 1), `an_interrupt_stops_a_child_on_another_worker`, `an_interrupt_reaches_worker_0_parked_in_join_wait`, `an_interrupt_reaches_a_parked_worker_without_a_doorbell`, `exit_abandons_a_child_on_another_worker`, `a_heap_error_in_a_placed_child_ends_the_run`, `a_depth_error_in_a_placed_child_is_reported_at_join`, `recovery_after_an_error_drops_n_heaps`, `a_timer_on_worker_0_and_a_child_on_worker_1_agree`, `nested_children_place_on_eight_workers`, `a_monitor_without_a_doorbell_wakes_a_parked_worker_on_a_stop_bit`; `signal::` gains N = 2 variants. CI TSan job (feasible [V: §7]) for `eml_vm --test integration -- workers:: signal:: preempt::` and `eml_rt trusted::`. All normal-run tests < 1 s.

## 2. Rationale

- Nothing else in this stage runs eml code off worker 0 [V: RM:31-32]. Option (a)'s testable surface is Rust-level only; it cannot exercise fork/join across two `Ctx`s, shutdown with a running thread, signal masks, per-worker PREEMPT, or the CLI flag. The consumer costs the placement decision (replaced later) plus pieces `par-steal` needs anyway.
- `par` placement is the cheapest real consumer: fork already marks regardless of N [V: vm.md:514-524]; the right child is a separate `Task` in `Unstarted(g)` [V: sched.rs:200-201]; `JoinNode` already handles either completion order [V: sched.rs:228-239, vm.md:532-533]; `Task: Send`, `CodeBase<M>: Sync` asserted [V: 01b §7]; children are `Row<Never>`.
- Roots: fork marks unmarked roots through worker 0's `Ctx` [V: vm.md:520], and `transfer_back` flips rc −1 objects in place without copying [V: transfer.rs:894-900], so after a `par` at N ≥ 2 a root set after the join may point into heap k's pages, which Q6(4) drops on success. Therefore `Machine::run` may be called repeatedly at any N, but **a session with roots, or code that can reach `RootSet`, runs at N = 1** (the gate is decided at run start: `ctx.roots().is_empty()` and `!code.uses_roots`, the flag ORed at every `load`). Roots exist only in REPL-lowered code [V: `Prim::RootSet` built only at translate/program.rs:601], so `eml run` is never gated. At a placement, checked mode asserts `sched.shared_roots == ctx.roots().len()` (vacuous under the gate, harmless).
- `transfer_back` at join touching rc<0 objects on the child's pages and the parent later freeing them is "ほかの worker のヒープの共有の物体 (rc < 0) を受け付けること" and "別のスレッドからの解放" [V: RM:31]; the child's last `decref` of the shared closure frees a parent-page object from the child's thread.
- Lazy spawn and driverless workers: pool and resolver threads are already lazy [V: pool.rs:72-74; resolve.rs:75]; still, N-1 threads + heaps per run for every script is visible waste; spawning at the first fork keeps a run without `par` identical to today, which is the condition under which N = 1 snapshots must hold. No `par` child can touch a driver, so none is created (Cf-8).
- Per-run worker threads + "worker 0 spawns/joins 1..N-1": heaps 1..N-1 cannot be dropped by their threads because transferred objects still live on their pages [V: OM:270-272]; returning `Ctx` to worker 0 and dropping after draining keeps `Machine` single-threaded and the driver thread-bound [V: vm.md:474, architecture.md:361].
- REPL N = 1: a persistent `Machine` with N heaps would need persistent workers plus a between-input quiescence protocol or per-input compaction; the driver cannot move threads [V: architecture.md:361].
- Writers-write-all-words: a **running** worker sees a stop bit at its next safe point with no intermediary, as worker 0 does today [V: OM:819, control.rs:110]; a **parked** worker is woken by the monitor in both designs (wakers are not signal-safe [V: vm.md:489]), which is why a monitor without a doorbell must keep ticking (X2). Verus accepted `Vec<AtomicU32>` in the `verus!` struct [V: §7]; S4's `Arc` form is tried first and falls back to this.
- Cap removal with a fallback: the cap exists only because "監視のスレッドのない run では、Ctrl-C の後に waker を鳴らす者がいない" [V: vm.md:489]; keeping the cap only for a failed monitor start preserves Ctrl-C responsiveness in that case.
- Tick bound: MC:77 ("どれかの worker がタスクを動かしている間は監視の刻みごとに起き、ほかの間は条件変数か時間切れで待つ") is met with a doorbell by the `running` gate; without a doorbell the signal handler cannot wake anyone, so the tick is the only wake path [V: sched.rs:357-366, monitor.rs:125-153].
- Fatal errors on worker k: MC:463 and vm.md:556 [V]; `Run.fatal` + `END` implements both without letting workers k write `Control::end`.
- Flush order (X4): today the result is copied, then `ctx.flush()`, then the checks [V: lib.rs:559-572]; flush touches no heap, so it precedes the N-heap checks and recovery unchanged.
- Virtual clock at N ≥ 2 must not advance while another worker runs [V: MC:127].
- `eml_sched`: MC:63 defers the crate until something is shared.
- Stack: the VM stack is `Task` data [V: vm.md:846]; 8 MiB is checked by the whole suite because every `execute` call runs on a spawned worker 0 after U2.
- `RunStats` at N ≥ 2: aggregation is sum for counts, max for `peak_objects` and `peak_stack`; every schedule-independent field is then the same at N = 1 and N = 2 for `par` [I, per field]: heap counts because marking and reuse are schedule-independent (MC:267); `peak_stack` because a placed child keeps its `depth_offset` [V: vm.md:565]; there is no `switches` field [V: lib.rs:45-89]; `peak_objects` is already zeroed [V: test_support lib.rs:296-300].

## 3. Alternatives considered and rejected

- (a) Infrastructure only: pushes the first real run of every stage artifact into `par-steal`.
- (c) Merge into `par-steal` or `async-threads`: too large to review and test incrementally.
- Spawn all workers at run start: per-run cost for every script.
- Driver per worker ≥ 1 now, or lazy creation on first use: nothing can use it in this stage (Cf-8); `async-threads` adds creation when the first placed task needs it.
- Place children only under a special policy: hides the default path.
- Parent parks its OS thread at join: violates invariant 4 and starves worker 0's `Async` tasks.
- Monitor copies stop bits (MC:82): see rationale.
- Persistent worker-0 actor thread for the REPL: mirrors the `Machine` API for no present gain.
- Host spawns and joins all N workers (MC:73 literal): forces run state and `CodeBase` out of `Machine` or `Machine: Send`.
- Workers k write `Control::end` on fatal errors: `end` carries the exit code; a separate first-writer `fatal` slot keeps the exit-code protocol unchanged.
- Keeping heaps 1..N-1 alive across runs to allow roots at N ≥ 2: makes `Machine` an N-heap persistent object (leak check across heaps, N-heap `close`/`drop`); rejected with REPL = N = 1. Compacting with `recover` after every successful run with roots: loses the leak check and costs O(live); rejected.
- Run-wide `Run.joins` mutex (r2): the outcome travels in `Joined`, so the node stays in the parent's worker and needs no lock (Cf-9).
- Dropping the TSan job: the build and run work [V: §7]; eml_rt uses AcqRel RMWs and no fences.

## 4. Assumptions made

- A1 [I]: `RuntimeError`, `JoinNode`, `Outcome` are `Send`. If false: wrap for transport.
- A2 [V for the fallback shape]: Verus accepts `Vec<AtomicU32>` in `Control`; the `Arc<AtomicU32>` per word form is S4's B1 [I], with the fallback gated by C7'.
- A3 [I]: `thread::scope` closures borrowing `&CodeBase<M>`, `&Run`, `Arc<Control>`, `HostRef` are `Send`; `Run` contains only `Sync` pieces.
- A4 [I, argued per field]: aggregated schedule-independent `RunStats` are identical across N for `par/`. If a field differs, zero it in `schedule_independent` with the reason (kind 2).
- A5 (S2 API, explicit): S2 provides (i) `Heap::reclaim`/drain callable when no other thread touches any heap, (ii) `Control.workers: WorkerIds` with `fork_worker`/`retire_worker`/`set_worker` keeping today's `Heap` signatures and `Control::check_owned` over all heaps, (iii) `recover` taking the N owned heaps and resetting the table, (iv) page registration/unregistration inside `Heap::new`/`Drop` on the worker's own thread, (v) Miri (g) pinning the copy from foreign pages. No checked remote-free counter is assumed; `Finished.placed` replaces it in VM tests. If (i)-(iii) differ, only U5c/U5d change.
- A6 [I]: tests using `with_driver` do not rely on the 10 ms cap; with a monitor now started for injected drivers (ticking without a doorbell), their wake path is the tick. Listed as a kind-1 candidate.

## 5. Implications for implementation

### Constraints (for S4 and the implementer)

- C1 `Machine` API stays single-threaded; `Machine::run` may be called repeatedly at any N; workers are spawned at the first fork only when the session has no roots and the loaded code has no `RootSet` (flag ORed at every `load`, re-read at every run start); otherwise the run proceeds at N = 1. A session with roots (the REPL) runs on one worker because a root may point into heap k's pages after a successful run (`transfer_back` does not copy) and heaps 1..N-1 are dropped at run end.
- C2 Per-worker state = `Ctx` (own heap, own `word`), own `Scheduler` (tasks, ready queue, policy, `driver: Option<Box<dyn IoDriver>>` which is `Some` only on worker 0 in this stage, switch counter, parker); worker 0 additionally owns `Registry`, roots, `shared_roots`, the monitor.
- C3 `Run` (per run): `workers: Vec<Slot>` (`inbox: Mutex<Vec<Notice>>`, parker, `waker: OnceLock<Arc<dyn IoWaker>>`, `switches: AtomicU64`), `idle: Mutex<Vec<u32>>` (worker 0 eligible), `in_flight: AtomicUsize`, `running: AtomicUsize`, `fatal: Mutex<Option<RuntimeError>>`. All words held by `Run` are counted references (MC invariant 2/9). The worker-ID table is `Control.workers` (Machine lifetime, reset by `recover`), not in `Run`.
- C4 Notices: `Child(Task)`, `Joined { join: JoinId, outcome: Outcome }`, existing `Signal`, `HandleDropped`, `Cancel` (worker 0 only). Push under the inbox mutex (the Release/Acquire edge), then wake.
- C5 Placement: fork, after marking, pops one idle worker under `Run.idle`'s lock, increments `in_flight`, pushes `Child`, wakes; none idle → local ready queue. Independent of `Sched`. Child completion on worker k: send `Joined { join, outcome }` to the parent's home worker (`task_failed` sends `Outcome::Error` the same way), then push self to `idle` and park. The parent's worker consumes `Joined`: if the node is an orphan, drop the outcome untouched; else write `right_outcome` and wake the parent; in both cases **decrement `in_flight` on consumption**, so the counter is never 0 while a `Joined` is unconsumed. Join completion (`transfer_back(w, child)` → `retire_worker(child)`) runs on the parent's worker as today.
- C6 Idle loop (every worker): lock own inbox; if non-empty, take all, unlock, process; else if a runnable exists run it; else (inbox empty under lock): worker 0 declares deadlock only if `in_flight == 0`, no timer, no pending op, not listening; otherwise, if the driver has pending ops or timers → `driver.wait(deadline)` (uncapped with a monitor, capped by `WAIT_CAP_MS` without one); under `Clock::Virtual` only when `running == 0` (else park); else park. `running` is incremented before processing and decremented under the inbox lock just before parking; wake = push under the lock, then unpark (+ driver waker if present).
- C7 Monitor: with a doorbell, ticks while `running > 0` and sleeps on the doorbell otherwise (a worker whose increment takes `running` from 0 to 1 unparks it); without a doorbell, `park_timeout(TICK)` every tick as today, so stop latency ≤ TICK. `Scheduler::set_current` bumps the worker's own `switches`.
- C8 Shutdown per Q6; `Control::end_run()` sets `END` in all words; `END` not in `stop`; workers k never write `Control::end`; a fatal on worker k goes to `Run.fatal` then `end_run`. Order after the join: reclaim all heaps → Host flush → (checks and drop heaps 1..N-1) or (recovery over N heaps).
- C9 Child error classes: recoverable child errors (depth limit, extern errors, uncaught `Panic`) → `Joined` with `Outcome::Error`, reported at join as today; "すぐに止める" errors (heap error, internal error) → `Run.fatal` + `END`; stop bits → the worker returns to its entry without writing anything. Replacement spec text in "Spec" below.
- C10 Signal masking per Q7; `eml_io::Masked` guard on the host across the join; grep test for spawns.
- C11 No thread-locals; compile-time asserts per G-S1-12.
- C12 `RunStats` aggregation at run end: sum every count field over all N `Ctx`/heaps/schedulers; `peak_objects` and `peak_stack` = max; `preemptions` = sum. `Finished` gains `workers` and `placed`. `RunStats` fields unchanged.
- C13 Stack: `WORKER_STACK = 8 MiB` constant in eml_vm for every VM worker.

### Revised roadmap.md text

- `worker-threads`: worker のスレッド、worker ごとのヒープ、スレッドをまたぐ知らせ (受け箱と起こし) を入れる。`eml run` は host のスレッド (プロセスのメインスレッド) が worker 0 のスレッドを作って待ち、worker 0 は run の最初の `par` の fork で worker 1..N-1 を作り、run の終わりに join する。`par` のない run と、セッションの根を持つか `RootSet` に届くコードの run はスレッドを作らない。N は `--workers` と `EML_WORKERS` で決め、既定は `available_parallelism` である。`Control` は worker ごとの止める語を持ち、書く側がすべての語に直接書く。監視のスレッドは worker ごとに `PREEMPT` を立て、眠る worker を起こし、自己パイプがあればどの worker も動いていない間は眠る (監視のある run では VM の 10 ms の待ちの上限を外す)。止める手順 (終わりのビット、ほかの worker の致命的な誤りの欄、各 worker が自分の `Ctx` を返す、worker 0 が join して取り込み、書き出してから、確かめるか回復する)、worker 0 のほかのスレッドで SIGINT と SIGTERM を塞ぐことを作る。`eml_rt` には、別のスレッドからの解放と取り込み、ほかの worker のヒープの共有の物体 (rc < 0) を受け付けること、`Control` の ID の表、join の後の N 個のヒープの回復を作る。共有にした `poly` の入れ物を送り直すときの rc > 1 の局所の物体の扱いを決める ([オブジェクトモデル](../spec/object-model.md) の「`share`」の制限)。この段の利用者は `par` で、fork は空いている worker があれば右の子をその受け箱に置き、親は join で worker を手放して待ち、子の終わりは結果ごと親の worker へ知らせる。deque と盗みは `par-steal` に残す。worker 1..N-1 は I/O の driver を持たない (この段では要らない)。REPL は worker 1 つのままである。前提: なし。設計: [マルチコア対応の設計](multicore.md) の「スレッドと worker」、同じ文書の「別のスレッドからの解放」、同じ文書の「止める手順」
- `async-threads`: worker をまたいで `Async` のタスクを動かす。登録表を run の lock の下に置き、`Counter` の表を atomic にし、worker 1..N-1 の driver を置いたタスクが最初に使うときにそのスレッドで作り、スレッドをまたぐ受け箱の知らせ (`Wake`、`Place`、`Cancel`、`Completion`、`Submit`)、タスクを置く worker の選び方、受け付けの転送、worker をまたぐ `Chan`、`compute` を入れ、worker の数に応じて速くなることを測る。前提: `worker-threads`。設計: (unchanged)
- `par-steal`: VM の `par` の右の子を、空いている worker の受け箱に置く形から、worker ごとの Chase-Lev の deque と盗みに替える。join の待ちと知らせは `worker-threads` のものをそのまま使う。前提: `worker-threads`。設計: (unchanged)
- その後の項目 「マルチコア対応」に追加:
  - REPL の複数の worker: REPL は worker 1 つで動く。セッションの根を持つ run は worker 1 つで動く
    - 後に回した理由: 移し戻しは物体を写さないので、`par` の後に置いた根が別の worker のヒープのページの物体を指しうる。run の終わりにそのヒープを落とすには、ヒープを入力の間も生かす静止の手順か、run の終わりに根から届く物体を写すことが要る。
    - 見直す条件: REPL の中の `par` を並列に動かしたいとき。
  - `eml_sched` の crate: worker のループ、受け箱、監視のスレッドは `eml_vm` に置く
    - 後に回した理由: 実行系が VM だけで、`Exec` の trait に実装が 1 つしかない。
    - 見直す条件: `eml_native` が同じスケジューラを使うとき。
  - `par` の子の配置の粒度: 空いている worker があれば fork のたびに置く
    - 後に回した理由: 粒度は `std-par` の集まりの関数が持つ (1024 要素)。
