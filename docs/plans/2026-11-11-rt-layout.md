# eml_rtを物体の位置の唯一の定義にする段 (rt-layout)

- 作成日: 2026-11-11
- 基準: main @ 2d53193c (この文書の「背景」と、`ファイル:行`の参照はこのコミットの状態を指す)

## 1. 目的と完了の条件

- 目的: `eml_rt`自身のコードが読む物体の語の位置 (ヘッダの形と、`Kind::Data`の数の語) を、`eml_rt`の1か所だけで定める。書き出す規則がヒープの不変条件の使う規則と同じであることをVerusで証明し、`eml_vm`と`eml_lir`にある写しをその定義へ移す。後の段 (jit-core、jit-effects、native-inline、native-aot) が同じ仕組みで広げる契約を決め、ロードマップに書く
- 完了の条件: 7のT0〜T4をそれぞれ1コミットで入れ、各作業の完了の条件と、9の全体の検証が、すべて期待どおりになること

## 2. 範囲

- 範囲に入るもの: 新しいモジュール`crates/eml_rt/src/layout.rs`。`eml_rt`の中で数の語の規則とヘッダの形を書いているすべての所を、このモジュールを通す形にすること。`eml_vm`の`data::count_word`を消し、VMのフィールドの位置、クロージャの位置、reuseの`meta`、決まった形の物体を、モジュールから取ること。`eml_lir`のreuseの上限を名前の付いた定数にし、コンパイル時のassertで結び付けること。`docs/spec/object-model.md` (新しい節「語の位置」と関わる所)、`vm.md`、`lir.md`、`docs/implementation/testing.md`、`crates/eml_rt/CLAUDE.md`、`docs/future/native.md`、`docs/future/roadmap.md`。段を閉じる作業
- 範囲に入らないもの (後の段の仕事で、T3がロードマップに書く): `Meta`のビットの位置、`Word`のタグ、rcの符号を外から見えるようにすることと、箱の値の語、`Ctx`の欄のオフセット (jit-core)。evidenceの欄の役割 (jit-effects)。`Raw`、`String`、`Bytes`の中身の位置 (native-inline)。リンク時のABIの確かめ (native-aot)

## 3. 背景

- `eml_vm/src/data.rs:11-14`は、規則を`count_word(scanned) = u32::from(scanned >= 255)`と写して持つ。使うのは`apply.rs:234`と`apply.rs:295` (クロージャの読みと組み立て)、`compile/emit.rs:1057-1060` (`field_word`、物理的な位置のオペランド) である
- `eml_vm/src/data.rs:370-378`は、reuseの`meta`を`Meta::new(tag, scanned as u8, Kind::Data, lin)`で作り、`scanned < 255`にコメントだけで頼っている。`compile/forks.rs:79-108`、`vm.rs:1928-1938`、`vm.rs:2396-2400`は、小さな決まった形の物体を、決まった物理的な位置で作る
- `eml_lir/src/lib.rs:789-793`の`Shape::reuse_words`は`(self.scanned < 255)...`で、`verify.rs:985`は文字列"255 or more scanned words"をそのまま書いている。`eml_lir`は`eml_extern`と`rustc-hash`だけに依存する葉のcrateである
- `eml_rt`の中では、テストでない38行が規則を255か`EXTENDED_SCAN`で書いている。4つの実行の復号 (`heap/core.rs`の`scan_get`、`heap/graph.rs:918`、`remote.rs:297`、`heap/ctx.rs:2492`)、`alloc_data*`のensures、specの関数`p_extended`と`p_first` (`heap/inv.rs`) などである。ヘッダの形も、`8 * (HEADER_WORDS + x)`や`8 * (1 + x)`のような数で書いてある (13行)

- object-model.mdの「配列」は、ネイティブのコードが数を`base + 8`から、i番目の要素を`base + 16 + 8*i`から読むと書く。native.mdの「生の要素の配列」(L120) は`base + 8 + 8*i`と書いていて、これは誤りである

## 5. 決定

### 5.1 長期の方針 (変えるには見直しが要る)

実装がこの節と食い違ったら、止めて報告する。全文と適合の基準G-1〜G-16は付録の`01-contract.md`にある (8節が基準)。

#### D-1: 配置の契約に入るもの (P1〜P5)
- 決定: ある事実を`eml_rt`が持つのは、`eml_rt`自身のコードが同じビットを解釈するときに限る (P1)。持つ事実はどれも、specの定義と実行の定義を`eml_rt`の中に1つずつ持ち、`eml_rt`自身もそれを使う (P2)。事実は、その主題を持つ1つの面 (形は`eml_rt::layout`、metaのビットは`Meta`と`Kind`、語のタグは`Word`、後で`rc`と`Ctx`) だけで定め、ほかの面に写さない (P3)。この段は、`Kind::Data`とヘッダについて形の面を全部扱う。ほかの事実は、出すコードがそのビットを初めて読む段で外に出す (P4)。コード生成器は値をすべて`eml_rt`の`const`と`const fn`から取り、配置の数を書かない (P5)
- 理由: 食い違うとメモリの安全が壊れる所に線を引く。`eml_rt`の外に置いた写しは、ヒープの使う規則と同じであることを証明できない
- 採らなかった案: `count_word`だけを`eml_rt`へ移す案 (中の復号とspecはそれぞれの書き方のまま残り、一致を証明するものがない)。今すべてを出す案 (読む所のない出力が増え、evidenceの役割にはこの段にない設計が要る)。種類ごとのバイトのオフセットの表 (1つの規則に2つの単位ができる)
- 及ぶ範囲: 今は`eml_rt`、`eml_vm`、`eml_lir`。jit-coreからは`eml_native`も
- 見直す条件: `eml_rt`が解釈しない配置の事実をネイティブのコードが要るとき。物体の種類を足すとき
- 適合の確かめ: G-1〜G-5、G-9、G-10、G-16 (コマンドはT1とT2)
- リポジトリに残す所: object-model.mdの「語の位置」(T1、T2) と`crates/eml_rt/CLAUDE.md` (T1)

#### D-2: eml_lirとeml_rtの受け持ち
- 決定: `eml_lir`は`eml_rt`に依存せず、`eml_rt`は`vstd`だけに依存する (G-6)。フィールドの順 (`LayoutCtor::shape`) は`eml_lir`に残し、`Shape.positions`は数の語を数えない論理的な位置のままにする (G-8)。`eml_lir`のreuseの上限は`eml_lir`自身の方針で、名前の付いた1つの定数にする。reuseを`eml_rt`の上に下ろすcrateは、それぞれコンパイル時のassert `limit <= INLINE_SCAN_LIMIT`を1つ持つ。2つを結ぶ確かめはほかに置かない (G-7)
- 理由: `eml_lir`から`eml_rt`への依存は、`vstd`と実行系を`core`のfeatureのビルドに持ち込み、葉のcrateの規則を破る。健全さに要るのは`<=`で、2つの数は下向きに離れてよい
- 採らなかった案: 共有の葉のcrateを新しく作る案、しきい値をパスの引数で渡す案、assertを等号にする案、バイトコードのコンパイルでreuseごとに確かめる案
- 及ぶ範囲: `eml_lir`、`eml_vm`、後で`eml_native`
- 見直す条件: `eml_lir`が`eml_rt`のほかの事実を要るとき
- 適合の確かめ: G-6、G-7、G-8 (コマンドはT2)
- リポジトリに残す所: object-model.mdの「ペイロード」とlir.mdの「reuse の元」(T2)

#### D-3: 後の段が足すものと、AOTの確かめ
- 決定: jit-coreは、`Meta`のビットの位置とマスク、`Word`のタグの定数、rcの定数を、それぞれの面で外から見えるようにする。箱の値の語を`eml_rt::layout`に足し、`eml_rt`の箱の所と`eml_vm`の`compile/constants.rs`をそれに通し直す。`Ctx`の欄のオフセットを、`Ctx`の隣で`eml_rt::layout`の外に、`offset_of!`から求めた`pub const`として出す。D-2の`eml_native`のassertを足す。jit-effectsは、evidenceの欄の役割を`Ctx`の面に移し、`eml_vm`とeml_rtの補題にある役割の番号を消す。native-inlineは、`Raw`、`String`、`Bytes`の中身のために種類で引く語の添字の定数を2つ足し、`eml_rt`の中身の所を通し直す。native-aotは、出したobjectと`libeml_rt.a`が同じABIから来たことを、リンク時に確かめる仕組みを足す。この段は版も指紋も足さない。`eml_rt`がすでに中で読む事実を外に出す段は、同じ段で`eml_rt`自身の所もそれに通す (G-10)
- 理由: JITでは、コード生成器と実行系が1つの実行ファイルの中の同じ`eml_rt`なので、食い違えない。AOTで一致が要るのは、ABIの全体である
- 及ぶ範囲: それらの段のロードマップの文
- 適合の確かめ: G-9、G-10、G-12、G-13
- リポジトリに残す所: `docs/future/roadmap.md`と`native.md` (T3)

- コメントと文書は日本語で書く。英語で下書きしてPLaMoで訳し (`form: plain`、識別子は用語集に入れる)、日本語とLatin文字やインラインコードの間に空白を入れない (CLAUDE.md)。`03-reference.diff`の英語の仮のコメントは書き直す

- evidenceの物体の役割の番号と、クロージャの詰め方`f | k << 32`は変えない (G-16)。その所は形だけを変える
- テストの変更: 種類(1)と種類(2)はない。`trust.rs`の変更は種類(3)である。`crates/eml_vm/tests/bench.rs`と`crates/eml_lir/tests/shape.rs`はバイト単位で変えない。`trusted::`には何も足さない
- 新しいファイルを作ったら、verusfmtの確かめの前に`git add`する (しないと`git ls-files`に出ない)
- verusfmtは`unsafe {…}.bits()`を末尾の式として読めないので、`let`に束ねる。`frozen.rs`のimportは、分けた2行どちらにも`#[cfg(verus_only)]`が要る
- `meta.rs`に`EXTENDED_SCAN`を書く2行目 (たとえばconstのassert) を足さない。G-1と走査のテストが落ちる
