# 文書の整理の設計

位置づけ: 作業用の設計文書。整理を終えたら削除する。

## 目的と範囲

S2 に入る前に、`docs/` 全体を、今のプロジェクトを説明する簡潔な文書の集まりに組み直す。各文書は経緯を含まずに単独で読めるようにし、1つの事実は1つの文書にだけ書く。経緯は git の履歴で参照する。

前提として、M1 と S2 の前に予定した作業 (構文の段階 S1、名前解決以降の段階1〜6b、リファクタリング R0〜R7) が完了していることを確かめた。`cargo test` は 905 件が通り、release ビルドの性能テスト 6 件も通る。clippy の警告はなく、`cargo fmt --check` も差分がない。M1 の成功条件5つには、どれにも対応する UI テストがある。

コードとテストは変えない。

## 決めたこと

- ファイルの配置は今のままにする。`docs/implementation/test-changes.md` を削除し、新しいファイルは作らない
- テストの変更の理由は、その作業の spec とコミットメッセージに書く。種類1と種類2の合意の取り方は `testing.md` に残す
- 浮動小数と文字のリテラルは、ロードマップの項目にする。S2 と S3 には入れない
- CLAUDE.md の Rules に、簡潔で洗練された実装を第一とする指針を足した (このコミットに含める)

冒頭には位置づけと、M1 と構文の段階 S1 が完了したという1文だけを置く。日付、M1 の成功条件、名前解決以降の段階とリファクタリングの表、完了した作業の表、crate ごとの状況の表は削除する。crate ごとの状況は、内容が `architecture.md` と各 spec に重なる。本文は次の4節で、全体を70行前後にする。

1. 今の言語の範囲: 今の「マイルストーン1 の範囲」の「含めるもの」と「含めないもの」を、今動く言語の説明として書き直す。浮動小数と文字にはロードマップへのリンクを付ける

## 進め方

計画は `docs/superpowers/plans/` に置き、作業を終えたら spec と一緒に削除する。実行は3段に分け、段ごとにコミットする。

1. 内容を移す段: `status.md` を作り直し、注意点の行き先 (`roadmap.md`、`exhaustiveness.md`、`diagnostics.md`) に項目を足し、`test-changes.md` を削除し、`testing.md` の記録先を改める。移す側と受ける側を同じ段に入れ、中身が行き場をなくさないようにする
2. 重複と古い記述を直す段: 上の2つの表と「直す古い記述」の一覧を片づける
3. 入口を合わせる段: `README.md`、`overview.md`、CLAUDE.md を新しい構成に合わせる
