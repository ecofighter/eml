# S9b-2a 凍結した領域

位置づけ: S9b-2a の設計。終えたら決めたことを [オブジェクトモデル](../../spec/object-model.md) に移し、この文書を消す。

## 目的と範囲

S9b-2 ([ロードマップ](../../future/roadmap.md) の「S9 共通ランタイム `eml_rt`」) を2つに分ける。

| 作業 | 中身 |
|---|---|
| S9b-2a (この文書) | 不死の定数を置く凍結した領域。作る、凍結する、ヒープに付ける、寿命 |
| S9b-2b | `Ctx`、基本操作、SIGINT |

S9b-2a を先にするのは、核の操作の安全の前提を広げる作業を、基本操作の証明より前に独立して確かめるためである。

判断の基準は、簡潔で洗練された実装を第一に、次に性能である。ネイティブ化と VM の並列化で要ることも、今の判断に含める。

## 定数を共有の凍結した領域に置く理由

- ネイティブ化では、文字列リテラルはバイナリの読み出し専用のデータに置いた rc 0 の物体にするのが自然である (Lean、Koka と同じ)。どのヒープにも属さないプロセス全体の物体なので、ヒープの操作は「自分のページにない rc 0 の物体」を受け付ける必要がある
- `share` は不死の物体でたどりを止めるので、`par` で値を別の worker に渡すと、受け手は渡し手のヒープの不死の物体を指す語を受け取る。「自分のヒープにない不死の物体を受け付ける」条件はいずれ要る
- Ctx ごとに定数を作る案は採らない。今は簡単だが、ネイティブ化で静的なデータの形に作り直すことになり、リテラルを使うたびに表を1回引く手間も残るためである
- 領域の物体には、どの操作も書き込まない。速いモードの `dup` と `decref` は rc 0 を読んで何もせず、`share` と `release` も rc 0 の物体に書き込まない。下の「検査モードでは数えない」により、検査モードも書き込まない。読むだけの権限を共有すれば足りる

## 領域の鎖

- 領域は、凍結した塊の鎖である。`Frozen<M>` は、親の塊への `Option<Arc<Frozen<M>>>` を持つ。親は、作り手のヒープに付けていた塊である
- 塊の物体の走査する語は、即値か、その塊か祖先の塊のブロックを指す。祖先は `Arc` で生きているので、塊が生きている間、指す先も生きている
- ヒープが付けるのは、鎖の先頭の塊1つである。付けた塊とその祖先のブロックを指す語を受け付ける
- S11 の REPL は、入力ごとに新しい定数を新しい塊にして鎖を伸ばし、入力の境目でヒープの塊を先頭に替える
- 塊ごとに、使う大きさの級ごとに少なくとも 64 KiB のページを1つ取る。入力ごとに塊を作ると、使うメモリは入力の数に比例して増える。定数をまとめて凍結するか、後で凍結のときに詰め直すことで抑える (下の「範囲の外」)

## API

| 操作 | 動作 |
|---|---|
| `Heap<M>::freeze(self) -> Result<Frozen<M>, HeapError>` | 作り手のヒープを、付けていた塊を親とする新しい塊にする |
| `Heap<M>::attach(&mut self, region: Arc<Frozen<M>>)` | 付けている塊を、その子孫の塊 `region` に替える。何も付けていなければ、そのまま付ける。子孫でなければ panic する |

### 作る

- 作り手は普通の `Heap<M>` である。定数は今ある `alloc_string_immortal` と `alloc_immortal` (と `set_field`) で作る。専用の作り手の型は作らない
- 作り手は、前の塊を付けていてよい。後から足す定数が前の塊の定数を指せるようにするためである

### 凍結する

- `freeze` は、構築中の物体を書き終えさせ (`settle`)、どちらのモードでも実行時に次を確かめる。凍結はまれなので、速さより単純さを優先する
  - 検査モードの解放したブロックを除き、どのブロックも生存の状態 (空ける途中でない) で、rc 0 である。token の箱もない (`NotImmortal`)
  - `Foreign` の物体は、rc 0 にできない (`alloc_immortal` は `Foreign` を断り、`alloc_foreign` は rc 1 で作る) ので、上の確かめで断られる。領域に破棄処理と、値を複数のスレッドから読むときの `T: Sync` を持ち込まない
- 走査する語で閉じていることは、別に確かめない。どのブロックも rc 0 なので、自分のブロックを指す語は rc 0 の物体を指し、ほかの語は即値か、付けていた塊とその祖先のブロックだからである
- 検査モードでは、前置きの数の欄をどれも `UNCOUNTED` にする (下の「検査モードでは数えない」)
- 誤りなら `Err` を返し、作り手のヒープは普通に落ちる
- 通れば、ページ (ページの頭の権限を含む) と生きているブロックの権限を `Frozen<M>` に移す。各級の今のページの切り出しの位置をページの頭に書き戻してから移す。ブロックとページの頭の権限は vstd の `Shared` に入れる。`Shared` は Verus のビルドでだけ現れるので、欄に `#[cfg(verus_keep_ghost)]` を付ける
- `Heap` は `Drop` を持つので、作り手の中身を新しい空の中身と入れ替えてから落とす。入れ替えた後も `Drop` が求める不変条件を保つ
- 型の引数 `M` を持つので、前置きの形はいつもモードと合う
- `Frozen<M>` の不変条件 (ブロックの形、生存、rc 0、ドメインが有限、祖先の鎖) は、Verus の型の不変条件にする

### 付ける

- `attach` は、付けている塊を子孫の塊に替える。子孫かどうかは、`region` の親をたどって実行時に確かめる (`Arc` の番地を比べる)
- 鎖でつなぐので、2つの塊のブロックが重ならないことは、子の塊を作った作り手のヒープの確保の証明から出る (確保したブロックは、付けていた塊のどのブロックとも重ならない。`PointsTo::is_disjoint`)
- ヒープ自身のブロックと、付ける塊のブロックが重ならないことは、`attach` のときに、ヒープの持つブロックの権限 (`&mut`) と塊の権限 (`&`) の組ごとに `is_disjoint` で示す。その後の確保でも、新しいブロックと付けた塊の権限で同じことを示す
- ヒープは、塊の `Arc` と、そこから写した ghost の権限を1つの欄にまとめて持つ。権限は `Arc` が指す `Frozen` から写すので、`Arc` なしに権限だけを持つことはない

### 寿命

- 最後の `Arc` を落とすと、`Frozen` の `Drop` がページを返す。親への `Arc` は、再帰せずに手放す (長い鎖でスタックを溢れさせないため)。信頼の一覧の T4 を広げる
- vstd は `Arc::clone` の約束を持たないので、`assume_specification` を足す。信頼の一覧の T5 に入れる

### スレッドの性質

- `Frozen<M>` は `Send + Sync` である。型の assert で固定する。凍結した後はどこにも書き込まないので、並行に読んでも安全である。信頼の一覧の T0 を改め、「凍結した塊のメモリは、`Arc` で公開した後は書き込まれず、どのスレッドも読むだけである」を足す
- [マルチコア対応の設計](../../future/multicore.md) の「VM の並列化の備え」の制約2 (`CodeBase` が `Sync`) は、これに頼る

## 検査モードでは数えない

- 領域の物体は、前置きの数の欄を `UNCOUNTED` にする。今のダミーと同じ扱いで、`acquire_immortal`、`dup`、`decref` は数を変えず、確かめもしない
- 失うのは、リテラルだけに起きる RC の誤り (手放しすぎと手放し忘れ) の検出である。速いモードでは、不死の物体の RC の誤りは何も起こさない。Perceus はリテラルを特別に扱わないので、同じ誤りは死ぬ物体の値でも起き、検査モードはそちらで見つける。Lean と Koka も、持続する物体を数えない
- atomic に数える案は採らない。権限の値が実際の数と食い違わないようにする印、worker をまたぐ確かめと変更を1つの CAS にまとめる手間、文字列の操作の巻き戻し、S11 の回復での数え直し、領域の leaks、ネイティブの検査ビルドの書き込める静的なデータが要り、得るものに比べて大きいためである
- ヒープ自身の不死の物体 (`alloc_immortal` で作り、凍結していないもの) は、今と同じく数える

## Verus のモデル

- `has(h)` (このヒープのブロックか、付けた塊とその祖先のブロック) を足す。`word_ok`、`edge_wf` の行き先、`safe_slot` を `has` にする。ヒープの物体のフィールドに、領域の語を入れてよい
- `perm`、`block`、`cap`、`state` は、領域のブロックでは塊の `Shared` の権限を読む。領域のブロックの状態はいつも生存である。読む補助の関数 (`rc_get`、`meta_get`、`slot_get`、`cap_get`、`prefix_*_get` など) は、借りる先を ghost の条件で選ぶ (`carved_meta` と同じ形)。実行時の分岐は足さない
- RC の遷移のモデルの側 (`count_ghost`、`count_model`) に、rc 0 の行き先の場合を足す。状態と数は変えず、辺だけを外す
- `share` は rc 0 で止まるので、たどりは領域に入らない。グラフの見方 (`node_ok` など) だけを `has` に広げる
- 核の操作の表の「どの操作も」の行の安全の前提は、「語は即値か、このヒープのブロックか、このヒープに付けた塊とその祖先のブロックである」になる

## 容量を読むのは一意な左辺だけ

- `string_push` は、左辺が一意なときだけ容量を読む。今は一意かどうかを見る前に読んでいる。共有と不死の左辺 (領域のリテラルを含む) は容量を使わないためで、`リテラル ++ x` の道が少し速くなる
- これで、速いモードの操作は、rc 0 の物体のページの頭を読まない。ネイティブの静的なデータにはページの頭がないので、この性質を不変の約束として spec に書く
- 検査モードの `raw_check` は領域のブロックでもページの頭を読む。そのため、ページの頭の権限も塊に入れる

## 範囲の外

- 定数の番号から語への表と、LIR からそれを組み立てること。`CodeBase` が鎖の先頭の塊と語を持つ形は、S10 で VM と一緒に作る
- 別の worker が持つ物体 (共有、rc < 0) を受け付けること。rc の並行の書き込みが要る別の問題で、`par` を入れるときに扱う。`has` を広げる形は、その拡張を妨げない
- ネイティブの静的なデータ。rc 0、書き込まない、検査ビルドでは前置き付き、という同じ約束に乗る。検査ビルドの `raw_check` のようにページの頭を読む道は、ネイティブ化のときに、起動時に `freeze` で定数を作る形か、静的なデータに容量を持たせる形で扱う
- 凍結のときに生きている物体を詰め直して、塊のページを減らすこと。S11 の REPL と、S13 で採りうるトップレベルの値の1回だけの評価で、塊が増えて困ったときに入れる
- S10 の `RunStats` で、不死の物体の参照の数え方 (`rc_increments`) を CEK と比べられる形にすること。S10 の「`RunStats` の各項目の VM での意味」で決める

## 検証とテスト

- 単体テスト (`both_modes!`)
  - 凍結が通る場合 (文字列、`BigInt`、前の塊の定数を指す定数)。断る場合 (rc が正の物体、token、`Foreign`。どれも `NotImmortal`)
  - 付けた後の領域の語で、`dup`、`decref`、`release` (領域の子を持つ)、`field`、`scanned`、`meta`、`is_unique`、`is_last`、`string`、`string_push` (領域の左辺からの写し)、`string_concat`、`unbox_int`、`share` (領域で止まる)、`acquire_immortal`。領域の中身と前置きは変わらない
  - ヒープの物体のフィールドに領域の語を入れ (`set_field`)、解放の連鎖で手放す。`check_invariants` が受け付ける
  - 鎖: 子孫の塊に替える `attach`、子孫でない塊の `attach` の panic、祖先の塊の定数を指す定数
  - `Arc` を落とす順 (ヒープが先、塊が先、子が先) によらず漏れない
  - 型の assert: `Frozen<M>` は `Send + Sync`、`Heap` は `Sync` でないまま
- Miri (`trusted::`): T4 (`Frozen` の `Drop` がページを返し、長い鎖を再帰せずに落とし、どの順に落としても漏れない)、T0 (2つのスレッドが同じ塊の物体を読み、`dup` と `decref` を呼ぶ)、T8 (領域のブロックを読む借用の規則)
- Verus: crate 全体が 0 errors で通る
- 計測: `bench/rt.sh` のどの計測も S9b-1 から +0.5% を超えて増えない。速いモードの速い道は変えない (変更は ghost と、`string_push` の容量の読み込みの位置だけ)
