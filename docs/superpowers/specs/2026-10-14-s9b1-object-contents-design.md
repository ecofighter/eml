# S9b-1 物体の中身

位置づけ: S9b-1 の設計。終えたら決めたことを [オブジェクトモデル](../../spec/object-model.md) に移し、この文書を消す。

## 目的と範囲

S9b ([ロードマップ](../../future/roadmap.md) の「S9 共通ランタイム `eml_rt`」) を3つに分ける。

| 作業 | 中身 |
|---|---|
| S9b-1 (この文書) | 物体の種類ごとの中身。データの物理的な形の規則、クロージャ、evidence の3つの物体、文字列、`File` の表し方 |
| S9b-2 | `Ctx`、`FnEntry`、`CodeBase`、`CodeBase` の不死の定数、基本操作、SIGINT |
| S9b-3 | 語の ABI の extern、今の実装との差分テスト、FFI の境界の信頼の一覧の行と Miri |

順序の理由: extern は文字列と `File` と出力先 (`Ctx`) を使い、`CodeBase` の定数は文字列とクロージャの形を使う。

判断の基準は、簡潔で洗練された実装を第一にし、その次に性能である。種類を分けて得られるのがリークの報告の名前や検査モードの種類の検査だけなら、種類を分けない。

## 種類

種類は `String` を1つだけ足し、`Data`、`BigInt`、`Foreign`、`String`、`Free` の5つにする。

| 種類 | 番号 | ペイロード | 走査の始まり | token | 破棄処理 |
|---|---|---|---|---|---|
| `String` | 3 | 生の1語目にバイト長、その後に UTF-8 のバイト列 | 0 (`scan` は 0) | できない | なし |

- `String` は token にできない。token の箱はいつも `Data` であるという性質 (`con_at` が書き直さない語の権限の扱い) を崩さないためである。reuse analysis も文字列を対象にしない
- `Foreign` と `String` のペイロードは、核の操作から見て不透明である。種類の欄に「ペイロードが不透明か」(`Foreign` か `String`) を足し、`raw` と `set_raw` はこの欄で断る。今の `raw` と `set_raw` が `Foreign` を断るのに使っている「破棄処理を持つか」を、この欄に置き換える。文字列の語は途中までしか書いていないことがあり、`raw` で語として読むと未初期化のメモリを読むためである
- 後の項目の種類の見通し: `Float` は `BigInt` と同じく1語の箱の種類を足すか `BigInt` の形を使う。`Bytes` は `String` と同じ形 (長さとバイト列) を使える。`Array` は別の種類が要る。種類の数の上限 16 には余裕がある

## 物体の形

| 物体 | 種類と tag | ペイロード |
|---|---|---|
| データ | `Data`、コンストラクタの添字 | 下の「物理的な形」 |
| クロージャ | `Data`、0 | 走査する語に [`&f` の即値, 引数...] |
| `evv` の節点 | `Data`、エフェクトの番号 | [evidence, next] |
| evidence | `Data`、エフェクトの番号 | [入口の表, 状態, 外側の `evv`] |
| 入口の表 | `Data`、0 | [入口のクロージャ...] |
| 文字列 | `String`、0 | 上の「種類」 |
| `File` | `Foreign`、`lin` ビットを立てる | 中身の型は S9b-3 で extern と一緒に置く |

### 物理的な形

- 宣言の順のフィールドのうち、Repr が `obj` か `tobj` のもの (`Repr::is_rc`) を宣言の順に走査する語として並べ、その後に残り (`int`、`enum`、`unit`) を宣言の順に生の語として並べる。`unit` のフィールドも1語を取る。宣言で `()` を持つフィールドはまれなので、語を取らない3つ目の場合を作らない
- 解放の連鎖は子を走査の逆の順に積むので、最初の走査する語を先に、最後の走査する語を後に解放する。cons セル (`a :: List a`) は [要素, 残り] になり、要素を解放し終えてから残りに進むので、要素が物体のリスト (`List (Int, Int)` など) でも作業リストの長さは定数に収まる。この性質は、再帰するフィールドが最後の走査する語であるときに成り立つ。`data Snoc a = Nil | Snoc (Snoc a) a` のように再帰するフィールドが前にある型では、作業リストは長さに比例して伸びる。作業リストはヒープの `Vec` なので、伸びても Rust のスタックは溢れない
- 規則を出す関数は `eml_lir` に置く (`Layout` から、宣言の位置ごとの物理的な位置と、走査する語と生の語の数を出す)。`eml_rt` は今と同じく tag、走査する語の数、生の語の数だけを受ける。規則を使うのは、`CodeBase` を組み立てる側 (S10 の VM) と後の reuse analysis で、どちらも `eml_lir` に依存するので、規則は1か所にあり、結び付けのテストは要らない。関数は、最初に使う S10 で足す。今足すと使われないコードになるためである。S9b-3 の extern が作るデータ (`Bool`、`Ordering`、`Fs.read_all` の組 `(File, String)`) は、どれもタグだけか走査する語だけなので、規則の関数がなくても形が決まる

### クロージャ

- 関数は、最初の走査する語の即値に置く。即値は走査で飛ばされるので、生の語に分ける必要がない。`apply` は即値か物体かを語で見分けるので、種類は要らない
- VM は関数を `scanned(w, 0)`、捕まえた値と部分適用の引数を `scanned(w, 1..)` で読み、その数を `scanned_len(w) - 1` とする。`field(w, 0)` では読まない。走査する語が 255 個以上のクロージャ (EP の継続のクロージャがありうる) では、ペイロードの先頭に数の語があり、関数は `field(w, 1)` にあるためである。`apply` の場所ではクロージャの形が静的に分からないので、この規則を守る
- 共有されたクロージャの中身を使うとき (`apply` が中身を写す) の別の操作 `copy` は作らない。VM が今ある部品を並べる。`is_last` なら引数を読んで `free_block`、そうでなければ引数を `dup` してから `decref` する。引数の数と関数の引数の数は、`apply` が読む `FnEntry` (S9b-2) と上の `scanned_len` で決まる
- VM が実行時に作るクロージャ (部分適用で引数を足したもの) の `lin` ビットは、元のクロージャのビットを写す。元が即値の `&f` ならビットを立てない。クロージャの印は捕まえた値の印の結びで ([LIR とインタプリタ](../../spec/lir.md) の「Kind の印」)、足す引数は `apply` のオペランドなので `poly` であり、ビットを立てる理由にならないためである
- クロージャを `Data` にして token にできても、reuse の危険はない。クロージャを `release` する命令はなく、reuse analysis は `release` を書き換えて token を作るためである

### evidence の3つの物体

- `evv` の節点の tag をエフェクトの番号にする。`ev_lookup` と `evv_mask` は、節点ごとに節点自身の `meta` の tag を比べるだけで済み、evidence の物体を読まない。`perform` のたびに、節点ごとの依存した読み込みが1回減る
- evidence の tag もエフェクトの番号にする。`evv_push` は引数の evidence の tag を1回読んで節点の tag に写す。入口の表の tag は読まないので 0 にする
- エフェクトの数の上限は、コンストラクタと同じ 65536 になる
- 3つを別の種類にしない。速いモードの振る舞いは `Data` と同じで、分けて得られるのはリークの報告の名前と検査モードの種類の検査だけだからである。リークの報告では、クロージャと evidence の物体も `Data` と数える。今の UI テストの出力に種類の名前は現れない
- `ev_set_state` と `ev_take_state` は、状態の欄を `set_field` でその場で書き換える。`set_field` の安全の前提 (ほかのスレッドが読めない) は、S10 のシングルスレッドの VM では成り立つ。`par` を入れるときに、evidence を共有の印の付いた物体にしない (子のタスクに渡さない) か、状態の欄の書き換えを見直す。evidence は `CodeBase` の不死の定数にしない (空の `evv` は即値の `()` である)

## 文字列

### 不変条件

- 種類 `String` の物体は、バイト長が容量以下で、バイト列が妥当な UTF-8 である。作れるのは下の文字列の操作だけにする
  - `alloc`、`alloc_immortal`、`con_at` は、安全の前提で種類 `String` の `meta` を断る (今の `Foreign` と `Free` と同じ)。`reuse_in_place` は箱と同じ種類の `meta` しか受けず、token の箱は `Data` なので、断る必要がない
  - `raw` と `set_raw` は、上の「種類」のとおり不透明なペイロードを断る。速いモードでは前提にし、検査モードは `WrongKind` を返す (今の `Foreign` と同じく、検査する前提)
  - `release` と `release_reuse` は今と同じくデータだけを受ける (`WrongLayout`)
- 文字列のバイト列は、Verus の ghost の値 (`Seq<u8>`) としてブロックの権限に持つ。バイト長はその長さに等しく、容量以下である。バイト列が UTF-8 であることは vstd の `valid_utf8` で書き、連結で保たれることを `valid_utf8_concat` で証明する。そのため、UTF-8 であることは信頼の一覧に入れず、Verus が確かめる
- この条件は、速いモードの不変条件 (`full`) と検査モードの不変条件 (`safe_wf`)、ブロックの形の条件 (`block_shape`) のすべてに置く。今の `BigInt` の値の条件と同じ場所である。速いモードの `string` が範囲の中を読むことの証明にも要るためである。`set_field` が `String` の物体の走査する語の数 0 を保つことも、同じ条件で示す

### 操作

| 操作 | 動作 |
|---|---|
| `alloc_string(s: &str) -> Word` | 安全な関数。`s` を写した文字列を作る。容量は級の大きさまで |
| `alloc_string_immortal(s: &str) -> Word` | 安全な関数。rc 0 で作る。S9b-2 の `CodeBase` の文字列の定数が使う。`alloc_immortal` が `String` を断るので、ここで足す |
| `string(w) -> Result<*const str, HeapError>` | `unsafe fn`。中身の位置を返す。`foreign` と同じく生のポインタにし、ヒープの借用に縛らない。指す先は、w の物体が生きていて、`string_push` でその物体を書き換えていない間だけ読める。検査モードは種類を照らして `WrongKind` を返す |
| `string_push(left, s: &str) -> Result<Word, HeapError>` | `unsafe fn`。left の参照を受け取り、`s` を後ろに足した文字列の参照を返す。文字列のバイトを書く操作はこれだけである |
| `string_concat(left, right) -> Result<Word, HeapError>` | `unsafe fn`。`++` そのもの。両辺の参照を受け取り、結果の参照を返す。`string_push(left, string(right))` の後に `right` を `decref` する |

`string_push` の動作は次のとおりである。

```
left が一意 (is_unique)
  容量が足りる → その場で s を書き、長さを書き換える
  足りない     → max(必要量, 2 × 容量) で確保し、left と s を写してから、left の箱を free_block
そうでない (共有、不死) → 和の長さで確保し、left と s を写してから、left を decref
```

- `s` は、ほかの文字列の物体の中身を指してよい (`string_concat` の右辺)。写すのは、left を手放す前である。速いモードでは、大きい物体のページを `free_block` がすぐに返すためである
- `s` は left 自身の中身を指さない。一意な left を作り直すと、`string_push` の中で left の箱を空け、大きい物体ならページも返す。引数の `&str` が指すメモリを呼び出しの間に返すと、写した後でも未定義の動作になるためである。自分自身との連結は `dup` と `string_concat(x, x)` で行う。右辺は `&str` の引数でなくヒープの権限から写す直前に借りるので、この制約を受けない
- `string_concat` の `x ++ x` は、`dup` で rc が 2 になって届くので、写す側に進む
- 容量は、今ある `cap_of` (ブロックのペイロードの語の数) から長さの1語を引いたバイト数である。大きい物体も、ページの頭のブロックの大きさから同じ式で出る。検査モードでは前置きの分だけ容量が1語小さくなることがあるので、テストは期待値を容量から求める
- 容量を倍にするので、一意な左辺に足していくループは、ならすと右辺の長さに比例する時間で済む。今の `eml_runtime` と同じ性質である
- 大きさの計算は `checked_add` と `checked_mul` で行い、桁あふれは今の確保と同じく `too_large` の panic にする (T5)
- `string_concat` を `string_push` の上に組むのは、バイトを書く信頼の関数を1つにするためである。S12 の extern (`join`、`replace` など) が Rust の側の `&str` を足すときも、`string_push` を使えば余分な写しが要らない

### 検査モードの誤り

- `string_push` と `string_concat` は、どの誤りも最初の確保より前に返す。そのため、`Err` を返したときのヒープは変わらない。文字列は子を持たないので、left と right の `decref` の誤り (`UseAfterFree`、`ImmortalOverRelease`、`WrongOwner`) をすべて先に確かめられる。left と right が同じ物体で rc が 1 のとき (モードの前提を破った呼び出し) も、2回の `decref` を続けて確かめるので、ここで断る
- 誤りは、語を受ける操作の共通の誤り (`UseAfterFree`、`WrongOwner`) と、種類が `String` でないときの `WrongKind`、不死の物体の手放しすぎ (`ImmortalOverRelease`) である
- 文字列の不死の定数のほかの扱い、`show`、比較、`println` は S9b-2 と S9b-3 で作る。どれも `string` で読むだけなので、ここで足す操作はない

## 信頼の一覧の T10

| # | 中身 | 理由 | Miri で確かめること |
|---|---|---|---|
| T10 | 文字列のバイトの読み書き。`String` のブロックの権限を受けてペイロードにバイトを写す関数と、ペイロードを `str` の位置として返す関数。約束は、メモリのバイト列が権限の ghost のバイト列 (`Seq<u8>`) に等しいこと、写すのは長さの語の後ろの容量の中だけで、長さの語の値と権限の位置を変えないこと | Verus の権限は語の単位で、語の中のバイトの位置を扱わない | 語に揃わない位置への追記、大きい物体のページをまたぐ長さ、大きい左辺からの作り直し、空の文字列、1ページの長さを含む自分自身との連結 (`x ++ x`)、`string` で読んだ位置の使用が終わった後の追記、2つの借用の規則での読み書き |

- 写すのは生のポインタ (`ptr::copy_nonoverlapping`) だけで行い、同じブロックに `&mut [u8]` と `&[u8]` を同時に作らない
- 範囲は、検証したコードの側の `requires` と `ensures` で縛る。今の `Foreign` (T3) と同じ形である
- `trust.rs` の番号の一覧に `T10` を足し、新しいファイルを走査の対象 (`FILES`) と信頼の項目の一覧に足す

## `Float` の語の表現

S9 の論点から外し、ロードマップの「`Float`、`Char`、`Num`」の項目に移す。ロードマップがすでに「型より前に入れると死んだコードになる」としているためである。方向は `BigInt` と同じく、`tobj` の位置では箱、`float` の位置では生の 64 ビットである。

## S10 への申し送り

- `RunStats` の `string_bytes_copied` は、VM が `string_push` を呼ぶ前に `is_unique` と容量を見れば数えられるので、`eml_rt` に欄を足さない。一意な左辺を作り直すときの数え方は、S10 の「`RunStats` の各項目の VM での意味」で決める

## 検証とテスト

- Verus: 文字列の操作を、ほかの核の操作と同じく抽象のモデルの上で証明する。`string_push` は「left の参照を1つ消費し、結果の参照を1つ作る」遷移で、その場で足す枝と作り直す枝と写す枝のすべてを含む。ghost のバイト列が連結になること、UTF-8 が保たれること、容量の計算、不変条件の長さの条件を保つことも証明する。`raw` と `set_raw` が不透明なペイロードを断ることで、ほかの検証した操作が文字列のバイトを書かないことも、Verus が確かめる
- 単体テスト (`both_modes!`): 空の文字列、級の境目と 128 語の境目をまたぐ長さ、一意な左辺のその場の追記、容量が足りないときの作り直し、共有と不死の左辺、容量に収まる長さと語を埋める長さの `x ++ x`、検査モードの `WrongKind` (`string`、`string_push`、`string_concat`、`raw`、`set_raw`)、`Err` の後にヒープが変わっていないこと
- 回数の性質: 一意な左辺へ 1 バイトずつ n 回足すループで、作り直しの回数 (`string_push` が返す語が左辺と違った回数) が log n で抑えられることを確かめる。容量を読む操作やテストのためだけの欄は足さない
- Miri: T10 の「Miri で確かめること」を `trusted::` に足す
- 計測: `rt_bench` に文字列の追記の場合を足し、`bench/rt.sh` の結果を [計測の基準](../../implementation/benchmarks.md) の「S9b-1」に記録する

## テストの変更

`eml_rt` はまだパイプラインから使わないので、UI テストの出力も `bench/` の仕事の回数も変わらない。成否の変更と期待値の変更はない。`eml_rt` の今の単体テストのうち、`raw` と `set_raw` の `Foreign` の断りを確かめるものは、欄の置き換えの後も同じ期待値で通る。
