# S12c ローカルの再帰関数の設計

## 目的と範囲

S12 (スクリプトの MVP) の3つ目の作業である。ブロックの中に、自分を呼べるローカル関数を書けるようにする。

ねらいは、accumulator を持つ再帰の補助関数を、使う関数の中に閉じ込めて書けるようにすることである。今は `std/List.em` の `map_onto` や `std/String.em` の `split_from` のような補助関数をトップレベルに置くしかなく、モジュールの名前空間に出てしまう。ローカルに移しても、トップレベルに書いたときと同じ性能を保つ。

ロードマップの S12 の「決めたこと」のうち、S12c のものは次の1つで、この spec はその細部を決める。

- ローカルの再帰関数を入れる。`let (f, text) = Fs.read_all f` のような再束縛を壊さないように、引数を持つ関数の形のローカル定義だけを再帰的にする。単相で、lambda lifting する

ロードマップの論点「ローカルの再帰関数の構文」は、ブロックの中に `let go acc xs = …` と書く形に決めた (下の「構文」)。

次のものは範囲に入れない。

- 多相なローカル関数
- ローカル関数どうしの相互再帰
- 複数の等式によるローカル関数の定義 (場合分けは本体の `match` で書く)
- ローカル関数のシグネチャと、結果の型の明示
- REPL の `let` の入力を関数の形で書くこと

多相と相互再帰は、ロードマップの論点として残す (下の「ロードマップ」)。今回の表現は、後でこの2つを足しても作り直さずに済む形にする (下の「拡張への備え」)。

決めたことは、段の終わりに下の「文書」の場所へ移す。

## 利用者から見た動き

### 構文

```haskell
pub map : (a -> <e> b) -> List a -> <e> List b
map f xs =
  let go acc ys =
    match ys with
      | Nil -> reverse acc
      | y :: rest -> go (f y :: acc) rest
  go Nil xs
```

- ブロックの文 `let name apat+ = body` で、ローカル関数 `name` を定義する。引数はラムダの引数と同じく `apat` で書き、`(acc : Int)` のように型を明示できる
- 1行の形 `let name apat+ = e in e2` も書ける。ブロックの文と同じ意味である
- 等式は1つだけである。同じ名前の `let` を続けて書くと、今と同じく後の定義が前の定義を隠す
- 関数の形のとき、引数の後ろに `: type` は書けない。書いたら E0011 にする (私の判断。結果の型の明示は、後で入れるシグネチャの形と合わせて決めるため)

関数の形かどうかは、`let` の直後のトークン列で決める。`let` の次が小文字の名前で、その次が `apat` を始めるトークンなら関数の形である。次の例はどれも今のとおりパターンの束縛のまま読む。

- `let x = e`、`let x : T = e` (名前の次が `=` か `:`)
- `let (f, text) = e`、`let Some x = e` (最初がパターン)
- `let x :: rest = e` (名前の次が演算子)

### 有効範囲

- 関数の形の `let` では、`name` の有効範囲が、その本体と、ブロックの残り (1行の形なら `in` の後ろ) を含む
- 引数の名前は本体の中で `name` を隠せる (`let go go = …` の本体の `go` は引数である)
- パターンの束縛の有効範囲は今のままである。`let x = x + 1` と `let f = fn y -> f y` の右辺の `x` と `f` は、外側の束縛を指す

### 型

- ローカル関数は単相である。本体を検査する前に、関数の型に推論用の型変数を1つ置き、自分の参照も同じ型として扱う。ラムダと同じく、各矢印の線形性と row も推論する
- 外側の関数のシグネチャの型変数と row 変数は、ローカル関数の本体でも見える。今のラムダと同じである
- row も単相である。ローカル関数を呼ぶと、その row を今の row に含める (`include_row`)。row の末尾が推論用の変数のままなら、最初の呼び出しの位置の row と単一化される。そのため、自分の handler の中と外の両方から同じローカル関数を呼ぶと、先に handler の中で呼んだときだけ E2002 になる。今のラムダと同じ制限で、今回は受け入れる。直すときは多相なローカル関数とあわせて決める (下の「ロードマップ」)

### 線形性

- 本体の中で自分を参照するローカル関数 (再帰するローカル関数) は、何度も呼ばれうる。そのため、その関数の型の Kind は `Unr` でなければならない。関数の型の最初の矢印の線形性に `Unr` の制約を加える
- 捕まえた値の Kind は、今のラムダと同じ規則 (`closure_kinds`) で矢印の線形性以下になる。そのため、再帰するローカル関数は `Unr` の値しか捕まえられない。`File` のような `Lin` の値は、捕まえずに引数で受け渡す。今のトップレベルの補助関数と同じ書き方である
- 後の矢印は、前の引数に `Lin` の値を受け取れば `Lin` になりうる。これも今のラムダと同じである。`let go f acc = …` の `go f` は、`f` が `File` なら1回だけ呼べる閉包である
- 本体の中で自分を参照しないローカル関数は、ラムダと同じ扱いになる。`Lin` の値を捕まえて、1回だけ使える関数になれる
- 再帰するローカル関数が `Lin` の値を捕まえたときの誤りは、捕まえた変数と、自分を参照した位置の両方を示す。文言は「自分を呼ぶので何度も呼ばれうる」ことが分かるものにする。今の Kind の誤りの経路に新しい由来 (`KindReason`) を足すか、新しい診断コードを足すかは実装で決める

### 性能

- ローカル関数は、外側の関数の中で直接呼ぶ。呼ぶたびに閉包を確保しない
- 自分への末尾呼び出しは、トップレベルの関数と同じく contract が `tail` にする。長いリストでも VM の深さの上限に当たらない
- ローカル関数を値として使ったとき (`map go xs` のように引数に渡したとき、引数が足りないとき) だけ、閉包を作る

完了の判定に、同じ計算をトップレベルの補助関数で書いたプログラムと、ローカル関数で書いたプログラムの `RunStats` が一致することを使う (下の「テスト」)。

### REPL

- REPL の `let` の入力は、今と同じく1つの名前だけを束縛する。`let f x = 1` は E0011 のままである。文言は、関数を定義するならシグネチャと等式で書くよう促すものに変えてよい (私の判断)
- 入力の中のブロックでは、ほかの関数と同じくローカル関数を書ける

## 設計

### 構文 (`eml_syntax`)

- `let_head_and_body` (`grammar/expressions.rs`) で、`LET_KW` の後が `LIDENT` で、その次が `apat` の始まりなら、関数の形として読む。名前、1つ以上の `apat`、`=`、本体の順である
- CST には、関数の形を表す節点を足す。ブロックの文の `LET_STMT` と `let … in` の `LET_EXPR` の両方で、関数の形を区別できるようにする。新しい節点の種類にするか、`LET_STMT` / `LET_EXPR` の中に引数の並びの節点を持たせるかは実装で決める
- 型付きの AST の `LetStmt` と `LetExpr` に、関数の形の名前と引数を取る関数を足す
- REPL の `let_or_expr_input` は今のまま、関数の形を E0011 にする
- 文法 (`docs/spec/grammar.md`) の `stmt` と `expr` の規則に、関数の形を足す

### HIR (`eml_hir`)

- `Stmt` に、ローカル関数の組を表す種類を足す。組は1つ以上の `LocalFunction` を持ち、今は要素が常に1つである。`LocalFunction` は、名前の `LocalId`、引数と本体 (今のラムダと同じ `Closure`)、定義の位置を持つ
- `lower_stmts` は、関数の形の `let` では、先に名前を有効範囲に入れてから、引数と本体を下ろす。パターンの束縛は今のまま右辺を先に下ろす
- `let … in` の関数の形も、今と同じく1つの文のブロックにする
- `Body` に、`LocalId` からローカル関数を引く表を足す。後の段は、この表でローカル関数の参照を見分ける
- `Body::closure_captures` は、ローカル関数の捕まえる変数も求められるようにする。自分自身の `LocalId` は捕まえる変数に入れない
- `eml_hir::known_arity` (`eval.rs`) は、ローカル関数の参照にも引数の数を返す。これで translate の `call_head` と `saturate` が、ローカル関数への呼び出しを、引数の数がちょうどの直接呼び出し、足りない呼び出し、余る呼び出しに分けられる

### 型検査 (`eml_types`)

- `stmts` (`check/body.rs`) は、ローカル関数の組を次の順に検査する
  1. 組の各関数に、推論用の型変数を置いて `typing.locals` に書く
  2. 各関数の本体を、ラムダと同じく `check_lambda` で検査する。`row` は今の `lambda_yields` と同じく関数ごとに記録する
- `usage.rs` は、ローカル関数をラムダと同じく扱う。加えて、本体の中に自分の参照があれば、関数の型の Kind に `Unr` の制約を加える (上の「線形性」)
- `carry.rs` も、ローカル関数をラムダと同じく扱う。捕まえる変数は、定義の位置で生きているものとする。translate が持ち上げの捕まえる変数を呼び出しのたびに渡しても、`go` の Kind はその捕まえた値の Kind 以上なので、`go` を持っていることの検査が、捕まえた値を持っていることの検査を含む
- `BodyTypes` で、ラムダの式で引く表 (`lambda_yields`) を、ローカル関数でも引けるようにする。キーを式にするかローカル関数の識別子にするかは実装で決める

### translate (`eml_core_ir`)

- ローカル関数は、外側の instance を変換するときに、今のラムダと同じく `lift` で内部の関数 (`internal`) にする。引数は、捕まえる変数を先に、宣言した引数を後に並べる。単相なので、外側の instance ごとに1つの関数になる
- 名前は `<外側の instance の名前>$<ローカル関数の名前>` とする (`map@[Int, Int]$go`)。同じ instance の中で名前が重なるときは、HIR の順で番号を付けて区別する。付け方は実装で決める
- ローカル関数への参照は次のように変換する
  - 引数がちょうどの呼び出しは、直接呼び出し `Call::Direct` にする。捕まえる変数を先に渡す。本体の中の自分への呼び出しでは、自分が受け取った捕まえる変数の引数をそのまま渡す
  - 引数が足りない呼び出しと、値としての参照は、使う位置で閉包 (`closure`) を作る。捕まえる変数がなければ `Atom::Fn` にする
  - 引数が余る呼び出しは、今のトップレベルの関数と同じく、直接呼び出しの後に `apply` を続ける
- 上の規則は、ローカル関数を参照するのがどの内部の関数でも同じである。ラムダ、`use` が作るラムダ、handle の本体、節、別のローカル関数、ローカル関数自身の本体の中のラムダから参照しても、直接呼び出しのままにする (私の判断。`use` と handle の中でも閉包を作らないため)
- そのため translate は、HIR の捕まえる変数とは別に、持ち上げた関数の引数にする変数 (持ち上げの捕まえる変数) を求める。持ち上げの捕まえる変数は、HIR の捕まえる変数に含まれるローカル関数を、そのローカル関数の持ち上げの捕まえる変数に置き換えたものである。ローカル関数が別のローカル関数を参照するので、置き換えを不動点まで繰り返す。自分自身は置き換えから外す
  - `usage.rs`、`carry.rs`、`closure_kinds` は、今のまま HIR の捕まえる変数を使う。入れ子のラムダがローカル関数 `go` を参照することは、`go` の1回の使用であり、`go` が捕まえた値の使用ではない。`closure_kinds` で `go` の Kind はその捕まえた値の Kind 以上になるので、`go` を捕まえたラムダの Kind も、`go` の捕まえた値の Kind 以上になる。持ち上げの捕まえる変数を直接渡しても、所有の数え方は変わらない
  - debug ビルドの `check_captures` も、HIR の捕まえる変数の型で確かめる
- `yields` の印は、ローカル関数の row から、外側の instance の row のビットで決める。ラムダと同じである
- debug ビルドの `check_captures` は、閉包を作る位置で今のまま確かめる
- ローカル関数は値として使うと、boxing が今の内部の関数と同じく扱う。直接呼ばれてかつ値として使われる関数は、形を保って `f$boxed` を作る

### 拡張への備え

多相なローカル関数と相互再帰を後で足すとき、次のところを広げるだけで済むようにする。

- HIR の `Stmt` は関数の組を持つ。相互再帰は、組に複数の関数を入れる構文を足すことで入れる
- 型検査は、組を単位に、全員の型変数を先に置いてから本体を検査する。相互再帰はこのまま動く。多相は、組の検査の後に汎化の手順を差し込む形で入れる。トップレベルの SCC と同じく、組の本体の型は組を解いた後に書き出す
- translate は、組の各関数を内部の関数にする。相互再帰では、組の捕まえる変数の和をすべての関数の引数にする

## テスト

### UI テスト

`run` には次のテストを足す。どれも checked と fast の両方で流れる。

- 末尾再帰の accumulator のループ (100,000 要素程度のリストで、VM の深さの上限に当たらないこと)
- 外側の引数を捕まえる再帰 (`map` の `f` を捕まえる形)
- `let … in` の1行の形
- 値として渡すローカル関数 (`map go xs`) と、部分適用 (`let add x y = x + y` の `add 1`)
- 自分を参照しないローカル関数が `File` を捕まえて1回だけ呼ばれる形
- `File` を引数で受け渡す再帰するローカル関数
- 同じ名前のローカル関数の再定義 (後の定義が前を隠す)
- エフェクトを起こすローカル関数 (handler の中で再帰しながら操作を起こす)。上の row の制限に当たらないよう、定義と呼び出しを handle の本体の中に置く
- `let x = x + 1` が外側の `x` を指すこと (今の振る舞いが変わっていないこと)

`check-fail` には次のテストを足す。

- 再帰するローカル関数が `File` を捕まえる
- 再帰するローカル関数が `once` の継続 `k` を捕まえる
- 関数の形の `let` に `: type` を書く (E0011)
- ローカル関数の型が決まらない誤り (ラムダと同じ扱いになることを確かめる)

REPL のトランスクリプトには次の2つを足す。

- `let f x = 1` の入力が E0011 になること
- 式の入力の中のローカル関数

### 段ごとのテスト

- parser: 関数の形とパターンの束縛の読み分け (上の「構文」の例すべて)、`let … in` の関数の形
- HIR: 有効範囲 (自分を参照できること、引数が名前を隠すこと)
- Core IR: ローカル関数が `<instance>$<名前>` の内部の関数になり、呼び出しが直接呼び出しになること。LIR で自分への末尾呼び出しが `tail` になること

### 性能の確かめ

`eml_vm` のテストで、同じ計算を2通りに書いたプログラムの `RunStats` が一致することを確かめる。1つはトップレベルの補助関数、1つはローカル関数で書く。トップレベルの版は、ローカル関数が捕まえる値を先頭の引数で受け取る形にする。lambda lifting 後の関数と同じ形になるためである。

### 標準ライブラリ

`std/List.em` と `std/String.em` の補助関数のうち、1つの関数からしか使わないものをローカル関数に移す (`length_from`、`map_onto`、`filter_onto`、`filter_map_onto`、`same_bytes`、`split_from`、`lines_from`、`join_onto`、`skip_space`、`trim_back`、`accumulate` など)。複数の関数から使うもの (`reverse_onto`、`matches_at`、`is_space` など) はトップレベルに残す (私の判断)。移した後も `tests/ui/run/std/` の UI テストがそのまま通ることを確かめる。

### テストの変更

- 種類 2 (期待値の変更): std の関数の名前や行を含むスナップショットを書き直す。Core IR や LIR のダンプに std の補助関数の instance 名 (`map_onto@[…]` など) が出るもの、実行時エラーの位置が `<std>/List.em` か `<std>/String.em` の行を指すものが当たる
- 種類 1 (成否の変更): なし

## ロードマップ

S13 の論点に次の2つを足す。

- 多相なローカル関数。シグネチャの書き方 (ブロックの中にシグネチャの行を書くか、`let` に型を明示するか) と、注釈のない汎化をするかを決める。あわせて、row が単相なことによる制限 (handler の中と外から同じローカル関数を呼ぶと、呼ぶ順序で E2002 になる) を直すかを決める。直し方の候補は、本体を検査した直後に自由な row の末尾を閉じ、値として参照するときにトップレベルの関数と同じく開くことである
- ローカル関数どうしの相互再帰。組を作る構文 (連続する関数の形の `let` を1つの組にするか、`and` のような区切りを入れるか) を決める
