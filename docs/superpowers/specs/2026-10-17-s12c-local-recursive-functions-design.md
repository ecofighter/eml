# S12c ローカルの再帰関数の設計

## 目的と範囲

S12 (スクリプトの MVP) の3つ目の作業である。ブロックの中に、自分を呼べるローカル関数を書けるようにする。

ねらいは、accumulator を持つ再帰の補助関数を、使う関数の中に閉じ込めて書けるようにすることである。今は `std/List.em` の `map_onto` や `std/String.em` の `split_from` のような補助関数をトップレベルに置くしかなく、モジュールの名前空間に出てしまう。ローカルに移しても、トップレベルに書いたときと同じ性能を保つ。

ロードマップの S12 の「決めたこと」のうち、S12c のものは次の1つで、この spec はその細部を決める。

- ローカルの再帰関数を入れる。`let (f, text) = Fs.read_all f` のような再束縛を壊さないように、引数を持つ関数の形のローカル定義だけを再帰的にする。単相で、lambda lifting する

ロードマップの論点「ローカルの再帰関数の構文」は、ブロックの中に `let go acc xs = …` と書く形に決めた (下の「構文」)。

ローカル関数の型は単相だが、row はトップレベルの関数と同じく扱う。本体を検査した後で自由な row の末尾を閉じ、値として参照するときに開く (下の「型」)。row を単相のままにすると、純粋なローカル関数でも、`<IO>` の `main` や handler の中で呼ぶと yield しうる関数になり、トップレベルの補助関数より遅くなる。自分の中で handler を張ってその中で自分を呼ぶ関数も、書けなくなる。

次のものは範囲に入れない。

- 多相なローカル関数 (型の汎化)
- ローカル関数どうしの相互再帰
- 複数の等式によるローカル関数の定義 (場合分けは本体の `match` で書く)
- ローカル関数のシグネチャと、結果の型の明示
- REPL の `let` の入力を関数の形で書くこと
- `let` で束縛したラムダ (`let g = fn x -> …`) の row の扱いを変えること ([実装の現在地](../../implementation/status.md) の「型と row の推論」の制限はラムダについて残る)

多相と相互再帰は、ロードマップの S13 の項目として残す (下の「ロードマップ」)。今回の表現は、後でこの2つを足しても作り直さずに済む形にする (下の「拡張への備え」)。

決めたことは、段の終わりに下の「文書」の場所へ移す。

## 利用者から見た動き

### 構文

```haskell
pub map : (a -> <e> b) -> List a -> <e> List b
map f xs =
  let go acc ys =
    match ys with
      | Nil -> reverse acc
      | y :: rest -> go (f y :: acc) rest
  go Nil xs
```

- ブロックの文 `let name apat+ = body` で、ローカル関数 `name` を定義する。引数はラムダの引数と同じく `apat` で書き、`(acc : Int)` のように型を明示できる
- 1行の形 `let name apat+ = e in e2` も書ける。ブロックの文と同じ意味である
- 等式は1つだけである。同じ名前の `let` を続けて書くと、今と同じく後の定義が前の定義を隠す
- 関数の形のとき、引数の後ろに `: type` は書けない。書いたら E0011 にする (私の判断。結果の型の明示は、後で入れるシグネチャの形と合わせて決めるため)
- 引数のパターンは、ラムダの引数と同じく反駁できないものでなければならない。`let go (Some x) = x` や `let go 0 = 1` は E4003 である。parser は受け付け、網羅性の検査が拒む

関数の形かどうかは、`let` の後の2つのトークンで決める。`let` の次が `LIDENT` で、その次が次のどれかなら関数の形である。

- `LIDENT`、`_`、`UIDENT`、整数、文字列の始まり (`STRING_START`、`RAW_STRING`)、文字、`(`、`[`

`-` は含めない。`apat` は `'-' INT` を含むが、トップレベルで `LIDENT OP` を演算子の定義として先に読むのと揃えるためである。次の例はどれも今のとおりパターンの束縛のまま読む。

- `let x = e`、`let x : T = e` (名前の次が `=` か `:`)
- `let (f, text) = e`、`let Some x = e`、`let P { name = n } = e` (最初がパターン)
- `let x :: rest = e` (名前の次が演算子)

### 有効範囲

- 関数の形の `let` では、`name` の有効範囲が、その本体と、ブロックの残り (1行の形なら `in` の後ろ) を含む
- 引数の名前は本体の中で `name` を隠せる (`let go go = …` の本体の `go` は引数である)
- パターンの束縛の有効範囲は今のままである。`let x = x + 1` と `let f = fn y -> f y` の右辺の `x` と `f` は、外側の束縛を指す

### 型

- ローカル関数の型は単相である。本体を検査する前に関数の型を置き、自分の参照も同じ型として扱う。注釈のない引数の型には、ラムダと同じく推論用の型変数を使う
- 外側の関数のシグネチャの型変数と row 変数は、ローカル関数の本体でも見える。今のラムダと同じである
- 引数の数を n とすると、最初の n − 1 個の矢印の row は `<>` で閉じる。トップレベルの関数と同じく、引数を受け取るだけの矢印は何も起こさないためである。最後の矢印の row は推論する
- 最後の矢印の row は、本体を検査した後で、末尾が自由な推論用の変数なら `<>` で閉じる (`<IO | ρ>` なら `<IO>` になる)。ただし、その変数が捕まえた変数の型に現れるときは閉じない。捕まえた値の型を通して外側の推論とつながっていて、閉じると外側の型を勝手に決めるためである。関数自身の引数か結果の型に現れるときも閉じない。`let app f = f ()` のような高階のローカル関数のエフェクトは、引数から来るためである。どちらのときも単相の row のまま残す
- 外から呼ぶときは、閉じた row を今の row に含める (`include_row`)。トップレベルの関数の呼び出しと同じく、handler の中でも外でも、呼ぶ順序によらず通る
- 値として参照するときは、トップレベルの関数と同じく、最後の矢印の閉じた row を新しい row 変数で開く (`map go xs` で、`go` を `<e>` の関数の引数に渡せる)
- 本体の中の自分への呼び出しは、row がまだ決まっていないので、今の row への包含の確かめを、row を閉じた後に回す。自分が handler を張って、その中で自分を呼ぶ形も、トップレベルの関数と同じく通る
- 本体の中で自分を値として参照するとき (`map go xs` を自分の中で書くとき) は、開かない単相の型を使う
- row を閉じなかったローカル関数 (上の例外) は、今のラムダと同じく、row が最初の呼び出しの位置で決まる

### 線形性

- 本体の中で自分を参照するローカル関数 (再帰するローカル関数) は、何度も呼ばれうる。そのため、その関数の型の Kind は `Unr` でなければならない。関数の型の最初の矢印の線形性に `Unr` の制約を加える。後の矢印は、`closure_kinds` が前の引数の Kind で下から抑えるので、これで足りる
- 捕まえた値の Kind は、今のラムダと同じ規則 (`closure_kinds`) で矢印の線形性以下になる。そのため、再帰するローカル関数は `Unr` の値しか捕まえられない。`File` や `once` の継続 `k` のような `Lin` の値は、捕まえずに引数で受け渡す。今のトップレベルの補助関数と同じ書き方である
- 後の矢印は、前の引数に `Lin` の値を受け取れば `Lin` になりうる。これも今のラムダと同じである。`let go f acc = …` の `go f` は、`f` が `File` なら1回だけ呼べる閉包である
- 本体の中で自分を参照しないローカル関数は、ラムダと同じ扱いになる。`Lin` の値を捕まえて、1回だけ使える関数になれる。使わなかったり2回呼んだりすれば、ラムダと同じ誤りになる
- 再帰するローカル関数が型変数の値を捕まえると、その型変数に `Unr` の制約が付き、外側の関数の Kind のスキームに残る (`rep x n` の中の `go` が `x : a` を捕まえると `a` が `Unr` になる)。トップレベルの補助関数で `x` を引数として受け渡せば付かない制約なので、制約を避けたいときは引数で渡す。この性質を [線形性](../../spec/linearity.md) に書く
- 再帰するローカル関数が `Lin` の値を捕まえたときの誤りは E3001 である。[線形性](../../spec/linearity.md) の「線形性の検査パス」が捕獲の由来を E3001 に送るのと同じ経路に、「再帰するローカル関数の自分への参照」という由来を足す。主な位置は捕まえた変数、副の位置は自分を参照した位置で、文言は「自分を呼ぶので何度も呼ばれうる」ことが分かるものにする。文言は [診断の表示](../../implementation/diagnostics.md) の「線形性の診断」の表に足して確定する

### 性能

- ローカル関数は、どこから呼んでも直接呼び出しにする。外側の関数の本体からも、ラムダ、`use` が作るラムダ、handle の本体、節、別のローカル関数、ローカル関数自身の本体の中のラムダからも同じである。呼ぶたびに閉包を確保しない
- 自分への末尾呼び出しは、トップレベルの関数と同じく contract が `tail` にする。長いリストでも VM の深さの上限に当たらない
- row を閉じるので、純粋なローカル関数は yield しうる関数にならない。`<IO>` の `main` や handler の節の中で呼んでも、トップレベルの純粋な補助関数と同じコードになる
- 閉包を作るのは、値として使ったとき (`map go xs`) と、引数が足りないときだけである

次の代償は受け入れて、[Core IR](../../spec/core-ir.md) に書く。

- 値としての参照は、使う位置ごとに閉包を作る。別の関数のループの中でローカル関数を値として渡すと、反復のたびに閉包を作り直す。トップレベルの補助関数に閉包を引数で渡す書き方なら、作るのは1回である
- ローカル関数を呼ぶラムダは、呼ぶローカル関数の捕まえる値をすべて捕まえる。ローカル関数の閉包を1つ捕まえるより、閉包の語と `dup` が増えることがある。EP の継続の閉包 (`f$kN`) も同じである
- ローカル関数は、外側の instance ごとに複製する。外側の型引数に関わらないローカル関数でも、外側の instance の数だけできる

### REPL

- REPL の `let` の入力は、今と同じく1つの名前だけを束縛する。関数の形 (`let f x = 1`) は E0011 の1件にし、文言を ``a `let` input cannot define a function; write a signature and an equation`` にする。今は ``expected `=` `` と ``a `let` input binds one name`` の2件が出る。パターンの束縛 (`let (a, b) = …`) の文言は変えない
- 入力の中のブロックと `let … in` の式の入力では、ほかの関数と同じくローカル関数を書ける

## 設計

### 構文 (`eml_syntax`)

- `let_head_and_body` (`grammar/expressions.rs`) で、上の「構文」の2つのトークンの先読みに当たれば、関数の形として読む。名前、1つ以上の `apat`、`=`、本体の順である。名前の後に `:` が来たら、今のとおり型の明示として読む。引数の後に `:` が来たら E0011 にする
- CST には、関数の形を表す節点を足す。ブロックの文の `LET_STMT` と `let … in` の `LET_EXPR` の両方で、関数の形を区別できるようにする。新しい節点の種類にするか、`LET_STMT` / `LET_EXPR` の中に引数の並びの節点を持たせるかは実装で決める
- 型付きの AST の `LetStmt` と `LetExpr` に、関数の形の名前と引数を取る関数を足す
- REPL の `let_or_expr_input` は、関数の形を見分けて、上の「REPL」の E0011 を1件だけ出す
- 入れ子の深さ (E0013) は、引数をパターンとして数える。HIR が包むものは増えない

### HIR (`eml_hir`)

- `Stmt` に、ローカル関数の組を表す種類を足す。組は1つ以上の `LocalFunction` を持ち、今は要素が常に1つである。`LocalFunction` は、名前の `LocalId`、引数と本体 (今のラムダと同じ `Closure`)、定義の位置を持つ
- `lower_stmts` は、関数の形の `let` では、先に名前を有効範囲に入れてから、引数と本体を下ろす。パターンの束縛は今のまま右辺を先に下ろす。引数の並びの中の重なりは、ラムダと同じく E1017 にする
- `let … in` の関数の形も、今と同じく1つの文のブロックにする
- `Body` に、`LocalId` からローカル関数を引く表を足す。後の段は、この表でローカル関数の参照を見分ける
- `Body::closure_captures` (`hir.rs` の `captures`) は、ブロックの文が束縛する変数にローカル関数の名前と引数を入れ、ローカル関数の捕まえる変数も求められるようにする。自分自身の `LocalId` は捕まえる変数に入れない。今は `if let Stmt::Let` で束縛を集めているので、新しい種類を落とさないように書き直す
- `eml_hir::known_arity` (`eval.rs`) は、ローカル関数の参照にも引数の数を返す。これで translate の `call_head` と `saturate` が、ローカル関数への呼び出しを、引数の数がちょうどの直接呼び出し、足りない呼び出し、余る呼び出しに分けられる。評価の順は `call_steps` が1か所で決めたまま変わらない

### 型検査 (`eml_types`)

- `stmts` (`check/body.rs`) は、ローカル関数の組を次の順に検査する
  1. 組の各関数に、引数の数だけ矢印を持つ型を置いて `typing.locals` に書く。最後でない矢印の row は `<>`、最後の矢印の row は推論用の変数にする
  2. 各関数の本体を、ラムダと同じく `check_lambda` の手順で検査する。本体の中の自分への呼び出しは、`include_row` を呼ばずに、呼び出しと今の row の組を記録しておく
  3. 最後の矢印の row の末尾が自由な推論用の変数で、捕まえた変数の型にも、関数自身の引数と結果の型にも現れなければ、`<>` で閉じる
  4. 2 で記録した自分への呼び出しについて、`include_row` で包含を確かめ、`mask` を記録する
- 外からの参照は次のように扱う
  - 呼び出しの row の包含は今のまま `include_row` で行う。閉じた row なので、今の row と単一化されない
  - 値としての参照は、トップレベルの関数の参照と同じく、最後の矢印の閉じた row を新しい row 変数で開く。開く処理 (今はトップレベルの関数と extern の参照に使っている) を共有する
- `usage.rs` は、ローカル関数をラムダと同じく扱う。加えて、本体の中に自分の参照があれば、最初の矢印の線形性に `Unr` の制約を、上の「線形性」の由来で加える
- `carry.rs` も、ローカル関数をラムダと同じく扱う。捕まえる変数は、定義の位置で生きているものとする。translate が持ち上げの捕まえる変数を呼び出しのたびに渡しても、`go` の Kind はその捕まえた値の Kind 以上なので、`go` を持っていることの検査が、捕まえた値を持っていることの検査を含む。持ち越しの検査で使う呼び出しの row は、閉じた row (開く前の宣言の row) である。トップレベルの関数の呼び出しと同じである
- `exhaustive.rs` は、ローカル関数の引数を、ラムダの引数と同じく `PARAMETER_LABEL` で検査する。今は `if let Stmt::Let` で `let` のパターンだけを見ているので、新しい種類を落とさないように書き直す。落とすと、反駁可能な引数が translate の `destructure` のパニックになる
- `BodyTypes` で、ラムダの式で引く表 (`lambda_yields`) を、ローカル関数でも引けるようにする。キーを式にするかローカル関数の識別子にするかは実装で決める
- 一様な位置 (`TypedProgram::uniform`、E2012) と REPL の E2018 は、ローカル関数の本体を外側の関数の本体の一部として扱う。ローカル関数の本体の参照は外側の関数の節点から辺を引く。ローカル関数は単相なので、新しい節点は要らない

### translate (`eml_core_ir`)

- ローカル関数は、外側の instance を変換するときに、今のラムダと同じく `lift` で内部の関数 (`internal`) にする。引数は、持ち上げの捕まえる変数 (下) を先に、宣言した引数を後に並べる。単相なので、外側の instance ごとに1つの関数になる
- 名前は `<外側の instance の名前>$let$<ローカル関数の名前>` とする (`map@[Int, Int]$let$go`)。`let` は識別子に使えないので、ローカル関数の名前が `lambda0`、`k0`、`boxed` などでも、translate、EP、boxing が作る名前 (`$lambdaN`、`$handleN`、`$externN`、`$kN`、`$jN`、`$boxed`) と重ならない。同じ instance の中で名前が重なるときは、HIR の順で2つ目から `#2`、`#3` を付ける (`$let$go#2`)。REPL の中段の名前と同じ形で、テキストの形では引用符で囲む
- ローカル関数の本体の中のラムダ、handle の本体、節、`$externN` は、今のまま外側の instance の名前を根にし、番号も外側の本体の中で HIR の式の ID の順に振る
- ローカル関数への参照は次のように変換する
  - 引数がちょうどの呼び出しは、直接呼び出し `Call::Direct` にする。持ち上げの捕まえる変数を先に渡す。`mask` は最後の矢印のものを使う。最後でない矢印の row は `<>` なので、ほかの矢印は `mask` を持たない
  - 引数が足りない呼び出しと、値としての参照は、使う位置で閉包 (`closure`) を作る。持ち上げの捕まえる変数がなければ `Atom::Fn` にする
  - 引数が余る呼び出しは、今のトップレベルの関数と同じく、直接呼び出しの後に `apply` を続ける
- この規則は、ローカル関数を参照するのがどの関数でも同じである。外側の本体からも、ラムダ、`use` のラムダ、handle の本体、節、別のローカル関数、自分の本体から参照しても、直接呼び出しのままにする
- 持ち上げの捕まえる変数は、HIR の捕まえる変数に含まれるローカル関数を、そのローカル関数の持ち上げの捕まえる変数に置き換えたものである。ローカル関数は、前に定義したローカル関数と自分しか参照できない。そのため、定義の順に1回ずつ求めればよい。自分自身は置き換えから外す。ラムダ、handle の本体、節も、捕まえる変数にローカル関数があれば同じく置き換える
- `usage.rs`、`carry.rs`、`closure_kinds`、debug ビルドの `check_captures` は、HIR の捕まえる変数を使う。入れ子のラムダがローカル関数 `go` を参照することは、`go` の1回の使用であり、`go` が捕まえた値の使用ではない。`closure_kinds` で `go` の Kind はその捕まえた値の Kind 以上になるので、`go` を捕まえたラムダの Kind も、`go` の捕まえた値の Kind 以上になる。持ち上げの捕まえる変数を直接渡しても、所有の数え方は変わらない。`check_captures` は、閉包を作る位置で、HIR の捕まえる変数の型を確かめる
- 継続 `k` を引数に渡す直接呼び出し (ローカル関数の持ち上げの捕まえる変数に `k` が入る形) では、節はその場で動かない。今の `runs_in_place` が `k` の原子を数えるので、そのまま正しく扱える。[Core IR](../../spec/core-ir.md) の、生の `k` をラムダや handle の本体が捕まえる場合の記述に、この場合を足す
- `yields` の印は、ローカル関数の最後の矢印の row から、外側の instance の row のビットで決める。閉じた row なら、ラベルだけで決まる
- ローカル関数は値として使うと、boxing が今の内部の関数と同じく扱う。値としてだけ使う関数はその場で一様にし、直接呼ばれてかつ値として使われる関数は、形を保って `f$boxed` を作る

### 拡張への備え

多相なローカル関数と相互再帰を後で足すとき、次のところを広げるだけで済むようにする。

- HIR の `Stmt` は関数の組を持つ。相互再帰は、組に複数の関数を入れる構文を足すことで入れる
- 型検査は、組を単位に、全員の型を先に置いてから本体を検査し、組の後で row を閉じて自分たちへの呼び出しの包含を確かめる。相互再帰では、組の中の呼び出しをすべて後に回す。多相は、row を閉じる手順の位置に型の汎化を差し込む形で入れる
- translate は、組の各関数を内部の関数にする。相互再帰では、組の持ち上げの捕まえる変数の和をすべての関数の引数にする

### 段ごとのテスト

- parser: 関数の形とパターンの束縛の読み分け (上の「構文」の例すべてと `let f -1 = …`)、`let … in` の関数の形、引数の後の `:` の E0011
- HIR: 有効範囲 (自分を参照できること、引数が名前を隠すこと)、引数の E1017
- 型: row を閉じること、捕まえた変数の型と、関数自身の引数と結果の型に現れる row は閉じないこと、値として参照すると開くこと

- LIR: 自分への末尾呼び出しが `tail` になること

### 性能の確かめ

`RunStats` は `prim yielding` の検査や命令の数を数えないので、`RunStats` だけでは足りない。次の2つを `eml_core_ir` と `eml_vm` のテストで確かめる。

- `RunStats` の一致: 同じ2つのプログラムを VM で流し、`RunStats` が一致することを確かめる

トップレベルの版は、ローカル関数が捕まえる値を先頭の引数で受け取る形にし、シグネチャには自然な row を書く (純粋なら `<>`)。比べる形には次の4つを含める。

- 純粋な外側の関数の中の accumulator のループ

- handler の節の中から純粋なローカル関数を呼ぶ形
- handle の本体の中から呼ぶ形
