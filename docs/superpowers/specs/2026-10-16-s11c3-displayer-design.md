# S11c-3 `Show` を持たない型の表示器の設計

## 目的と範囲

REPL の式の入力のうち、型が `Show` を持たないものの値を表示する。今は型だけを `_ : T` の形で書く。S11c-3 では、値と型を `値 : 型` の形で書く。値は型に従って組み立て、関数は `<fn>` と書く。これで S11 を終える。

範囲に入れないもの: `Show` を持つ型の表示の変更 (今と同じく値だけを書く)。`let` の入力の表示。表示の上限を利用者が変えるコマンド。`IO` 以外のエフェクトの既定の handler など、ロードマップの「S11 REPL」の「論点」に残る項目。

決めたことは、[REPL の端末](../../spec/repl.md) の「結果の表示」、[Core IR](../../spec/core-ir.md) の「REPL の入力」と「導出とタプルの生成器」、[型と Kind](../../spec/types.md) の「REPL の入力」に移す (下の「文書」)。

## 利用者から見た動き

### 形

- 型が `Show` を持たない式の入力は、`値 : 型` の1行を書く。型の書き方は今の `_ : T` の `T` と同じで、診断の表示と同じである。OCaml のトップレベルは `- : 型 = 値` と書くが、eml は値を先に書く
- 型が `Show` を持つ式の入力は、今と同じく値だけを書く。型が `Unit` の入力は何も書かない

```
> Box 3
Box 3 : Box
> fn x -> x + 1
<fn> : Int -> Int
> [fn x -> x, inc]
[<fn>, <fn>] : List (Int -> Int)
> (1, "a", inc)
(1, "a", <fn>) : (Int, String, Int -> Int)
> P { f = inc, n = 2 }
P { f = <fn>, n = 2 } : P
> 1 + 2
3
```

### 値の書き方

値は型に従って書く。部分ごとに次の規則を当てる。書き方は導出した `Show` ([宣言](../../spec/declarations.md) の「deriving」) に合わせる。

- 型が `Show` を持つ部分 (`Int`、`String`、instance のある利用者の型) は、その型の `show_prec` で書く。利用者の instance の書き方をそのまま使う。`"a"` は引用符付きで書き、負の数はコンストラクタの引数の位置で括弧に入る (`Box (-3)`)。`()` は `Show` を持つので `()` と書く
- 関数 (handler の継続を含む) は `<fn>` と書く
- タプルは `(…, …)` と書き、要素を優先度 0 で書く
- `List` は `Show` のリストと同じく `[…, …]` と書き、要素を優先度 0 で書く。空のリストは `[]` である
- `data` のコンストラクタは、導出した `Show` と同じく書く。前置のコンストラクタは `Box <fn>` で、引数を優先度 11 で書く。中置のコンストラクタは `a :+ b` で、優先度 p の演算子の左右を p + 1 で書く (fixity を宣言していない中置のコンストラクタは `infixl 9`)。外から渡された優先度が前置なら 10、中置なら p を超えると括弧で囲む。レコードは `P { f = <fn> }` で、フィールドを優先度 0 で書き、括弧で囲まない
- コンストラクタの名前は、導出した `Show` と同じく書いた名前のまま (修飾も `#N` も付けない) である。定義し直した型の古い版の値は `Circle : Shape#1` になる
- 型の `Show` の instance が、文脈が型引数で解けないために使えないとき (`instance Show a => Show (Box a)` のもとの `Box (Int -> Int)`) は、その型を構造で書く (`Box <fn>`)。「`Show` を持つ」は、型検査が式の入力の表示の仕方を決めるのと同じ判定 (制約が完全に解けるか) で決める
- `Show` を持たない extern の型は、今は `File` だけで、`File` の値は式の入力の結果にならない (E2016)。表示器がほかの extern の型に届けば内部の誤りにする。`Show` を持たない extern の型を足すときに書き方を決める

### 上限

OCaml のトップレベルの既定の値 (`print_depth` 100、`print_length` 300) と同じ2つの上限を置く。値の大きさに上限はなく、部分を共有した値 (`t(k+1) = Node t(k) t(k)`) は小さなヒープで巨大な木になるためである。

- 予算: 値全体で 300 個の節点まで書く。節点は、書くコンストラクタ、タプル、リスト、`<fn>`、`show_prec` で書く部分、深さで切って書く `...` の1つずつで、それぞれ予算を1つ使う。区切りと括弧は予算を使わない。予算が尽きた後の部分は、予算を使わずに `...` と書く
- リスト: リストは節点として予算を1つ使い、要素はそれぞれの節点の分を使う。要素を書く前に予算が尽きていれば、その要素から後を書かずに `...` と書いて閉じる (`[a, b, ...]`。1つも書いていなければ `[...]`)。残りの要素がなければ `]` で閉じる
- 深さ: 入れ子のコンストラクタ、タプル、リストを 100 段たどった先の部分は `...` と書く。コンストラクタのフィールド、タプルの要素、リストの要素は、それを持つ値より1段深い。`List` の背骨 (`::` のつながり) は段を増やさない。利用者が定義したリストの形の型 (`data L = | LNil | LCons (Int -> Int) L`) は、背骨のコンストラクタが段を増やすので、予算か深さで切れる
- 深さで切って書く `...` も予算を1つ使う (OCaml と同じ)。そのため、深さで切れた大きなリストも、予算の分の要素で止まる
- `show_prec` で書く部分の中には上限を当てない。今の `Show` を持つ型の表示と同じである

### 割り込みと実行時エラー

表示は入力と同じ実行の中の普通のコードで行う。表示の間の Ctrl-C は VM の安全点 (呼び出しと戻り) で止まり、ほかの入力の実行と同じく `interrupted` になる。確保量と深さの上限も同じである。利用者の `show_prec` が実行時エラーを起こせば、入力の実行時エラーとして表示する (今の `Show` の入力と同じ)。

## 設計

### `eml_types`

- `InputDisplay::TypeOnly(String)` を `InputDisplay::Display(String)` にする。中身は今と同じく型の表示 (` : ` の後に書く文字列) である
- `check/input.rs` の非公開の `satisfies(program, types, class, ty)` を、`eml_types` の公開の関数にする。translate が部分ごとに「`Show` を持つか」を同じ規則で決めるためである。名前は `satisfies` のままで、crate の根から再公開する

### `eml_core_ir` の translate

新しい生成器 `translate/display.rs` を `derive.rs` の隣に置く。表示器が届く型ごとに、単相の Core IR の関数 (表示関数) を1つ組む。

#### 表示関数の形

```
display$N$k (acc: String, budget: Int, depth: Int, prec: Int, x: T) -> (String, Int)
```

- `acc` に書いた結果を後ろに足して返す。`show_rest` と同じく、左辺を一意な文字列として伸ばすので、書く量に比例する時間で済む ([オブジェクトモデル](../../spec/object-model.md) の「文字列の操作」)。括弧も `acc` に先に足すので、入れ子の括弧で写しが増えない
- `budget` は残りの予算で、使った後の残りを結果の組の2つ目で返す
- 関数の始めで、`budget` が 0 なら `...` を足して返す (予算は 0 のまま)。`depth` が 100 以上なら `...` を足し、予算を1つ使って返す。どちらでもなければ予算を1つ使って値を書く
- 部分ごとの扱い (部分の種類 `Part`)。部分は、それを持つ値より1段深い (`depth + 1`) ところで、上の予算と深さの検査を受ける:
  - `Show`: 型が `Show` を持つ部分。その型の `show_prec prec x` の結果を `acc` に足す。行き先は既存のメソッドの解決 (`Collector::method_target`) で決め、方程式の引数がメソッドより少ない instance のメソッドは、`derive.rs` の `call_target` と同じく返った関数に残りを適用する
  - `Function`: 関数型の部分。`<fn>` を足す
  - `Ellipsis`: 表示関数を作らない型の部分 (下の「名前と集め方」の段と数の上限)。`...` を足す
  - `Display(k)`: 構造で書く部分。表示関数 `display$N$k` を `depth + 1` で呼ぶ
- `Show`、`Function`、`Ellipsis` の部分は関数を作らず、呼び出し側でその場に組む (予算と深さの検査もその場で行う)
- タプル、`data` のコンストラクタ、レコードは、`derive.rs` の書き方 (上の「値の書き方」の優先度と括弧) と同じに組む。`List` は、`LangItems` の `list` で見分け (セッションの利用者の `List` と取り違えない)、要素をたどる補助の関数 (同じ番号の `display$N$k$rest`) で背骨をたどる。要素は `depth + 1` で書く。要素の前に予算が尽きていれば `...` と書いて閉じる
- 結果の組 `(String, Int)` は、2要素のタプルの配置 (`obj` で、フィールドは `tobj`、`Int` は箱に入れる) で返す。呼び出し側は `unpack` で受ける。組を解放した後、文字列は一意なので、次の連結もその場で伸ばせる

#### `derive.rs` との共有

`derive.rs` の値の形 (`shape`、`Constructor`) は、今は instance (`GeneratedInstance`) から型を読み、フィールドの `Repr` だけを持つ。表示関数は instance のない型にも作るので、`shape` を「型の定義 (`TypeDefId`) とコンストラクタごとのフィールドの型 (`TypeId`)」か、タプルの要素の型から作る形に直し、導出した instance の生成器と表示器が共有する。`Constructor` はフィールドの `TypeId` も持つ。導出した instance の出力は変わらない (このリファクタは機械的な追従である)。

#### 名前と集め方

- 表示関数の名前は、入力の番号 N と、入力の中で見つけた順の番号 k から作る (`display$N$k` と、`List` の補助の `display$N$k$rest`)。型から名前を作らない理由は2つある
  - 後の入力が `instance Show Box` を足すと、前からある型 (`(Box, Int -> Int)`) の書き方が変わる。名前を型だけで決めると、同じ名前で違うコードができ、「同じ名前の関数はいつも同じコードになる」規則 ([Core IR](../../spec/core-ir.md) の「変換の規則」) が破れる。入力の番号は使い回さないので、表示関数はその入力にだけある
  - 入れ子の型 (`data Nest a = | NNil | NCons a (Nest (a, a))`) では、たどる型の表示が段ごとに倍に伸びる。型の表示から名前を作ると、名前を作るのに指数の時間がかかる
- 集め方: instance の集め手 (`instances.rs` の `Collector`) が、入口の型から幅優先で型をたどり、型ごとに入口からの最小の段を記録する。表示関数の型は入口の型か別の表示関数の型からだけ見つかるので、幅優先で初めて見た段が最小の段である
  - 初めて見た段が 100 以上の型は、表示関数を作らずに `Ellipsis` にする。その型の値を書く時点の段はいつも 100 以上で、`...` しか書かないためである
  - 1つの入力で作る表示関数は 1000 個までにする。幅優先で 1000 個を超えて見つけた型は `Ellipsis` にする。入れ子のフィールドを2つ持つ型 (`data W a = | WNil | W a (W (a, Int)) (W (a, Bool))`) は、段ごとに型の数が倍になり、段の上限だけでは 2^100 個の型をたどるためである。lowering は止める語を読む前に走るので、ここで止まらないと Ctrl-C でも抜けられない
  - 番号 k は幅優先で見つけた順である。部分の `show_prec` の行き先も同じ集め手が集める
- 表示関数は新しい `Found::Display` として、導出した instance の関数の後に並ぶ
- 表示関数は `internal` でない (導出した instance の生成器と同じ)。互いに呼び合い、値としては使わない。`yields` でない。変数の印はすべて `unr` である。表示する値はいつも `Unr` で (式の入力の結果が `Unr` でなければ E2016)、`Unr` の値の部分も `Unr` だからである。写しと解放は Perceus に任せる
- 入力ごとに表示関数を作るので、`Show` を持たない型を表示する入力のたびに `CodeBase` の関数が増える。`entry$input$N` が入力ごとに増えるのと同じで、受け入れる

#### 入口

- 型が関数型の入力は、`<fn> : T` の1つの定数を `println` に渡す
- ほかの `Show` を持たない型の入力の `entry$input$N` は、入力の値に `display$N$0("", 300, 0, 0, v)` を呼び、結果の組の文字列に `" : T"` を足して `println` に渡す
- `println` の位置は今と同じく入力の式の先頭である。型が `Show` を持つ入力と `Unit` の入力の入口は変えない

### VM と `eml_rt`

変えない。表示関数は普通のコードなので、割り込みと確保量の上限は今の安全点で働く。

## テスト

TDD で進める。

- `eml_types`: 公開した `satisfies` で、今の `show_is_satisfied_only_when_every_part_has_an_instance` が通る。`InputDisplay::Display` が型の表示を持つ
- Core IR (`crates/eml_core_ir/tests/session.rs`)
  - `Show` を持たない式の入力の入口が、`display$N$0` を呼び、` : T` を足して `println` に渡す。関数型の入力は1つの定数を渡す
  - 表示関数の名前が入力の番号を含む
  - 入れ子の型 (`Nest (Int -> Int)`) の入力の lowering が終わり、表示関数の数が段の上限で抑えられる
  - 入れ子のフィールドを2つ持つ型 (`W (Int -> Int)`) の入力の lowering が終わり、表示関数の数が 1000 個で抑えられる
- トランスクリプト (新しい `basics/displayer.repl`)
  - 関数の名前とラムダ
  - 前置と中置のコンストラクタ、レコード
  - `Show` を持つ部分と持たない部分を混ぜたタプル。文字列は引用符付き、負の数は括弧付き (`Box (-3)` の形)、`()` を含む
  - 関数のリストと、関数の空のリスト (`[] : List (Int -> Int)`)
  - 入れ子のリスト
  - 文脈が解けない型 (`instance Show a => Show (Box a)` のもとの `Box (Int -> Int)`)
  - 予算で切れる値 (300 個の関数のリストは 299 個を書いて `, ...]` で終わり、部分を共有した深い木は `...` を含む)
  - 深さで切れる値 (100 段より深い入れ子) と、深さで切れたリストが予算で止まること
  - 入れ子の型 (`NCons inc (NCons (inc, inc) NNil)`)
  - 定義し直した型の古い版 (`Circle : Shape#1`)
  - 後の入力で `instance Show Box` を足す。その後の入力は `Box` を `show` で書き、debug ビルドの同じ名前のコードの比較が食い違いを報告しない
- lib API (`crates/eml_cli/tests/api.rs`)
  - 関数の大きなリスト (10 万要素) は、予算の分だけ書いて `, ...]` で終わる
  - 終わらない `show_prec` を持つ型を表示する入力を、別のスレッドから `Control::interrupt` で止めると、`Failed` で割り込みになり、セッションは続く。検査モードで `close` がリークを報告しない。入力は値を作る前に `println` で1行を書き、別のスレッドは捕まえた出力にその行が出てから割り込む。`eval` は始めに止める語を下ろし、前端の検査の間の割り込みは `Interrupted` になるので、早すぎる割り込みは確かめたいことを確かめない
- 2つのモード: トランスクリプトの harness は検査モードと速いモードで流すので、生成したコードのリークも見つかる

### 既存のテストの変更

- 期待値の変更 (種類 2): `basics/display.repl` のスナップショットの `_ : T` を `値 : T` にする (`<fn> : Int -> Int`、`Box 3 : Box`)。`crates/eml_core_ir/tests/session.rs` の `a_value_without_show_prints_its_type_at_the_input` は、新しい入口の形に書き直し、名前も中身に合わせて直す
- 機械的な追従 (種類 3): `eml_types` の `a_function_value_is_shown_by_its_type` の `InputDisplay::TypeOnly` を `InputDisplay::Display` に直す (期待する文字列は同じ)。`derive.rs` の `shape` のリファクタで、導出した instance のテストの期待値は変わらない
- 合否の変更 (種類 1) はない
