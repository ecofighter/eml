# ロードマップの引き直し (S4〜S13)

位置づけ: この作業の spec。作業を終えたら削除する。

## 目的

`docs/reports/` の2本の調査レポート (VM とネイティブコード生成、REPL 向けのランタイム) を踏まえて、[ロードマップ](../../future/roadmap.md) の段の列を引き直す。次の4つを優先する。

- VM、インタプリタ、REPL
- evidence passing (EP) の実装
- 型クラスと、translate での単相化
- ランタイムの再編

この作業は文書だけを変える。コードはコメントの段の名前だけを直す。

## レポートの要点

- レポート1 (`20261009-205804-…/report.md`)
  - HIR と Core IR の骨格は変えなくてよい。
  - `eml run` の実行命令の約53%は、確保と解放、引数と退避の `Vec` の組み立てである。
  - VM は、エフェクトを下げた後の IR から直接レジスタ型のバイトコードを作る。
  - 単相化は translate で (関数, 型引数) を鍵にして行う。
- レポート2 (`20261009-212828-…/report.md`)
  - VM とネイティブで共有する共通ランタイム (8 バイトの語、ヘッダ付きのオブジェクト、`unsafe` の核と検査モード) を作る。
  - EP は VM より前に入れる。
  - 入力ごとにプログラム全体を処理し直す費用は小さい (関数 1000 個で約 37 ms)。
  - 割り込みの確認は `Machine::transfer` の1か所で足り、費用は測定の揺れの範囲だった。
  - 実行時エラーの後には、ヒープにフレームと局所変数が残る。REPL では、根からの走査で回復する。

## 決定

- D1: 4つの優先を、今の S4 (スクリプトの MVP) より前に置く。S4 は小さくする。
- D2: リスト、文字列、レコードも4つの優先と同じく前に置く。データ構造のランタイム表現を、実際のデータで詰めるためである。スクリプトの MVP に残すのは、`try_io` / `exit`、ローカルの再帰関数、extern の標準ライブラリ、`eml file.em args...` である。
- D3: 関数のコードは全面的に単相化する。
  - translate が (関数, 型引数) の instance の表を持ち、`main` から届く具体化だけを変換する。
  - 多相再帰で具体化が上限を超えたときは、一様な版を使う。
  - 操作ごとに量化した型変数を持つ操作の節も、一様な版を使う ([宣言](../../spec/declarations.md) の「`effect`」)。節が呼ぶ総称な関数は、「一様」という型引数の鍵で instance の表に入り、その鍵は呼ぶ先にも伝わる。
  - row は単相化しない。row の多相は EP で扱う。
  - 型クラスは辞書を持たない。制約付きの多相再帰は型検査で弾く。
- D4: ランタイムは、共通ランタイム `eml_rt` を1つ持つ。値は 8 バイトの語、オブジェクトはヘッダと記述子を持ち、`unsafe` の核と検査モードを持つ。VM とネイティブが共有する。
- D5: CEK のインタプリタは削除する。EP と VM が揃い、VM が全 UI テストを通した時点で消す。それまでの CEK は、EP の差分テストの基準である。エフェクトを直接扱う部分は、EP の段の終わりに先に消す。
- D6: データの配置は一様のまま変えない。型変数のフィールドは `tobj` のままで、`Option Int` と `Option a` は同じ配置を使う。`tobj` の `Int` は `eml_rt` で 63 ビットの即値にし、収まらない値は box の物体にする。`Int` の意味は 64 ビットのまま変えない。
- D7: LIR を新設する。境界は EP の直後、box の挿入の前に置く。
  - Core IR は意味の層である。ブロック、Repr、配置、エフェクトの命令を持ち、RC と box は持たない。後の最適化パス (インライン化、jump threading など) も Core IR に置く。
  - EP は Core IR から Core IR への変換である。エフェクトのない Core IR から LIR への変換は構造を写すだけで、エフェクトの命令が残っていれば断る。
  - LIR はエフェクトの命令を持たない。`box` / `unbox`、`dup` / `decref` / `release`、evidence と yield の基本操作を持つ。box の挿入、縮約、Perceus と所有の verifier は LIR に移る。LIR は VM とネイティブの共通の入力である。
- D8: Perceus の reuse の解析は、VM の後の「その後の項目」に置く。データの配置と `eml_rt` の API は、reuse を後から入れられる形で決める (S9)。
- D9: 段の名前は、再設計の続きとして S4〜S13 に振り直す。
- D10: レポートは、md と小さい実験ファイルだけをコミットする。

### 順序の理由

- S4 を先頭に置く。translate の出力の形を、EP、`eml_rt`、VM のすべてが受け取るためである。表面の構文を変えないので、段を小さく保てる。
- CPS のラムダの位置の変換 (試作で 200,125 回) は、単相化では消えない。既知の閉包への特殊化 (後の最適化パス) が要る。そのため S4 は、減る量を約束せず、回数を記録するにとどめる。
- S6 が S5 に依るのは、補間と `deriving` だけである。
- S7 は Core IR から Core IR への変換なので、LIR がなくても今の経路で CEK に流して比べられる。
- S8 を S9 より前に置く。`eml_rt` の関数表と `CodeBase` は、LIR の関数の集合を前提にするためである。関数の集合は、box の挿入が `f$boxed` を足して初めて決まる。
- S9 を S6 の後に置く。データの表現を、実際のリスト、文字列、レコードで測って決めるためである。S11 が要る仕組み (`CodeBase`、生存の列挙、RC の上限) は S9 で入れる。後から差し込むと作り直しになるためである。
- CEK の確保の除去 (レポート1の提案1) と、CEK の上の REPL (レポート2の提案1) は行わない。どちらも消す CEK への投資になるためである。

## 各段の中身

ロードマップの各段の節は、次の中身を「決めたこと」と「論点」に分けて書く。今のロードマップの節から移す項目は、移し先を括弧で示す。

### S4 単相化と計測の基準

- 表面の構文は変えない。
- translate に (関数, 型引数) の instance の表を持たせ、`main` から届く具体化だけを変換する。多相再帰の上限、一様な版、操作の節の扱いは D3 のとおりである。
- データの配置は一様のまま変えない (D6)。
- 計測の基準を作る。`fib`、`loop`、`state`、リスト、木のプログラムを基準にし、`RunStats` に `box` / `unbox` の回数を足す。callgrind の実行命令数を、測定の環境と一緒に記録する。
- instance の数とコンパイル時間の scaling テストを、具体的な上限付きで足す。
- `f$boxed` の規則の根拠のうち「標準ライブラリを一度だけ変換して使い回す」は、単相化で総称な std のコードがプログラムごとに変換されるので書き直す。
- 期待値の変更: Core IR のダンプのうち、多相な関数を含むもの。
- 論点: 具体化の上限の値。instance の名前の付け方 (ダンプと診断での表示)。

### S5 型クラス

今の S4 の組み込みのクラスと、今の「型クラス」の段をまとめる。

- 表面は Haskell 98 の形の単一引数の型クラスにする。`class`、`instance`、上位クラス、`deriving` を持つ (今の「型クラス」の決めたこと)。
- Prelude に `Eq` / `Ord` / `Show` を置く。タプルには処理系が構造的な instance を与える。
- 一貫性、orphan 規則、重なる instance を持たないことは、今の「型クラス」の決めたことのまま移す。
- 証拠は S4 の instance の表で確定し、実行時の辞書は持たない。制約付きの多相再帰は型検査で弾く。
- 操作のシグネチャとコンストラクタのフィールドには制約を書けない。制約はトップレベルのシグネチャへ推論で足さない。defaulting は持たない。線形性は Kind のままにする (今の S4 の決めたこと)。
- `=>` を予約の記号に、`deriving` をキーワードにする。`=>` を定義するテストは成否の変更になる。
- 持ち越しの制約の表示 `a => <e> <= Once` を、`=>` と重ならない形に変える (期待値の変更)。
- `==` の特別扱い (`equality` と E2006) を置き換える。
- 論点 (今の S4 と「型クラス」の論点から移す): `Ord` のメソッドの形、`!=` の扱い、`Show` と `Display` を分けるか、メソッドの Kind、導出した instance で比べないフィールドを `drop` する形、既定のメソッド、orphan 規則をパッケージ単位に広げるか。

### S6 リスト、文字列、レコード

- リストのリテラルと `::` を入れる。`List`、`Option`、`Result` を標準ライブラリに置く。
- 名前的なレコード、`t.0` の射影、0 要素のタプルとしての Unit を入れる (今の S4 のレコードの決めたことを移す)。
- レコードの更新 `{ p | age = 31 }` は意味として不変で、写す。一意な値のその場の書き換えは reuse (D8) に任せる。
- 複数行の文字列、raw 文字列、補間と、そのための lexer のモードを入れる。補間の穴の型は、S5 で決めた表示のクラスに従う。
- レコード、`List`、`Option`、`Result` に `deriving` を使えるようにする。
- 論点 (今の S4 の論点から移す): lexer のモードのスタック、`{…}` と `[…]` とレイアウト規則3、借用のオペランドと `Field`、`::` の fixity、補間とレコードとリストの CST、未対応のリテラルの E0004 を1か所で出すか。

### S7 evidence passing

[evidence passing の設計](../../future/evidence-passing.md) を実装する。

- Core IR に row を持たせ、エフェクトのラベルの順序を決める。
- EP を Core IR から Core IR への変換として、translate と box の挿入の間に置く。
- EP の出力を、Core IR の下位言語として定める。
  - `handle` / `perform` / `resume` / `mask` を含まない。
  - evidence と yield の基本操作を、extern の行と同じく Repr の決まった表の形で持つ。box の挿入と Perceus に特別な規則を足さないためである。
  - Core IR の verifier に、この下位言語を確かめる段を足す。
  - 出力は、既存の命令の種類と上の基本操作だけにする。S8 で LIR に移す作業を機械的にするためである。
- 末尾の位置は縮約の定義に合わせ、末尾の位置の呼び出しの後には yield の確認を入れない。末尾呼び出しの保証を守るためである。
- T3 と `never` の操作の規則を、EP の出力 (`perform` と `resume` が `apply` になった形) に合わせて書き直す。
- すぐに再開する節を、継続を取り出さずにその場で実行する。
- `never` の中断で、途中の `Lin` の値を破棄する。この中断の経路は、S12 の `try_io` と `exit` も使う。
- 操作の宣言した Repr を決める (今の「処理系」の項目から移す)。
- 開発中は、CEK に EP の基本操作を一時的に足し、変換の有無で UI テストの出力を比べる。RC の回数は変換で変わるので比べない。
- 段の終わりに EP を常に通すようにし、エフェクトを直接扱う部分を消す。消すのは、CEK の handler の連鎖と継続の区間と、box の挿入、Perceus、verifier の `perform` / `handle` / `resume` の規則である。
- 新しい指標を `RunStats` に足す (evidence を引いた回数、yield が越えたフレームの数など)。`handler_visits` は CEK のフレームをたどる回数なので、EP の後は意味を持たない。
- 論点 (今の evidence-passing.md の未決の論点から移す): yield の確認の費用、開いた row で evidence を探すときのキャッシュ、`never` の中断での `Lin` の値の破棄の方法。

### S8 LIR

- LIR の型、テキスト形式、パーサ、verifier を作る。
- Core IR から LIR への変換を作り、box の挿入、縮約、Perceus と所有の verifier (R6、R7) を LIR に移す。
- CEK が読む IR を LIR に替える。S7 の後の CEK はエフェクトを持たないので、型の付け替えで済む。
- 関数、配置、文字列、extern の、プログラム単位の表を LIR に置く。
- Core IR から RC と box を消す。
- 層の分担は次のとおりにする。

  | 項目 | 置き場所 |
  |---|---|
  | 変数の Repr | Core IR で決まり、LIR に写す |
  | 配置の表と `internal` の印 | Core IR と LIR で共有する。LIR が配置を足せるかは S8 の spec で決める |
  | `mask` | Core IR だけ。EP が使う |
  | extern の位置 | LIR に写す。エラー位置の表に使う |
  | T3、`f$boxed`、一様化 | LIR の規則 |
  | verifier の段 | Core IR (translate の後、EP の後) と LIR (スコープ、所有) |

- 期待値の変更: Perceus の後の Core IR のダンプは、LIR のダンプになる。
- spec: `core-ir.md` を、Core IR と LIR の2つの spec に分ける。

### S9 共通ランタイム `eml_rt`

- 値を 8 バイトの語にする。`obj` と `tobj` の位置は「ポインタか即値」で、`int`、`enum`、`unit` の変数は生のスロットに置く。
- `tobj` の `Int` は 63 ビットの即値にし、収まらない値は box の物体にする (D6)。
- オブジェクトは、ヘッダとフィールドが続く1つのブロックにする。ヘッダは RC、タグ、記述子を持つ。
- RC の符号は、0 を RC なし (今の不死の物体)、正を単一スレッド、負を複数スレッド用に予約する。上限に達したカウントは動かさない。
- 検査モードを持つ。解放した領域を再利用せず、ヘッダに印を付け、確保の台帳で生存を数える。生きているオブジェクトを列挙できるようにする。
- reuse に対応した確保の API (`alloc_at` と token) と、検査モードでの再利用の扱い、ヘッダのタグを書き換える規約を入れる。ランタイムの単体テストで、手で組んだ「解放して、同じ箱でコンストラクタを作る」列を流し、生存の数と RC の釣り合いを確かめる (D8)。
- extern を語の ABI で1回だけ書く。
- 実行文脈 `Ctx` を持つ。割り込みの旗、深さと確保量の上限、yield の印と evidence のベクタ、セッションの根、出力先を置く。
- 関数表 `FnEntry` と、追記だけの `CodeBase` (関数、文字列、配置、エフェクト) を、S8 の LIR の表をもとに作る。
- リスト、文字列、レコードの物理的な表現を決める。
- `unsafe` は小さい核 (確保、解放、ヘッダ、フィールドの読み書き、`dup`、`decref`) に閉じる。
- 記述子の形を決める (今の「処理系」の記述子の項目から移す)。
- 論点: 確保器の選定、文字列の表現 (一意なときのその場の連結を保つ形)、`Float` を入れたときの語の表現、SIGINT の受け方。

### S10 VM と切り替え

- LIR からレジスタ型のバイトコードを作る。中間に別の IR は挟まない。
- レジスタは関数ごとの連続した枠にし、生存区間の彩色でスロットに割り当てる。
- ブロック引数は並列な代入の `move` の列に展開する。
- 算術と比較は extern の行ごとに専用の命令にする。それ以外の extern は、行の番号と引数のレジスタの範囲を持つ命令にする。
- 自己の末尾呼び出しは、バイトコードの出力で関数の入口へのジャンプにする。R2 は緩めない。
- 呼び出しと戻りを安全点にし、割り込み、深さの上限、確保量の上限を確かめる。
- エラー位置の表 (pc から位置) と逆アセンブラを作る。
- `eml run` を VM に切り替え、CEK、今の `eml_runtime`、`saved` を消す。
- spec を改める: `runtime.md`、`evidence-passing.md` (CEK の役割)、`multicore.md`、`architecture.md`、`testing.md`。
- 論点: 比較と分岐の融合命令の有無 (試作で実行命令数を測って決める)、`RunStats` の項目の VM での意味。

### S11 REPL

今の「REPL」の段の決めたことと論点を移し、次を足す。

- セッションの根と、入力ごとの関数 `input$N` を入れる。入力が使うセッションの値は、`input$N` の引数として `dup` して渡す。
- 総称な定義は使われたときに変換し、(定義, 型引数) ごとの instance をキャッシュする。
- 再定義は、新しい番号の関数と、名前から最新の番号への写像で表す。古いクロージャは古い定義を呼び続ける。
- 配置の番号を、translate のたどり方によらない正規の順にする。
- 異常終了と割り込みからは、根からの走査で回復する。根から届くものを残し、届かないものを解放し、RC を数え直す。
- 表示は `Show` で行う。`Show` を持たない型には、型に従う表示器を使う。表示器は深さと要素の数の上限を持ち、表示中も割り込みを見る。
- 式は、まず row が `<IO>` に収まるものに限る。
- 論点 (今の論点に足す): 型を定義し直したときの古い値の表示、`:load` で型が変わるときのセッションの値の扱い、セッションの値への連結がいつも写しになること (RC が 2 以上になるため)。

### S12 スクリプトの MVP

今の S4 から、次の項目だけを残す。

- `try_io` と `exit`。中断の経路は S7 のものを使う。戻らない extern の結果の Repr の扱いも残す。
- ローカルの再帰関数。
