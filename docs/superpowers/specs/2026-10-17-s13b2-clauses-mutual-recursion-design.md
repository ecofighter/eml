# S13b-2 `fn` と `ctl` の節、ローカル関数どうしの相互再帰の設計

## 目的と範囲

S13b (std のエフェクトと `Iter`) の2つ目の作業である。次の2つを入れる。

- `k` を書かない節 `| fn op 引数 -> 本体` と、`k` を操作する節に書く `ctl` (`| ctl op 引数 k -> 本体`)
- ブロックの中で続けて書いた関数の形の `let` どうしの相互再帰

ロードマップの S13b の「決めたこと: `k` を書かない節と相互再帰 (S13b-2)」(`docs/future/roadmap.md`) を、この spec が細部まで決める。S13b-3 の std の handler は `fn` の節で書くので、この作業はその前提になる。

ねらいは2つある。1つ目は、S12d の `grep` で枝ごとに `k ()` を書いていたような、すぐに再開するだけの節を短く書けるようにすることである。`fn` と `ctl` で、その場で値を返す節と継続を操作する節を行の先頭で読み分けられるようにする。2つ目は、`csv2jsonl` で E1001 になった状態機械 (欄を読む関数、行を流す関数、次の行を始める関数) を、相互再帰でそのまま書けるようにすることである。

完了の条件は次の2つである。

- `fn` の節と `ctl` の節を持つ handler が、状態のない handler とパラメータ付き handler の両方で動く。yield の地点を持たない `fn` の節は、EP でその場で動く節になる
- ブロックの中の相互再帰するローカル関数 (偶奇の判定と、CSV のような状態機械) が動く

次のものは範囲に入れない。

- std の `Yield`、`Fail`、`State`、`Std.Iter`、`Fs.read_line`、S12d のスクリプトの書き換え: S13b-3 で入れる
- 多相なローカル関数: ロードマップに置いたまま
- トップレベルの REPL の入力での関数の形の `let`: 今と同じく E0011 のまま

## 規則: `fn` と `ctl` の節

### 書き方

- 操作の節は、`|` の直後に `fn` か `ctl` を書いて始める。`return` の節にはどちらも書かない
- `ctl` の節は今の節と同じ意味である。`k` を受け取る節 (`| ctl op 引数 k -> 本体`、パラメータ付き handler では `| ctl op 引数 k st -> 本体`) と、`never` の操作の節 (`| ctl fail e -> 本体`) に書く
- `fn` の節は `k` を受け取らない。状態のない handler では `| fn op 引数 -> 本体` と書き、`| ctl op 引数 k -> k (本体)` と同じ意味になる。パラメータ付き handler では `| fn op 引数 st -> 本体` と書き、本体は操作の結果と次の状態の組を返す。意味は `| ctl op 引数 k st -> let (v, st2) = 本体 in k v st2` と同じである。組の順は `k v st` の引数の順に合わせる
- `fn` の節では、`k` を名前で参照できない。隠れた `k` を `drop` することも、データにしまうこともできない
- `ctl` を予約語にする ([字句](../../spec/lexical.md) の「キーワード」)。そのため、`ctl` は操作名にも変数名にも使えなくなる。名前は Koka の `ctl` の節に合わせた

### 引数の個数 (E1010)

E1010 の規則は変えない。`fn` の節は `k` を書かないので、期待する個数は「操作の引数の個数 + 状態の1個 (パラメータ付き handler のとき)」である。`ctl` の節は今と同じく、`never` でない操作なら `k` の1個を足す。E1010 の文言と注は、`fn` の節では `k` に触れない。

### 誤り

新しい診断 E1051 (`CLAUSE_KEYWORD`、HIR) を足す。次の3つの場合に出す。

- 操作の節に `fn` も `ctl` も書いていない。直し方として、`|` の後に `ctl ` を足す fix を付ける。`ctl` を足すと今の意味のまま通るためである。この節は `ctl` の節として下ろし、後の検査を続ける
- `never` の操作の節に `fn` を書いた。`never` の操作は再開しないので、`fn` の節の意味 (`k (本体)`) が成り立たない
- `return` の節に `fn` か `ctl` を書いた

パーサは `fn` と `ctl` を省ける形で受け付け、誤りは HIR が報告する。`fn` を書いた `never` の操作の節を見分けるには操作の宣言が要り、fix を付けられるのも HIR の側だからである (私の判断)。

E1013 (`MISSING_CLAUSE`) の help の例は、`ctl` を足した形 (`| ctl op _ k -> ...`、`never` の操作では `| ctl op _ -> ...`) にする (私の判断)。

### 型の誤りの文言

`fn` の節の本体の型が合わないときは、本体を指して「操作の結果の型 (パラメータ付き handler では結果と状態の組) と合わない」と報告する。隠れた `k` の引数の誤りとしては報告しない (私の判断)。

隠れた `k` が線形性の診断に現れる場合が1つある。`once` の操作の `fn` の節の本体が `multi` の操作を起こすと、本体の間ずっと生きている `Lin` の `k` が区間をまたぐので、持ち越し規則の誤り (E3006) になる。`ctl` で `| ctl ask () k -> k (choose ())` と書いても同じ誤りなので、健全さのために必要な誤りである。この診断は、`$k` ではなく「この `fn` の節の継続」(the continuation of this `fn` clause) と書き、節を指す (私の判断)。持ち越しの診断の値の種類 (`carry.rs` の `CarriedValue`) に、`fn` の節の継続を足す。

## 規則: ローカル関数どうしの相互再帰

### 組

- ブロックの中で続けて書いた関数の形の `let` の文の並びを、1つの組にする。組の中のどの本体からも、組のすべての名前が見える
- 組は、式の文、値の `let` (パターンの形の `let`)、`use` の文で切れる。コメントと空行では切れない (どちらも trivia で、文にならないため)
- 1行の形 (`let f x = e in e2`) は組を作らない。ブロックの中では式の文なので、前後の組も切る
- 組の名前の有効範囲は、組のすべての本体とブロックの残りである。そのため、組の後ろの関数の名前が外側の同じ名前を隠すのは、組の前の本体の中からも同じである (Haskell の `let` の組と同じ)
- 組の中で同じ名前を2回定義したら、E1017 (`DUPLICATE_BINDING`) にする。2つ目の定義を指して報告し、組の中の参照は1つ目を指すものとして続ける (私の判断)。E1017 の説明に「ローカル関数の組」を足す。組の外のシャドーイングは今のままで、式の文などで切れた後の同じ名前の `let` は前の定義を隠す

### 型検査

- 組の中の参照から依存のグラフを作り、強連結成分ごとに、呼ばれる側から順に検査する (Haskell の `let` の依存解析と同じ)。互いに呼ばない関数を続けて書いた今のプログラムでは成分がそれぞれ1つの関数になるので、今と同じ規則で検査される
- 成分の中の相手への呼び出しは、自分への呼び出しと同じく、本体を検査し終えるまで包含の確かめを後回しにする
- 成分の関数は、今と同じく関数ごとに最後の矢印の row を持つ (ユーザーが決めた)。成分で1つの row を共有する案は採らなかった。成分の中で張った handler が処理するエフェクトも成分のすべての関数の row に出てしまい、そのエフェクトを許さない文脈から呼ぶと E2002 になるためである。次の `f` は、`Ask` を外に出さないので `<>` の文脈から呼べる

  ```haskell
  let f n = handle g n with
    | fn ask () -> 1
  let g n = if n == 0 then ask () else f (n - 1)
  ```

- 成分ごとの検査は次の順に行う
  1. 成分のすべての関数の本体を、テキストの順に検査する。成分の中の相手への呼び出し (自分への呼び出しを含む) は、呼び出し先と、呼び出しの位置の今の row を記録して後に回す
  2. 固定点: 記録した呼び出しを、変化がなくなるまで繰り返したどる。呼び出しごとに、呼び出し先の row の今のラベルのうち、呼び出しの位置の今の row に足りないものを、今の row の自由な末尾に足す。足りるかどうかは、scoped labels の対にし方 (同じエフェクトのラベルを row の中の順で対にする) で数える。呼び出し先の自由な末尾は使わない (末尾どうしをつながないので、自分を含む row の中に自分が現れることはない)。今の row の末尾が rigid な変数か閉じた row で足せないときは、そこでは何もしない (その呼び出しは 4 で E2002 になる)
  3. 各関数の row の末尾を閉じる。閉じない例外 ([型と Kind](../../spec/types.md) の「ローカル関数の推論」) は関数ごとに今と同じく当てはめる。ただし、捕まえた変数から成分の関数を除く
  4. 記録した呼び出しについて、今と同じく包含を確かめ、`mask` を記録する
- 2 は止まる。ラベルは足すだけで減らない。呼び出しの位置の今の row は、呼び出す側の row に、呼び出しを囲む handler のラベルを足したものである。そのため、どの関数の row でも、1つのエフェクトのラベルの数は、成分の関数の本体が直接起こすラベル (成分の外の関数の呼び出しで起こすものを含む) の数の最大を超えない。自分への呼び出しだけの成分では、呼び出し先の row が呼び出す側の row そのものなので、2 は何も足さない。そのため、自分を呼ぶ今のローカル関数は今と同じ型になる
- 2 で足す先が、呼び出しを含むラムダの row のこともある。ラムダの row は、そのラムダを渡した先の型を通して、ほかの row とつながっていることがある。足せない場合 (つながった先が閉じた row や rigid な変数のとき) は、4 の包含の確かめが E2002 を報告する。足すときに型の単一化が失敗しても、2 の途中では報告しない。表を変えずに足りないラベルを数えてから足す
- 再帰する成分の関数は、`Unr` の値しか捕まえられない (E3001)。再帰しない成分の関数は今と同じく `Lin` の値も捕まえられる。E3001 の文言は「a recursive local function cannot capture a linear value」に改め、自分を呼ぶ場合と相互に呼ぶ場合で同じにする
- 使用回数のパスと持ち越しのパスは、成分の中の相手への参照を、自分への参照と同じく捕獲に数えない。別の成分の関数への参照は、今の「前に定義したローカル関数」への参照と同じに扱う。組の中では定義の順と依存の順が違いうるので、テキストの順ではなく成分の順で扱う

### Core IR の持ち上げ

- 持ち上げた関数の名前と番号 (`<instance>$let$<name>`、`#2`) は今と同じく定義の順に決める
- 成分の関数は、成分全体が捕まえる変数の和を、共通の追加の引数として受け取る。並びは成分の中で決まった1つの順 (変数の番号の順) にする。捕まえたローカル関数は、今と同じくその関数が捕まえる変数に置き換える。別の成分の関数は先に持ち上げ終えているので、そのまま置き換えられる
- 成分の中の呼び出しは、今の自分への呼び出しと同じく、共通の追加の引数を先頭に渡す直接の呼び出しになる

## 設計

### 構文 (`eml_syntax`)

- 字句: `ctl` を `CTL_KW` にする。`fn` は今の `FN_KW` を使う
- `handler_clause` は `|` の後に `FN_KW` か `CTL_KW` を省ける形で読み、`OP_CLAUSE` か `RETURN_CLAUSE` に含める。`| fn return x -> e` のような形も読み、誤りは HIR に任せる
- AST: `OpClause` と `ReturnClause` に、先頭のキーワードを返すメソッドを足す (`HandleExpr::from_keyword` と同じく `support::token`)
- 文法 ([文法](../../spec/grammar.md)) の `clause` の生成規則を `'|' ('fn' | 'ctl') qvar apat* '->' body` に改め、`'fn' | 'ctl'` を省いた形はパーサが受け付けて HIR が E1051 にすると補足に書く

### HIR (`eml_hir`)

- `lower/handler.rs` の `op_clause` が `fn` の節を下ろす。隠れた `k` (名前 `$k`) を引数の並びに足し、本体を `$k (本体)` (パラメータ付き handler では `let ($v, $st) = 本体 in $k $v $st`) に書き換える。HIR の `OpClause` は今の形 (`resumes: true`) のままなので、型検査、translate、EP は変えずに済む。省いた `return` の節の `$r` と同じく、隠れた名前は利用者のコードから解決できない
- 型の誤りの文言のために、`fn` の節の本体だと分かる印 (たとえば本体の式の側表) を HIR に残し、型検査はその式の期待する型の由来を「`fn` の節の本体」にする。印の形は実装に任せる
- `lower_stmts` が組を作る。続けて現れる関数の形の `LET_STMT` を集め、まず組のすべての名前を束縛し、その後で本体を順に下ろす。`Stmt::Functions(Vec<LocalFunction>)` は組の関数を定義の順に持つ。1行の形 (`LET_EXPR`) は今と同じく1個の組になる
- HIR の表示 (`pretty.rs`) は下ろした形 (`$k` を含む) を表示する

### 型検査 (`eml_types`)

- `check/body.rs` の `local_functions` が、組の強連結成分を求めて成分ごとに検査する。求め方は `scc.rs` と同じ Tarjan の方法でよい。組のすべての名前は、どの成分を検査するよりも前に型を置いて束縛する
- 固定点 (上の「型検査」の 2) は、`Table` に「呼び出し先の row の今のラベルのうち、今の row に足りないものを数える」操作と「自由な末尾にラベルを足す」操作を足して作る。`include_row` は使わない。`include_row` は呼び出し先の末尾を今の row とつなぐためである
- `usage.rs` と `carry.rs` の、自分への参照を除く箇所 (`defining.get(id)` との比較) を、成分の関数の集合との比較にする。`usage.rs` の `debug_assert_eq!` (捕獲は `closure_captures` から自分を除いたもの) も成分を除く形にする
- `KindReason::RecursiveLocal` の文言を改める (上の「型検査」)

### Core IR (`eml_core_ir`)

- `translate/mod.rs` の `lifted_functions` が成分ごとに捕獲を求める。成分の関数を同じ `captured` の並びで予約する
- EP は変えない。`fn` の節は HIR で `k (本体)` の形になるので、`evidence/handlers.rs` の `runs_in_place` が今のまま、yield の地点を持たない節をその場で動く節にする

## テスト

### 構文 (`crates/eml_syntax/tests`)

- `fn` と `ctl` の節、`return` の節を持つ handler の CST
- `fn` も `ctl` もない節と、`| fn return x -> e` を誤りなく読むこと

### HIR (`crates/eml_hir/tests`)

- E1051 の3つの場合。キーワードのない節の fix が `ctl ` を足すこと
- `fn` の節の下ろし方 (状態のない handler とパラメータ付き handler) の HIR の表示
- `fn` の節の引数の個数の誤り (E1010) の文言が `k` に触れないこと
- 組の作り方: 式の文、値の `let`、`use` で切れること。コメントと空行で切れないこと。1行の形が組を作らないこと
- 前の本体から組の後ろの関数を参照できること。組の後ろの関数が、組の前の本体の中でも外側の同じ名前を隠すこと
- 組の中の同じ名前の2回目の定義が E1017 になること

### 型検査 (`crates/eml_types/tests`)

- `fn` の節の本体の型の誤りの文言 (状態のない handler とパラメータ付き handler)
- 相互再帰する成分のエフェクトの推論: 成分の中の関数がエフェクトを起こすとき、成分のどの関数を呼んでもそのエフェクトが row に出ること。上の `f` と `g` の例で、`f` の row が `<>`、`g` の row が `<Ask>` になり、`<>` の文脈から `f 3` を呼べること
- 3つの関数の成分で、固定点が2回以上たどって決まる例 (`f` が `g` を、`g` が `h` を、`h` が `f` を呼び、`h` だけがエフェクトを起こす)
- 成分の中の呼び出しの位置の row の末尾が rigid な変数のとき、足せないラベルが E2002 になること
- 互いに呼ばない関数を続けて書いた組が、今と同じ型になること (後ろの関数が前の関数を呼ぶ形と、前の関数が後ろの関数を呼ぶ形)
- 再帰する成分の関数が `Lin` の値を捕まえると E3001 になること。再帰しない成分の関数は捕まえられること

### Core IR (`crates/eml_core_ir/tests`)

- 相互再帰する成分の持ち上げ: 成分の関数が同じ追加の引数を受け取ること。捕まえた変数がそれぞれの関数で違うとき、和になること
- `fn` の節が、`ctl op x k -> k (e)` と同じ entry になり、その場で動く節になること (yield の地点がある本体では yield する entry になること)

### `run` (`tests/ui/run`)

- `effects/fn_clauses.em`: 状態のない handler の `fn` の節、`multi` の操作の `fn` の節、別のエフェクトを起こす本体を持つ `fn` の節 (その場で動かない節)、`fn` と `ctl` の節を混ぜた handler
- `effects/fn_clauses_state.em`: パラメータ付き handler の `fn` の節 (上の `run_state` の形)
- `functions/mutual_recursion.em`: 偶奇の判定、捕まえた変数を持つ相互再帰、エフェクトを起こす相互再帰、3つの関数の成分、互いに呼ばない関数と成分が混ざった組
- `functions/mutual_recursion_csv.em`: CSV の欄と行を読む状態機械を相互再帰で書いたもの (引用符のある欄を含む)

### `check-fail` (`tests/ui/check-fail`)

- `names/clause_without_keyword.em` (E1051 と fix)、`names/fn_clause_for_never.em` (E1051)
- `names/duplicate_local_function.em` (E1017)
- `linearity/mutual_recursion_captures_file.em` (E3001)

## テストの変更

- 種類2: 既存の handler の操作の節に、すべて `ctl` を足す。対象は `tests/` の `.em`、`crates/*/tests` のテストの中のソース文字列、REPL のトランスクリプト、`crates/eml_syntax/tests/corpus`、`std/Prelude.em` の `try_io`、`bench/state.em` である。節の挙動を変えずに確かめ続けるため、すぐに再開するだけの節も `fn` には書き直さない。`fn` の節は新しいテストで確かめる。これに伴って、CST のダンプ、ソースの行を引用する診断のスナップショット、列の位置が変わる。`bench/state.em` は `RunStats` のスナップショット (`crates/eml_vm/tests/bench.rs`) を変えないように `ctl` を足すだけにする。`RunStats` が変わったら、それは調べるべき発見として扱う
- 種類2: E1013 の help の例に `ctl` が入る
- 種類2: E3001 の、再帰するローカル関数の捕獲の文言が変わる (`check-fail/linearity/recursive_local_captures_file.em`、`recursive_local_captures_once_continuation.em` と、文言を見る単体テスト)
- 種類2 (見直しの結果による): 組の名前の有効範囲が変わるので、`tests/`、`std/`、`bench/`、`crates/*/tests` のソース文字列、REPL のトランスクリプトから、続けて書いた関数の形の `let` の前の本体が、後ろの関数と同じ名前の外側の定義を参照している箇所を探す。見つかったら、意味を保つように入力を直す (間に式の文を挟むか名前を変える) か、期待する値を改めるかをその箇所ごとに選び、計画とコミットの記録に残す
- 種類2: `crates/eml_core_ir/tests/translate.rs` の `local_function_names_do_not_collide_with_generated_names` は、同じ名前 `k0` の関数の形の `let` を続けて書いているので、E1017 になる。2つの `let` の間に式の文を挟み、期待する名前 (`main$let$k0#2`) を保つ

## 計測

`RunStats` のスナップショットは変わらない見込みである (上の「テストの変更」)。`bench/run.sh` と `bench/rt.sh` は測らない。速さに関わる変更は `fn` の節が今の「すぐに再開する節」の最適化に乗ることだけで、新しい仕組みを足さないためである。

## 私の判断で決めたこと

- `ctl` を予約語にする
- `fn` も `ctl` もない節はパーサが受け付け、HIR が E1051 にして `ctl ` を足す fix を付ける。`never` の操作の `fn` と、`return` の節の `fn` / `ctl` も同じ E1051 にする
- E1013 の help の例を `ctl` の形にする
- `fn` の節は HIR で `k (本体)` の形に下ろし、型の誤りは「`fn` の節の本体」として報告する
- 組の中の同じ名前は E1017 に含め、2つ目を指して報告し、参照は1つ目を指す
- 固定点で足りないラベルを数えるとき、呼び出し先の自由な末尾を使わない
- `fn` の節の継続を持ち越す誤りは「この `fn` の節の継続」と書く
- 組の名前の有効範囲の変化で意味の変わるテストを探し、見つかったものを種類2として扱う
- 成分の共通の追加の引数は、変数の番号の順に並べる
