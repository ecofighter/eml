# S2b 組み込みを extern にする 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 組み込みを `extern` の宣言と `eml_extern` の表で表し、`IO` を操作のないラベルにし、標準ライブラリを埋め込んだ `std/` ツリーから読んでファイルの操作を `Fs` に移す。

**Architecture:** 6つのタスクで、各タスクの終わりにすべてのテストが通る形で進める。構文 (T1) と `std/` のローダー (T2) を先に入れ、純粋な組み込みを extern にし (T3)、`IO` を extern のエフェクトにし (T4)、ファイルの操作を `std/Fs.em` に移し (T5)、最後に文書を直す (T6)。T3 と T4 のあいだは、`IO` だけが今の操作を持つエフェクトのまま残る。

**Tech Stack:** Rust (edition 2024)、insta、eml の UI テスト。

**Spec:** `docs/superpowers/specs/2026-10-08-s2b-externs-design.md`

**Code map (付録):** `docs/superpowers/plans/2026-10-08-s2b-code-map.md`。変える箇所の行番号と今のコードの説明がある (行番号は 32402a4 のもの。末尾の「9. Addendum」は設計のレビューで確かめた事実)。各タスクは、指示した節を読んでから始める。

## Review Focus

- import でつながっていないモジュールどうしで、修飾子の意味が混ざらないこと。モジュール A が `import Fs` でユーザーの `Fs.em` を指し、モジュール B が import なしで `Fs.open` を書いたら、B は標準ライブラリに届く (T5 の `user_module_named_fs` に B を足す)
- `IO` がエフェクトの表から外れても、ユーザーのエフェクトの番号がずれないこと。`mask` と `handle` と `perform` が正しい handler に届く (T4 で、`IO` と2つのユーザーのエフェクトと `mask` を使う Core IR の translate のテストを足す)
- ユーザーのモジュールの `extern` が、宣言を使っても E1033 だけになること (T3 で、3つの形を本体で使うテストを書く)
- `==` と `!=` を `Int`、`String`、`Bool` で使い、値として使ったとき (ラムダへの脱糖) も、型ごとの行が選ばれること (T3 の translate のテストと、既存の run の UI テスト)
- 根に `std/` というユーザーのディレクトリがあっても、標準ライブラリの読み込みに混ざらないこと (T2 で、`MemorySource` に `std/Prelude.em` を置いても読まれないことを確かめる)

- [ ] **Step 3: 実装する**

`item` を次の形にする。`pub` の後に `extern` があれば、`extern_decl` だけを受ける。

```rust
let public = p.eat(PUB_KW);
let external = p.eat(EXTERN_KW);
let kind = item_kind(p);
// extern は、等式のないシグネチャ、`=` のない `data`、`where` のない `effect` にだけ付く
// (docs/spec/grammar.md の `item`)
if external && !matches!(kind, Some(ItemKind::Signature | ItemKind::Data | ItemKind::Effect)) {
    p.error_at_previous(
        codes::SYNTAX_ERROR,
        "`extern` cannot be written on this item",
        "`extern` goes on a signature, a `data` without `=`, or an `effect` without `where`",
    );
}
match kind {
    Some(ItemKind::Data) if external => extern_data(p, m),
    Some(ItemKind::Effect) if external => extern_effect(p, m),
    // ここから下は今の `match kind` の腕のまま。extern のシグネチャは普通のシグネチャと同じく読む
    Some(ItemKind::Data) => data_item(p, m),
    Some(ItemKind::Type) => type_item(p, m),
    Some(ItemKind::Effect) => effect_item(p, m),
    Some(ItemKind::Fixity) => fixity_item(p, m),
    Some(ItemKind::Import) => import_item(p, m, declared),
    Some(ItemKind::Reserved) => reserved_item(p, m),
    Some(ItemKind::Signature) => signature(p, m),
    Some(ItemKind::Equation) => equation(p, m),
    Some(ItemKind::OperatorEquation) => operator_equation(p, m),
    None => { /* 今の「expected an item」の腕のまま */ }
}
```

誤りを出した後は、項目を今のとおりに読む (`extern f x = x` は E0011 の後に等式として読む)。

`extern_data` と `extern_effect` は、キーワードと `UIDENT` を読んでノードを閉じる。型引数 (`LIDENT`)、`=`、`where` が続けば E0011 を1つ出して、項目の終わりまで読み飛ばす。`extern pub` は、`extern` の後の `pub` を E0011 にする (`p.at(PUB_KW)` なら誤りを出して読み飛ばす)。誤りのメッセージは「`extern` cannot be written on …」の形で、今の `pub` の誤り (`items.rs:63-74`) に合わせる。extern のシグネチャの後に等式が続くかどうかは、構文では見ない (HIR が読み捨てる。T3)。

`item_kind` は `pub` と同じく `extern` を見ない。`at_item_start` は `p.at(PUB_KW) || p.at(EXTERN_KW) || item_kind(p).is_some()` にする。
