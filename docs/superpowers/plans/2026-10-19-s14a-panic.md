# S14a `Panic` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Value-dependent runtime errors (integer overflow, division by zero, string index / slice / char-boundary errors, out-of-range script arguments) and a user-raised `panic` become the typed extern effect `Panic`. `try_panic` catches them by unwinding. Calls to functions that cannot abort stop being unwind points.

**Architecture:** `Panic` mirrors `IO`:
- an extern effect with one hidden `never` operation `panicked`;
- a Prelude handler `try_panic`;
- a VM dispatch that finds the nearest `Panic` evidence with `Ctx::ev_find` and calls the clause entry, which unwinds through the S13c tables.

With no evidence, the error stays today's runtime error. The types side adds `<Panic>` to every faulting extern and to the std and test signatures that reach them. The LIR side computes a per-function "may abort" least fixpoint and builds unwind points only where an abort can pass.

**Tech Stack:** Rust (`eml_extern`, `eml_syntax`/`eml_hir`, `eml_types`, `eml_core_ir`, `eml_lir`, `eml_vm`, `eml_rt` with Verus), insta, `eml_test_support`, the UI and REPL harnesses, `crates/eml_vm/tests/bench.rs`, `bench/run.sh` (macOS).

**Spec:** `docs/superpowers/specs/2026-10-19-s14-numeric-design.md`, sections 「2026-10-19 に決めたこと」 and 「S14a `Panic`」 through 「S14a のテストの変更」.

## Global Constraints

- Code comments and docs are Japanese, written with the `yomiyasu:yomiyasu` skill; comments explain why and cite `docs/` paths. CLAUDE.md stays English.
- Prelude declarations, exactly:
  - `pub extern effect Panic where` / `  never panicked : String -> a`
  - `pub extern panic : String -> <Panic> a`
  - `pub try_panic : (Unit -> <Panic | e> a) -> <e> Result String a` (handles `ctl panicked message -> Err message`, `return x -> Ok x`)
- `eml_extern`:
  - `Purity` becomes `Pure | Panics | Effectful`. `Panics` replaces `MayFail` and means "raises `Panic`". `Effectful` means "raises `IO`", and may also raise `Panic` (`Std.Env.arg`).
  - `ExternEffect::Panic` has row name `"Prelude.Panic"`.
  - `Extern::Panic` has the row `"Prelude.panic"`, params `[Obj]`, `ret: OpRet::Never`, `Purity::Panics`.
- Faults that go to `Panic`: `Fault::Arith(_)` and `Fault::Index(_)` (all four `IndexFault` kinds). All other faults keep today's behaviour.
- Messages, exact:
  - The `Err` payload is the user's string for `panic s`, and `fault.to_string()` for a built-in fault.
  - An uncaught user panic prints `panicked: {message}` with the usual `\n  at path:line:column`.
  - E2004: ``"`main` must have type `Unit -> <IO, Panic> Unit`, with either label optional"``.
  - E2015: ``"{name} performs {quoted}, but an input may perform only `IO` and `Panic`"``.
- Rows:
  - `main` passes when its row has only `IO` and/or `Panic` labels (any order, `<>` included) and no tail.
  - REPL `Expr` / `Let` inputs get the closed ambient `<IO, Panic>`.
  - Top-level values and `Eq` / `Ord` / `Show` methods keep empty rows. No code change is needed there: E2002 and its existing help already cover them.
- Negative literals: HIR folds a prefix `-` whose operand is directly an `INT` / `FLOAT` literal token into a negative literal. `f -1` is unchanged, and `-9223372036854775808` stays a lexer error.
- Test changes:
  - Kind 2, within the spec's 「種類2」. Adding `<Panic>` to test sources is kind 2.
  - Kind 1: none. A UI test that would change between `run`, `run-fail` and `check-fail` is a bug; stop and report.
  - Bench `RunStats` may change only where the spec names a reason: negative-literal folding (Task 1), the under form (Task 3). Any other change is a bug.
- `eml_rt` changes pass `cargo verus verify -p eml_rt` and `verusfmt --verus-only --check $(git ls-files 'crates/eml_rt/src/*.rs')`, plus the Miri trusted tests if `externs.rs` code moves.
- Gate per task: the task's tests, then `cargo test`, `cargo clippy --all-targets`, `cargo fmt --check`. Use `git diff --no-ext-diff`.
- Commit messages end with the attribution lines the controller gives.

**Interfaces:**
- Produces: `eml_lir::unwind::may_abort(&Program) -> Vec<bool>`.
- Rules:
  - A function may abort when one of its statements or terminators is a direct call or `tail` to a function that may abort, any `apply` or `clause` (tail or not), a non-`Pure` extern, or `prim yield_abort`.
  - The points are the non-tail ones of these: direct calls to aborting functions, `apply`, `clause`, non-`Pure` externs, and `yield_abort`.

  - `recursive_pure_functions_do_not_abort`: mutual recursion with no aborting statement.

  - Source test `map_with_pure_function_has_no_unwind_point_at_the_call`: `List.map (fn s -> s ++ "!") xs` inside `main`. The call to the specialized copy is not a point.
