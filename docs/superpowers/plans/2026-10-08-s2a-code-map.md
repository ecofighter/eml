## 8. Risks

- **R1 evaluation steps for `k v st`.** `eml_hir::known_arity` (eval.rs:54-63) is `None` for a local callee, so `call_steps` flushes `Arrow(0)` before a non-value second argument: `k st (st + 1)` becomes `Eval k, Eval st, Arrow 0, Eval (st+1), Arrow 1`. Translate would then emit an `Apply` of a partial application, not one `Call::Resume`, and `translate.rs:628` dump (`resume k1(st2, t3)`) changes. Options: make `known_arity` return the continuation arity for clause-k locals (eval.rs is shared by carry.rs and translate, comment at eval.rs:1-3 requires they agree; HIR can find the clause via `OpClause::k()`), or let the direct form evaluate all args first (sound because the first arrow's row is empty). Decide in the plan.
- **R2 direct vs wrap classification.** `a_resume_inside_an_inner_handle_is_masked` expects a raw `resume` inside the inner handle's body closure (k captured by a lifted closure). The spec lists "ラムダで捕まえる" as wrap form. The rule must say whether a saturated call inside a nested lambda/handle body/clause is "direct". Also FnLowering for nested lifts starts with empty `locals`; the raw/wrapped status of k must be threaded through `lift`.
- **R3 E2001 messages with identical types.** `Type::Fn` has no linearity, so a Lin/Unr arrow clash (`unify_arrow_lin` `Known(Lin)` vs `Known(Unr)` -> `UnifyError::Mismatch`) prints "expected `Int -> Int`, found `Int -> Int`". It happens when a `once` k meets an arrow fixed to `Unr`: `data` field arrows (`Arrows::Unr`, shape.rs:66-76) and outermost signature arrows. Operation parameters are inferred but pinned by `unrestricted` -> E3001 instead.
- **R4 `continuation_stored` for a `once` k.** Storing k in the handle's own result needs a recursive data type (`R = Option (Int -> R)` is an occurs failure, E2005), and a `data` field arrow is fixed `Unr`, so a `once` k cannot be stored there (R3). The test probably needs a `multi` op or a polymorphic container outside the handle's result type.
- **R5 partial application of a stateful k where `r` is a type variable.** `k v` in a stateful handler returns `σ -> r`; if `r` is still a variable, unifying with the clause type `r` is an occurs failure, so the error is E2005 "infinite type" rather than E2001.
- **R6 linearity of the second arrow for `multi`.** With `a -[Unr]-> σ -[Unr]-> r`, `let g = k v` captures `v` in an Unr closure. If `a` is Lin, `g` could run twice. Constructors and lambdas use `closure_kinds` (kinds.rs:78-98) or a fresh var for inner arrows to avoid this. Either constrain `kind(a) ≤ m2` with `m2` fresh and `m ≤ m2`, or argue that `a` is never Lin for `multi`.
- **R7 a `resume` that is not bound.** After the keyword is removed, any remaining `resume k v` is E1001 "cannot find value `resume`". The hidden ones: `README.md:31`, `docs/spec/modules.md:87`, the docs/future files, `crates/eml_syntax/tests/corpus/s1.em`, and every test source string.
- **R8 `unparenthesized_lambda.em`.** Its `inc resume k 1` case loses the E0012. The file still fails because of the `fn` case, but the header comment and snapshot change; this is a behavior/expected-output change. A `drop` case could replace it.
- **R9 diagnostics wording to rewrite.** E3005 help (`call `resume {name} v` or `drop {name}``, report.rs:552); E3005 message ("must be resumed or dropped"); E3006 "resuming `k`" (report.rs:611-612, linearity.rs:638); `Origin` notes for resume (report.rs:396-404); `LINEAR_NOTE`/`CARRY_NOTE` keep generic "resumed". HIR E1010 notes (handler.rs:195-203) and the E1013 help example (`clause_example`, handler.rs:411-423) mention "the continuation `k`" (still valid). The E2007 fixes ("pass the current state `st`", "remove the state argument") disappear with no replacement fix.
- **R10 display-name table.** Removing the `CONT` entry in `eml_hir/src/names.rs:40` changes how a user `data Cont` is displayed (`Main.Cont` -> `Cont`) in `def_map.rs:474` and `eml_types/tests/modules.rs:134-136`.
- **R11 field and doc names.** `OpClause::resumes` (hir.rs:466), `Call::Resume`, and the Core IR text keyword `resume` stay. Only the surface keyword goes. `KEYWORD_ARITY`/`KEYWORD_APPS` now cover only `drop`.
- **R12 `k` annotations.** A clause can now write `(k : Int -> Int)` (it used to fail because `Cont` had no syntax). Annotated arrows get fresh lin vars, which unify with `Known(Lin)`. `usage::check_continuation` and `bound_variable` already look through `Annot`.
