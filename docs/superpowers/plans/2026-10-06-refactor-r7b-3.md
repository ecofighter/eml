# リファクタリング R7b-3 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 名前解決を `ItemTree` (item の収集)、`DefMap` (モジュールごとのスコープ表)、item ごとの変換の3段に分け、重複の扱いを3つの規則にそろえ (不具合2)、`pub` と定義に付く fixity を実装し、Prelude の組み込みの型を `=` のない `data` にする。

**Architecture:** `item_tree` はファイルごとに宣言を集め、`def_map` は全モジュールの `ItemTree` から名前の表と ID と lang item を作り、`lower` は `DefMap` を引きながら item と本体を HIR にする。変換が名前を引く口は、`DefMap` とモジュールの組である `Resolver` にまとめ、今の `ItemScope` と同じ問い合わせの名前 (`value`、`constructor`、`operation`、`type_item`、`fixity` など) を持たせる。型検査と Core IR は変えない。

**Tech Stack:** Rust (edition 2024)、`insta`、`cargo test`。

**Spec:** `docs/superpowers/specs/2026-10-06-refactor-r7-design.md` の 1.1 (段階と入口)、1.5 (`pub` と名前の解決の順)、2.2 (`data` の `=` の省略)、3章 (名前解決)、7.1 の R7b の行。

## spec からの補い

- spec 3.1 は E1005 (シグネチャだけで等式がない) も `ItemTree` が出すとした。Prelude の等式のないシグネチャは intrinsic で誤りではないので、モジュールの種類を知らない `item_tree` では判定できない。E1005 は `lower` が、入口のモジュールの関数について出す。E1020 (等式の引数の個数の違い) は、今と同じく本体の変換が出す
- spec 4.3 の `IO` のエフェクトは R7d で Prelude に宣言する。R7b-3 の間は、`DefMap` が Prelude のモジュールの型の名前空間に、操作のない `IO` を処理系の item として足す。これを「合成の item」と呼ぶ。Task 5 までは `Int`、`String`、`Unit`、`File` も合成の item で、Task 5 で Prelude の `=` のない `data` に置き換える
- item の局所の番号は、`DefMap` と `lower` の両方が同じ規則で決める。モジュールの中で、合成の item を先に、続けて `ItemTree` の順に並べる。コンストラクタと操作は、`data` とエフェクトの宣言の順に、その中の宣言の順で通し番号にする。`lower` はアリーナに item を置くたびに、得た番号が `DefMap` の番号と同じであることを `debug_assert_eq!` で確かめる
- 「使えない」定義 (重複した `data` のコンストラクタ、重複した `effect` の操作) は、重複の判定 (E1003) に加えない。名前を引いたときに、同じ名前の使える定義がなければ `Unusable` を返す。今の `define_unusable_constructor` の扱い (`or_insert`) と同じである
- 種類を指定して引く位置 (規則3) で見つかった定義が使えない定義なら、診断を出さずにその位置を `Missing` にする。handler の節では、その節を捨てる
- fixity の `pub`: 演算子の定義が別のモジュールから引かれたとき、その定義の fixity は、fixity の宣言が `pub` のときだけ効く。`pub` でなければ `infixl 9` である。Prelude の fixity の宣言はすべて `pub` である
- `pub data` は型とコンストラクタを、`pub effect` はエフェクトと操作を公開する (docs/spec/declarations.md の「`pub`」)
- lang item は、Prelude のモジュールから `pub` によらずに名前で引く (spec 3.4)。lang item の表は `def_map` が作り、`DefMap::lang` に置く

## Review Focus

- 不具合2: `effect E where get : Unit -> Int` の後に関数 `get` を定義し、handler に `| get () k -> …` を書いたプログラム: E1003 だけが出て、節の E1001 は出ない。関数を先に定義した場合も同じ (Task 4 にテストを置く)
- 重複した `effect` の操作を使った式と節: 診断を重ねずに `Missing` になる。今は型検査で E2002 が連鎖する (Task 3 と Task 4 にテストを置く)
- ユーザーが Prelude の演算子 (`+`) を定義し、fixity を宣言しない場合: Prelude の `infixl 6` を引かず、`infixl 9` になる。`1 + 2 * 3` の組み方が今と同じになる (Task 3 にテストを置く)
- `pub` を付けないユーザーの関数とデータ: 入口のモジュールの中では今と同じに使える (`pub` は別のモジュールから引くときだけ効く)。Prelude の `pub` でない `negate` は、今と同じく名前で書けない (Task 3 と Task 4 にテストを置く)
- ユーザーが `data Int = | I` を定義した場合: Prelude の `Int` を隠す。整数のリテラルは今と同じく lang item の `Int` の型を持つので、`f : Int` と `f = 1` は今と同じ E2001 (「expected `Int`, found `Int`」) になる (Task 5 にテストを置く)

#[derive(Clone, Copy)]
pub struct Resolver<'a> { /* def_map と module */ }
pub enum ValueItem { Function(FunctionId), Operation(OperationId), Constructor(ConstructorId), Unusable }
pub enum TypeItem { Type(TypeDefId), Effect(EffectId) }
pub enum Lookup<T> { Found(T), Unusable, NotFound }

    pub fn value(&self, name: &str) -> Option<ValueItem>;

    pub fn type_params(&self, id: TypeDefId) -> usize;

`def_map` の手順:

1. モジュールごとに ID を決める。合成の item (Prelude だけ: 型 `Int`、`String`、`Unit`、`File`、エフェクト `IO`) を先に、続けて `ItemTree` の順に局所の番号を振る
2. 型の名前空間に、合成の型とエフェクト、`data`、`effect` を入れる。`data` と `effect` の重複は名前空間の中で1つの並びにする (今の `type_names` の共有と同じ)
3. 重複した `data` (名前の2つ目以降の定義) のコンストラクタと、重複した `effect` の操作を「使えない」にする
4. 値の名前空間に、関数、操作、コンストラクタを入れる
5. 名前空間ごとに、名前の定義をソースの位置で並べ、使える定義の2つ目以降に E1003 を出す。合成の item の位置は空の範囲で、最初に来る
6. fixity の宣言を読み、演算子を自分のモジュールの値の名前空間で引いて、最初の定義に fixity を付ける。見つからなければ E1022、同じ定義への2回目の宣言は E1021 (今の `declare_fixities` と同じ文言と位置)
7. Prelude のモジュールから lang item を引いて `LangItems` を作る (今の `scope::lang_items` の名前の表と同じ)。見つからなければ panic する

`Resolver` の問い合わせ:

- `value(name)`: 自分のモジュールの `values[name]` の使える定義の最初、なければ使えない定義があれば `Unusable`、なければ (自分が Prelude でなければ) Prelude の `values[name]` の使える定義のうち `pub` の最初
- `constructor(name)`、`operation(name)`: 自分のモジュールの `values[name]` のうち、その種類の使える定義の最初 → その種類の使えない定義があれば `Unusable` → Prelude の `pub` の、その種類の定義 → `NotFound`
- `type_item(name)`: `value` と同じ順で型の名前空間を引く
- `fixity(op)`: `value(op)` の定義に付いた fixity。定義が別のモジュールにあり、fixity の宣言が `pub` でなければ `infixl 9`。定義がなければ `infixl 9`
- `is_unusable(name)`: `value(name)` が `Some(Unusable)` か
- `prelude_function(name)`: Prelude の `values[name]` の `pub` の関数

`lib.rs` に `mod def_map; pub use def_map::*;` と、`pub fn def_map(trees: &[ItemTree]) -> (DefMap, Vec<Diagnostic>)` を出す。

`eml_test_support` に足す (`hir` の feature)。

```rust
/// Prelude と入口のファイルの `ItemTree` から `DefMap` を作り、`def_map` の診断だけを返す。
#[cfg(feature = "hir")]
pub fn def_map(text: &str) -> (eml_hir::DefMap, Vec<String>) {
    let parsed = parse(text);
    let prelude = parsed.prelude.expect("the `hir` feature registers the Prelude");
    let prelude_tree = eml_hir::parse_prelude(prelude);
    let (prelude_items, _) = eml_hir::item_tree(prelude, &prelude_tree);
    let (items, _) = eml_hir::item_tree(parsed.file, &parsed.parse.tree());
    let (map, diagnostics) = eml_hir::def_map(&[prelude_items, items]);
    (map, short(&parsed.files, &diagnostics))
}
```

`lower` を次の形にする。

```rust
pub fn lower(def_map: &DefMap, trees: &[ItemTree]) -> (Program, Vec<Diagnostic>) {
    let mut diagnostics = Vec::new();
    let mut modules = Arena::new();
    for (index, tree) in trees.iter().enumerate() {
        let id = modules.alloc(Module::new(tree.file, def_map.module_name(module_id(index))));
        debug_assert_eq!(id, module_id(index));
    }
    for (index, tree) in trees.iter().enumerate() {
        let module = module_id(index);
        lower_items(def_map, module, tree, &mut modules[module].items, &mut diagnostics);
    }
    for (index, tree) in trees.iter().enumerate() {
        let module = module_id(index);
        let bodies = lower_bodies(def_map, module, tree, &mut modules, &mut diagnostics);
        modules[module].bodies = bodies;
    }
    (Program { modules, prelude: def_map.prelude(), entry: def_map.entry(), lang: def_map.lang() }, diagnostics)
}
```

`lower_items` は、モジュールの item を局所の番号の順にアリーナに置く。合成の型とエフェクト、`data` の型 (`TypeDef` と型引数)、エフェクト (`EffectDef` と型引数)、関数 (シグネチャ)、コンストラクタのフィールド、操作のシグネチャの順に変換する。名前はすべて `def_map.resolver(module)` で引く。アリーナに置くたびに、得た番号が `def_map.function_id(module, k)` などと同じであることを `debug_assert_eq!` で確かめる。Prelude のモジュールの関数はすべて intrinsic (`intrinsic: true`) で、E1005 を出さない。入口のモジュールの関数で等式がないものは E1005 を出す (今と同じ文言と位置)。重複した `data` のコンストラクタも今と同じくアリーナに置き、型の `constructors` の並びに入れる。

`lower_bodies` は、今の本体の変換の繰り返し (`std::mem::take` で型変数の表を取り出す形) を、モジュールごとに行う。
