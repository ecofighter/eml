#### T4.3 Borrowing while writing output
- `Machine.out: &'p OutputSink` (machine.rs:31) is a separate reference. `self.out.write_str(text)` can therefore run while `text: &str` borrows `self.heap`, because both are shared borrows of `self`.
- `OutputSink::write_str` (output.rs:23-30) does `write_all` + `flush`, so two calls for `println` mean two flushes. The bytes are identical.
- In a single method, NLL lets `concat` hold `head`/`tail` (`&str` borrowed from the heap) across `is_unique` and then call `append_str(&mut)` in the branch that no longer uses them. The scratch prototype compiled and was clippy-clean.

#### T4.4 The scaling program and its Core IR
- `++` is `pub extern (++) : String -> String -> String` (std/Prelude.em:54), `pub infixr 5 ++` (:10), and lowers to `extern Prelude.++` (Extern::StrConcat, eml_extern lib.rs:182).
- Program: `grow n acc = if n == 0 then acc else grow (n - 1) (acc ++ "x")`, `main () = println (grow 2000 "s")`. It typechecks and runs on 1e7d9a5 (`cargo run -p eml_cli -- run --debug-heap`), prints `s` followed by 2000 `x`, and is leak-free.
- Its Core IR (pretty-printed on the scratch copy): `fn grow(n0, acc1^) { ... let s4^ = const "x"; let t5^ = extern Prelude.++(acc1, s4); tailcall grow(t3, t5) ... #1 -> return acc1 }`, `fn main(p0) { let s1^ = const "s"; let t2^ = call grow(2000, s1); let t3 = extern Prelude.println(t2); return t3 }`. There is no `dup` of `acc1`, so after the first `++` the left side arrives with rc 1.

#### T4.5 Measured byte counts (scratch copy of 1e7d9a5 with a T2-like counter in `alloc`)
- Before T4 (literals still allocated per evaluation): 2,005,001 bytes = sum of new-object lengths 2..=2001 (2,003,000) + 2001 literal allocations.
- With the T4 prototype (still without T3): 4,001 bytes, made of 2000 `"x"` literal allocations, 2000 one-byte appends and `"s"`.
- Expected on top of T3: before T4 ≈ 2,003,000 (+2 if `alloc_immortal` counts the literal text); after T4 = 2 (first `++` copies the immortal `"s"` plus `"x"`) + 1999 appends = 2,001 (+2 if immortal allocation counts). The bound is 4n = 8,000.
