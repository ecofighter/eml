#### T2.4 Design decisions (verified behavior-preserving)
- `Piece::Operator(Operator { text, range, resolved, fixity: Fixity })`; undecided tokens are collected separately and reported after all operands are lowered, so the push order of diagnostics is the same as today (operand diagnostics first, then E1028 in token order). Prefix `-` is still resolved and can still make the sequence undecided.
- `climb` destructures all four fields in `while let`, so its body text is unchanged except `fixity` and the `binary` call; `resolved` is moved into `binary` and `text` is still usable (owned clone from `peek`).
- `binary` takes `resolved: Resolved<ValueItem>` (6 params incl. self, under clippy's 7). The unresolved-diagnostic arm keeps `if let Some(diagnostic) = unresolved(..)` so T3 still finds exactly six such sites (types.rs:116, types.rs:214, expr.rs:351, expr.rs:711, ops.rs:198, handler.rs:116).
- `undecided_operator(op, range) -> bool` and `BodyLowering::fixity(&str)` are deleted; replaced by `report_undecided(op, range, &resolved)` used by `lower_op_seq`, `section`, `lower_infix_pat`. Sections pass the outer `Fixity` to `looser_operator` and to a free fn `right_operand_minimum(Fixity)`. Infix patterns pass `&[Fixity]` (parallel to `operators`) to `climb_pat`.
- After T2, `Resolver::fixity(NameRef)` callers: `section.rs` `looser_operator` (pre-check and inner tokens, 2 sites) and 9 assertions in `eml_hir/tests/def_map.rs`.
- New test `an_undecided_sequence_reports_no_other_operator` was run against pre-T2 code too (passes both before and after): it pins that E1028 sequences emit no E1001. Its E1028 position is `5:9`.

Equivalence (old `line_indent` vs new `line_indent`), checked by reasoning and by the prototype's full test run:
- Old `Some(n)` iff the token before the statement is WHITESPACE containing '\n'; n = byte length after the last '\n'.
  Whitespace is `[ \t\r\n]+` (lexer/mod.rs:60) and line comments stop before '\r'/'\n' (lexer/mod.rs:207, `line_len`
  :278), so the text after that '\n' is exactly the new "line prefix". Same result when it is spaces only.
- Old `None` cases: preceded by a comment or other token on the same line (`{- c -} 0`, `x; y`, `f x = drop x`) give a
  prefix with non-blank characters -> new `None`. A block comment spanning lines ending `-} y` likewise.
- Differences: tabs (old: one space per tab; new: copies the tabs) and pathological '\r' inside indentation (old counts
  it, new refuses). The statement can never be on line 1 with only blanks before it (a declaration precedes it).
