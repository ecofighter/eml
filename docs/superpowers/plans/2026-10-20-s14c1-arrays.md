# S14c-1 `Array` and `MutArray` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the immutable `Array a` and the `Lin` `MutArray a` with `freeze` / `thaw`, index errors as `Panic`, and allocation-free reads, as the core that S14c-3's `var` builds on.

**Architecture:**
- Both types are Prelude extern types with one type parameter. `Array a` takes the Kind of `a`; `MutArray a` is always `Lin`. Both are covariant.
- At run time both are one `Data`-shaped `eml_rt` object (tag 0) whose scanned words are the elements (`tobj`; `Float` elements are boxed). The extended count word is used from 255 elements. A `MutArray` object has the `lin` bit, and `freeze` / `thaw` flip it in place on a unique object.
- Extern rows gain borrowed parameters, so `get` and `length` read without RC traffic. Rows also gain `with_arg`, so `MutArray.read` / `length` lower to a borrowed read plus a `con` of the pair, which fusion removes where the pair is opened at once.
- Extern calls gain `box` / `unbox` at their boundary, as primitives have, because array rows have `tobj` parameters and results.
- The VM runs `get`, `length` and `set` / `write` as dedicated ops.

**Tech Stack:** Rust (`eml_syntax`, `eml_hir`, `eml_types`, `eml_extern`, `eml_core_ir`, `eml_lir`, `eml_vm`, `eml_rt` with Verus), insta, `eml_test_support`, the UI and REPL harnesses.

**Spec:** `docs/superpowers/specs/2026-10-20-s14c-arrays-var-design.md` (sections S14c-1 and the test changes). The S14 design `docs/superpowers/specs/2026-10-19-s14-numeric-design.md` still applies.

## Global Constraints

- Code comments and docs are Japanese, written with the `yomiyasu:yomiyasu` skill. Comments explain why and cite `docs/` paths. CLAUDE.md stays English.
- Prelude declares `pub extern data Array a` (row `Prelude.Array`, `Repr::Obj`, Kind follows the parameter) and `pub extern data MutArray a` (row `Prelude.MutArray`, `Repr::Obj`, always `Lin`). Both parameters are covariant. User modules still get E1033 for any `extern`.
- `std/Array.em` (`Std.Array`), exactly these public items:
  - `extern make : Int -> a -> <Panic> Array a` (row `Std.Array.make`, `Panics`)
  - `tabulate : Int -> (Int -> <e> a) -> <Panic | e> Array a` (eml: `MutArray.freeze (MutArray.tabulate n f)`)
  - `from_list : List a -> Array a`, `to_list : Array a -> List a` (eml)
  - `extern length : Array a -> Int` (row `Std.Array.length`, `Pure`, arg 0 borrowed)
  - `extern get : Array a -> Int -> <Panic> a` (row `Std.Array.get`, `Panics`, arg 0 borrowed)
  - `extern set : Array a -> Int -> a -> <Panic> Array a` (row `Std.Array.set`, `Panics`)
  - `extern thaw : Array a -> MutArray a` (row `Std.Array.thaw`, `Pure`)
- `std/MutArray.em` (`Std.MutArray`), exactly these public items:
  - `extern make : Int -> a -> <Panic> MutArray a` (row `Std.MutArray.make`, `Panics`)
  - `tabulate : Int -> (Int -> <e> a) -> <Panic | e> MutArray a` (eml; calls `f` in index order)
  - `extern empty : Unit -> MutArray a` (row `Std.MutArray.empty`, `Pure`; length 0. It is needed by `from_list []` and `tabulate 0`, and is my addition to the spec's list)
  - `extern length : MutArray a -> (Int, MutArray a)` (row `Std.MutArray.length`, `Pure`, arg 0 borrowed, `with_arg: Some(0)`, row result `Repr::Int`)
  - `extern read : MutArray a -> Int -> <Panic> (a, MutArray a)` (row `Std.MutArray.read`, `Panics`, arg 0 borrowed, `with_arg: Some(0)`, row result `Repr::TObj`)
  - `extern write : MutArray a -> Int -> a -> <Panic> MutArray a` (row `Std.MutArray.write`, `Panics`)
  - `extern freeze : MutArray a -> Array a` (row `Std.MutArray.freeze`, `Pure`)
- Type variables that occur in an extern function's parameters are fixed to `Unr` in its scheme. Result-only variables (`exit`, `panic`, `empty`) are not fixed.
- Panic texts, exact, as new `IndexFault` variants so that `Fault::panics()` holds:
  - `IndexFault::Array { index, len }`: ``"array index {index} is out of range for length {len}"``
  - `IndexFault::Length { len }`: ``"array length {len} is negative"``
- Runtime semantics:
  - `set` / `write` write in place when the object is unique (`is_unique`), and otherwise copy. The copy `dup`s each kept element and keeps the source's `lin` bit. Both rows share one `Ctx` method.
  - `thaw` sets the `lin` bit in place when unique, and otherwise copies with the bit. `freeze` clears the bit in place; a `MutArray` is always unique, and a non-unique one is a `HeapError` in checked mode.
  - `get` / `read` `dup` the element and leave the array alone. `make n x` with `n = 0` releases `x`.
  - Failed calls: a borrowed argument stays owned by the caller, and the unwind table releases it. Consumed arguments are released by the extern, as today.
- VM ops: `Op::ArrayGet { dst, a, b }` (serves `Std.Array.get` and `Std.MutArray.read`), `Op::ArrayLength { dst, a }` (both `length` rows), `Op::ArraySet { dst, at }` (`set` and `write`; `at` lists array, index, value, because `Op` stays 8 bytes). All three are added to `step_failed`.
