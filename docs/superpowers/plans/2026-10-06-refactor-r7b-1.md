# リファクタリング R7b-1 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 組み込みを Prelude の intrinsic の関数にし、`Builtin` の表と `Res::Builtin` などの組み込み専用の経路を HIR、型検査、Core IR からなくす。

**Architecture:** Prelude (`prelude.em`) の等式のないシグネチャを、HIR の `Function` (`intrinsic: true`) として関数のアリーナに置き、名前は `Res::Function` に解決する。見え方は Prelude の `pub` で決め、処理系が役割で引く関数 (`negate`、`==`、`&&` など) は lang item にする。型検査は intrinsic の関数を本体のない宣言として扱い、Core IR は intrinsic の名前から実装 (`PrimOp`、`IoOp` など) を引く表を1つ持つ。

**Tech Stack:** Rust (edition 2024)、`insta`、`cargo test`。

**Spec:** `docs/superpowers/specs/2026-10-06-refactor-r7-design.md` の 4.2 (intrinsic) と、3.3 の `&&` などの扱い、3.4 の lang item。

## R7b の分け方

spec の R7b (1章、3章、4.2) は、HIR の名前解決の作り替え、プログラム全体の ID、組み込みの置き換えを含み、1つの計画には大きすぎる。互いに依存の少ない順に、3回に分けて進める。

| 回 | 範囲 | 下流の crate |
|---|---|---|
| R7b-1 (この計画) | 組み込みを Prelude の intrinsic の関数にする。`&&`、`||`、`|>`、`<|` を Prelude の関数と lang item にする | 型検査と Core IR の組み込みの経路 |
| R7b-2 | プログラム全体の ID (`ModuleId`)、`hir::Program`、Prelude を別のモジュールのアリーナに置く、本体を `Module::bodies` に分ける、Prelude の本物の `FileId`、session 型の lib API | ID の型の追随 (機械的) |
| R7b-3 | `ItemTree`、`DefMap`、`pub`、重複の3つの規則と不具合2、fixity を定義に付ける、`::` の fixity を外す、`=` のない `data` と E1025、Prelude の `Int` などの型 | ほぼなし |

R7b-1 を先にするのは、組み込みの経路が1つになっていれば、R7b-2 で Prelude をモジュールに分けるときに、Prelude の item が関数・コンストラクタ・型だけになり、特別な表を持ち越さずに済むためである。

## spec からの補い

- `pub` は、R7b-1 では Prelude の中だけで読む。ユーザーのモジュールの `pub` は、R7a のとおり HIR が E0004 を出す (R7b-3 で実装する)。Prelude の関数のうち `pub` のものだけを、ユーザーのモジュールから名前で引ける。`negate` は `pub` にしない
- spec 4.3 の `IO` のエフェクトは R7d で入れる。R7b-1 の間、`println`、`open`、`read_all`、`close` は Prelude の intrinsic の関数で、E1009 は lang item の `LangItems::io_operations` で判定する。今の `Builtin::is_io_operation` と同じく、ユーザーが同じ名前の関数を定義していても、節の名前が Prelude の `IO` の操作の名前なら E1009 にする
- `&&`、`||`、`|>`、`<|` は、Prelude の本体のないシグネチャ (intrinsic) で、lang item にする。HIR は、二項演算の演算子がこれらの lang item に解決したときだけ脱糖する。Core IR の intrinsic の表には入れない。脱糖するので Core IR に届かないためである
- 標準の演算子の fixity は、R7b-3 で定義に付けるまで、今の `prelude_fixities` (文字列の表) のままにする。`::` の fixity も R7b-3 まで残す
- `not`、`>>`、`<<` の本体を eml で書くのは R7d である。R7b-1 では今のまま intrinsic にする
- `eml_hir::PRELUDE_SOURCE` を R7b-1 で公開する (spec 1.4)。Core IR の intrinsic の表の網羅を確かめる単体テストが、Prelude のソースを読むためである
- HIR の pretty は、intrinsic の関数の参照を、今の組み込みと同じく `@` なしの名前で表示し、intrinsic の関数の宣言は表示しない。`eml_types::dump` も intrinsic の関数を表示しない。どちらも Prelude の `Bool` を表示しない今の扱いと同じで、テストの表示を Prelude に左右させないためである

## Review Focus

- 部分適用した intrinsic が `Lin` の値を捕まえる場合 (`(fn u -> close h) >> (fn u -> u)` を2回呼ぶ): 今と同じく E3002 になる。intrinsic の Kind のスキーム (`closure_kinds`) が、本体のない関数の空のスキームで上書きされると、黙って通ってしまう (Task 2 にテストを置く)
- ユーザーが `+` や `&&` を定義した場合: ユーザーの定義が Prelude の関数を隠し、`&&` は脱糖されずに普通の呼び出しになる (Task 1 にテストを置く)
- ユーザーが `println` という関数を定義し、handler の節に `| println s k` と書いた場合: 今と同じく E1009 になる (Task 1 にテストを置く)
- `negate` を名前で書いた場合と、前置の `-` を使った場合: 前者は E1001、後者は今と同じく `negate` の呼び出しになる (既存の `internal_builtins_cannot_be_named` と演算子のテストで確かめる)
- intrinsic を値として渡す場合 (`map show_int xs` のような形、`(+)` のセクション): Core IR は今と同じく `builtin$名前` の包む関数を作る (Task 3 で、既存の Core IR のスナップショットが変わらないことで確かめる)

            id = *ret;

        let range = self.exprs[lhs].range.cover(self.exprs[rhs].range);
        // 解決した先が Prelude の脱糖する演算子のときだけ脱糖する。ユーザーの定義は Prelude の演算子を隠すので、
        // `&&` を定義すれば普通の呼び出しになる (docs/spec/declarations.md の「fixity」)
        let res = match self.items.value(op) {
            Some(ValueItem::Function(id)) if id == self.lang.and => {
                let otherwise = self.alloc(ExprKind::Path(Res::Constructor(self.lang.false_ctor)), op_range);
                return self.alloc(ExprKind::If { condition: lhs, then_branch: rhs, else_branch: Some(otherwise) }, range);
            }
            Some(ValueItem::Function(id)) if id == self.lang.or => {
                let then = self.alloc(ExprKind::Path(Res::Constructor(self.lang.true_ctor)), op_range);
                return self.alloc(ExprKind::If { condition: lhs, then_branch: then, else_branch: Some(rhs) }, range);
            }
            Some(ValueItem::Function(id)) if id == self.lang.pipe => return self.pipe(lhs, rhs, range),
            Some(ValueItem::Function(id)) if id == self.lang.apply => return self.call(lhs, vec![rhs], None, range),
            Some(ValueItem::Function(id)) => Some(Res::Function(id)),
            Some(ValueItem::Constructor(ctor)) => Some(Res::Constructor(ctor)),
            Some(ValueItem::Operation(op)) => Some(Res::Operation(op)),
            Some(ValueItem::Unusable) => None,
            None if op == "::" => {
                let callee = self.unsupported(op_range, "lists are not supported yet");
                return self.alloc(ExprKind::Call { callee, args: vec![lhs, rhs], evaluate_first: None }, range);
            }
            None => {
                self.diagnostics.push(Diagnostic::error(
                    codes::UNDEFINED_NAME,
                    format!("cannot find operator `{op}`"),
                    Label::new(self.file, op_range, "not found in this scope"),
                ));
                None
            }
        };
        let callee = match res {
            Some(res) => self.alloc(ExprKind::Path(res), op_range),
            None => self.alloc(ExprKind::Missing, op_range),
        };
        self.alloc(ExprKind::Call { callee, args: vec![lhs, rhs], evaluate_first: None }, range)
