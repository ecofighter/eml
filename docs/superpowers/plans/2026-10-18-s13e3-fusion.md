# S13e-3 Inlining and Fusion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `fuse` phase to `optimize` that inlines small non-recursive functions, resolves known constructors (locally and through block parameters), and copies functions on known `con` values whose fields are known closures. After it, `Iter.generate` pulled by `Iter.fold`, with or without `Iter.map` / `Iter.filter`, allocates nothing per element. The S13e-1 bench programs also match their hand-specialized twins in RC counts and instruction counts.

> **Amended after Task 1 (binding; the text below predates it).** There is no frozen `Base` copy read by every inlining and no `MAX_INLINE_DEPTH`. `fuse` freezes only the call graph (direct calls plus value references, Tarjan) and rewrites each function once, callees and referenced functions first. A call is inlined from the callee's *fused* code, never re-inlined inside the caller; inlinable means not recursive in the direct graph, fused size (terminators included) <= `INLINE_LIMIT` (40), and no `handle` / `resume` / `clause`. Fusion-created calls are inlined for at most `MAX_INLINE_ROUNDS` (8) rounds per function. Con-shape copies are built from the callee's fused code and fused once at creation; their names are `<callee>{<pos>=<layout> #<tag>(<fields>)}`. "Base code" below means the callee's fused code. The function ABI is fixed by the name (`internal` = born as a value, always uniform). The normative text is `docs/spec/core-ir.md` 「融合」 through 「融合が止まること」.

**Architecture:** `crates/eml_core_ir/src/optimize/fuse/` runs after `handlers` and its `yields` recomputation.

- At entry it freezes the program as the **base**. Every inlining and every copy reads the callee's base code, which is already a function of the callee's name, so names keep determining code (the REPL rule).
- A per-function worklist applies rules until nothing changes:
  - inline a call to a small non-recursive function;
  - drop dead pure `let`s;
  - fold constant switches;
  - resolve a `switch` / `unpack` on a known `con`;
  - thread a `jump` that carries a known `con` into a block that starts by matching it;
  - turn an `apply` of a known closure into a call (S13e-1's rule);
  - turn a call with known-closure or known-`con` arguments into a key-named copy.
- Then `yields` is recomputed and unreachable functions are dropped, as today.

**Tech Stack:** Rust (`crates/eml_core_ir`), insta, `eml_test_support`, UI and REPL harnesses, `bench/` with `crates/eml_vm/tests/bench.rs`, `bench/run.sh` (macOS).

**Spec:** `docs/superpowers/specs/2026-10-18-s13e-specialization-design.md` (「S13e-3 インライン化と融合」 and 「最適化パスの共通の形」). S13e-1 and S13e-2 are described in `docs/spec/core-ir.md` 「最適化」.

## Global Constraints

- Code comments and docs are Japanese, written with the `yomiyasu:yomiyasu` skill. Comments explain why and cite `docs/` paths. CLAUDE.md stays English.
- Pass order inside `optimize`, in this order:
  1. `specialize`
  2. `yields` recompute
  3. `handlers`
  4. `yields` recompute
  5. `fuse`
  6. `yields` recompute
  7. `retain_reachable`

  `fuse` emits no `tail`, `box`, `unbox` or RC instruction, and its output passes `verify_translated`.
- Determinism:
  - The base is frozen at `fuse` entry.
  - Every decision depends only on the key and on base code: whether to inline, the size threshold, the inline depth, whether to copy, and the cutoff.
  - No whole-program budget.
  - Copy names extend S13e-1's scheme. A `con` shape is written `<Ctor>(<field shapes>)`, where a field is a closure `<fn>/<captures>`, or `_` for a non-closure field passed as a parameter. Names longer than `NAME_LIMIT` are hashed as before.
- Inlining:
  - It applies only to a `Direct` call of a function in no non-trivial SCC of the base call graph (and not self-recursive), whose base body has at most `INLINE_LIMIT` statements (start at 40; tune and record why in `benchmarks.md`).
  - Nesting is bounded by `MAX_INLINE_DEPTH` per function (start at 8).
  - It never inlines a function that contains a `handle`, a `resume` or a `clause`. EP needs each clause function to belong to one `handle`.
  - It never inlines when an argument's mark is above the callee parameter's mark (unr < poly < lin), because inlining can duplicate uses.
  - Inlined extern calls keep their `at` positions.
- Known constructors:
  - A `con`-bound variable is opened by a `switch` / `unpack` only when that is its only use. This is the same rule translate uses, so ownership moves exactly once.
  - Jump threading follows `docs/future/roadmap.md` 「jump threading とインライン化」. Its 「R3 を守る作り方」 governs block splitting.
- `con` shapes: a key position holds a known `con` whose fields include at least one known closure. Closure captures and the other fields become parameters. `MAX_KEY_DEPTH` bounds nesting, counting `con` shapes like closure shapes.
- Test changes:
  - Kind 1: none expected. Any one goes into the spec's 「種類1」 with its reason and the user's confirmation before commit.
  - Kind 2: within the spec's 「種類2」.
  - Standing ruling: a test whose program now gets inlined or fused, and whose purpose was to exercise a later pass, is rewritten so the value reaches its use through data (`hide x = Box x`). Its assertions are kept, and it is listed in the commit message and in 「種類2」.
  - A changed UI stdout/stderr is a bug.
- Gate per task: the task's tests, then `cargo test`, `cargo clippy --all-targets`, `cargo fmt --check`. Use `git diff --no-ext-diff`.
- Commit messages end with the attribution lines the controller gives.

### Task 1: The `fuse` phase skeleton, inlining and dead pure lets

**Files:**
- Create: `crates/eml_core_ir/src/optimize/fuse/mod.rs` (base snapshot, worklist, phase entry), `crates/eml_core_ir/src/optimize/fuse/inline.rs`

**Interfaces:**
- Produces (crate-private):
  - `pub(crate) fn fuse(program: &mut Program)`.
  - `struct Base { functions: Vec<CoreFn>, recursive: Vec<bool>, size: Vec<usize> }`, frozen at entry. `recursive[f]` is true for members of a non-trivial SCC and for self-recursive functions in the base `Direct` call graph. `size[f]` counts statements.
  - `fn inlinable(base: &Base, f: FnIdx) -> bool`.
  - `fn inline_call(function: &mut CoreFn, at: (BlockId, usize), callee: &CoreFn, args: &[Atom])`. It splits the block after the call: the rest goes to a new block whose parameter is the call's result. It splices the callee's blocks with fresh variables, substitutes the parameters, and turns each `return r` into a `jump` to the rest block. If the call is in tail position (`crate::tail::tail_position_call`), the callee's returns stay returns. Blocks are renumbered so every edge goes forward (R2). A `switch` that becomes constant is folded by reusing `handlers::piece::constant_target` (move it to a shared module).
  - `fn drop_dead_pure_lets(function: &mut CoreFn)` uses the purity rule of `crate::tail` (`pure`).
- Constants: `INLINE_LIMIT = 40` statements and `MAX_INLINE_DEPTH = 8`.

### Task 2: Known constructors and jump threading

**Files:**
- Create: `crates/eml_core_ir/src/optimize/fuse/known_con.rs`
- Modify: `crates/eml_core_ir/src/optimize/fuse/mod.rs`
- Test: `crates/eml_core_ir/tests/optimize.rs`, `crates/eml_vm/tests/bench.rs`

**Interfaces:**
- Produces:
  - `fn known_cons(function: &CoreFn) -> HashMap<VarId, (Ctor, Vec<Atom>)>`: variables bound by `con`.
  - `fn resolve_known(function: &mut CoreFn) -> bool`. A `switch` on a single-use known `con` becomes a `jump` to its case, with the case fields substituted by the `con` arguments. An `unpack` of one is substituted the same way. In both cases the `con` let is deleted. The return value says whether anything changed.
  - `fn thread_jumps(function: &mut CoreFn) -> bool`. It applies the roadmap rule: a `jump M(a…)` where block `M(p…)` starts with `switch p_i` / `unpack p_i`, `p_i` has no other use, and `a_i` is a constant `Tag`/`Int` or a single-use known `con`. The `switch` is decided on the jump's side, and blocks are split per 「R3 を守る作り方」.
  - Inside the worklist, a field of a resolved known `con` that is a known closure becomes a known closure for S13e-1's `apply`→`call` rule (reuse `known::rewrite` or its `KnownClosure` recognition).
