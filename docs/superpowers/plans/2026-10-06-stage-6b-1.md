# 段階6b-1 handler の形の作り替え 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** パラメータ付き handler (6b-2) の前に、HIR の closure の形、Core IR の `Handle` / `Resume` / `Perform` と `Atom::Fn`、ランタイムの handler フレームの `Link` を作り替え、状態の通り道をすべて作る。観測できる振る舞いは変えない。

**Architecture:** HIR では、ラムダ、handle の本体、操作の節、`return` の節を `Closure` にそろえ、省いた `return` の節を合成する。Core IR では、捕獲のない関数をクロージャを確保しない値 `Atom::Fn` にし、`Handle` がつねに初期値と `return` の節を、`Resume` がつねに次の状態を、`Perform` が再開するかどうかを持つ。ランタイムの handler フレームは、つながっている間だけ `Link { next, state }` を持つ。状態はこの段階ではつねに `()` である。

**Tech Stack:** Rust (edition 2024)、`insta` (インラインのスナップショット)、`cargo test`。

**Spec:** `docs/superpowers/specs/2026-10-06-stage-6b-design.md` の1章 (6b-1)。0章の決定は 6b-2 で使う。

## spec からの補い

- spec 1.1 は `k` を `OpClause::k(&self, module)` のような読み口で取り出すとした。`module` を引かずに済むよう、`OpClause` に操作の引数の数 (`arity`) と `k` を持つか (`resumes`) を持たせ、`OpClause::args()` と `OpClause::k()` で取り出す。6b-2 の状態の引数は `closure.params` の残りになる
- spec 1.2 の verifier の節の引数の数の検査は、`Atom::Fn` の節と、同じ関数の中で `closure` (`Rhs::MakeClosure`) で束縛した変数の節に対して行う。それ以外 (関数の引数で受け取ったクロージャなど) は、静的に関数が分からないので確かめない。verifier は、関数ごとに `closure` で束縛した変数から関数と渡した引数の数への表を持つ
- spec 1.2 の節の引数の数の検査 (「捕まえた変数 + 操作の引数 + `k` + 状態」) のために、Core IR のエフェクトの表の操作 (`OperationInfo`) に引数の数 `arity` を足す。テキストの形では、`effect` の行の操作の名前の後に `/` と引数の数を書く (`effect Ask { ask/1, never stop/1 }`)。ユーザーのエフェクトを持つすべての Core IR のスナップショットの先頭の行が変わる (種類2。ユーザーの了承済み)
- `Rhs::MakeClosure` の引数は1つ以上とし、verifier が空の引数を拒否する。捕獲のない関数の値は `Atom::Fn` だけで表し、同じ値に2つの書き方を残さないためである
- 6b-1 の途中 (Task 3) では、Core IR の `Handle::ret` がまだ `Option` で、ランタイムの `ret` は `Value` になる。Task 1 の後は、変換がつねに `ret` を作るので、インタプリタは `None` を内部の誤りにする。Task 4 で Core IR の側も `Atom` にして、この分岐を消す

## Review Focus

- 外側のエフェクトの `multi` の操作で、つながったままの内側の handler フレームを含む区間を写す: 写した handler フレームの `Link` の `next` は写した次のフレームを指し、`state` の参照が増える (Task 3 に heap の単体テストを置く)
- 外側のエフェクトの `never` の操作や `drop k` で、つながったままの内側の handler フレームを含む区間を解放する: `Link` の `state` のオブジェクトも解放され、リークしない (Task 3 に heap の単体テストを置く)
- 捕獲のないラムダを部分適用し、足りない分を後で渡す、または余分に渡す: `Value::Fn` が eval/apply の3つの場合 (等しい、足りない、余る) でクロージャと同じに動く (Task 2 にインタプリタのテストを置く)
- 関数の値 `&f` を束縛した boxed の変数への `dup` と `decref`、`data` のフィールドに入れた `&f`: 何もせず、`debug_heap` のリークにならない (Task 2 にインタプリタのテストを置く)
- 外側の `multi` の操作で2回再開される区間の中で、内側の handle の本体が値を返す: どちらの再開でも `return` の節が値と状態 `()` を受ける (Task 4 に UI ではなく Core IR のテキストの実行テストを置く)

```rust
/// ラムダ、handle の本体、操作の節、`return` の節の共通の形。Core IR では、捕まえた変数を先頭の引数に持つ関数に
/// 持ち上げる (docs/spec/core-ir.md)。
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Closure {
    pub params: Vec<PatId>,
    pub body: ExprId,
}

ExprKind::Lambda(Closure)
ExprKind::Handle {
    /// 引数のない closure。Core IR では `()` を受ける関数になる。
    body: Closure,
    effect: Option<EffectId>,
    clauses: Vec<OpClause>,
    ret: ReturnClause,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct OpClause {
    pub op: OperationId,
    /// 操作の引数、`k` (`resumes` のとき) の順。
    pub closure: Closure,
    /// 操作の引数の数。
    pub arity: usize,
    /// `k` を受けるか。`never` の操作の節は受けない (docs/spec/expressions.md の「handler」)。
    pub resumes: bool,
    pub range: TextRange,
}

impl OpClause {
    pub fn args(&self) -> &[PatId];
    pub fn k(&self) -> Option<PatId>;
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ReturnClause {
    /// 本体の値の1つ。
    pub closure: Closure,
    pub source: ClauseSource,
    pub range: TextRange,
}

impl ReturnClause {
    pub fn value(&self) -> PatId;
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ClauseSource {
    Written,
    /// HIR が合成した節。`range` は handle のキーワードを指す。
    Omitted,
}

impl Body {
    /// closure の本体で参照する局所変数のうち、本体の中でも引数でも束縛していないもの。`LocalId` の順に並べる。
    pub fn closure_captures(&self, closure: &Closure) -> Vec<LocalId>;
}
```

- `Body::lambda_captures` は消す。`Body::captures(root, bound)` は `closure_captures` の中だけで使う非公開の関数にする

fn an_omitted_return_clause_is_synthesized() {
    let text = "effect Ask where\n  ask : Unit -> Int\n\nf : Unit -> Int\nf () =\n  handle ask () with\n    | ask () k -> resume k 1";
    let lowered = lower_clean(text);

        .exprs
        .iter()
        .find_map(|(_, expr)| match &expr.kind {
            eml_hir::ExprKind::Handle { ret, .. } => Some(ret),
            _ => None,

        .unwrap();

- [ ] **Step 3: HIR の型を変える**

`hir.rs` に Interfaces の型を置く。`OpClause::patterns` は消し、`closure.params` を使う。読み口は次のとおり。

```rust
impl OpClause {
    pub fn args(&self) -> &[PatId] {
        &self.closure.params[..self.arity]
    }

    pub fn k(&self) -> Option<PatId> {
        self.resumes.then(|| self.closure.params[self.arity])
    }
}

impl ReturnClause {
    pub fn value(&self) -> PatId {
        self.closure.params[0]
    }
}
```

`walk_child_exprs` は `..` を使わずに書く。

```rust
            ExprKind::Lambda(Closure { params: _, body }) => f(*body),
            ExprKind::Handle {
                body,
                effect: _,
                clauses,
                ret,
            } => {
                f(body.body);
                for clause in clauses {
                    f(clause.closure.body);
                }
                f(ret.closure.body);
            }
```

`captures` の作業リストでは、`Lambda` の `closure.params` と、`Handle` の各節と `return` の節の `closure.params` を束縛に足す。`closure_captures` は次のとおり。

```rust
    pub fn closure_captures(&self, closure: &Closure) -> Vec<LocalId> {
        self.captures(closure.body, &closure.params)
    }
```
