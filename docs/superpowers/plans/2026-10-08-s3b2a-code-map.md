#### T3.6 Text-form decisions not fixed by the spec (implemented and tested)
- `jump bN(..)` always has parentheses; labels omit them when there are no params (`b1:`). `unpack v.N #t(..)` always has parentheses; switch cases omit them without fields.
- Empty forms: `switch a {}`, `handle E(i, b) {} return r`, `effect E {}` (the old pretty printed `effect E {  }`, which the old parser rejected).
- `mask []`, `save []`, numbers with leading zeros and trailing commas are parse errors (round-trip identity).
- Labels are recognised by position (the word after a terminator), not by column; `pretty` puts them at column 0.
- Filler variables: name `""`, repr `Unit`; a variable used but never bound keeps its written name and gets `Unit`.
- Positions: lexed as Word(`@`), Str(path), Word(`:L:C`); paths are interned into `Program.files` in order of first appearance; `pretty` drops them, `pretty_with_positions` prints them.

#### T4.4 v2 verifier structure (crates/eml_core_ir/src/v2/verify.rs, 996 lines after fmt)
- `shape` (:102-178): one pass over terminators in block order. Per edge: out of range, R1 (target is `BlockId::ENTRY`, message "an edge from bN goes to the entry block"), R2 (target <= source, "goes back to"), jump arity (R4), in-edge counts per kind, and the CHK idom update `idom[to] = intersect(idom[to], from)` (`intersect` :181-191 moves the larger block number up). - `Checker::run` (:254-273): blocks in order; block 0 starts with nothing owned; others take their `Entry` from `pending: HashMap<u32, Entry>` (removed on arrival, so it is sparse).
- Sites: `Site { block, index: i64 }`, params and case fields at -1, terminator at `stmts.len()`. Case fields are defined when the switch is checked (site = target, -1), so R5 catches a field that reuses a parameter number.

- Ownership: `Owned = BTreeMap<VarId, u32>`, zero counts removed. `consume` gives up one reference for RC vars at the ownership level, otherwise only checks visibility. `merge` (:469-495) stores the first jump's multiset and compares later ones ("a jump to bN owns [..] but an earlier jump to it owns [..]").

#### T7a.3 FnBuilder (v2/translate/builder.rs)
- Blocks are numbered in creation order (`new_block` :79); entry is block 0, made current by `new` :40. Switch targets are created when the switch is emitted; a label becomes a block only in `place` :142, after all its jumps exist, so creation order has forward edges only.
- `jump` :112 leaves the current block open and records `(block, args)` on the label; `resolve` :127: 0 pending -> `None`, 1 -> `reopen` that block and return its args (label params are never created), 2+ -> `place`: new block with fresh params (from the label's `VarInfo`s), every pending block gets `Term::Jump`.
- `finish` :160: collects jump predecessors, folds `b(p): return p` blocks (no stmts, not entry) from the highest index down (chains fold in the same loop), renumbers, maps successors with `Term::for_each_successor_mut`, and calls T5's `tail_call` on every block.
- debug assertions: no jump into a resolved label, arity of jump args, no pending label at `finish`, `reopen` only with no current block.

#### T7a.4 Conditions (v2/translate/mod.rs)
