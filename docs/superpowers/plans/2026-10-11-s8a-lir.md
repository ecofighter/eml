## Review Focus

spec が求めるが、どのタスクのテストも直接は確かめない形のうち、使う人が最初に踏みそうなもの。各行のテストか確かめは、対応するタスクに入れてある。

- verifier はデバッグビルドだけでかかるので、リリースビルドの `eml run` が LIR の経路で動くことは、テストの通過では分からない。`cargo run --release -p eml_cli -- run bench/fib.em` が `75025` を出す (Task 6 の Step 9、Task 8 の Step 6 で `nix build` も)
- `eml_cli` の `core` の feature だけ (`run` なし) で、`eml_lir` を含めて組み立たなければならない。`eml_interp` を入れない組み立てで、LIR の型を名前で使う所が残る (Task 6 の Step 8 の `cargo clippy -p eml_cli --no-default-features --features core` と、`eml_test_support` の同じ feature)
- 実行時エラーの位置 (`at path:line:column`) は、extern の `Loc` と `Program.files` を `to_lir` が写すことで保たれる。表の添字がずれると、別のファイルの位置を出す (Task 5 の `lowering.rs` の、複数のファイルを持つ UI テストを含む全プログラムでの比較と、手書きの IR で `files` を比べるテスト)
- 手で書いた LIR を `passes_until` に渡すと、入口の `verify_lowered` が `dup` などを拒む。入口の検査を忘れると、box の挿入が約束の外の入力を黙って受ける (Task 6 の `passes_until_checks_its_input`)
- Core IR のテキスト形式に LIR の語を書いたとき (`tail`、`dup`、`save`) と、その逆は、行の番号の付いた分かりやすい誤りになる (Task 7 の `text.rs` の新しいテスト)

```rust
//! パイプラインを通して比べるテストが使う、プログラムの一覧。UI テストの `run` と `run-fail` のすべてのテストと、
//! `bench/` のプログラムである (docs/implementation/testing.md の「UI テスト」)。

use std::fs;
use std::path::{Path, PathBuf};

/// 1つのプログラム。`modules` は入口のディレクトリからの相対パスと本文の組で、
/// `eml_test_support::core_until_files` にそのまま渡す。
pub struct UiProgram {
    /// `run/basics/hello.em`、`run/names/import_cycle`、`bench/fib` の形の名前。
    pub name: String,
    pub entry: String,
    pub modules: Vec<(String, String)>,
}

impl UiProgram {
    pub fn module_refs(&self) -> Vec<(&str, &str)> {
        self.modules
            .iter()
            .map(|(path, text)| (path.as_str(), text.as_str()))
            .collect()
    }
}

fn workspace() -> PathBuf {
    Path::new(env!("CARGO_MANIFEST_DIR")).join("../..")
}

/// 名前の順に並べる。比べた結果の報告を、ファイルシステムのたどり方によらず同じ順にするためである。
pub fn ui_programs() -> Vec<UiProgram> {
    let mut programs = Vec::new();
    for top in ["run", "run-fail"] {
        let top_dir = workspace().join("tests/ui").join(top);
        for category in sorted_entries(&top_dir) {
            for entry in sorted_entries(&category) {
                let category_name = file_name(&category);
                if entry.is_dir() {
                    programs.push(directory_program(top, &category_name, &entry));
                } else if entry.extension().is_some_and(|ext| ext == "em") {
                    programs.push(UiProgram {
                        name: format!("{top}/{category_name}/{}", file_name(&entry)),
                        entry: fs::read_to_string(&entry).unwrap(),
                        modules: Vec::new(),
                    });
                }
            }
        }
    }
    for entry in sorted_entries(&workspace().join("bench")) {
        if entry.extension().is_some_and(|ext| ext == "em") {
            programs.push(UiProgram {
                name: format!("bench/{}", entry.file_stem().unwrap().to_string_lossy()),
                entry: fs::read_to_string(&entry).unwrap(),
                modules: Vec::new(),
            });
        }
    }
    programs.sort_by(|a, b| a.name.cmp(&b.name));
    programs
}

/// ディレクトリのテスト。入口は `main.em` で、ほかの `.em` はディレクトリからの相対パスのモジュールである。
fn directory_program(top: &str, category: &str, dir: &Path) -> UiProgram {
    let mut modules = Vec::new();
    collect_modules(dir, dir, &mut modules);
    modules.sort();
    UiProgram {
        name: format!("{top}/{category}/{}", file_name(dir)),
        entry: fs::read_to_string(dir.join("main.em")).unwrap(),
        modules,
    }
}

fn collect_modules(root: &Path, dir: &Path, modules: &mut Vec<(String, String)>) {
    for entry in sorted_entries(dir) {
        if entry.is_dir() {
            collect_modules(root, &entry, modules);
        } else if entry.extension().is_some_and(|ext| ext == "em") && entry != root.join("main.em") {
            let relative = entry
                .strip_prefix(root)
                .unwrap()
                .to_string_lossy()
                .replace('\\', "/");
            modules.push((relative, fs::read_to_string(&entry).unwrap()));
        }
    }
}

fn sorted_entries(dir: &Path) -> Vec<PathBuf> {
    let mut entries: Vec<PathBuf> = fs::read_dir(dir)
        .unwrap_or_else(|error| panic!("{}: {error}", dir.display()))
        .map(|entry| entry.unwrap().path())
        .collect();
    entries.sort();
    entries
}

fn file_name(path: &Path) -> String {
    path.file_name().unwrap().to_string_lossy().into_owned()
}

//! S8a の間だけ置く一時的なテスト。パスを LIR に移す前後で、すべてのプログラムのダンプが変わらないことを確かめる
//! (docs/superpowers/specs/2026-10-11-s8a-lir-design.md の「バイト単位の一致の確かめ方」)。基準のダンプは手元にしか
//! ないので、普通の `cargo test` では走らせない。
//!
//! 書く: `EML_S8A_BASELINE=/abs/dir EML_S8A_BLESS=1 cargo test -p eml_core_ir --test integration s8a_baseline -- --ignored`
//! 比べる: `EML_S8A_BASELINE=/abs/dir cargo test -p eml_core_ir --test integration s8a_baseline -- --ignored`

use std::fs;
use std::path::PathBuf;

use eml_core_ir::{Pass, pretty_with_positions};

use crate::common::programs::ui_programs;

const PASSES: [(Pass, &str); 4] = [
    (Pass::Evidence, "evidence"),
    (Pass::Boxing, "boxing"),
    (Pass::Contract, "contract"),
    (Pass::Perceus, "perceus"),
];

/// パスの直後の IR を、extern の位置付きで表示する。
fn dump(entry: &str, modules: &[(&str, &str)], pass: Pass) -> String {
    pretty_with_positions(&eml_test_support::core_until_files(entry, modules, pass))
}

#[test]
#[ignore = "needs EML_S8A_BASELINE; run with --ignored"]
fn dumps_match_the_baseline() {
    let dir = PathBuf::from(
        std::env::var("EML_S8A_BASELINE")
            .expect("set EML_S8A_BASELINE to an absolute directory for the baseline dumps"),
    );
    assert!(dir.is_absolute(), "EML_S8A_BASELINE must be absolute");
    let bless = std::env::var("EML_S8A_BLESS").is_ok_and(|value| value == "1");
    if bless {
        fs::create_dir_all(&dir).unwrap();
    }
    let mut mismatches = Vec::new();
    for program in ui_programs() {
        let modules = program.module_refs();
        for (pass, label) in PASSES {
            let shown = dump(&program.entry, &modules, pass);
            let file = dir.join(format!("{}.{label}", program.name.replace('/', "__")));
            if bless {
                fs::write(&file, &shown).unwrap();
                continue;
            }
            let expected = fs::read_to_string(&file)
                .unwrap_or_else(|error| panic!("no baseline {}: {error}", file.display()));
            if expected != shown {
                let line = expected
                    .lines()
                    .zip(shown.lines())
                    .position(|(a, b)| a != b)
                    .map_or_else(|| "the length".to_string(), |index| format!("line {}", index + 1));
                mismatches.push(format!("{} after {label}: differs at {line}", program.name));
            }
        }
    }
    assert!(
        mismatches.is_empty(),
        "dumps differ from the baseline:\n{}",
        mismatches.join("\n")
    );
}

//! LIR のパスの順番 (docs/spec/core-ir.md の「パス」)。LIR の層の順番を知っているのはこのファイルだけにする。
//! Core IR から LIR への変換までの順番は `eml_core_ir` が知る。

use crate::{Program, VerifyError, boxing, contract, perceus, verify, verify_lowered, verify_scopes};

/// `passes_until` で止める位置。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Pass {
    Boxing,
    Contract,
    Perceus,
}

impl Pass {
    fn name(self) -> &'static str {
        match self {
            Pass::Boxing => "boxing",
            Pass::Contract => "contract",
            Pass::Perceus => "perceus",
        }
    }
}

/// 変換の直後の LIR に、box の挿入から `last` までをかける。入力の約束 (`tail`、`box`、`unbox`、RC の命令、`saved`
/// がないこと) を入口で確かめるので、手で書いた LIR を渡すテストもこの検査を通る
/// (docs/superpowers/specs/2026-10-11-s8a-lir-design.md の「パスの順番」)。検査は debug ビルドでかける。
pub fn passes_until(program: &mut Program, last: Pass) {
    if cfg!(debug_assertions)
        && let Err(error) = verify_lowered(program)
    {
        panic!("internal error: invalid LIR before boxing: {error}");
    }
    boxing(program);
    check(program, Pass::Boxing);
    if last == Pass::Boxing {
        return;
    }
    contract(program);
    check(program, Pass::Contract);
    if last == Pass::Contract {
        return;
    }
    perceus(program);
    check(program, Pass::Perceus);
}

/// 誤りを、それを作ったパスの名前で報告する。
fn check(program: &Program, pass: Pass) {
    if !cfg!(debug_assertions) {
        return;
    }
    let result = match pass {
        Pass::Boxing | Pass::Contract => verify_scopes(program),
        Pass::Perceus => verify(program),
    };
    if let Err(error) = result {
        fail(pass, error);
    }
}

fn fail(pass: Pass, error: VerifyError) -> ! {
    panic!("internal error: invalid LIR after {}: {error}", pass.name());
}
```

/// `last` の直後の Core IR で止める。
pub fn core_until(hir: &HirProgram, typed: &TypedProgram, entry: FunctionId, files: &SourceFiles, last: Pass) -> Program {
    let mut program = translate::translate(hir, typed, entry, files);
    check(&program, Pass::Translate);
    if last == Pass::Translate {
        return program;
    }
    evidence(&mut program);
    check(&program, Pass::Evidence);
    program
}

pub fn lower(hir: &HirProgram, typed: &TypedProgram, entry: FunctionId, files: &SourceFiles) -> eml_lir::Program {
    lower_until(hir, typed, entry, files, eml_lir::Pass::Perceus)
}

/// EP の後の Core IR を LIR に写し、`last` までの LIR のパスをかける。
pub fn lower_until(hir: &HirProgram, typed: &TypedProgram, entry: FunctionId, files: &SourceFiles, last: eml_lir::Pass) -> eml_lir::Program {
    let mut program = to_lir(core_until(hir, typed, entry, files, Pass::Evidence));
    eml_lir::passes_until(&mut program, last);
    program
}
