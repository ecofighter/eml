# リファクタリング R7b-2 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** item の ID をプログラム全体で一意にし (`ModuleId` と局所の番号)、HIR の出力を Prelude と入口のモジュールからなる `hir::Program` にする。Prelude に本物の `FileId` を与え、lib API を `Session` にする。

**Architecture:** `eml_hir` に `ItemId<T>` (`ModuleId` と `Idx<T>`)、`ItemMap<T, V>`、`Program`、`Module`、`Items` を置く。`lower` は Prelude と入口のファイルを別々のモジュールのアリーナに変換し、関数の本体を `Module::bodies` に分ける。型検査と Core IR は、`Program` の索引 (`program[id]`) と `ItemMap` を使うように追随する。`eml_cli` は Prelude を `SourceFiles` に登録する `Session` を公開する。名前解決の作り (`ItemScope`) は R7b-3 まで変えない。

**Tech Stack:** Rust (edition 2024)、`la-arena`、`insta`、`cargo test`。

**Spec:** `docs/superpowers/specs/2026-10-06-refactor-r7-design.md` の 1.2 (ID)、1.3 (HIR のプログラムの形)、1.4 (Prelude と session)。R7b の分け方は `docs/superpowers/plans/2026-10-06-refactor-r7b-1.md` の「R7b の分け方」にある。

## spec からの補い

- spec 1.1 の `item_tree`、`def_map` の入口は R7b-3 で作る。R7b-2 の `eml_hir::lower` は、Prelude と入口のモジュールの構文木を受け取る `lower(prelude: (FileId, &ast::SourceFile), main: (FileId, &ast::SourceFile)) -> (Program, Vec<Diagnostic>)` にする。どちらも呼ぶ側が構文解析する (R7b-3 の `item_tree` も構文木を受け取るので、呼ぶ側の形が変わらない)
- Prelude の構文解析は `eml_hir::parse_prelude(file: FileId) -> ast::SourceFile` にまとめる。`PRELUDE_SOURCE` を構文解析し、誤りがないことを確かめる。呼ぶ側 (session、`eml_test_support`、`eml_types` の単体テスト) が同じ処理を重ねないためである。表示するパスは `eml_hir::PRELUDE_PATH` (`"Prelude.em"`) である
- spec 1.2 の ID は、型ごとの別名を持つ1つの総称型 `ItemId<T>` で表す (`FunctionId = ItemId<Function>` など)。下流が `ArenaMap<FunctionId, V>` で持っている表は、同じ API を持つ `ItemMap<T, V>` に置き換える。`iter`、`get`、`insert`、索引、`collect` の書き方が変わらないので、下流の追随が型の名前の置き換えで済む
- `Program` は、Prelude のモジュール (`prelude`) と入口のモジュール (`entry`) の番号を持つ。HIR の pretty と `eml_types::dump` は入口のモジュールだけを表示し、`main` は入口のモジュールから探す。今の「Prelude の `Bool`、`IO`、intrinsic を表示しない」という個別の除外は、モジュール単位の除外になる
- 関数の本体は `Module::bodies: ArenaMap<Idx<Function>, Body>` に置き、`Function::body` をなくす。`Function::arity` は本体を読むので、`Program::arity(FunctionId)` にする
- Core IR のエフェクトの番号は、今は `EffectId` の添字である。プログラム全体の ID では添字が一意でないので、`Program::effects()` の順 (Prelude の `IO` が 0、次に入口のモジュールの宣言の順) に番号を振る。今と同じ番号になる
- 本体を変換する間、`BodyLowering` はシグネチャの型変数の表 (`Generics`) を書き換えられる形で受け取る。表は関数のアリーナの中にあり、ほかの item は同じアリーナを読むので、変換の間だけ `std::mem::take` で取り出し、終わったら戻す

## Review Focus

- ユーザーが Prelude と同じ名前の型やコンストラクタ (`data Bool = | True | False`) を定義した場合: 今と同じく、ユーザーの定義が名前を隠す。`if` の条件にユーザーの `True` を書くと、今と同じ E2001 (「expected `Bool`, found `Bool`」) になる。2つの `Bool` が別のモジュールの ID になっても、ふるまいは変わらない (Task 2 にテストを置く)
- ユーザーが `IO` 以外のエフェクトを宣言した場合の Core IR のエフェクトの番号: `IO` が 0、ユーザーのエフェクトが宣言の順に 1、2、… のまま (Task 3 で、既存の Core IR のスナップショットが変わらないことで確かめる。加えて、エフェクトを2つ宣言したプログラムのテキストを確かめるテストを置く)
- 診断の位置: ユーザーのファイルの `FileId` が 0 から 1 になっても、診断の並び、行と列、UI の表示のパスは変わらない (Task 4 で、UI テストが変わらないことで確かめる)
- `eml check` に、Prelude にある名前 (`println`、`show_int`) の関数をユーザーが定義したプログラム: 今と同じく、ユーザーの定義が使われる (既存の `functions_resolve_in_any_order_and_shadow_builtins` と UI テストで確かめる)
- Prelude の範囲を指す診断が将来出たとき: `SourceFiles` に Prelude が登録されているので、表示が panic しない (Task 4 にテストを置く。`Session` が Prelude を登録することを確かめる)

- [ ] **Step 2: `hir.rs` に型を足す**

`hir.rs` の先頭の ID の別名 (`pub type FunctionId = Idx<Function>;` など) を消し、次を足す。`Hash` などを手で書くのは、`derive` が `T` にも同じ trait を求めるためである。

```rust
pub type ModuleId = Idx<Module>;

/// item の ID。モジュールと、モジュールの中の番号の組で、プログラム全体で一意である
/// (docs/superpowers/specs/2026-10-06-refactor-r7-design.md の 1.2)。
pub struct ItemId<T> {
    pub module: ModuleId,
    pub local: Idx<T>,
}

impl<T> ItemId<T> {
    pub fn new(module: ModuleId, local: Idx<T>) -> ItemId<T> {
        ItemId { module, local }
    }
}

impl<T> Clone for ItemId<T> {
    fn clone(&self) -> Self {
        *self
    }
}
impl<T> Copy for ItemId<T> {}
impl<T> PartialEq for ItemId<T> {
    fn eq(&self, other: &Self) -> bool {
        (self.module, self.local) == (other.module, other.local)
    }
}
impl<T> Eq for ItemId<T> {}
impl<T> std::hash::Hash for ItemId<T> {
    fn hash<H: std::hash::Hasher>(&self, state: &mut H) {
        (self.module, self.local).hash(state);
    }
}
impl<T> PartialOrd for ItemId<T> {
    fn partial_cmp(&self, other: &Self) -> Option<std::cmp::Ordering> {
        Some(self.cmp(other))
    }
}
impl<T> Ord for ItemId<T> {
    fn cmp(&self, other: &Self) -> std::cmp::Ordering {
        (self.module.into_raw(), self.local.into_raw())
            .cmp(&(other.module.into_raw(), other.local.into_raw()))
    }
}
impl<T> std::fmt::Debug for ItemId<T> {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(
            f,
            "{}:{}",
            u32::from(self.module.into_raw()),
            u32::from(self.local.into_raw())
        )
    }
}

pub type FunctionId = ItemId<Function>;
pub type TypeDefId = ItemId<TypeDef>;
pub type ConstructorId = ItemId<Constructor>;
pub type EffectId = ItemId<EffectDef>;
pub type OperationId = ItemId<Operation>;

/// item の ID から値を引く表。モジュールごとに `ArenaMap` を持つ。`ArenaMap` と同じ使い方にして、下流の表の
/// 置き換えを型の名前だけで済ませるため。
pub struct ItemMap<T, V> {
    modules: Vec<ArenaMap<Idx<T>, V>>,
}

impl<T, V> Default for ItemMap<T, V> {
    fn default() -> Self {
        ItemMap { modules: Vec::new() }
    }
}

impl<T, V> ItemMap<T, V> {
    pub fn insert(&mut self, id: ItemId<T>, value: V) {
        let module = u32::from(id.module.into_raw()) as usize;
        if self.modules.len() <= module {
            self.modules.resize_with(module + 1, ArenaMap::default);
        }
        self.modules[module].insert(id.local, value);
    }

    pub fn get(&self, id: ItemId<T>) -> Option<&V> {
        self.modules
            .get(u32::from(id.module.into_raw()) as usize)?
            .get(id.local)
    }

    pub fn get_mut(&mut self, id: ItemId<T>) -> Option<&mut V> {
        self.modules
            .get_mut(u32::from(id.module.into_raw()) as usize)?
            .get_mut(id.local)
    }

    /// モジュールの順、モジュールの中の番号の順にたどる。
    pub fn iter(&self) -> impl Iterator<Item = (ItemId<T>, &V)> {
        self.modules.iter().enumerate().flat_map(|(module, map)| {
            let module = ModuleId::from_raw(RawIdx::from(module as u32));
            map.iter().map(move |(local, value)| (ItemId::new(module, local), value))
        })
    }

    pub fn values(&self) -> impl Iterator<Item = &V> {
        self.iter().map(|(_, value)| value)
    }
}

impl<T, V> std::ops::Index<ItemId<T>> for ItemMap<T, V> {
    type Output = V;
    fn index(&self, id: ItemId<T>) -> &V {
        self.get(id).expect("the id has a value in the map")
    }
}

impl<T, V> FromIterator<(ItemId<T>, V)> for ItemMap<T, V> {
    fn from_iter<I: IntoIterator<Item = (ItemId<T>, V)>>(iter: I) -> Self {
        let mut map = ItemMap::default();
        for (id, value) in iter {
            map.insert(id, value);
        }
        map
    }
}

impl<T, V: std::fmt::Debug> std::fmt::Debug for ItemMap<T, V> {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        f.debug_map().entries(self.iter()).finish()
    }
}
```

`use la_arena::{Arena, ArenaMap, Idx, RawIdx};` にする。

今の `pub struct Module { file, functions, types, constructors, effects, operations, lang }` を、次の3つに置き換える。`Module` の今の欄のコメント (`types`、`constructors` などの説明) は `Items` の欄に移す。`TypeDef` などのほかの型は変えない。

```rust
/// プログラム全体の HIR。Prelude と入口のモジュールからなる。
#[derive(Debug)]
pub struct Program {
    pub modules: Arena<Module>,
    pub prelude: ModuleId,
    /// `eml check` と `eml run` に渡したファイルのモジュール。`main` はここから探す。
    pub entry: ModuleId,
    pub lang: LangItems,
}

/// HIR のノードは `SyntaxNodePtr` ではなく範囲を持つ。演算子の列を組み直した部分式のように、対応する構文ノードの
/// ない式があるため。
#[derive(Debug)]
pub struct Module {
    pub file: FileId,
    pub name: String,
    /// ほかのモジュールと型検査の段0が見るもの。
    pub items: Items,
    /// 関数の本体。等式のある関数だけを含む。本体を item から分けるのは、本体を書き換えても item が変わらない
    /// ようにするため (docs/superpowers/specs/2026-10-06-refactor-r7-design.md の 1.3)。
    pub bodies: ArenaMap<Idx<Function>, Body>,
}

#[derive(Debug, Default)]
pub struct Items {
    pub functions: Arena<Function>,
    /// (今の `Module::types` のコメント)
    pub types: Arena<TypeDef>,
    /// (今の `Module::constructors` のコメント)
    pub constructors: Arena<Constructor>,
    /// (今の `Module::effects` のコメント)
    pub effects: Arena<EffectDef>,
    /// (今の `Module::operations` のコメント)
    pub operations: Arena<Operation>,
}

impl Program {
    fn items<'a, T>(
        &'a self,
        arena: impl Fn(&'a Items) -> &'a Arena<T> + 'a,
    ) -> impl Iterator<Item = (ItemId<T>, &'a T)> + 'a {
        self.modules.iter().flat_map(move |(module, data)| {
            arena(&data.items)
                .iter()
                .map(move |(local, item)| (ItemId::new(module, local), item))
        })
    }

    /// Prelude、入口のモジュールの順に、モジュールの中の宣言の順でたどる。
    pub fn functions(&self) -> impl Iterator<Item = (FunctionId, &Function)> {
        self.items(|items| &items.functions)
    }

    pub fn types(&self) -> impl Iterator<Item = (TypeDefId, &TypeDef)> {
        self.items(|items| &items.types)
    }

    pub fn constructors(&self) -> impl Iterator<Item = (ConstructorId, &Constructor)> {
        self.items(|items| &items.constructors)
    }

    pub fn effects(&self) -> impl Iterator<Item = (EffectId, &EffectDef)> {
        self.items(|items| &items.effects)
    }

    pub fn operations(&self) -> impl Iterator<Item = (OperationId, &Operation)> {
        self.items(|items| &items.operations)
    }

    pub fn body(&self, id: FunctionId) -> Option<&Body> {
        self.modules[id.module].bodies.get(id.local)
    }

    /// 引数がそろうまで本体が動かない引数の数。intrinsic はシグネチャの一番外側の `->` の数、ほかは等式の引数の数
    /// である。本体のない関数 (E1005) は `None`。
    pub fn arity(&self, id: FunctionId) -> Option<usize> {
        let function = &self[id];
        if function.intrinsic {
            return function.signature.as_ref().map(Signature::arity);
        }
        self.body(id).map(|body| body.params.len())
    }

    pub fn file(&self, module: ModuleId) -> FileId {
        self.modules[module].file
    }
}

macro_rules! program_index {
    ($($item:ident => $arena:ident,)*) => {$(
        impl std::ops::Index<ItemId<$item>> for Program {
            type Output = $item;
            fn index(&self, id: ItemId<$item>) -> &$item {
                &self.modules[id.module].items.$arena[id.local]
            }
        }
    )*};
}

program_index! {
    Function => functions,
    TypeDef => types,
    Constructor => constructors,
    EffectDef => effects,
    Operation => operations,
}
```

```rust
/// 1回の検査や実行で読むソースの集まり。Prelude を最初に登録し、入口のファイルと一緒に変換する
/// (docs/superpowers/specs/2026-10-06-refactor-r7-design.md の 1.4)。import をたどるローダは S2 で足す。
pub struct Session {
    files: SourceFiles,
    prelude: FileId,
}

impl Default for Session {
    fn default() -> Self {
        Session::new()
    }
}

impl Session {
    pub fn new() -> Session {
        let mut files = SourceFiles::new();
        let prelude = files.add(eml_hir::PRELUDE_PATH, eml_hir::PRELUDE_SOURCE);
        Session { files, prelude }
    }

    pub fn add_file(&mut self, path: impl Into<String>, text: impl Into<String>) -> FileId {
        self.files.add(path, text)
    }

    pub fn files(&self) -> &SourceFiles {
        &self.files
    }

    pub fn prelude(&self) -> FileId {
        self.prelude
    }

    pub fn check(&self, entry: FileId) -> Vec<Diagnostic> {
        let mut diagnostics = self.front(entry).2;
        sort_diagnostics(&mut diagnostics);
        diagnostics
    }

    pub fn compile(&self, entry: FileId) -> Compiled {
        …今の `compile` の本体。`front(files, file)` を `self.front(entry)` に、`eml_core_ir::lower(&module, &typed)` を
        `eml_core_ir::lower(&program, &typed)` にする…
    }

    /// エラーがあっても止めずに、検査の段階をすべて実行する。1回の実行で、独立した複数のエラーを報告するため。
    fn front(&self, entry: FileId) -> (eml_hir::Program, eml_types::TypedModule, Vec<Diagnostic>) {
        let (parse, mut diagnostics) = eml_syntax::parse(entry, self.files.text(entry));
        let prelude = eml_hir::parse_prelude(self.prelude);
        let (program, stage) = eml_hir::lower((self.prelude, &prelude), (entry, &parse.tree()));
        diagnostics.extend(stage);
        let (typed, stage) = eml_types::check(&program);
        diagnostics.extend(stage);
        (program, typed, diagnostics)
    }
}
```
