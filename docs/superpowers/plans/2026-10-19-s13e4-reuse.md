# S13e-4 Reuse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a LIR pass `reuse` after Perceus. It turns a `release` (or a `decref` of a value whose constructor is statically known) into a token, and a later `con` of the same physical size into a `con` that reuses the token's box. When the constructor is the same, the `con` skips the header and the unchanged fields. The VM runs the new instructions, unwinding drops live tokens, and checked mode counts reuses.

**Architecture:** Every reuse decision is static LIR. Tokens are LIR variables of a new Repr `token`; they flow forward inside a block and into `switch` targets, never through `jump`, calls, closures or `return`, and never across a yield point. The pass pairs greedily per path, reverts sources that no path uses, and drops a token at the entry of every `switch` target whose subtree does not consume it. The VM lowers each instruction to a fixed sequence of `eml_rt` parts, the same sequence a native backend will emit.

**Tech Stack:** Rust (`eml_extern`, `eml_lir`, `eml_vm`, `eml_rt` with Verus), insta, `eml_test_support`, UI harness, `bench/` with `crates/eml_vm/tests/bench.rs`, `bench/run.sh`, `bench/scripts.sh`, `bench/rt.sh` (macOS).

**Spec:** `docs/superpowers/specs/2026-10-19-s13e4-reuse-design.md`. It replaces the 「S13e-4 reuse analysis」 section of `docs/superpowers/specs/2026-10-18-s13e-specialization-design.md`; that document's other sections still apply. The spike is commit `8ab8efb8` on the local branch `spike/reuse` (programs and measuring scripts under `spike/`).

## Global Constraints

- Code comments and docs are Japanese, written with the `yomiyasu:yomiyasu` skill; comments explain why and cite `docs/` paths. CLAUDE.md stays English.
- LIR pass order: `boxing`, `contract`, `perceus`, `reuse`. `eml_lir::Pass` gains `Reuse`; only `passes_until` knows the order; debug builds run `verify` (the ownership level) after `reuse`.
- Pairing is by physical words: `scanned + raw` of the constructor's `Shape`. A constructor with `scanned >= 255` never takes part (its payload has an extra count word that only `eml_rt` knows).
- Tokens never appear as call / `apply` / `clause` / extern / `prim` arguments, closure captures, `con` fields, `jump` arguments, `return` values, or `switch` scrutinees.
- A token is never live after a call that may yield (`may_yield`, Task 1). Non-yielding calls, `Effectful` externs and `never` clauses may be crossed.
- In-place (`reuse_in_place`, no header write) only when the source and the `con` have the same layout and tag and (the source variable's mark is `unr` or the `con` binder's mark is `lin`) (`docs/spec/object-model.md` 「`lin` ビット」). Otherwise the box gets a fresh `meta` (`con_at`).
- A `con` argument is skipped only when it is a variable bound by a `switch` case or `unpack` of the token's source value, both fields are scanned or both are raw, and the source's physical position equals the `con`'s physical position for that argument.
- A function without token instructions compiles to exactly the bytecode it has today.
- Test changes:
  - Kind 1: none expected. Any one goes into the spec's 「種類1」 with its reason and the user's confirmation before commit.
  - Kind 2: within the spec's 「種類2」.
  - A changed UI stdout/stderr is a bug.
  - If `specialization_matches_hand_written_work` or `_rc` starts failing, stop and report the cause before changing anything.
- `eml_rt` changes pass `cargo verus verify -p eml_rt` and `verusfmt --verus-only --check $(git ls-files 'crates/eml_rt/src/*.rs')`.
- Gate per task: the task's tests, then `cargo test`, `cargo clippy --all-targets`, `cargo fmt --check`. Use `git diff --no-ext-diff`.
- Commit messages end with the attribution lines the controller gives.

**Interfaces:**
- Produces:

  - `UnwindPoint { block, stmt, owned, tokens: Vec<VarId>, landing }`: `tokens` are the tokens live after the point, ascending; `owned` never lists a token.
  - `pub fn eml_lir::reuse::may_yield(program: &Program, function: &LirFn, call: &Call) -> bool`: false unless `function.yields`; then `Direct(f)` → `program.functions[f].yields`, `Apply { yields, .. }` → `yields`, `Clause { effect, op, .. }` → the operation is `resumable`.   - `liveness::step_back` sees token definitions and uses (the `con` reuse token, `drop_token`), so VM slot allocation gives tokens slots.
- Text form (normative for the tests):
  - `let r.9: token = release x.2 Tree #1(_, l.4, k.5, _, r.7)`
  - `let d.3: tobj = con Tree #1(lv.4, b.5) reuse r.9` (writes `meta`)
  - `let d.3: tobj = con Tree #1(=lv.4, b.5) reuse r.9 in place` (`=` marks a skipped argument)
  - `drop_token r.9`
- Verifier, ownership level only (`verify_lowered` and `verify_scopes` reject all token instructions, like RC instructions). Track tokens per path in the checker state:
  - a token is defined only by a `release` with `token`; used exactly once on every path by a `con … reuse` or `drop_token`; owned at `jump`, `return`, `tail` → error;
  - forbidden positions (Global Constraints) → error;
  - live after a statement whose call `may_yield` → error;
  - `reuse_words` of the `con` constructor equals the source's; both `Some`;
  - `in_place` needs the in-place condition; each `skip[i]` needs the skip condition (use the checker's `origins` table and both `Shape`s).

### Task 3: The `reuse` pass

**Files:**
- Modify: `crates/eml_lir/src/reuse.rs`, `crates/eml_lir/src/lib.rs` (`pub use reuse::reuse`), `crates/eml_lir/src/pipeline.rs`, `docs/spec/lir.md`
- Test: `crates/eml_lir/tests/reuse.rs` (new; declare in `tests/main.rs`), the UI tests named in Review Focus, kind-2 snapshots across `eml_core_ir`, `eml_lir`, `eml_vm`

**Interfaces:**
- Consumes: Task 1 types and `may_yield`; Task 2 makes the result runnable.
- Produces: `pub fn reuse(program: &mut Program)`; `Pass::Reuse` (name `"reuse"`).
- Algorithm (per function; blocks in order; per-path state copied to `switch` targets, joins start empty):
  1. Known constructors on the path: a `switch` tag case target knows its scrutinee's `Ctor`; `unpack x` knows `x`'s.
  2. Sources: each `release x L #t(..)`, and each `decref x` with `x` known and boxed (`obj` / `tobj`), whose `reuse_words` is `Some`. Each adds a tentative token `{ source, words, ctor, value }`.
  3. At a `con` with `reuse_words == Some(w)`, take a token of size `w`: most skipped arguments, then in-place-able, then latest defined. Record the pairing with its `in_place` and `skip`.
  4. Before a statement whose call `may_yield`, and at `jump` / `return` / `tail`, the path's tokens expire.
  5. Afterwards, a source with no pairing on any path stays as it was. Every kept token gets `drop_token r` at the start of each `switch` target where it is available and that target's switch-subtree (blocks reached through `switch` edges only) consumes it nowhere.
  6. Rewrite: sources → `release … token` (a `decref` source becomes `release x L #t(_, …, _)`), paired `con`s get `reuse`. New token variables get `Repr::Token`, `Mark::Unr`.
