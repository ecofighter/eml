## Review Focus

spec が触れていないが、利用者が当たりやすい入力と、期待する振る舞いである。各行の確かめを、持ち主のタスクに足してある。

1. 空の入力 (空の標準入力、空のファイル): wc は `0 0 0`、grep は何も出さず終了コード 1、logstat は全部 0 (平均も 0 で、0 で割らない)、csv2jsonl はヘッダだけなら空のファイルを書く (Task 2〜5 の空の入力の比較)
2. 最後の行に行の終わりがない入力: 最後の行も1行として扱う (各タスクの付属のファイルに含める)
3. `\r\n` の行の終わり: `\r` を行の中身に残さない (各タスクの付属のファイルに含める)
4. ASCII でない UTF-8 (日本語): wc の `-c` はバイトの数、grep と JSON の出力は文字を壊さない (各タスクの付属のファイルに含める)
5. 数十 MB の入力: 末尾再帰でない行の繰り返しで深さやメモリの上限に当たらない (Task 7 の計測が実行時エラーなしで終わること)

### Task 5: csv2jsonl

**Files:**
- Create: `bench/scripts/csv2jsonl.py`
- Create: `tests/ui/run/scripts/csv2jsonl/main.em`、`main.args`、`in.csv`
- Modify: 作業メモ

**Interfaces:**
- Consumes: `bench/scripts/compare.sh` (`@OUT` を使う。Task 2)

- [ ] **Step 1: `csv2jsonl.py` を書く**

仕様は spec の「CSV の変換」と次のとおりである。起動は `csv2jsonl --columns NAMES INPUT OUTPUT` の形だけで、それ以外は使い方の誤り (`usage: csv2jsonl --columns NAME,NAME... INPUT OUTPUT`)。空の行は飛ばす。引用符で囲まない欄の中の `"` は文字のまま。閉じた引用符の直後が `,` でも行の終わりでもなければ誤りにする。誤りの文言は次のとおりで、どれも `csv2jsonl: ` を前に付けて `exit 1` で終える。

- `line N: expected K fields, found M`
- `line N: unclosed quote`
- `line N: unexpected text after a closing quote`
- `line 1: missing header` (空の入力)

ヘッダにない列名は ``csv2jsonl: unknown column `NAME` `` で `exit 2`。出力は1行に1つの `{"<列名>":"<値>",…}` で、空白を入れない。エスケープは `json.dumps(…, ensure_ascii=False, separators=(",", ":"))` と同じで、`"` → `\"`、`\` → `\\`、0x08 → `\b`、0x0C → `\f`、`\n`、`\r`、`\t`、ほかの 0x00〜0x1F → `\u00xx` (小文字の16進)。ASCII でない文字と 0x7F はそのまま書く。Python の版は `csv.reader(…, strict=True)` を使ってよいが、上の誤りの判定と行番号は eml の規則に合わせる (比べるのは正しい入力の出力だけである)。

- [ ] **Step 2: 付属のファイルを書き、Python の版で期待値を確かめる**

`main.args` は `--columns`、`name,note`、`in.csv`、`out.jsonl` の4行。`in.csv` はヘッダの行と5行ほどで、`,` を含む引用符の欄、`""`、欄の中の改行、`\r\n` の行、タブと 0x01 のバイト、日本語、空の行、最後の行の終わりなし、選ばない列を含む。

- [ ] **Step 3: `main.em` を書く**

入力は `File` で開いて読む。欄の数の誤りと閉じていない引用符は、`never` の操作を持つ `Fail` エフェクトで中断する。結果を全部組み立ててから `Fs.write_text` で書く。
