# eml_rt

The runtime core under the VM, verified with Verus. Its specification is docs/spec/object-model.md; how it is checked is docs/implementation/testing.md の「`eml_rt` の検証」.

- A change to `eml_rt` must pass `cargo verus verify -p eml_rt` and `verusfmt --verus-only --check $(git ls-files 'crates/eml_rt/src/*.rs')` besides the tests (`cargo nextest run` or `cargo test`), `cargo clippy --all-targets` and `cargo fmt`. `verusfmt` formats inside `verus!`, `cargo fmt` the rest.
- All code is inside `verus!` except the safe glue that docs/spec/object-model.md の「`unsafe` の核」 lists. What Verus does not check is the named trust list T0-T13 in the same section, pinned by `src/trust.rs`: a new FFI boundary adds a row there and a Miri test in `src/heap/tests/trusted.rs`.
- Unit tests take the mode as a type parameter and `both_modes!` runs them in fast and checked mode; internal functions get `Tracked::assume_new()` for their permissions. Miri runs only the `trusted` module, which holds only tests that allocate on a `Heap` or `Ctx`, start threads, or cross the `Foreign`, Host or `Drop` boundary; a test that only compares the values of pure functions goes in the ordinary unit tests (`src/heap/tests/externs.rs`). Tests do not shrink under `cfg!(miri)`; large bodies use `LARGE_BODY` or `LARGE_BODY` plus a small unaligned remainder (e.g. `LARGE_BODY + 3`). Each Miri command must stay within its CPU budget, the `user` time of `/usr/bin/time -p` on an already-built tree: `trusted::` 60 s under Stacked Borrows and 120 s under Tree Borrows, and each `trusted` test (both modes) may add 5 s under Tree Borrows to the command's `user` time (docs/implementation/testing.md の「Miri」).
- `src/heap/tests/expected.txt` pins the externs' results; an `#[ignore]` test rewrites it from `eml_rt`'s own results (docs/implementation/testing.md の「期待値の表」).
- `eml_rt` installs no signal handler; `eml_cli` owns SIGINT (docs/spec/object-model.md の「実行の制御」).
