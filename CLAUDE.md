# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

eml is an experimental functional language exploring "linear types × algebraic effects" (Rust, Cargo workspace, edition 2024). Source files use the `.em` extension.
The documentation lives under `docs/`; start from `docs/README.md`. `docs/spec/` is normative (what to implement), `docs/implementation/` covers architecture, testing, diagnostic presentation and the current status, and `docs/future/` holds future designs (multicore, roadmap, stdlib notes).

## Rules

- The documents under `docs/` are the source of truth.
- eml is unreleased and under development, so ignore backward compatibility and develop aggressively: change syntax, APIs, internal representations, and diagnostics freely, without deprecation paths or compatibility shims.
- Put a concise, refined implementation first. Accept a reasonable cost in revising tests, in further design discussion, and in implementation effort to reach it.
- When a test fails and there is a sound reason that the test itself is what should change, put the change in the work's spec with its kind (see Testing); approving the spec is the agreement. Mechanical follow-ups need no agreement.
- Code comments and docs are written in Japanese. Code comments explain why, not what: do not restate the code, and cite `docs/` paths when pointing at a rule.
- Whenever you write Japanese text (docs under `docs/`, code comments, or anything else), always follow the `yomiyasu:yomiyasu` skill: invoke it before writing and apply its rules to everything you write.

## Commands

The dev environment is a Nix flake (`direnv` with `use flake`). The devShell provides clippy, rustfmt, and cargo-insta.

```sh
cargo build                          # all crates
cargo test                           # all tests
cargo test -p eml_syntax --test integration parser::empty_file   # a single test
cargo test -p eml_cli --test integration ui::   # UI tests
cargo insta review                   # accept snapshots
cargo clippy --all-targets && cargo fmt
cargo clippy -p eml_cli --no-default-features --features types   # non-default features (none, types, core; eml_test_support also hir)
cargo run -p eml_cli -- check <file.em>    # or: run [--debug-heap] <file.em>
nix build                            # build the eml binary (eml_cli)
```

## Architecture

A batch pipeline. Dependencies flow strictly top to bottom; every crate that reports diagnostics uses `eml_diagnostics` (currently all but `eml_extern`, `eml_core_ir`, `eml_lir`, `eml_runtime`, and `eml_interp`; `eml_core_ir` reports none but uses its `SourceFiles` to turn extern call positions into lines and columns).

```
eml_cli          check / run; the only pipeline driver (`Session`), stage features types < core < run (lib API is called from tests)
eml_interp       runs LIR on a CEK machine (reads only `eml_lir`, no front end)
eml_runtime      object model, heap, RC, debug_heap checks, OutputSink
eml_core_ir      typed HIR -> Core IR (forward-edge basic blocks; translate -> evidence), then `to_lir` and the LIR passes
eml_lir          LIR (leaf crate on `eml_extern` only): types both IRs share, boxing -> contract -> Perceus, the LIR verifier
eml_types        Kind/type/row inference, class constraints; linearity, multiplicity, and exhaustiveness checks
eml_hir          module loading, CST -> HIR, name resolution
eml_syntax       logos lexer, layout stage, event-based parser, rowan CST, typed AST wrappers
eml_diagnostics  Diagnostic, FileId/SourceFiles, ariadne rendering (does not depend on rowan)
eml_extern       dependency-free extern table (types, effects, functions, with value `Repr`s); consulted by HIR, types, Core IR, LIR and the interpreter
```

- Each stage is a pure function `fn stage(&In) -> (Out, Vec<Diagnostic>)` with no global mutable state, so it can later move onto queries (salsa).
- Never stop on errors: `eml_cli::Session` is the only pipeline driver (the CLI, UI tests and `eml_test_support` all go through it), and each stage method (`def_map` / `lower` / `check` / `compile`) runs every stage up to its own and returns all their diagnostics, sorted. `Session` keeps no intermediate results. The parser recovers with `ERROR` nodes; type checking onward inserts an `Error` type and suppresses cascading diagnostics.
- The parser follows rust-analyzer (event stream -> rowan tree built in `sink.rs`). A layout stage (`layout.rs`) between the lexer and the parser inserts virtual `LAYOUT_OPEN` / `LAYOUT_SEP` / `LAYOUT_CLOSE` tokens (`docs/spec/layout.md`); the parser emits no events for them, so the CST is always lossless. Grammar rules are confined to `eml_syntax/src/grammar/`.
- From HIR onward, nodes are referenced by IDs and analysis results (types, ...) live in side tables. HIR is a `Program` of modules (module 0 is the Prelude, module 1 the entry file, then the other standard-library modules in embedded order, then the imported modules in the order the loader found them; the loader reads files through a `ModuleSource`); items use program-wide `ItemId`s (module + local index, side tables are `ItemMap`), while body nodes use per-body arena IDs (`ExprId`, etc.). HIR nodes carry a `TextRange` (not a `SyntaxNodePtr`), because some expressions, such as reassociated operator subexpressions, have no syntax node. Records are nominal: a `data` constructor may name its fields (`Constructor::field_names`), and field names are not in any namespace. HIR keeps construction as `ExprKind::Record` (fields in source order with their declared index; `A {}` becomes a constructor `Path`), updates as `ExprKind::Update` and projections (`p.name`, `t.0`) as `ExprKind::Field` with the field still a name or index, record patterns as `PatKind::Con` in declared order, and section `(.f)` as a lambda over a hidden parameter; `Body::omitted_fields` marks the `_` of fields a pattern left out and `Body::use_lambdas` the lambdas `use` built (`docs/implementation/architecture.md`).
- Built-ins are `extern` declarations backed by one table in `eml_extern`. The standard library lives in the repository's `std/` tree (`Prelude.em`, `Fs.em`), embedded into the binary as `eml_hir::STD`; its modules have canonical names `Prelude` and `Std.<Name>` (the root `Std` is reserved) and display paths `<std>/Fs.em`, and every program loads all of them. The Prelude also declares `List` (constructors `Nil` and `::`), `Option` and `Result`; the list syntax `[…]` names the Prelude's `Nil` and `::` through `eml_hir`'s `LangItems` without name lookup, so a user's own `Nil` does not change it. Only standard-library modules may write `extern` (E1033 otherwise), including `extern m` inside an `instance`, which binds a method to the row `<module>.<Class> <Type>.<method>` (`Prelude.Eq Int.==`). `IO` is a label-only extern effect: extern functions run in place (`Rhs::Extern`, no handler, no evidence, no continuation frame). Table rows and `std/` are tied together by a test in `eml_hir` (every row is named by exactly one extern function or instance `extern`). `Repr` lives in `eml_extern` (re-exported by `eml_lir`): type rows carry a `repr`, which translate reads, and function rows carry `params` and `ret`; `crates/eml_core_ir/tests/externs.rs` ties them to the `std/` signatures through `eml_core_ir::type_repr`.
- Types after checking are `TypeId`s into one program-wide hash-consed `eml_types::TypeStore` (`TypedProgram.types`); `TypeStore::intern` is crate-private; later stages add types only through `TypeStore::substitute` (monomorphization). Exported types carry linearity: `TypeKind::Fn` has `lin: Lin` (`Unr`, `Lin`, `Poly`, or `Var(u32)`, a declaration's Kind variable), `Flexible(Lin)` and `OpVar(_, Lin)` carry a Kind, and `TypeStore::linearity(ty)` gives a type's value (a debug assertion fires on declaration-relative types whose value depends on a `Rigid` or `Var`). `check_module` goes through call-graph SCCs from the callees up, checking the bodies, solving the SCC's Kinds, and only then exporting the bodies' types (`Exporter::solved`; `Exporter::diagnostic` is the pre-solve export for messages and prints no linearity), so a body's types depend on its SCC's solution. `TypedProgram::kind_values(decl, args, store)` evaluates a declaration's `Var`s at an instance (the argument of `Substitution::new(type_args, kind_values)`; `Substitution::partial` leaves `Var` alone), `uniform_kind(function, position)` gives the Kind of a uniform-position or entry `Flexible`, and `needs_substitution(decl)` says whether a body must be copied (`docs/spec/types.md`, "Kind の書き出し"). Only `Lin` is public; `Linearity`, `Multiplicity` and `ArrowLin` stay inside `eml_types`. Tuples are label-free `Tuple(Vec<_>)` in `TyShape`, `TypeKind` and `ShapeTy` (`Unit` is the empty tuple). Projections and updates resolve their field from the type known at that point (`check/field.rs`; E2013 when it is still a variable, E2014 when there is no such field; only single-constructor types and tuples have projections), and the results go to the side tables `BodyTypes::fields`, `updates` and `discarded` (the fields a projection or update drops, which the linearity pass treats like `_`). Lambda arguments of a call are checked after its other arguments (`docs/spec/types.md`), so `map (.name) people` needs no annotation. Walks over inference-table types visit each union-find representative once (the `Walk` guard in `eml_types/src/table/mod.rs`), and `Exporter` memoizes per type, so shared types cost their store size, not their unfolded tree size.
- Two IR layers with separate types. Core IR (`docs/spec/core-ir.md`) is the semantic layer: statements `let` / `unpack`, terminators `return` / `jump` / `switch`, effect instructions `handle` / `perform` / `resume` and call `mask`s, and no RC, `box` or tail calls. LIR (`docs/spec/lir.md`, crate `eml_lir`) is Core IR after evidence passing, copied by `eml_core_ir::to_lir` with the same names and numbers: no effect instructions or `mask`s, but `dup` / `decref` / `release`, `box` / `unbox`, terminator `tail` and call `saved` (kept until the CEK is removed in S10). Both are lists of basic blocks per function with block parameters and forward edges only (rules R1-R9, written once in `docs/spec/lir.md`; Core IR follows the unmarked parts) and a `Repr` (`obj`, `tobj`, `int`, `enum`, `unit`) per variable. Every variable and every function's `ret` also has a Kind mark (`eml_lir::Mark { Unr, Lin, Poly }`: `VarInfo.mark`, `ret_mark`; `unr` may be dupped and decref'd, `lin` and `poly` may not), decided in translate from `TypeStore::linearity` (`linearity_or_poly` for types read without the instance substitution), by EP and boxing for the variables they add (boxing adds `unr` scalars and copies the original marks for `f$boxed` and re-received parameters), and never changed by later passes. The text form writes the mark after the Repr only when it is not `unr` (`x.1: tobj lin`, `-> tobj poly`, `ask(unit) -> tobj poly`); writing `unr` is a parse error. The extern rows (`param_kinds` / `ret_kind`), the primitive table (`param_marks` / `ret_mark`) and the operation table (`OperationInfo::param_marks` / `ret_mark`) have mark columns. The shared types (`Atom`, `VarInfo`, `Layout`, `Ctor`, `Prim`, `EffectInfo`, ..., and `Repr` re-exported from `eml_extern`) live in `eml_lir` and are not re-exported by `eml_core_ir`; `eml_lir::syntax` and `eml_lir::check` hold the text-form and verifier parts both IRs share. Uniform positions (`apply` operands and results, type-variable and tuple fields) are `tobj` (a `clause` call instead takes the evidence as `obj` and the operation's declared `params` / `ret` from the effect table), and a function used as a value must be uniform (every parameter and its `ret` compatible with `tobj`); `box` / `unbox` convert the boxed scalars (`int`, `enum`; `Repr::BOXED_SCALARS`) to and from `tobj`, while `unit` and `obj` pass without an instruction (`Repr::compatible`; the 位置の規則 section of `docs/spec/lir.md`). `Program.layouts` is the data layout table (one layout per data type the IR names, one per tuple size, in first-use order; field `Repr`s from the declared types): `con` / `unpack` / `release` carry a `Ctor` (layout id and tag) and a `switch` with tag cases carries its layout id. The verifier checks every instruction against its layout (R9) and extern calls against the rows' `Repr`s (R8), but not which layout built a value; the interpreter reads only the tag. `switch`, `unpack`, `unbox` and a primitive's borrowed arguments (`PrimRow::borrowed`, e.g. the evidence of `ev_clause`; `Rhs::for_each_consumed` leaves them out) only read their value. Fields start borrowed and stay borrowed while only read; Perceus takes ownership of a field only where it is needed (consumed, live after a call, live at a jump target, or live after its owner's last reference is consumed), by `dup` when the owner is still needed there and otherwise by resolving the owner with `release` from the parent down (which frees a unique box and hands its references to the kept fields); a retained owner is decref'd once its last borrowed field dies (the Perceus section of `docs/spec/lir.md`). So a `Lin` field is never dupped, and `eml_runtime`'s `Heap::dup` of a `File` object is always a heap error (`HeapError::LinShared`, "a Lin object is shared"), with or without `debug_heap`. `eml_core_ir::lower(hir, typed, entry, &SourceFiles) -> eml_lir::Program` (and `lower_until(.., eml_lir::Pass)`) runs `Pass::{Translate, Evidence}` (`core_until` stops there and returns Core IR), then `to_lir`, then `eml_lir::passes_until`, which runs `eml_lir::Pass::{Boxing, Contract, Perceus}`; each crate's `pipeline.rs` knows only its own order. Debug builds also run three linearity checks in translate (`docs/spec/core-ir.md`): `check_linearity` in `translate/instances.rs` compares each reference with its callee instance, each `perform` with its operation's declared type, and each handler clause with the operation (`TypeStore::lin_compatible` rejects an `unr` meeting a `lin`), and `check_captures` in `translate/expr.rs` requires that an `unr` closure captures only `Unr` values; a body that translate does not copy is asserted to hold no `Var`. Verifiers run in debug builds: Core IR has two levels (`verify_translated` after translate, which rejects `prim` / `clause` before EP; `verify_evidence` after evidence, which rejects `handle` / `perform` / `resume` / `mask`), LIR has three (`verify_lowered`, run by `passes_until` on its input and reported as `invalid LIR before boxing`, rejects `tail`, `box`, `unbox`, RC instructions and `save`; `verify_scopes` after boxing and contract adds the boundary checks of calls, function values and `tobj` fields; `verify` after Perceus adds ownership). The mark checks are V2 (sender and receiver marks are compatible: only an `unr` meeting a `lin` fails, `poly` meets both, constants meet any; run wherever Repr compatibility is compared, so Core IR and the LIR entry level check only `jump` and `return`, and `perform` / `handle` / `resume` are never compared; binders of a `never` result are exempt, a `clause` call's evidence argument and a `clause` function's evidence parameter are `unr`), V1 (LIR ownership level only: no `dup` or `decref` of a non-`unr` variable) and the build check (a `con` or `closure` binder's mark is at least the join of its arguments' marks, `unr` < `poly` < `lin`, at every level). Compatibility is not transitive, so contract's tail-call formation and translate's `jump` forwarding also require compatible (forwarding: equal) marks. `unpack` and case field marks are trusted (layouts carry no Kind). `drop x` (release one reference, not "destroy") is a consuming rhs that Perceus adds nothing around: EP emits it for the dead yield result `x` on slow paths (a dummy) and in `prompt$` and the `compose$` / `mask$` slow paths, and for `ret` on the abort path of `prompt$` (the one real cleanup: it closes a captured `File`); translate emits `drop v` at a decision-tree leaf that takes apart a non-`unr` value and binds no non-`unr` variable out of it. A non-`unr` `con` variable is opened by the decision tree (its arguments read directly) only when the scrutinee is its only use (a let-bound local referenced exactly once) and the decision is static or no arm receives it; `materialize_once` merges only `unr` occurrences. Hence Perceus emits only `release` on a non-`unr` variable. Translate lowers each (function, type arguments, row bits) instance that `translate/instances.rs` collects from the entry (names `f@[Int]`, with arrow linearity shown as `%1` for `Lin` and `%m` for `Poly` (`id@[Int %1 -> Int]`, so instances differing only in linearity get distinct names); row bits set for row variables that may yield written `twice<e>`, uniform positions `_`, polymorphic recursion made uniform per type-variable position; the row bits come from `eml_types`' per-reference `Instantiation::rows: Vec<RowYield>`; the uniform positions are computed by `eml_types` after type checking, `TypedProgram::uniform`, which also reports E2012), resolves each method reference through `eml_types::resolve` to an instance method, a class default, an extern row, or a function generated for a derived or tuple instance (`translate/derive.rs`; names like `"Show Color.show"`, quoted in the IR text like extern names with spaces), builds blocks forward (`FnBuilder`), makes case-of-case itself, forwards jumps to return-only blocks, marks lifted and helper functions `internal`, marks functions and `apply`s that may yield `yields` (splitting an `apply` after each arrow that may yield), and gives extern calls source positions; translate alone emits `handle` / `perform` / `resume` and call `mask`s. Evidence (`evidence/`, `docs/spec/core-ir.md` evidence passing) replaces them: a context `evv` (persistent list of evidence objects, innermost first) and a yield state replace handler frames (the primitives and the runtime model are in `docs/spec/lir.md`); `perform` becomes `prim ev_lookup` + `prim ev_clause` + a `clause E.op` call; each clause becomes an in-place entry function (`clause` mark): immediately resuming clauses with no yield point run in place, others start a yield (`yield_to`, or `yield_abort` for `never`); each non-tail yield point in a `yields` function gets a `prim yielding` check whose slow path composes a continuation closure `f$kN` (join blocks reached become `f$jJ`); helper functions `id$` / `compose$` / `prompt$` / `resume$` / `rewind$` / `mask$[…]` are not `internal`; a yielding function returns a dummy (`prim dummy()`, `0`, `#0`, `()`) that `box` / `unbox` / `dup` / `decref` / `drop` must pass through. Boxing fixes the whole-program ABI (T3 raises a scalar `ret` to `tobj` when a tail-position call's result would need a conversion; a `never` operation's `clause` returns nothing, so T3, boxing and the verifier never compare its result and contract makes a tail one a `tail clause`; value-only internal functions become uniform in place, `clause`-marked functions conform to their operation's ABI, other functions used as values get a uniform `f$boxed`) and inserts `box` / `unbox`; contract removes unused pure `let`s and is the only pass that forms tail calls, when the call's result is compatible with the caller's `ret`. The interpreter's control is (function, block, statement); its frames are `Frame::{Return, Apply, Root}` (`Frame::Root` is the bottom of every continuation), `Frame::Return.resume` is an executor-defined `u64`, primitives live in `eml_interp/src/prims.rs` (their table, `Prim::row`, in `eml_lir`) and do not release their borrowed arguments, `clause` runs like `apply`, and `Value::Dummy` is a non-heap value. Runtime errors from an extern call print `{fault}` and `  at path:line:column`.
- Diagnostic codes are defined in a per-stage `codes` module (e.g. `eml_syntax::codes`, E0xxx). E0004 (not yet supported) is used by every stage, so it lives in `eml_diagnostics` (`NOT_YET_SUPPORTED`, `Diagnostic::not_yet_supported`).
- `eml_cli::Session` is `Send + Sync` (asserted in `crates/eml_cli/tests/api.rs`) for the front end's sake (moving onto salsa, parallel compilation): `ItemTree` holds no rowan red nodes, only `AstPtr`s into each module's `LoadedModule.parse`. HIR keeps only positions of written names and nodes; derived layout (line starts, indentation) is computed from the source text where needed (`eml_types::check` takes `&SourceFiles` for the E3003 fix). The interpreter and `eml_runtime` are single-threaded (`u32` RC, `OutputSink` wraps `Rc<RefCell<dyn Write>>`, `eml_interp::run` and `eml_cli::execute` take `&eml_lir::Program` and return `RunStats`; `Session::compile` / `compile_until(eml_lir::Pass)` return `Compiled<eml_lir::Program>` and `compile_core_until(eml_core_ir::Pass)` returns `Compiled<eml_core_ir::Program>`); parallelism is planned for a native runtime only (`docs/future/multicore.md`). `RunConfig` is `#[non_exhaustive]`; build it from `Default`.
- `eml_syntax` implements the grammar of the finished milestones M1 and M2 (modules: `import`, `pub`, qualified names; `docs/implementation/status.md`), of S5 (type classes: `class`, `instance`, contexts with the reserved `=>`, `deriving`; `docs/spec/grammar.md`), of S6a (list expressions and patterns `[…]`; `::` is the Prelude's `List` constructor, reserved to the Prelude by E1044), of S6b (string interpolation `\{…}`, whose holes call the Prelude's `Show.display` through `LangItems`; multi-line `"""` and raw `r"…"` strings; `docs/spec/lexical.md`), and of S6c (nominal records: `| P { name : T }` constructors, construction `P { name = e }`, update `{ p | name = e }`, record patterns, projections `p.name` and `t.0`, sections `(.name)` and `(.0)`; `docs/spec/records.md`; inside `{` a line-final `=` opens no block; a `,` closes every block above the innermost bracket, an effect row `<…>` after `->` counts as a layout bracket, a line-start `,` or closing token skips layout rules 1-3, and a line that continues at the column of a block a mid-line `,` closed is E0015, `docs/spec/layout.md`). The lexer keeps a stack of modes (`Code`, `String`, `Command`) and splits ordinary and multi-line strings and command literals into tokens (`STRING_START`, `STRING_TEXT`, `ESCAPE`, `INTERP_START`, `INTERP_END`, `STRING_END`; `CMD_*` for commands), while a raw string stays one `RAW_STRING` token; it emits exactly one `INTERP_END` per hole (zero-width when the hole is unclosed at a line end or at end of file) so the layout stage and the parser always find where a hole ends. An operator run starting with `-><` is split into `->` and the rest, so operators starting with `-><` cannot be declared. Constructs planned for later (float and char literals and command literals after S13, and `type` aliases) are lexed and parsed far enough for HIR to report E0004; the parser reports no E0004, and a `{` without a constructor (an anonymous record) is an E0011 that skips to its `}` (`docs/implementation/status.md`). The order of the work is in `docs/future/roadmap.md`.

## Testing

- Work test-first (TDD). Snapshots use `insta`, mostly inline (`@"..."`).
- Each crate's integration tests build into one binary, `integration` (`autotests = false`; `tests/main.rs` declares every file as a module). A file not declared there does not run. Libs set `doctest = false`, and libs without unit tests also set `test = false` (`docs/implementation/testing.md`).
- UI tests (`crates/eml_cli/tests/ui.rs`): `tests/ui/run/**/*.em` must run to completion and `tests/ui/run-fail/**/*.em` must compile cleanly and end in a runtime error, and `tests/ui/check-fail/**/*.em` must produce at least one error; output is snapshotted. Pass/fail expectation is decided by the top-level directory, and every test sits in a category subdirectory below it (`docs/implementation/testing.md`). A test is one file `<top>/<category>/<name>.em` or one directory `<top>/<category>/<name>/main.em` whose other `.em` files are the modules it imports; the harness fails on any other layout. Run tests always enable `debug_heap`.
- `crates/eml_cli/tests/cli.rs` checks the binary's exit codes (0 success / 1 diagnostic or runtime error / 2 usage error).
- Benchmarks (`docs/implementation/benchmarks.md`): the programs in `bench/` have their `RunStats` pinned by inline snapshots in `crates/eml_interp/tests/bench.rs`, so a change in work counts shows up as a snapshot diff (an expected-value change). `bench/run.sh` (macOS only) measures `instructions retired` with `/usr/bin/time -l` on a release build; record its output in `benchmarks.md` at the end of a stage.
- Test changes come in three kinds (`docs/implementation/testing.md`): (1) pass/fail changes (moving a test between `run`, `run-fail` and `check-fail`, deleting a test, UI or unit) are listed one by one in the work's spec; (2) expected-value changes (UI output, diagnostic codes or wording, stage-dump snapshots such as Core IR, moving a UI test without changing pass/fail) are described as a scope in the work's spec (e.g. "rewrite every UI test that uses E3005"); approving the spec is the agreement for kinds 1 and 2, and the reason goes in the spec and the commit message; (3) mechanical follow-ups that keep every expected value byte-identical need no agreement, and the commit message is the record.
- Never bend the design to keep existing tests unchanged (no parallel enum variants, flags, test-only fields, or spec exceptions for that purpose). Put the test change in the work's spec instead, stating its kind.
- `eml_test_support` (dev-only) wraps `eml_cli::Session` for integration tests (`lower` / `def_map` / `check` / `core_until` / `lir` / `lir_until` / `run` / `run_stats` / `execute`, multi-file `*_files` variants that take root-relative `(path, text)` modules read through `MemorySource`, and `parse_clean` / `lower_clean` that assert a clean source; `lower_clean` needs `hir`; `lower_with_std` / `check_with_std` substitute the standard-library tree, which must still contain `Prelude.em` and the real `Fs.em`) and formats diagnostics (`short` / `short_text` / `full`, fixes with `fixes`, joined to a stage dump with `with_diagnostics`). `parse` runs only the syntax stage and needs no feature. `Lowered` / `Checked` keep the `Session` and expose `files()` / `file()`; `core_until(text, eml_core_ir::Pass)` returns Core IR, `lir(text)` the final LIR and `lir_until(text, eml_lir::Pass)` an intermediate one; `execute` takes an `eml_lir::Program`; `run_stats` also returns the interpreter's `RunStats` (eight work counts `evidence_steps`, `yields`, `yield_frames`, `string_bytes_copied`, `rc_increments`, `rc_decrements`, `boxes`, `unboxes`, and `peak_objects`, the peak number of live heap objects), which `eml_interp`'s scaling tests bound instead of timing; `def_map*` return the loading and def_map diagnostics. Core IR tests are written as IR text read by `eml_core_ir::parse`, LIR tests as IR text read by `eml_lir::parse` (hand-written LIR tests live in `crates/eml_lir/tests` and call `boxing` / `contract` / `perceus` directly; source-pipeline tests stay in `crates/eml_core_ir/tests`). Use it only from `tests/`, never from `#[cfg(test)]` in `src/`: the crate under test would be linked twice. For the same reason `eml_types` unit tests cannot use `eml_cli`; its `#[cfg(test)]` helper `test_program_with_files` in `src/lib.rs` wires load -> def_map -> lower directly. Stages are features (`hir` < `types` < `core` < `run`) that also enable the matching `eml_cli` features; each crate enables only up to its own stage, so its tests still build while downstream crates are broken mid-refactor. Tests of a stage's own API (loading in `eml_hir`, `eml_hir::item_tree`, `eml_types` scaling, entry selection in `eml_core_ir` translate) call the stage functions directly.

## Syntax

The final syntax is defined in `docs/spec/` (`lexical.md`, `layout.md`, `grammar.md`, `declarations.md`, `expressions.md`, `records.md`, `modules.md`; program examples in `examples.md`). When a syntax choice is undecided, lean toward Haskell conventions.
